# 기록 파일 형식 — record.json

케이스 폴더마다 `record.json` 을 하나 둔다. `scripts/build_report.py` 가 이 파일을 읽어 검사하고, 케이스마다 보고서 한 장과 결과 폴더의 케이스 목록 한 장을 만든다.
스크립트는 아래 표에 없는 키를 오타로 보고 막는다. 표에 키를 더하려면 스크립트의 `*_FIELDS` 도 같이 고친다.

## 폴더 구조

```text
{앱 루트}/.mcp_screenshots/test-evidence/
├── index.html                          ← 케이스 목록. 스크립트가 만들고 다시 돌리면 덮어쓴다
├── TC-001-transfer-leader-cancel/
│   ├── index.html                      ← 이 케이스 보고서. 스크립트가 만든다
│   ├── record.json
│   ├── 00-start.png                    ← 첫 조작을 누르기 직전 화면
│   ├── 01-picker.png
│   └── 02-after-picker-cancel.png
└── TC-002-appoint-vice-leader/
    ├── index.html
    ├── record.json
    ├── 01-menu.png
    ├── 02-picker.png
    └── 02-picker-title.png              ← 확대 사진도 같은 폴더에 둔다
```

폴더 이름은 `TC-{번호}-{영문 요약}` 으로 짓는다. 케이스를 고친 뒤 다시 돌리면 같은 폴더에 덮어쓴다 — 이전 결과는 남기지 않는다. 사진 이름은 소문자 · 숫자 · 하이픈으로 된 `.png` 만 받는다 (`01-menu.png`). 대문자나 공백이 들어가면 HTML 경로에서 깨진다.

## 키

### 케이스

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `id` | 예 | 문자열 | 케이스 번호 (`TC-002`). 케이스끼리 겹치면 안 된다 |
| `title` | 예 | 문자열 | 기대 동작을 한 문장으로 |
| `summary` | 예 | 문자열 | 결론 한 문장. 실패가 있으면 어느 시나리오에서 무엇이 틀렸는지 쓴다 |
| `meta` | 예 | 객체 | 실행 정보 — 아래 표 |
| `fix` | 아니오 | 객체 | 고친 뒤 다시 돌린 결과일 때 무엇을 고쳤는지 — 아래 표. 케이스 보고서 머리에 붙는다 |
| `background` | 아니오 | 문자열 목록 | 테스트 전 상태. 옆 칸에 항목으로 붙는다 |
| `scenarios` | 예 | 객체 목록 | 시나리오 하나 이상 — 아래 표 |
| `run` | 아니오 | `[이름, 값]` 목록 | 접어 둔 "실행 정보" 에 들어간다. 호출한 MCP 도구와 핵심 결과를 적는다 |

### meta

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `date` | 예 | 문자열 | 실행 시각 (`2026-09-24 22:09`) |
| `device` | 예 | 문자열 | 기기와 운영체제 판 |
| `commit` | 아니오 | 문자열 | 앱 커밋. 머리 줄에 `커밋 {값}` 으로 붙는다 |

### fix

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `note` | 예 | 문자열 | 고친 내용 한 문장 |
| `commit` | 아니오 | 문자열 | 고친 커밋. 커밋하기 전에 다시 돌렸으면 뺀다. 시험한 코드의 커밋은 `meta.commit` 에 쓴다 |

### 시나리오

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `name` | 예 | 문자열 | 시나리오 이름 |
| `steps` | 예 | 객체 목록 | 단계 하나 이상 — 아래 표 |
| `shots` | 아니오 | 사진 객체 목록 | 시나리오 왼쪽에 크게 붙는 캡처 |
| `skipped` | 아니오 | 문자열 | 진행하지 못한 이유. 있으면 시나리오가 미실행이 되고, 판정한 단계가 있으면 오류다 |

### 단계

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `kw` | 예 | 문자열 | Gherkin 한국어 키워드 — `먼저` · `조건` · `만일` · `만약` · `그러면` · `그리고` · `하지만` · `단` |
| `text` | 예 | 문자열 | 단계 문장. 사용자가 하려는 일(의도)을 쓴다 |
| `do` | 행동 단계면 예 | 조작 항목 목록 | 실제로 한 조작을 순서대로 — 아래 표. 첫 `그러면` 앞의 `만일` · `만약` · `그리고` · `하지만` · `단` 에 필수, `먼저` · `조건` 과 판정 없는 확인 구간 단계는 선택, 판정한 단계에는 붙이지 않는다. 조작이 3 개를 넘으면 보고서에서 나머지를 접고, 8 개를 넘으면 경고한다 |
| `result` | 아니오 | `pass` · `fail` | 판정. 확인 단계에만 붙인다 |
| `seen` | `result` 가 있으면 예 | 문자열 | 실제로 본 것. 도구가 돌려준 관측값을 쓴다 |
| `zoom` | 아니오 | 사진 객체 | 판정한 단계 바로 아래 붙는 확대 사진 |

### 조작 항목

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `act` | 예 | 문자열 | 조작 하나 (`"⋯ 버튼 탭"`) |
| `shot` | 건너뛰지 않은 시나리오면 예 | 문자열 | 그 조작을 하기 직전 캡처의 케이스 폴더 안 파일 이름. 누른 결과는 다음 조작이나 확인 단계 사진에서 보인다. 사진 객체와 같은 이름 규칙 · PNG 검사를 받는다. 같은 파일을 여러 조작이 가리켜도 된다 |
| `at` | 아니오 | 숫자 두 개 목록 `[x, y]` | 누르거나 밀기 시작한 곳. `shot` 사진의 픽셀 좌표라 `shot` 이 있어야 하고 사진 안이어야 한다. 있으면 보고서가 조작 칸에 화면 폭은 그대로 두고 위아래만 누른 곳 주변으로 잘라 넣고 동그라미로 표시한다. 없으면 화면 전체를 줄여 보여 준다 |

### 사진 객체

| 키 | 필수 | 형식 | 뜻 |
| --- | --- | --- | --- |
| `file` | 예 | 문자열 | 케이스 폴더 안 파일 이름 |
| `caption` | 예 | 문자열 | 사진 아래 설명 |

## 판정 계산

판정은 적지 않는다. 스크립트가 단계의 `result` 로 계산한다.

- 확인 단계는 첫 `그러면` 과 그 뒤의 `그리고` · `하지만` · `단` 이다. `먼저` · `조건` · `만일` · `만약` 과 첫 `그러면` 앞의 단계에 `result` 를 붙이면 오류다.
- 시나리오: `skipped` 가 있으면 미실행, 확인 단계 중 `fail` 이 하나라도 있으면 실패, 아니면 통과. 건너뛰지 않았는데 판정한 단계가 없으면 오류다.
- 케이스: 실패한 시나리오가 있으면 실패, 통과한 시나리오가 있으면 통과, 전부 미실행이면 미실행.
- 케이스 목록에서 실패한 케이스가 위로 온다.

## 스크립트가 막는 것

아래는 종료 코드 1 로 멈추고 `index.html` 을 하나도 쓰지 않는다 — 목록과 케이스 보고서 전부를 검사가 끝난 뒤에만 쓴다. 오류 줄에 케이스 폴더와 문제 필드가 찍힌다.

- JSON 문법 오류 · 표에 없는 키 · 필수 키 누락 · 형식이 틀린 값 · 빈 문자열
- 케이스 폴더에 없는 사진 · 규칙에 안 맞는 사진 이름 · PNG 가 아닌 파일
- Gherkin 한국어 키워드가 아닌 `kw` · `pass` · `fail` 이 아닌 `result` · 확인 단계가 아닌 곳의 `result` · `seen` 없는 `result`
- `do` 없는 행동 단계 · 목록이 아니거나 빈 `do` · 객체가 아니거나 `act` 가 비었거나 모르는 키가 든 조작 항목 · 건너뛰지 않은 시나리오에서 `shot` 없는 조작 항목 · 숫자 두 개가 아니거나 `shot` 없이 쓰거나 사진 밖을 가리키는 `at` · 판정한 단계의 `do` · `note` 없는 `fix`
- 판정한 단계가 없는 시나리오 · 판정이 있는 건너뛴 시나리오 · 겹치는 `id` · `record.json` 이 있는 케이스 폴더가 하나도 없음

한 단계의 조작이 8 개를 넘으면 경고만 찍고 계속한다. 기록이 가리키지 않는 PNG 가 케이스 폴더에 있어도 경고만 찍고 계속한다. 다시 돌리며 이름이 바뀐 캡처가 남은 경우다 — 그 케이스 폴더 안의 그 파일만 지운다.
