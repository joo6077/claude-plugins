# Bambu Model

출력할 부품을 코드로 만든다. 두 갈래다 — 없는 부품을 새로 그리기(CadQuery), 있는 원본 설계 파일의 치수 바꾸기(퓨전 360).
결과는 STL 이고, 출력 설정은 이 스킬이 만들지 않는다.

## Gotchas

1. **퓨전은 화면 프로그램이라 못 다룬다고 결론 내지 마라.** 명령줄로는 못 부르지만 켜질 때 저절로 도는 추가 기능으로 다룬다.
   `scripts/fusion-job.sh` 가 깔고, 퓨전을 다시 켜고, 끝나면 걷어 낸다. 실측(2026-11-01): 다른 세션이 이걸 몰라 원본 치수를 못 바꿨다.
2. **CadQuery 를 가상 환경이나 세션 임시 폴더에 따로 깔지 마라.** 전역 python3 에 깔고, 있으면 그대로 쓴다.
   임시 폴더에 깔면 다음 세션이 못 찾는다.
3. **CadQuery 를 `python3 -I`(격리 모드)로 부르지 마라.** 의존 패키지(fontTools)가 사용자 폴더 `~/.local` 에만 있으면
   `No module named 'fontTools'` 로 죽는다 (2026-11-01 실측).
4. **퓨전을 TERM 이나 KILL 로 끄지 마라.** 퓨전은 TERM 을 충돌로 받아 충돌 보고 장치가 기록하다 다시 죽고, 그동안 1~2 분 프로세스가 남는다.
   그래서 «안 꺼짐»(종료 코드 4)과 «다시 켜기 거부»(`Operation already in progress`)가 번갈아 났다 — 실측(2026-11-09): 껐다 켤 때마다 충돌 기록이 하나씩 쌓였다.
   실행 스크립트는 `scripts/fusion-restart.sh` 로 정상 종료 요청을 보내고 완전히 꺼질 때까지 기다린다. 그래도 남으면 종료 코드 4 로 멈추니, 사용자에게 퓨전을 직접 끄게 한다.
5. **모양은 그림으로 확인한 뒤 사용자에게 보인다.** 크기 숫자만 보고 「됐다」 하지 마라 — 신발 걸이 시안은 숫자가 맞는데도
   사용자가 원한 모양과 달라 다섯 번 고쳤다. 사용자가 고른 시안을 기준으로 작게 고쳐 간다.
6. **AddIns 폴더에 다른 추가 기능이 있으면 먼저 치워라.** manifest 의 `runOnStartup` 을 `false` 로 바꿔도 퓨전은 자기 목록대로 계속 켤 때마다 돌린다.
   두 추가 기능이 같이 돌면 이 킷의 작업 신호가 처리되지 않아 시간 초과(종료 코드 3)로 끝난다 — 실측(2026-11-01): 옛 추가 기능을 지우자 15 초 만에 끝났다.
   지원 운영체제 값은 `windows|mac` 이다. 다른 값을 쓰면 퓨전이 추가 기능을 조용히 건너뛴다.
7. **원본 부품의 구멍 · 결합부를 새 부품에 맞출 땐 원본에서 재라.** 짐작한 나사 지름을 쓰지 마라 —
   `report.txt` 의 `HOLE` 줄이 원본의 실제 구멍 지름이다.
8. **CadQuery 의 모서리 둥글리기 · 윤곽 굵히기가 깨지면 STEP 으로 내보내 퓨전에서 마감한다.** 복잡한 모양에서 `fillet` 이
   `BRep_API: command not done` 으로 죽거나 고체가 깨진다(실측 2026-11-07, 옷 거는 부속 4 종). 모양만 CadQuery 로 정하고
   `cq.exporters.export(part, "<이름>.step")` 으로 낸 뒤 `scripts/fusion-fillet/fillet-job.sh` 가 둥글리기 · STL · 그림을 맡게 한다.
9. **부품 끝에 공을 붙이지 마라.** 끝 공은 고체를 자주 깨뜨리고 사용자가 「끝 공은 앞으로 하지마」 라고 했다.
   끝은 둥근 마감(굵기 그대로 반원)이나 살짝 들린 갈고리로 끝낸다.
10. **확인 그림에 부품 이름을 넣는다.** 비슷한 걸이를 여러 개 보이면 사용자가 「어떤게 헤드셋이고 어떤게 가방임?」 하고 묻는다.
    그림 파일 이름과 그림 제목에 부품 이름을 넣고, 여러 장을 한 판에 모으면 칸마다 이름을 적는다.
11. **다른 부품에 붙는 부품은 상대의 원본 STEP 과 합쳐서 이음매를 둥글리고, `seam-check.py` 로 이음매를 검사한다.** 붙는 쪽만 따로 둥글리면
    맞닿는 자리가 각진 채 남는다 — STL 은 둥글릴 수 없어서다. 상대 부품의 f3d 를 4 단계로 돌려 `<부품>__<몸체>.step` 을 받고, 3 단계의 `join` 작업으로 합친다.
    실측(2026-11-08, 지갑 쟁반에 붙는 워치 받침): 받침만 둥글려 보이자 사용자가 «이어진 부분이 부자연스럽다 · 벽에서 튀어나온 부분 · 잘린 느낌» 을 여러 번 짚었다.
    둥글리기 전 합친 모양을 검사기에 넣자 바로 그 벽 안쪽 끝에서 날카로운 모서리 16 개가 나왔다.

## Process

### 1. 도구 확인

```bash
bash "<이 스킬 폴더>/scripts/ensure-cadquery.sh"
```

`있음: CadQuery <판>` 이면 그대로 쓰고, 없으면 이 스크립트가 `python3 -m pip install` 로 깐다. 종료 코드 1 이면 출력된 import 오류를 사용자에게 보인다.

### 2. 새 부품 그리기 (CadQuery)

0. 참고 모델을 찾는다. 같은 쓰임새의 모델을 MakerWorld · Printables · Thingiverse 에서 인기순(좋아요 · 만든 사람 수)으로 모아
   그림마다 번호를 붙여 한 장으로 보이고, 사용자가 번호로 고르게 한다. 고른 모델이 있으면 내려받아 단면 · 치수를 재서 따른다 — 짐작으로 다시 그리지 않는다.
   - MakerWorld 는 자동 접속이 막힌다. `https://3dfinder.io/model/makerworld/<모델 번호>` 쪽의 og:image 그림과 좋아요 수를 쓴다.
   - Printables 는 `https://api.printables.com/graphql` 의 `searchPrints2` 를 `ordering: makes_count` 로 부른다.
   - Thingiverse 그림은 받아지지 않을 때가 많다 — 받은 파일이 그림인지(파일 종류) 확인하고 아니면 목록에서 뺀다.
1. `references/design-language.md` 와 `references/charlie-design.md` 를 읽는다. 사용자가 다른 스타일을 말하지 않으면 「공통 결정 10가지」(색 하나 · 부품마다 기본 도형 하나 · 긴 직선 + 꺾임 하나 · 또렷한 이음 · 작은 모서리 · 줄 맞춤)로 그린다.
2. 결합 치수(막대 지름 · 구멍 · 벽 두께)를 먼저 확정한다. 원본과 맞물리면 4 단계 보고에서 잰 값을 쓴다.
3. 부품 코드를 `.py` 하나로 쓰고, 바뀔 치수는 인자로 받는다. 결과는 `cq.exporters.export(part, "<이름>.stl")`.
4. 그림으로 모양을 확인한다. 각도를 바꿔 두세 장 찍는다.

   ```bash
   python3 "<이 스킬 폴더>/scripts/render.py" <이름>.stl <이름>-front.png 10 -90
   python3 "<이 스킬 폴더>/scripts/render.py" <이름>.stl <이름>-iso.png 25 -55
   ```

5. 그림과 크기(그림 제목에 나온다)를 사용자에게 보이고 고칠 점을 받는다. 코드와 STL 은 사용자 작업 폴더에 둔다.

### 3. 마감 — 퓨전 둥글리기 · 그림

CadQuery 로 모양이 정해졌는데 둥글리기가 깨지거나 그림이 거칠면, STEP 으로 내보내 퓨전 추가 기능이 마감하게 한다.

1. 부품마다 `cq.exporters.export(part, "<이름>.step")` 으로 둥글리기 없는 STEP 을 낸다.
2. 작업 파일을 쓴다. `radii` 는 큰 값부터 시도할 둥글기(mm)다 — 모든 모서리를 한 번에 둥글리다 실패하면 다음 값, 끝까지 실패하면 모서리를 하나씩 시도한다.

   ```json
   {"out_dir": "/abs/path/fusion-out", "parts": [{"name": "bag_hook", "step": "/abs/path/bag_hook.step", "radii": [3, 2.5, 2, 1.5, 1]}]}
   ```

3. 사용자에게 퓨전이 한 번 꺼졌다 켜진다고 알리고 돌린다.

   ```bash
   bash "<이 스킬 폴더>/scripts/fusion-fillet/fillet-job.sh" job.json
   ```

4. 결과를 읽는다. `out_dir` 에 부품마다 `<이름>.stl` 과 그림 네 장(`<이름>_iso` · `_front` · `_side` · `_top` .png)이 생긴다. `fillet-job.log` 의 `PART <이름> fillet=<값>` 이 쓰인 둥글기다 — 숫자면 한 번에, `하나씩 성공/전체` 면 모서리별로 둥글렸다. 하나씩일 때 실패 수가 많아도 대개 이미 매끈하게 이어진 모서리라 그림으로 판정한다.
5. 그림 네 장을 사용자에게 보인다. 퓨전 화면 그림이 `render.py` 그림보다 면 이음이 정확하다.
6. 종료 코드별로 다음을 한다.

   | 코드 | 뜻 | 다음 |
   | --- | --- | --- |
   | 0 | 끝남 | 위 4 번처럼 결과를 읽는다 |
   | 1 | 추가 기능이 실패 | 출력된 `fillet-job.log` 의 오류를 읽고 STEP · 작업 파일을 고친다 |
   | 2 | 작업 파일 · 첫 STEP 경로 오류 | 경로를 고친다. 퓨전은 건드리지 않았다 |
   | 3 | 시간 초과(`BAMBU_FUSION_TIMEOUT`, 기본 600 초) | 퓨전이 로그인 창에서 멈췄는지 사용자에게 묻는다 |
   | 4 | 퓨전이 안 꺼짐 — 정상 종료 요청에도 남음 | 확인 창이 떠 있는지 사용자에게 묻고, 퓨전을 직접 끈 뒤 다시 돌린다 |
   | 5 | 퓨전을 못 켬 — 다시 시도해도 macOS 가 거부 | 퓨전이 아직 꺼지는 중일 수 있다. 잠시 뒤 다시 돌린다 |

#### 다른 부품에 붙는 부품 — 합쳐서 이음매 둥글리기 · 검사

쟁반 벽에서 자라 나오는 받침처럼 다른 부품에 붙는 부품은 상대 원본과 한 몸으로 합쳐 맞닿는 자리까지 둥글린다.

1. 상대 부품의 f3d 를 4 단계로 돌려 `<부품>__<몸체>.step` · `.stl` 을 받는다. 붙는 부품은 CadQuery 로 같은 좌표에 그려 STEP · STL 을 낸다.
2. 작업 파일의 부품에 `"step"` 대신 `"join"` 을 준다. 첫째가 바탕(자기 모서리는 둥글리지 않는다), 둘째부터 붙일 것이다. 먼저 합치고, 붙인 것에서 온 모서리를 `radii` 로, 새로 생긴 이음매를 `seam_radii` 로 둥글린다. 합치기 전에 붙일 것을 둥글리면 바탕 벽과 같은 평면으로 맞닿을 모서리까지 깎여 홈이 생긴다. 이음매 둥글기는 얇은 쪽 벽 두께의 1/4~1/2 에서 시작한다.
   - `"round_base_touch": true` 를 주면 이음매 꼭짓점으로 이어진 바탕의 각진 모서리(예: 쟁반 안쪽 바닥-벽 모서리)도 이음매와 한 번에 둥글린다. 바탕 모양이 바뀌니 사용자에게 먼저 묻는다.
   - 붙일 것은 바탕의 둥근 모서리 위에 각지게 걸치지 않게 그린다. 바탕 STEP 의 면을 재서(평면 · 원통 반지름) 평평한 구간 안에서 같은 평면으로 맞붙이면 이음매가 둥글려진다.
   - `radii` 는 바탕의 둥근 모서리와 만나는 붙인 것 모서리에서 너무 크거나 작으면 그 꼭짓점에서 깨진다. 워치 받침은 `[2, 1.5, 1]` 이 맞았다(3 이나 1 은 실패).

   ```json
   {"out_dir": "/abs/path/fusion-out", "parts": [{"name": "stand_join", "join": ["/abs/path/base__Body1.step", "/abs/path/stand.step"], "radii": [2, 1.5, 1], "seam_radii": [3, 2.5, 2, 1.5, 1], "round_base_touch": true}]}
   ```

3. `fillet-job.sh` 로 돌린다. 기록 줄 `PART <이름> fillet=<붙인 것 모서리> seam=<꺾인 이음매 수> seam_smooth=<이미 매끈한 이음매 수> seam_fillet=<값> base=<함께 둥글린 바탕 모서리 수>` 을 읽는다. 이미 매끈하게 이어진(양쪽 면 방향이 5° 안) 이음매는 퓨전이 둥글리지 못하고 한꺼번에 둥글리기를 망쳐서 뺀다. 두 몸체가 안 닿으면 `이음매 모서리 0 개` 로 FAIL 한다.
4. 합친 STL 을 두 원본 STL 과 대어 이음매를 검사한다.

   ```bash
   python3 "<이 스킬 폴더>/scripts/seam-check.py" <out_dir>/<이름>.stl <바탕>.stl <붙일 것>.stl
   ```

   seam-check.py 가 통과(종료 코드 0)하기 전에는 그림을 사용자에게 보이지 않는다. 검사는 두 원본 표면 양쪽에서 `--near`(기본 1.5 mm) 안에 있는 모서리 가운데, 이웃 면이 `--angle`(기본 30°) 넘게 꺾인 것을 센다. 원본에 이미 있던 꺾임은 빼고 센다. `join` 부품의 마감 STL 은 이웃 삼각형 법선 차이 15° 로 촘촘히 내므로 30° 넘는 꺾임은 진짜 꺾임이다. «높음» 품질은 둥글기 2 mm 를 33~36° 로 나눠 헛 실패가 났다. 대신 STL 이 커진다(쟁반 하나에 약 95 MB).

   | 코드 | 뜻 | 다음 |
   | --- | --- | --- |
   | 0 | 통과 — 이음매에 날카로운 모서리 없음 | 그림 네 장을 사용자에게 보인다 |
   | 1 | 날카로운 모서리 있음 | `SHARP angle=… at=(x,y,z)` 자리를 보고 `seam_radii` 를 키우거나, 붙는 부품의 뿌리 모양을 고쳐 다시 돌린다 |
   | 2 | 입력 오류 — 파일 없음 · 못 읽음 · 이음매 근처 모서리 0 개 | 경로와, 세 STL 이 같은 좌표인지 본다 |

### 4. 원본 f3d 치수 바꾸기 (퓨전 360)

1. 작업 파일을 쓴다.

   ```json
   {"source": "/abs/path/model.f3d", "out_dir": "/abs/path/out", "params": {"dowel_size": "32 mm"}, "holes_under_mm": 40}
   ```

   매개변수 이름을 모르면 `params` 를 비워 한 번 돌려 `report.txt` 의 `BODY` · `HOLE` 줄로 원본을 먼저 잰다.
2. 사용자에게 퓨전이 한 번 꺼졌다 켜진다고 알리고 돌린다.

   ```bash
   bash "<이 스킬 폴더>/scripts/fusion-job.sh" job.json
   ```

3. 결과를 읽는다. `out_dir` 에 보이는 몸체마다 `<부품>__<몸체>.stl` 과 같은 좌표의 `<부품>__<몸체>.step` 이 생긴다. STEP 은 이 부품에 붙는 새 부품을 3 단계 `join` 으로 합칠 때 쓴다. `report.txt` 에는 `PARAM`(바뀐 값) · `BODY`(크기 mm) · `HOLE`(원통 구멍 지름 · 길이 · 축) 줄이 있다.
4. 종료 코드별로 다음을 한다.

   | 코드 | 뜻 | 다음 |
   | --- | --- | --- |
   | 0 | 끝남 | 아래 3 번처럼 결과를 읽는다 |
   | 1 | 추가 기능이 실패 | 출력된 `fusion-job.log` 의 오류를 읽고 작업 파일을 고친다 |
   | 2 | 작업 파일 · 원본 경로 오류 | 경로를 고친다. 퓨전은 건드리지 않았다 |
   | 3 | 시간 초과(`BAMBU_FUSION_TIMEOUT`, 기본 600 초) | 퓨전이 로그인 창에서 멈췄는지 사용자에게 묻는다 |
   | 4 | 퓨전이 안 꺼짐 — 정상 종료 요청에도 남음 | 확인 창이 떠 있는지 사용자에게 묻고, 퓨전을 직접 끈 뒤 다시 돌린다 |
   | 5 | 퓨전을 못 켬 — 다시 시도해도 macOS 가 거부 | 퓨전이 아직 꺼지는 중일 수 있다. 잠시 뒤 다시 돌린다 |

### 5. 출력 설정으로 넘기기

STL 이 확정되면 `/bambu-print-profile` 로 출력 설정을 만든다. 부품 이름 · 크기 · 결합 치수(공차가 필요한 구멍)를 같이 넘긴다.
