## 2. 목표와 수단을 구분해 저장한다

**저장하는 것은 목표(품질)이고, 속도는 수단이다.** 이 구분을 흐리면 "품질 우선" 이 "저속" 으로
번역되어, 저속이 오히려 품질을 해치는 소재(PETG 의 ooze 누적)에서 틀린 값이 나간다.

| 구분 | 저장 여부 | 이유 |
|---|---|---|
| 목표 — "표면 품질이 최우선" | **저장한다** | 세션과 무관하게 유지되는 사용자 의도 |
| 제약 — "시간은 상관없다" | **저장한다** | 트레이드오프 판단의 입력 |
| 수단 — "외벽을 30 mm/s 로" | **저장하지 않는다** | 소재·형상마다 달라진다. `surface-recipes.md` §3 이 정한다 |

> 사용자 원문 (2026-09-05): *"난 속도보다 퀄리티 우선이라고 항상 말해야하고 근데 퀄리티가
> 나올라면 속도가 빨라야한다면 괜찮고 걍 퀄리티임"*

> 사용자 원문 (2026-09-05): *"솔직히 랜덤 별로임"*

⚠️ **2026-05-17 의 반대 방향 피드백과 함께 읽어라.** 그때는 *"차라리 랜덤"* · *"내가 뭘
페인팅해야 한다는 거"* 였고 거부 대상은 **수작업 부담**이었다. 두 발언 모두 목표는 품질이며,
`spiral_mode` + `spiral_mode_smooth` 는 수작업 0 + 진짜 해결이라 둘을 동시에 만족한다.
자세한 정리는 `seam-recipes.md` §0.

즉 **느림은 목표가 아니다.** 품질을 위해 속도를 올려야 하면 올린다. 속도를 낮추는 것이 품질에
기여한다는 근거가 그 소재·형상에 있을 때만 낮춘다.

## 3. Phase 1.8 이 이 파일을 쓰는 방법

```text
Phase 1.8 진입
  │
  ├─ 이 파일이 있는가?
  │      YES → §1 표면 의도를 그대로 적용하고 사용자에게 되묻지 않는다.
  │            판정 근거로 "user-preferences.md §1 (확인일 YYYY-MM-DD)" 을 인용한다.
  │      NO  → 기존 대화형 판정 절차를 따른다.
  │
  └─ 사용자가 이번 출력에 한해 다른 의도를 명시했는가?
         YES → 이번 실행만 그것을 따른다. 이 파일은 고치지 않는다.
```

**일회성 예외로 이 파일을 갱신하지 마라.** 지속 선호가 실제로 바뀌었을 때만 §1 표와 확인일을
고친다.

## 4. 이 선호가 무효화하지 않는 것

표면 우선이어도 아래는 그대로 지킨다.

- 유량비 게이트 (`SKILL.md` §유량비 게이트) — 표면 우선이라고 유량 계단을 허용하지 않는다
- 소재 안전 조건 (PETG · PA · PC 건조, CF 소재 hardened nozzle)
- Creator 명시 제약 (`comment-analysis.md` §5 권장 강도별 적용 범위)
- fit-critical 공차 (`tolerance.md`)
