api-kit / static evidence viewer contract

정적 증거 뷰어 계약

검증 결과를 사람이 읽는 단일 HTML 리포트가 지켜야 할 제약. 외부 의존 0건, file:// 직접 열람, 신뢰할 수 없는 응답 본문의 안전한 인라인, 비밀 마스킹을 다룬다. 확정 시안은 .mockups/api-ui-v7.html 이다. v0.1.0 · 최종 갱신 2026-09-04

중심 제약 — 의존성 0, 단일 ui.html

뷰어는 외부 참조 0건의 단일 HTML 이어야 한다. 설계문서 §12 확정 결정표는 UI 를 "정적 뷰어 — 의존성 0 단일 ui.html, 브라우저 발사 없음"으로 못박았다. 고급 기능도 런타임 의존성을 늘리는 대신 생성 시점 precompute 로 해결한다.

외부 JS·CSS·폰트·이미지를 하나라도 요구하는 순간, 리포트는 file:// opaque origin, CDN 장애, supply-chain 변조 셋 모두에 노출된다. 에어갭 환경에서는 아예 열리지 않는다.

이 페이지 자체가 그 제약의 실물 예시다. 지금 보고 있는 문서는 외부 subresource 를 하나도 부르지 않는다 — <script src 0건, <link rel=stylesheet 0건, 웹폰트·원격 이미지 0건. CSS 와 스크립트는 전부 인라인이고, 열었을 때 나가는 네트워크 요청도 없다. 아래 본문에 보이는 fetch( 와 XMLHttpRequest 는 안티패턴 예시의 텍스트일 뿐 실행되는 코드가 아니다.

01 · 이 문서가 결정하는 것

리포트 한 장을 만들 때 세 가지를 정한다. 무엇을 파일 안에 넣을지(인라인 범위), 브라우저가 무엇을 하지 못하게 막을지(차단), 그리고 그 데이터를 어떤 순서로 사람에게 보여줄지(표시 계층). 셋 중 하나라도 빠지면 증거 리포트가 아니라 그냥 결론 페이지가 된다.

Step 1 — 인라인 전부 파일 안으로 CSS·JS·데이터·아이콘까지 단일 파일에 넣는다. sidecar JSON 을 옆에 두고 읽는 방식은 file:// 에서 막힌다.
Step 2 — 차단 나가는 요청 0건 CSP connect-src 'none' 으로 fetch·XHR·WebSocket·EventSource·beacon·ping 을 명시적으로 막는다.
Step 3 — 표시 raw · normalized · diff 세 단계를 각각 보여주고, 비밀은 기본 비표시로 덮는다. 중간 단계를 감추면 판정을 재현할 수 없다. 
ui.html (단일 파일)
 │
 ├─ <style> ............ 인라인 CSS (외부 폰트·CSS 0)
 │
 ├─ <script type="application/json">
 │     escape( raw )        ← < · </script · <!-- 세 패턴 escape
 │     escape( normalized )
 │     escape( diff )
 │  </script>
 │
 ├─ <script> ........... 인라인 파서 + 렌더러
 │     JSON.parse(block.textContent)
 │     el.textContent = value       ← innerHTML 금지
 │
 └─ CSP meta
       default-src 'none'; connect-src 'none';
       object-src 'none'; base-uri 'none'; form-action 'none'

나가는 네트워크 요청: 0
읽는 외부 파일: 0

데이터는 실행 코드가 아니라 데이터 블록으로 들어간다. JS 리터럴로 넣으면 응답 본문이 곧 실행 코드가 된다.

02 · 확정 결정과 자기 검증

브라우저는 요청을 쏘지 않는다. 요청 실행은 이미 Hurl + CLI 가 맡고 있고, 브라우저 Try it 을 넣으면 얻는 것 없이 CORS·프록시·토큰 저장 세 문제가 새로 생긴다.

설계문서 §12 — UI 관련 확정 결정

폼: 편집 가능, 실행 은 커맨드를 클립보드 복사 (§11.2)

고급 기능: 생성 시점 precompute 로 런타임 의존성 0 유지 (§11.7)

확정 시안: .mockups/api-ui-v7.html

설계문서 §11.1 · §11.2 · §11.7 · §12 확정 결정표

이 페이지에 적용한 같은 제약

뷰어 계약을 설명하는 문서가 그 계약을 어기면 문서 자체가 반례가 된다. 그래서 이 페이지도 같은 규칙으로 만들었다. 아래는 이 파일을 직접 센 값이다.

<script src 0건
<link rel=stylesheet 0건
웹폰트 · 원격 이미지 0건
실행되는 네트워크 호출 0건

fetch( · XMLHttpRequest 문자열은 안티패턴 예시 안에 텍스트로 등장한다. 실행되는 호출은 없으므로 위 표에서는 "실행되는 네트워크 호출" 로 세었다.

출처 없음 — 이 문서의 자체 측정값
주의. 이 문서는 docs-site 페이지이므로 CSP <meta> 를 넣지 않는다. 뷰어(ui.html)는 넣는다. 다만 <meta> CSP 는 헤더의 완전한 대체가 아니므로, <meta> 를 넣었다는 사실만으로 네트워크 차단을 보증했다고 보고하면 안 된다.
03 · 원칙

열 개 원칙은 두 축으로 나뉜다. 1–2 는 "무엇에도 의존하지 않는다", 3–6 은 "신뢰할 수 없는 본문을 안전하게 담는다", 7–10 은 "판정을 재현 가능하게 보여준다".

1

Zero Runtime Dependency

중심 제약

뷰어는 외부 참조 0건의 단일 HTML 이어야 한다. 외부 JS/CSS/font/image 를 요구하면 file:// opaque origin, CDN 장애, supply-chain 변조에 그대로 노출된다.

file:// 문서는 현대 브라우저에서 대체로 opaque origin 으로 취급되므로 같은 폴더의 파일조차 same-origin 으로 가정할 수 없다. 모든 데이터를 인라인한다.

→ MDN Same-origin policy — file origins → MDN Subresource Integrity
2

No Browser Network Calls

차단

리포트를 열었을 때 fetch, XHR, WebSocket, EventSource, beacon, link ping 중 어느 것도 나가면 안 된다. CSP connect-src 'none' 으로 이 계층을 명시적으로 차단한다.

증거 리포트가 네트워크를 쓰는 순간, 열람 행위 자체가 관측 대상 시스템에 영향을 준다.

→ MDN CSP connect-src
3

Data-as-Data Embedding

인라인

JSON 증거는 실행 스크립트가 아니라 데이터 블록으로 넣는다. <script type="application/json"> 같은 non-JS MIME 은 브라우저가 실행하지 않고 author script 가 파싱한다.

증거를 JS 리터럴로 넣으면 응답 본문이 곧 실행 코드가 된다.

→ HTML Standard — script element → MDN — embedding data in HTML
4

Script-block Escape 규칙

escape

데이터 블록에 넣더라도 신뢰할 수 없는 본문은 그대로 쓰지 않는다. script 요소 내용에는 문법 제약이 있어 </script 문자열이 블록을 조기 종료시킬 수 있다.

인라인 전에 <, </script, <!-- 세 패턴을 escape 한다.

→ HTML Standard — restrictions for contents of script elements
5

XSS-safe Rendering

렌더링

응답 본문은 신뢰할 수 없는 입력이다. raw body 를 innerHTML 에 넣지 말고 HTML entity encoding 또는 textContent 같은 safe sink 로만 렌더링한다.

대상 API 가 반환한 문자열이 리포트를 여는 사람의 브라우저에서 실행되면 안 된다.

→ OWASP XSS Prevention Cheat Sheet
6

Redacted-by-default Rendering

마스킹

토큰, 쿠키, Authorization, API key 는 기본 비표시다.

Hurl 이 secrets redaction 을 제공하더라도 raw stdout 과 저장된 응답에는 비밀이 남을 수 있다고 문서가 경고한다. 그래서 뷰어는 자체 redaction 레이어를 따로 갖는다.

→ Hurl Secrets → Hurl Redacting Secrets
7

Raw / Normalized / Diff 분리

재현

raw evidence, normalize 후 비교 입력, 최종 diff 를 각각 따로 보여준다.

Hurl assertion 은 status/header/body/query/predicate 단위로 실패를 설명한다. 중간 단계를 감추면 "왜 실패로 판정했는가"를 재현할 수 없다.

→ Hurl Asserting Response
8

Operation Grouping + Severity Filtering

집계

operation/testcase 단위 그룹핑과 failure / error / skipped 필터를 제공한다.

JUnit XML 생태계의 testsuite/testcase 구조와 집계 필드를 그대로 따르면 같은 결과를 CI 대시보드와 뷰어가 동일하게 센다.

→ JUnit XML 포맷 레퍼런스
9

Copy-safe Reproducer

재현 커맨드

재현 명령은 복사 가능해야 하지만 비밀은 제거되어야 한다. Hurl 은 --curl 로 curl 커맨드를 내보내므로, 뷰어는 마스킹된 curl/hurl 재현 커맨드를 artifact 에 포함한다.

붙여넣기만으로 토큰이 유출되는 경로를 남기지 않는다.

→ Hurl Debug Tips — export curl commands
10

Offline Bundle Integrity

무결성

단일 HTML 안에 digest manifest 를 넣어 증거의 변조 여부를 확인할 수 있게 한다.

SRI 자체는 fetch 된 리소스 검증용이지만, "기대 content 를 해시로 검증한다"는 운영 원칙은 오프라인 번들에도 그대로 적용된다.

→ W3C Subresource Integrity → MDN Subresource Integrity
04 · 수치 기준

아래 값 중 상당수는 표준 문서에서 온 것이고, 일부는 확정 시안 실측 또는 운영 임계값이다. 근거 열에서 둘을 구분해 표기한다.

항목값근거
CSP 최소 정책 default-src 'none'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none' → MDN default-src → MDN connect-src
외부 참조 개수 <script src 0 / <link rel=stylesheet 0 / fetch( 0 / XMLHttpRequest 0 확정 시안 .mockups/api-ui-v7.html 실측
텍스트 대비 일반 4.5:1 이상, large text 3:1, UI component·graphical object 3:1 → WCAG 2.2
텍스트 확대 200% 까지 정보 손실 없음 → WCAG 2.2
클릭 타깃 최소 크기 44px 확정 시안 .mockups/api-ui-v7.html 실측

해시 알고리즘 sha256 최소, 가능하면 sha384 이상 (sha256 / sha384 / sha512) → W3C SRI
단일 HTML evidence payload 10MiB 초과 warning, 50MiB 초과 시 split·excerpt 모드 출처 없음 — 이 킷의 설계 결정 (표준 한계가 아니라 브라우저 parse·메모리·UX 리스크를 줄이는 운영 임계값)
redaction 검증 통과 기준 known secret pattern unredacted match 0건 출처 없음 — 이 킷의 설계 결정 (추론)

인라인 payload 크기 구간

정상 < 10MiB
warning 10 ~ 50MiB
split · excerpt > 50MiB

이 구간은 표준 한계가 아니라 운영 임계값이다. MDN 이 기재한 data URL 한계(512MB / 2048MB)와는 다른 축의 수치다.

05 · 안티패턴

뷰어를 만들 때 가장 자주 나오는 다섯 가지 실수다. 앞의 셋은 코드로, 나머지는 표로 정리한다.

BADsidecar JSON 을 fetch 로 읽는다
// file://report.html 에서 실행
const data = await fetch('./data.json')
  .then(r => r.json());
render(data);

opaque origin 때문에 CORS 로 막혀 리포트가 빈 화면이 된다. 한 브라우저에서 열리더라도 다른 브라우저에서는 막힌다.

GOOD데이터 블록에서 파싱한다
// 같은 파일 안의 데이터 블록
const el = document.getElementById('evidence');
const data = JSON.parse(el.textContent);
render(data);

외부 요청이 없으므로 origin 정책과 무관하게 어느 브라우저에서든 열린다.

인라인만이 이식 가능한 유일한 방법이다. "내 크롬에서 열리니까 괜찮다"는 검증이 아니다.

BADraw body 를 innerHTML 로 렌더링
panel.innerHTML = response.body;

대상 API 가 반환한 문자열이 열람자 브라우저에서 실행된다. 증거를 보는 행위가 공격 경로가 된다.

GOODsafe sink 로만 넣는다
panel.textContent = response.body;

textContent 는 마크업을 해석하지 않는다. 하이라이팅이 필요하면 파싱 후 요소를 직접 만들어 붙인다.

BADescape 없이 데이터 블록에 넣는다
<script type="application/json">
{"body":"... </script> ..."}
</script>

본문 안의 종료 태그 문자열이 블록을 조기 종료시켜 이후 마크업이 파서에 노출된다. 실행되지 않는다는 것과 안전하다는 것은 다르다.

GOOD세 패턴을 escape 한다
escape 대상:
  <        →  <
  </script →

HTML Standard 의 script 내용 제약을 그대로 반영한 escape 다. 생성 파이프라인에서 한 번만 적용하면 된다.

Bad — 결론만 남은 리포트

redacted view 만 있고 raw·normalized·diff 단계가 없다.

판정 근거를 재현할 수 없다. "실패"라는 글자만 남고, 왜 실패인지는 다시 CLI 를 돌려야 안다.

Good — 세 단계 모두 보인다

raw evidence → normalize 후 비교 입력 → 최종 diff 를 각각 펼칠 수 있다.

비밀은 기본 비표시로 덮되, 어느 단계에서 값이 갈렸는지는 그대로 보인다.

06 · Gotchas 체크리스트

ui.html 을 생성하고 배포하기 전에 확인한다. 하나라도 미흡하면 리포트가 열리지 않거나, 열리는 대신 비밀을 흘린다.

  • ✗외부 참조가 정말 0건인가. <script src, <link rel=stylesheet, 웹폰트 URL, 원격 이미지까지 전부 센다. 아이콘 하나 때문에 에어갭 환경에서 깨지는 경우가 흔하다.
  • !file:// origin 처리는 브라우저마다 다르다. 한 브라우저에서 로컬 파일 읽기가 되더라도 다른 브라우저에서는 막힌다. "내 크롬에서 열리니까 괜찮다"는 검증이 아니다. 인라인만이 이식 가능한 유일한 방법이다.
  • !<script type="application/json"> 도 안전하지 않다. 실행되지 않을 뿐, 본문에 </script 가 있으면 블록이 조기 종료되어 이후 마크업이 파서에 노출된다. escape 를 건너뛰지 마라.
  • !CSP <meta> 는 헤더의 완전한 대체가 아니다. 정적 HTML 에서 유용하지만 일부 지시어는 <meta> 로 적용되지 않는다. <meta> CSP 를 넣었다는 사실만으로 네트워크 차단을 보증했다고 보고하지 마라.
  • ✗Hurl secret redaction 은 저장된 raw 응답까지 보증하지 않는다. 마스킹은 도구 출력 계층의 기능이고, 뷰어가 인라인하는 원본에는 비밀이 남을 수 있다. 마스킹은 Hurl 문서를 믿지 말고 리포트 생성 파이프라인에서 한 번 더 수행한다.
  • ✓raw body 를 넣는 sink 가 textContent 인가. innerHTML 이 한 곳이라도 남아 있으면 나머지 아홉 곳의 방어가 무의미하다.
  • ✓copy 버튼이 마스킹된 커맨드를 복사하는가. Authorization 헤더가 그대로 들어가면 리포트 공유가 곧 자격증명 유출이다.
  • ✓digest manifest 를 넣었는가. SRI 는 fetch 된 리소스용이지만 해시 검증 원칙은 오프라인 번들에도 적용된다. sha256 이 최소, 가능하면 sha384 이상.
  • ✓대비와 확대 기준을 만족하는가. 일반 텍스트 4.5:1, large text 와 UI component 3:1, 텍스트 200% 확대에서 정보 손실 없음. 라이트·다크 둘 다 확인한다.
  • !payload 크기를 확인했는가. 10MiB 초과면 warning, 50MiB 초과면 split·excerpt 모드로 내린다. 이건 표준 한계가 아니라 파싱·메모리·UX 를 지키는 운영 임계값이다.
