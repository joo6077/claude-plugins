Planning Kit v0.1 · Flows

Flows

"화면이 어디로 가는가"만이 flow가 아니다. User Flow · Journey Map · Service Blueprint · IA는 해상도와 질문이 다르다. Mermaid는 이들을 lightweight하게 문서화할 때 유용한 공식 문법을 제공한다.

01 · Artifacts

Flow Artifacts

각각은 대체 관계가 아니라 질문이 다른 도구다.

1

User Flow vs Journey Map vs Service Blueprint

User Flow는 task completion 경로, Journey Map은 감정과 시간 순 경험, Service Blueprint는 frontstage/backstage 운영 체계.

  • "checkout drop-off" → User Flow
  • "신뢰가 깨지는 순간" → Journey Map
  • "지원 문의 반복" → Service Blueprint
NN/g — Journey Mapping 101
2

Service Blueprint

사용자 접점 뒤의 내부 운영/시스템 계층까지 함께 그린다. customer action · frontstage · backstage · support process · 시스템 4레이어가 핵심.

  • line of interaction · line of visibility를 기준으로 레이어 구분
  • pain point와 handoff 실패 지점을 동시에 보여줌
  • CX 개선 + 내부 운영 개선을 동시에 추적
NN/g — Service Blueprints
3

IA (Information Architecture)

콘텐츠와 기능을 사람이 이해하고 찾기 쉬운 구조로 조직한다. Rosenfeld/Morville의 organization · labeling · navigation · search 4축이 전통적 축.

  • 라벨은 내부 조직 용어가 아닌 사용자 언어
  • navigation depth · breadth 균형 (3레벨 넘으면 경고)
  • search-first vs browse-first 영역 구분
O'Reilly — Information Architecture 4e
4

Mermaid Flowchart

빠른 decision flow · onboarding path · approval branch를 Markdown 안에 직접. flowchart LR 선언 + 노드/엣지 정의.

  • 방향: LR (funnel), TD (hierarchy)
  • 분기 조건은 edge label로
  • 소문자 end 같은 예약어 피하기
Mermaid — Flowchart Syntax
5

Mermaid Sequence Diagram

actor/system 간 메시지 순서를 표현. API handshake · payment callback · async flow에 적합.

  • participant를 역할 단위로 정의
  • 시간축 = 위→아래
  • 분기는 alt/else
Mermaid — Sequence Diagram
6

Mermaid State / Journey

stateDiagram-v2는 엔터티 상태 전이 (order · ticket · review lifecycle). journey는 간단한 user journey + 만족도 점수.

  • state: 상호배타적 · terminal state 명시
  • journey: section별 score(1~5) + actor
  • 복잡한 blueprint는 표현 부족 — 도구를 혼합하라

04 · Anti-patterns

안티패턴 vs 좋은 패턴

한 도표에 모든 해상도를 욱여넣으려는 유혹.

Bad

한 장에 user flow + journey + blueprint 섞기

가독성이 무너지고 어느 질문에도 답하지 못한다.

Good

질문별로 artifact를 분리 생성

각 artifact 상단에 "이 문서가 답하려는 질문"을 한 문장으로 적는다.

Bad

IA를 사이트맵만으로 축소

실제 탐색 경험(search · filter · cross-link)을 놓친다.

Good

IA + tree test / card sort 결과 첨부

사용자 mental model 기반 검증 결과를 함께 관리.

Bad

화면 이동을 Sequence Diagram으로 표현

screen navigation에는 부적합 — flowchart나 sitemap이 낫다.

Good

Sequence = 시스템 상호작용 전용

actor/API/service 간 메시지 순서에 한정.

05 · Gotchas

Gotchas

flow artifact에서 반복되는 실수.

!
Journey Map이 마케팅 문서로 전락

"긍정적 경험"만 그리지 말고 실제 pain point · drop point를 포함해야 진단 도구로 기능한다.

!
Service Blueprint에 시스템 레이어 누락

backstage까지만 그리고 시스템 의존/데이터 흐름을 빼면, 지원팀 개선은 되지만 엔지니어링 요구는 나오지 않는다.

!
Mermaid Flowchart의 예약어 충돌

소문자 end 같은 노드 이름은 파서가 flow block으로 해석할 수 있다. 노드 id는 명시적 식별자로.

!
State Diagram과 화면 네비 혼동

상태 전이는 엔터티(order/ticket)의 lifecycle이다. 화면 A→B 이동은 flowchart가 맞다.

!
Mermaid journey로 상세 blueprint 대체 시도

점수 1~5만으로는 backstage/support 흐름을 표현할 수 없다. 간단한 as-is 정리용.
