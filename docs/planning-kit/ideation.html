Planning Kit v0.1 · Ideation

Ideation

Discovery 이전의 0단계 — 막연한 직관을 넓게 펼친 뒤 구조화된 후보군으로 바꾼다. Guilford의 발산–수렴 사고와 Double Diamond를 뼈대로, HMW · Crazy 8s · SCAMPER · Affinity Diagram · Dot Voting 등 17가지 방법론을 발산 → 정리 → 수렴의 왕복 리듬으로 연결한다.

00 · Rhythm

3박자 리듬

너무 빨리 수렴하면 변주만 남고, 너무 오래 발산하면 아이디어 무덤이 된다.

Phase 1

Divergent · 발산

관점 전환과 조합 가능성을 늘린다. 평가·반박 금지. HMW · Crazy 8s · SCAMPER · Brainwriting 6-3-5 · Analogous · Reverse.

Phase 2

Organize · 정리

유사성으로 묶고 언어를 정제한다. 라벨링은 마지막에. Affinity · Mind Map · Concept Map · Story Map.

Phase 3

Convergent · 수렴

기준과 트레이드오프로 좁힌다. 인기투표 아니다. Dot Voting · Impact-Effort · Decision Matrix · NUF.

01 · Methods

17가지 방법론

상위 프레임 2개 + 발산 7 + 정리 4 + 수렴 4.

1Frame

Divergent ↔ Convergent / Double Diamond

Guilford의 발산-수렴 사고를 Design Council이 실무 프로세스로 번역한 상위 프레임. 한 번 넓히고 한 번 좁히는 리듬이 discovery와 development 양쪽에 반복된다.

  • 지금은 발산 시간인가 수렴 시간인가
  • 평가가 발산을 침범하고 있진 않은가
  • 넓히기/좁히기의 종료 조건을 정했는가
Design Council — Double Diamond
2Frame

IDEO 3 Lenses (Desirability · Feasibility · Viability)

아이디어의 질을 세 렌즈의 교차점으로 본다. 죽이는 체크리스트가 아니라 약한 축을 보강하는 도구로 써야 한다.

  • 세 렌즈 중 하나만 강하고 둘이 비어 있지 않은가
  • desirability 약점은 치명, feasibility 약점은 실험으로 감축 가능
IDEO — Design Thinking
3Sprint

Design Sprint Week의 Ideation 위치

월(맵) → 화(sketch) → 수(결정). Ideation은 문제 정의 뒤, 의사결정 전의 짧고 강한 발산-수렴 구간이다.

  • 월요일 HMW가 충분히 준비됐는가
  • 화요일 스케치에 개인 작업 시간을 보장했는가
  • 아이디어를 외화된 형태로 남겼는가
Sprint Book — How
4Divergent

How Might We (HMW)

관찰·불편을 기회 질문으로 리프레이밍. How might we + [누구] + [원하는 변화] + [제약]? 너무 열리지도 닫히지도 않게.

  • 해결책이 질문에 이미 박혀 있지 않은가
  • 한 insight에서 HMW 여러 개 뽑았는가
  • 결핍 언어 대신 가능성 언어인가
IDEO Design Kit — HMW
5Divergent

Crazy 8s

8분 동안 8개의 거친 스케치. 손이 생각보다 먼저 움직이게 해 자기검열을 줄인다. 완성도가 아니라 양과 변주가 핵심.

  • 1칸당 1분 타임박스
  • 말보다 손 스케치
  • 베스트 1이 아니라 패턴을 읽는다
Miro — Crazy 8s Template
6Divergent

SCAMPER

Substitute · Combine · Adapt · Modify · Put to another use · Eliminate · Reverse. 기존 해법을 비틀어 변형을 만들 때 강하다. 완전 무(無)에서 시작하지 않는다.

  • 제거(Eliminate)하면 오히려 좋아지는 것은
  • 순서를 뒤집으면 무엇이 보이는가
  • 출발점이 빈약하면 변주도 빈약
Miro — SCAMPER Template
7Divergent

Brainwriting 6-3-5

6명 × 3개 × 5분 라운드로 타인 아이디어를 빌드업한다. 위계가 강한 팀, 원격 협업, 발화 편중 세션에서 편차를 줄인다.

  • 새 아이디어와 확장 둘 다 허용
  • 익명성 또는 반익명성
  • 마지막 라운드 직후 클러스터링
Springer — 6-3-5 연구
8Divergent

Analogous Inspiration

같은 행동·감정·제약이 일어나는 전혀 다른 맥락에서 영감을 가져온다. 표면 카피가 아니라 구조적 원리를 번역해야 한다.

  • 핵심 행동·감정·제약을 먼저 추출
  • 유사 산업/서비스를 탐색
  • 맥락 번역 실패 시 얄팍한 모방으로 전락
IDEO Design Kit — Analogous
9Divergent

Reverse Brainstorming / Worst Possible Idea

"어떻게 망하게 만들까?"를 묻고 뒤집어 설계 원칙을 추출한다. 막힌 팀과 심리적 안전에 강하다. 반드시 뒤집기 단계를 붙여야 한다.

  • 최악 → 역발상 실마리
  • 웃긴 아이디어에서 실제 리스크 신호 추출
  • 아이스브레이커로 끝내지 말 것
Miro — Reverse Brainstorming
10Divergent

Mash-ups (조합 자극)

Analogous의 확장. 서로 무관한 두 맥락을 강제로 결합해 새 컨셉을 만들어본다. "X와 Y를 합치면?"이 출발점.

  • 제약이 강할수록 창의적 결과
  • 우스꽝스러운 조합도 먼저 적어라
  • 결과는 조합 원리만 남기고 표면은 버린다
IDEO Design Kit — Mash-ups
11Organize

Affinity Diagramming / KJ Method

Kawakita Jiro의 KJ Method 계열. 개별 메모를 먼저 읽고 유사성으로 묶은 뒤 라벨을 마지막에 붙인다. 묶음 이름은 카테고리가 아니라 통찰 문장.

  • 미리 정한 카테고리 배치 금지
  • 고립 메모와 큰 묶음 모두 의미를 읽는다
  • HMW의 바닥이 된다
KJ Method 공식
12Organize

Mind Mapping

Tony Buzan의 방사형 구조. 중심 주제에서 가지를 뻗어 자유 발산과 빠른 구조화를 동시에 한다. 1차 가지는 서로 다른 관점 축.

  • 중심 주제 한 단어
  • 세부 가지는 키워드, 설명문 금지
  • 트리 고정이 너무 일찍 일어나지 않게
Tony Buzan — The Mind Map Book
13Organize

Concept Mapping

Novak의 명제 네트워크. 노드-선-연결어로 의미 관계를 드러낸다. Mind Map보다 인과·교차 링크에 강하다.

  • 선 위의 연결어가 관계를 설명하는가
  • cross-links가 필요한가
  • focus question이 명확한가
IHMC — Concept Map Theory
14Organize

Story Mapping (Ideation 변형)

Jeff Patton. 사용자 활동 흐름을 backbone으로 두고, 그 아래에 여러 대안 아이디어를 꽂는다. 플랫 backlog가 아닌 서사 전체를 본다.

  • 흐름의 빈칸을 드러내기
  • 상세 user story로 내려가지 말기
  • outcome 우선, 기능 나중
O'Reilly — User Story Mapping
15Convergent

Dot Voting / Multi-voting

선호를 빠르게 가시화하는 약한 신호 수집기. 최종 결정 도구가 아니다. 투표 전 기준을 공유해야 한다.

  • 점수는 결정이 아닌 토론 입력
  • 코멘트와 이견도 함께 기록
  • novelty 아이디어가 익숙한 아이디어에 지는 편향 주의
Miro — Dot Voting
16Convergent

Impact-Effort Matrix

기대 효과 × 실행 부담. quick wins · major projects · fill-ins · low-value로 사분면을 가른다. 불확실성을 effort 낮음으로 착각하지 말 것.

  • impact 기준 명시 (고객·사업·학습 가치)
  • effort에 운영·법무 비용 포함
  • impact vs certainty 분리
Miro — Impact-Effort Matrix
17Convergent

Decision Matrix / NUF Test

다기준 가중 점수화(Decision Matrix)와 New·Useful·Feasible 세 렌즈(NUF). 숫자는 객관성을 보장하지 않는다 — 기준 선정이 전부다.

  • 기준 충돌을 드러내는 도구로 써라
  • 민감도 분석을 덧붙여라
  • NUF는 가벼운 1차 필터로만
Miro — Decision Matrix

03 · Anti-patterns

안티패턴 vs 좋은 패턴

Ideation이 "의견 강자 변명 세션"으로 전락하는 실수들.

Bad

발산 중인데 평가·반박이 섞인다

"그거 예전에 해봤는데 안 됐어"가 나오면 아이디어 수가 급감한다.

Good

발산 시간과 수렴 시간을 물리적으로 분리

퍼실리테이터가 "지금은 발산"이라 명시하고 평가 금지 룰을 강제한다.

Bad

브레인스토밍만으로 끝낸다

외화된 산출물이 없다. 다음 날이면 대부분 잊힌다.

Good

Crazy 8s + Brainwriting으로 외화

스케치·노트·보드로 남겨 Affinity · HMW 재료가 된다.

Bad

Dot Voting을 최종 결정으로 사용

인기투표가 되어 novelty 아이디어가 죽는다.

Good

투표는 토론 입력, 결정은 기준 + 매트릭스

Impact-Effort 또는 Decision Matrix로 기준 충돌을 드러내고 합의한다.

Bad

Affinity 전에 카테고리를 미리 정한다

KJ Method가 아니라 정리정돈이 된다. 새로운 묶음이 떠오르지 않는다.

Good

개별 메모 먼저, 라벨은 마지막

묶음 이름은 추상 카테고리가 아니라 통찰 문장에 가깝게.

04 · Gotchas

Gotchas

세션이 산으로 가는 전형.

!
HMW 문장이 좋다고 아이디어가 좋아지지 않는다

추상적이면 공허해지고, 너무 solution-leading이면 아이디어 폭이 급감한다. 1 insight → 여러 HMW로 변주하라.

!
Reverse Brainstorming을 아이스브레이커로만 쓰지 말 것

뒤집기와 설계 원칙 추출 단계를 반드시 붙여야 생산적이다.

!
Mind Map은 인과·교차 링크에 약하다

개념 관계가 중요하면 Concept Map을 쓰고, 자유 연상이 필요하면 Mind Map을 써라. 혼용하지 말라.

!
Impact-Effort Matrix는 self-confirmation 도구가 되기 쉽다

점수 근거가 빈약하면 팀 선호를 숫자처럼 포장한다. 각 축 정의를 명시하고 불확실성을 별도 차원으로 둬라.

!
Story Mapping을 ideation에서 너무 상세하게 내려가지 말 것

user story 단위로 쪼개면 솔루션 공간이 좁아진다. ideation에서는 흐름과 옵션만 본다.

!
NUF는 다른 기법보다 원전 계보가 약하다

가볍게 1차 필터로 쓰고, 중요한 결정에는 기준과 근거를 보강하라.
