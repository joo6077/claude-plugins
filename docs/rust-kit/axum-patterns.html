Axum 패턴

tokio + tower 생태계 위에 구축된 ergonomic Rust 웹 프레임워크. 0.8.x부터 Router, State, Extractor 구성 방식이 확립되었다. 매크로 없이 타입 시스템으로 라우팅과 미들웨어를 표현하는 것이 핵심이다.

핵심 원칙

Axum이 강제하는 타입 안전 패턴 5가지. 각 원칙의 출처는 axum 공식 문서 및 0.8.x 마이그레이션 가이드에서 도출했다.

1

Router 계층적 구성

도메인별로 Router를 분리하고 .nest()로 조합한다. 각 도메인 모듈이 자체 router() 함수를 반환하게 하면 변경 범위가 제한된다.

pub fn router() -> Router<AppState> {
    Router::new()
        .route("/", get(list_users).post(create_user))
        .route("/:id", get(get_user).delete(delete_user))
}

// lib.rs — 조합
Router::new()
    .nest("/users", users::router())
    .nest("/posts", posts::router())
    .with_state(state)

2

State는 Clone 비용이 낮아야 한다

State<T>는 요청마다 T를 클론한다. PgPool, Arc<dyn Port> 같은 경량 핸들만 담는다. 무거운 리소스를 직접 포함하면 요청마다 복사 비용이 발생한다.

#[derive(Clone)]
pub struct AppState {
    pub db: PgPool,           // 내부 Arc 사용
    pub auth: Arc<dyn AuthPort>,
    pub config: Arc<Config>,
}
O(1) clone 보장
3

Extractor 조합으로 요청 파싱 선언

Path, Query, Json 등을 함수 파라미터로 선언하면 Axum이 자동으로 파싱하고 실패 시 400 응답을 반환한다. 핸들러 내에서 request.body()를 직접 파싱하지 않는다.

async fn list_users(
    State(state): State<AppState>,
    Query(pagination): Query<Pagination>,
    Json(filter): Json<UserFilter>,
) -> impl IntoResponse { ... }
타입 안전 파싱
4

IntoResponse 구현으로 응답 타입 통일

핸들러마다 (StatusCode, Json<...>) 튜플을 반복하지 않는다. ApiResponse<T> 래퍼에 IntoResponse를 구현하고 공통 에러 변환을 처리한다.

pub enum ApiResponse<T: Serialize> {
    Ok(T), Created(T), Error(ApiError),
}

impl<T: Serialize> IntoResponse for ApiResponse<T> {
    fn into_response(self) -> Response {
        match self {
            Self::Ok(d) => (StatusCode::OK, Json(d)).into_response(),
            Self::Created(d) => (StatusCode::CREATED, Json(d)).into_response(),
            Self::Error(e) => e.into_response(),
        }
    }
}
응답 추상화
5

FromRequestParts로 커스텀 Extractor

인증 토큰 추출, 요청 컨텍스트 주입 등 반복되는 파싱 로직은 커스텀 Extractor로 추출한다. 핸들러 시그니처가 의도를 명시적으로 표현하게 된다.

pub struct AuthUser(pub Claims);

#[async_trait]
impl<S> FromRequestParts<S> for AuthUser
where
    S: Send + Sync,
    AppState: FromRef<S>,
{
    type Rejection = ApiError;
    async fn from_request_parts(
        parts: &mut Parts, state: &S,
    ) -> Result<Self, Self::Rejection> {
        // Bearer 토큰 추출 → 검증 → Ok(AuthUser(claims))
    }
}

안티패턴

Axum 코드베이스에서 반복적으로 발견되는 잘못된 패턴과 올바른 대안.

Bad — with_state() 중복 호출
// 서브 라우터에서 미리 호출
let user_router = users::router()
    .with_state(state.clone()); // ❌

Router::new()
    .nest("/users", user_router)
    .with_state(state) // 충돌
Good — 최상위에서 한 번만
// 서브 라우터: 타입 파라미터만 명시
pub fn router() -> Router<AppState> {
    Router::new().route("/", get(handler))
}

// 최상위에서 한 번만 with_state()
Router::new()
    .nest("/users", users::router())
    .with_state(state) // ✅
Bad — Extension으로 데이터 전달
// Extension은 타입당 하나만, 런타임 패닉 위험
app.layer(Extension(db_pool.clone()))

async fn handler(
    Extension(pool): Extension<PgPool>, // 런타임에 없으면 500
) { ... }
Good — State 또는 커스텀 Extractor
// State로 타입 안전하게 공유
async fn handler(
    State(state): State<AppState>,
) -> impl IntoResponse {
    let pool = &state.db; // ✅ 컴파일 타임 보장
}
Bad — 핸들러에서 Request 직접 파싱
async fn handler(req: Request<Body>) {
    let body = req.into_body();
    let bytes = hyper::body::to_bytes(body).await?;
    let data: MyDto = serde_json::from_slice(&bytes)?;
    // Extractor 우회 — 타입 안전성 없음 ❌
}
Good — Json Extractor 사용
async fn handler(
    Json(data): Json<MyDto>, // 자동 파싱, 실패 시 400
) -> impl IntoResponse {
    // 이미 파싱 완료 ✅
}
Gotchas 체크리스트

Axum 작업 시 반복적으로 실수하는 포인트. 구현 전후로 확인하라.

  • ✓ FromRef 부분 추출 — 서브 라우터가 AppState의 일부만 필요하면 FromRef<AppState> for SubState를 구현한다. 전체 AppState를 공유하지 않아도 된다.
  • ✓ Extractor 순서 — Body를 소비하는 Extractor (Json, Bytes, String)는 함수 파라미터 중 마지막에 위치해야 한다. Path, Query, State가 먼저 와야 컴파일된다.
  • ✓ Router Send + Sync 요구 — 핸들러에서 Rc, Cell 등 !Send 타입을 캡처하면 컴파일 에러. tokio 멀티스레드 런타임에서 모든 핸들러는 Send여야 한다.
  • ✓ 404 폴백 — 매칭되지 않는 경로는 Router::fallback(handler)로 설정한다. 미들웨어에서 처리하지 않는다.
  • ✓ ServiceBuilder 레이어 순서 — .layer() 호출 순서가 요청에 대해서는 역순(마지막 layer가 먼저 실행), 응답에 대해서는 정순으로 적용된다. auth → rate-limit처럼 의존성 있는 미들웨어는 ServiceBuilder로 명시적으로 묶는다.
  • ✓ Router::layer() 선언 위치 — .layer()는 그 시점까지 추가된 라우트에만 적용된다. 모든 라우트를 먼저 등록하고 마지막에 .layer()를 호출한다.
