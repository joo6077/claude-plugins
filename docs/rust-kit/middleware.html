미들웨어 원칙

tower는 Rust 비동기 서비스 추상화 라이브러리다. Service trait이 미들웨어 합성의 핵심이며, axum은 tower 위에 구축되어 있다. ServiceBuilder로 레이어를 조합하고, tower-http가 HTTP 전용 미들웨어를 제공한다.

핵심 원칙

tower + axum 미들웨어 설계 원칙 4가지. 레이어 순서와 적용 범위가 핵심이다.

1

ServiceBuilder로 레이어 선언적 조합

ServiceBuilder::new().layer(A).layer(B)는 A → B → inner 순서로 요청을 처리한다. 나중에 추가한 레이어가 요청을 나중에 본다. 응답은 반대 방향이다.

let middleware = ServiceBuilder::new()
    .layer(SetRequestIdLayer::x_request_id(MakeRequestUuid))
    .layer(TraceLayer::new_for_http())
    .layer(CorsLayer::permissive())
    .layer(CompressionLayer::new());

let app = Router::new()
    .route("/", get(handler))
    .layer(middleware);
request-id → trace → cors → compression → handler
docs.rs/tower/service_builder
2

from_fn으로 간단한 미들웨어 작성

tower Service 구현 없이 async fn 하나로 미들웨어를 정의한다. 상태가 필요하면 from_fn_with_state를 사용한다.

async fn auth_middleware(
    State(state): State<AppState>,
    request: Request,
    next: Next,
) -> impl IntoResponse {
    let token = request.headers()
        .get("Authorization")
        .and_then(|v| v.to_str().ok())
        .and_then(|v| v.strip_prefix("Bearer "));

    match token {
        Some(t) if state.auth.verify(t).is_ok() => {
            next.run(request).await
        }
        _ => StatusCode::UNAUTHORIZED.into_response(),
    }
}

let app = Router::new()
    .route("/protected", get(handler))
    .layer(axum::middleware::from_fn_with_state(
        state.clone(), auth_middleware,
    ));
axum::middleware::from_fn

4

TraceLayer 커스터마이징

기본 TraceLayer는 정보가 부족하다. make_span_with, on_response, on_failure를 커스터마이징하여 구조화 스팬을 만든다.

TraceLayer::new_for_http()
    .make_span_with(
        DefaultMakeSpan::new()
            .level(Level::INFO)
            .include_headers(false),
    )
    .on_response(
        DefaultOnResponse::new()
            .level(Level::INFO)
            .latency_unit(LatencyUnit::Micros),
    )
    .on_failure(
        DefaultOnFailure::new().level(Level::ERROR)
    )

안티패턴

미들웨어 작업에서 반복되는 실수와 올바른 대안.

Bad — .layer() 순서 혼동
// Router::layer()는 ServiceBuilder와 반대!
// 나중에 추가한 레이어가 요청을 먼저 처리
Router::new()
    .layer(compression) // 요청을 먼저 처리 ❌
    .layer(trace)
    .layer(request_id)
Good — ServiceBuilder로 묶기
// ServiceBuilder로 한 번에 묶으면 순서 명확
let stack = ServiceBuilder::new()
    .layer(request_id)  // 요청을 먼저 처리 ✅
    .layer(trace)
    .layer(compression);

Router::new().layer(stack)
Bad — 응답 바디 소비 후 재전달 누락
async fn logging_middleware(
    req: Request, next: Next,
) -> impl IntoResponse {
    let res = next.run(req).await;
    // 바디를 소비하면 클라이언트에 전달할 바디 없음 ❌
    let body = res.into_body();
    let bytes = to_bytes(body).await?;
    // 재구성 없이 반환하면 빈 응답
}
Good — 버퍼링 후 재구성
async fn logging_middleware(
    req: Request, next: Next,
) -> impl IntoResponse {
    let res = next.run(req).await;
    let (parts, body) = res.into_parts();
    let bytes = to_bytes(body, usize::MAX).await?;
    // 로깅...
    // 재구성 후 반환 ✅
    Response::from_parts(parts, Body::from(bytes))
}
Bad — 모든 라우트에 무거운 미들웨어
// 공개 엔드포인트에도 인증 미들웨어 적용
Router::new()
    .route("/health", get(health)) // 불필요 ❌
    .route("/protected", get(secret))
    .layer(auth_middleware)
Good — Router::merge로 분리
// 인증 필요/불필요 라우터 분리
let public = Router::new()
    .route("/health", get(health));

let protected = Router::new()
    .route("/protected", get(secret))
    .layer(auth_middleware); // 필요한 곳에만 ✅

Router::new().merge(public).merge(protected)
Gotchas 체크리스트

tower 미들웨어 작업 시 반복적으로 실수하는 포인트.

  • ✓ tower 0.4 → 0.5 호환성 — tower 0.5에서 ServiceExt, ServiceBuilder API 일부가 변경됐다. axum 0.8은 tower 0.5를 요구한다. 직접 tower 의존성을 추가할 때 버전을 맞춰야 컴파일 에러가 나지 않는다.
  • ✓ from_fn에서 Request 소유권 — next.run(request) 호출 전에 request를 분해하면 소유권이 이동한다. 헤더나 경로만 검사할 때는 request.headers()로 참조만 가져오고, 요청 전체를 넘겨야 할 때 소유권을 유지한다.
  • ✓ CorsLayer::permissive() 프로덕션 금지 — permissive()는 모든 출처, 헤더, 메서드를 허용한다. 프로덕션에서는 CorsLayer::new().allow_origin(...)으로 허용 목록을 명시한다.
  • ✓ 레이어와 라우터 선언 순서 — Router::layer()는 그 시점까지 추가된 라우트에만 적용된다. .layer() 이후에 추가한 라우트에는 적용되지 않는다. 모든 라우트를 먼저 등록하고 마지막에 .layer()를 호출한다.
  • ✓ from_fn_with_state 상태 타입 — from_fn_with_state에 전달하는 상태 타입과 미들웨어 함수의 State<T> 타입이 일치해야 한다. 타입 불일치 시 컴파일 에러가 발생한다.
