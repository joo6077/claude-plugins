헥사고날 아키텍처

Alistair Cockburn이 2005년 제안한 Ports & Adapters 패턴. 애플리케이션을 외부 세계(UI, DB, 메시지 브로커, 외부 API)로부터 격리하는 것이 핵심이다. 외부 시스템이 교체되어도 도메인 로직은 변경되지 않는다. Rust에서는 trait이 Port, impl이 Adapter 역할을 한다.

의존성은 항상 인프라 → 도메인 단방향이다. Cargo.toml 의존성으로 규칙이 컴파일 타임에 강제된다.

핵심 원칙
1

도메인은 인프라를 모른다

Dependency Inversion

도메인 크레이트(domain/)는 어떤 DB, 브로커, HTTP 클라이언트도 use하지 않는다. 도메인은 Port(trait)만 정의하고, 인프라 크레이트가 Adapter(impl)를 제공한다.

// 올바른 Port — 도메인 타입만 사용
#[async_trait]
pub trait DatabasePort: Send + Sync {
    async fn find_user(&self, id: UserId)
        -> Result<User, DomainError>;
    async fn save_user(&self, user: &User)
        -> Result<(), DomainError>;
}

// 잘못된 Port — 인프라 타입 노출
pub trait DatabasePort {
    async fn find_user(&self, id: i64)
        -> Result<sqlx::Row, sqlx::Error>; // ❌
}

Port는 최소화된 trait으로 표현한다

Interface Segregation

Port는 도메인이 필요한 능력만 선언한다. trait의 파라미터가 인프라 타입(sqlx::Row, hyper::Response 등)을 포함하면 Port가 아니라 구현 상세가 누출된 것이다.

포트당 메서드 수 권장: 3~7개. 그 이상이면 포트 분리를 검토한다.

// domain/src/ports/
pub trait DatabasePort: Send + Sync { ... }
pub trait StoragePort: Send + Sync { ... }
pub trait EmailPort: Send + Sync { ... }
// 각 Port는 도메인 타입만 참조

Adapter는 인프라를 Port로 변환한다

Translation Only

Adapter는 인프라 라이브러리를 호출하고 결과를 도메인 타입으로 변환한다. 에러 변환(sqlx::Error → DomainError)도 Adapter 책임이다. 도메인 로직이 Adapter에 들어오면 서비스 레이어로 옮겨야 한다.

pub struct PostgresUserAdapter { pool: sqlx::PgPool }

#[async_trait]
impl DatabasePort for PostgresUserAdapter {
    async fn find_user(&self, id: UserId)
        -> Result<User, DomainError>
    {
        let row = sqlx::query_as::<_, UserRow>(
            "SELECT * FROM users WHERE id = $1"
        )
        .bind(id.0)
        .fetch_one(&self.pool)
        .await
        .map_err(|e| DomainError::NotFound(e.to_string()))?;
        Ok(row.into()) // 변환만 담당
    }
}

제네릭 vs Box<dyn Port> 선택 기준

Static vs Dynamic Dispatch

포트 수에 따라 디스패치 방식을 선택한다. 실용 기준: 포트 1~2개면 제네릭, 3개 이상이면 Arc<dyn Port> 혼용.

제네릭 (정적 디스패치)
+ 컴파일 타임 최적화
+ vtable 없음, 인라인 가능
- 타입 파라미터 증가 시 제네릭 폭발
Arc<dyn Port> (동적 디스패치)
+ 포트 많을 때 구조체 단순
+ DI 컨테이너 연동 용이
- vtable 간접 호출 ~5ns/call
// 3개 이상 — Arc<dyn Port> 혼용
pub struct UserService {
    db: Arc<dyn DatabasePort>,
    storage: Arc<dyn StoragePort>,
    email: Arc<dyn EmailPort>,
}

안티패턴

헥사고날 아키텍처에서 자주 저지르는 설계 실수.

Bad — 포트에 인프라 타입 노출
// ❌ 모든 어댑터가 sqlx에 의존해야 함
pub trait DatabasePort {
    async fn find(&self, id: i64)
        -> Result<sqlx::Row, sqlx::Error>;
}
Good — 도메인 타입만 사용
// ✅ 어댑터 교체 자유
pub trait DatabasePort: Send + Sync {
    async fn find(&self, id: UserId)
        -> Result<User, DomainError>;
}
Bad — Adapter에 도메인 로직 삽입
// ❌ 비즈니스 규칙이 인프라에 분산됨
impl DatabasePort for PostgresUserAdapter {
    async fn save_user(&self, user: &User) {
        if !is_valid_email(&user.email) { // 도메인 로직
            return Err(...);
        }
        // DB 저장...
    }
}
Good — Adapter는 변환만 담당
// ✅ 도메인 로직은 Service에
impl UserService {
    async fn create_user(&self, cmd: CreateUserCmd) {
        validate_email(&cmd.email)?; // Service 책임
        self.db.save_user(&user).await?;
    }
}
Bad — 단위 테스트에 실제 인프라 사용
// ❌ Port 추상화를 쓰지 않은 신호
#[test]
async fn test_service() {
    let pool = PgPool::connect(&DB_URL).await.unwrap();
    let service = UserService::new(pool);
}
Good — MockPort 주입
// ✅ DB 없이 도메인 로직 테스트
#[tokio::test]
async fn test_service() {
    let mock_db = MockDatabasePort::new();
    let service = UserService::new(Arc::new(mock_db));
}
Gotchas

헥사고날 아키텍처를 Rust로 구현할 때 자주 발생하는 함정.

  • !
    Rust 1.75+ AFIT로 async_trait 없이 async fn in trait 가능
    #[async_trait]는 매 호출마다 힙 할당이 발생한다(~5ns). hot path에서는 impl Future를 직접 사용하거나 AFIT(Return Position Impl Trait in Trait)로 대체할 수 있다. 
    // Rust 1.75+ — async_trait 없이
pub trait DatabasePort: Send + Sync {
    fn find_user(&self, id: UserId)
        -> impl Future<Output = Result<Option<User>, DomainError>> + Send;
}
  • !
    dyn Trait은 Send + Sync 명시가 필요하다
    Arc<dyn DatabasePort>가 Send + Sync를 요구하면 trait 정의에도 : Send + Sync 수퍼트레잇이 있어야 한다. tokio 런타임에서 task를 spawn할 때 Send가 없으면 컴파일 에러가 발생한다.
  • !
    제네릭 폭발 — 포트 4개 이상이면 Arc<dyn Port>로 전환
    UserService<D, S, M, A>처럼 타입 파라미터가 4개 이상이면 컴파일 시간이 증가하고 바이너리 크기가 커진다. ServiceDeps 구조체로 묶어 전달하거나 트레잇 객체로 전환한다.
  • !
    어댑터 초기화 에러는 main에서 처리한다
    PgPool::connect, AWS SDK 설정 등은 실패할 수 있다. main.rs에서 모든 어댑터를 초기화하고 실패 시 즉시 종료한다. 서비스 레이어에서 lazy init하면 에러를 늦게 발견한다.
  • !
    MockAdapter는 #[cfg(test)] 또는 test-helpers 크레이트에만 둔다
    MockDatabasePort를 프로덕션 코드에 포함하면 테스트 코드가 바이너리에 배포된다. #[cfg(test)]나 별도 test-helpers 크레이트로 분리한다.
