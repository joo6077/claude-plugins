CI/CD

GitHub Actions에서 Rust 프로젝트의 빌드, 테스트, 보안 감사를 자동화한다. cargo-nextest로 빠른 테스트, cargo-deny로 의존성 보안 감사, Swatinem/rust-cache로 컴파일 캐시를 구성하면 CI 실행 시간을 크게 줄일 수 있다.

파이프라인 구조

표준 4단계 CI 잡

각 잡은 독립적으로 병렬 실행된다. 실패한 잡만 재실행할 수 있어 피드백이 빠르다.

check
  • checkout
  • rust-toolchain
  • rust-cache
  • cargo check --all-targets
test
  • postgres service
  • rust-cache
  • install nextest
  • cargo nextest run
lint
  • clippy + rustfmt
  • rust-cache
  • cargo fmt --check
  • cargo clippy -D warnings
audit
  • install cargo-deny
  • cargo deny check
  • 취약점 + 라이선스
  • yanked 크레이트
1

표준 CI 워크플로우 전체 구성

RUSTFLAGS: "-D warnings"로 경고를 에러로 처리한다. DB가 필요한 테스트는 서비스 컨테이너를 사용한다.

# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  CARGO_TERM_COLOR: always
  RUSTFLAGS: "-D warnings"

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: cargo check --all-targets

  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: testdb
        ports: ["5432:5432"]
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - uses: taiki-e/install-action@nextest
      - run: cargo nextest run --all-features
        env:
          DATABASE_URL: postgres://postgres:postgres@localhost:5432/testdb

  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: clippy, rustfmt
      - uses: Swatinem/rust-cache@v2
      - run: cargo fmt --all -- --check
      - run: cargo clippy --all-targets --all-features -- -D warnings

  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: taiki-e/install-action@cargo-deny
      - run: cargo deny check

cargo-nextest로 테스트 속도를 높인다

테스트를 프로세스 단위로 격리하여 병렬 실행한다. 기존 cargo test보다 2~3배 빠른 경우가 많다.

- uses: taiki-e/install-action@nextest
- run: cargo nextest run
# 특정 테스트만 실행
- run: cargo nextest run --test integration_tests
# 병렬 스레드 수 제한
- run: cargo nextest run --test-threads 4

cargo-deny로 의존성 보안과 라이선스를 감사한다

취약점, 라이선스, 중복 버전, yanked 크레이트를 한 번에 검사한다.

# deny.toml
[advisories]
db-path = "~/.cargo/advisory-db"
db-urls = ["https://github.com/rustsec/advisory-db"]
vulnerability = "deny"
unmaintained = "warn"
yanked = "deny"

[licenses]
allow = [
    "MIT",
    "Apache-2.0",
    "Apache-2.0 WITH LLVM-exception",
    "ISC",
    "Unicode-DFS-2016",
]
deny = ["GPL-2.0", "GPL-3.0", "AGPL-3.0"]

[bans]
multiple-versions = "warn"

Swatinem/rust-cache로 빌드 캐시를 공유한다

~/.cargo/registry, ~/.cargo/git, target/을 자동으로 캐시한다.

- uses: Swatinem/rust-cache@v2
  with:
    # 워크스페이스 루트 명시 (기본값은 자동 감지)
    workspaces: ". -> target"
    # 캐시 키 추가 구분자 (캐시 무효화 시 v2로 bump)
    key: "v1"
수치 기준

액션 버전 및 설정값

항목기준값비고
Rust toolchain action dtolnay/rust-toolchain@stable 고정 버전보다 stable 권장
캐시 action Swatinem/rust-cache@v2 actions/cache 직접 사용보다 간편
RUSTFLAGS -D warnings 경고를 에러로 처리 — CI 필수
nextest 설치 taiki-e/install-action@nextest 바이너리 직접 다운로드, 빠름
안티패턴

흔한 실수 4가지

피해야 할 패턴

cargo test 그대로 사용

cargo test는 테스트 바이너리를 순차적으로 실행한다. 테스트가 많을수록 CI 시간이 길어진다.

올바른 패턴

cargo nextest run 사용

cargo-nextest는 더 세밀한 병렬화와 더 나은 출력을 제공한다. 동일한 테스트가 2~3배 빠르게 실행된다.

피해야 할 패턴

캐시 없이 매 CI 전체 재컴파일

의존성 컴파일은 수 분이 걸릴 수 있다. 캐시 없이 실행하면 PR마다 동일한 시간이 낭비된다.

올바른 패턴

Swatinem/rust-cache@v2 적용

모든 잡에 Swatinem/rust-cache@v2를 추가한다. registry와 target 디렉토리를 자동 캐시하여 반복 빌드 시간을 크게 줄인다.

피해야 할 패턴

clippy를 -D warnings 없이 실행

경고를 에러로 처리하지 않으면 clippy가 통과해도 코드 품질 경고가 누적된다.

올바른 패턴

-- -D warnings 항상 추가

cargo clippy --all-targets --all-features -- -D warnings로 경고를 에러로 처리한다. RUSTFLAGS=-D warnings와 함께 사용한다.

피해야 할 패턴

cargo audit만 사용

cargo audit은 취약점만 검사한다. 라이선스 위반이나 yanked 크레이트는 감지하지 못한다.

올바른 패턴

cargo deny로 통합 검사

cargo deny는 취약점 + 라이선스 + 중복 의존성 + yanked 크레이트를 deny.toml 한 파일로 통합 관리한다.

Gotchas

반드시 알아야 할 함정

  • ✓
    SQLX_OFFLINE=true를 check/lint 잡에 설정해야 한다
    DB 없는 CI 단계(check, lint)에서 sqlx query 매크로를 컴파일하려면 .sqlx/ 캐시와 SQLX_OFFLINE: "true"가 필요하다. 설정 없이 실행하면 DB 연결 시도 후 컴파일 실패한다.
  • ✓
    dtolnay/rust-toolchain은 rust-toolchain.toml을 자동으로 읽는다
    프로젝트 루트에 rust-toolchain.toml이 있으면 toolchain 버전이 자동으로 고정된다. action에 별도 버전을 명시하지 않아도 된다.
  • ✓
    cargo-deny의 deny.toml이 없으면 cargo deny check가 실패한다
    cargo deny init으로 기본 설정 파일을 생성한 뒤 커밋한다. 파일이 없으면 CI에서 즉시 실패한다.
  • ✓
    서비스 컨테이너는 localhost로 접근한다
    services.postgres로 정의한 PostgreSQL은 localhost:5432로 접근한다. DATABASE_URL에 localhost를 사용한다. 컨테이너 이름(postgres)으로 접근하는 것은 동작하지 않는다.
