SQLx 패턴

sqlx 0.8.x는 컴파일 타임 SQL 검증을 지원하는 비동기 Rust DB 라이브러리다. 매크로 기반 쿼리(query!, query_as!)와 런타임 쿼리(query, query_as)를 상황에 맞게 나눠 사용한다.

version 0.2.0 updated 2026-09-25 sqlx 0.8.x
Principles

원칙

정적·동적 쿼리의 경계부터 트랜잭션, 풀 공유, 시각 타입까지 SQLx 데이터 계층의 여섯 가지 기준이다.

1

정적 SQL은 query_as!, 동적 SQL은 query_as로 분리한다

query_as!는 컴파일 타임에 SQL과 Rust 타입을 검증한다. 조건이 동적으로 붙으면 QueryBuilder나 query_as::<_, T>()를 사용한다.

// 컴파일 타임 검증 — 정적 쿼리
#[derive(Debug, FromRow)]
pub struct UserRow {
    pub id: Uuid,
    pub email: String,
    pub name: String,
    pub created_at: DateTime<Utc>,
}

pub async fn find_by_id(
    pool: &PgPool,
    id: Uuid,
) -> Result<Option<UserRow>, sqlx::Error> {
    sqlx::query_as!(
        UserRow,
        "SELECT id, email, name, created_at
         FROM users WHERE id = $1",
        id
    )
    .fetch_optional(pool)
    .await
}
// 런타임 동적 쿼리
pub async fn search_users(
    pool: &PgPool,
    email_like: Option<&str>,
) -> Result<Vec<UserRow>, sqlx::Error> {
    let mut qb = QueryBuilder::new(
        "SELECT id, email, name, created_at
         FROM users WHERE 1=1"
    );
    if let Some(email) = email_like {
        qb.push(" AND email ILIKE ")
          .push_bind(format!("%{email}%"));
    }
    qb.build_query_as::<UserRow>()
      .fetch_all(pool)
      .await
}

#[derive(FromRow)]로 DB 컬럼을 Rust 구조체에 매핑한다

컬럼명과 필드명이 다르면 #[sqlx(rename = "...")]을 쓴다. query_as!는 FromRow를 무시하고 컬럼 순서로 매핑하므로 SELECT 컬럼 순서와 구조체 필드 순서를 맞춘다.

#[derive(Debug, Clone, FromRow)]
pub struct UserRow {
    pub id: Uuid,
    pub email: String,
    #[sqlx(rename = "display_name")]
    pub name: String,
    pub created_at: DateTime<Utc>,
    pub deleted_at: Option<DateTime<Utc>>,
}

타입 매핑은 feature로 활성화한다

Uuid, DateTime<Utc>, JSON, Decimal을 쓰려면 해당 SQLx feature를 명시한다. 시간 타입은 이 구성에서 time 대신 chrono를 선택한다.

[dependencies]
sqlx = { version = "0.8", features = [
    "postgres",
    "runtime-tokio-native-tls",
    "uuid",       # Uuid 타입 지원
    "chrono",     # DateTime<Utc> 지원 (time 대신 chrono 선택)
    "json",       # serde_json::Value 지원
    "rust_decimal", # Decimal 타입 지원
] }

트랜잭션은 pool.begin()으로 시작하고 명시적으로 commit한다

트랜잭션 객체가 drop되면 자동 rollback된다. 성공 경로에서는 반드시 commit()을 호출하고, 같은 트랜잭션의 executor로 &mut *tx를 넘긴다.

pub async fn transfer_credits(
    pool: &PgPool,
    from_id: Uuid,
    to_id: Uuid,
    amount: i64,
) -> Result<(), sqlx::Error> {
    let mut tx = pool.begin().await?;

    sqlx::query!(
        "UPDATE accounts
         SET credits = credits - $1
         WHERE id = $2",
        amount, from_id
    )
    .execute(&mut *tx)
    .await?;

    sqlx::query!(
        "UPDATE accounts
         SET credits = credits + $1
         WHERE id = $2",
        amount, to_id
    )
    .execute(&mut *tx)
    .await?;

    tx.commit().await?;
    Ok(())
}

6

시각은 종류부터 나누고, 종류마다 Rust 타입과 열 타입을 정한다

시각 종류 셋의 정의와 시간대 출처 규칙은 docs/backend/fundamentals/database.md 원칙 10이 정본이다. 여기서는 Rust 타입과 PostgreSQL 열 타입의 짝을 정한다.

시각 종류 SQLx SeaORM Entity PostgreSQL 열
순간 chrono::DateTime<Utc> DateTimeWithTimeZone (chrono::DateTime<FixedOffset>) TIMESTAMPTZ
받는 사람 지역을 따라가는 벽시계 chrono::NaiveDateTime · 시각만이면 chrono::NaiveTime DateTime (chrono::NaiveDateTime) · Time (chrono::NaiveTime) TIMESTAMP · TIME
특정 지역에 묶인 벽시계 벽시계 타입 + 시간대 이름 String 벽시계 타입 + String 벽시계 열 + IANA 시간대 식별자 TEXT

TIMESTAMPTZ는 입력 순간을 UTC로 바꿔 저장하고 원래 시간대 이름은 남기지 않는다. 서머타임이 드나드는 지역의 미래 반복 일정은 벽시계 값과 IANA 시간대 식별자를 함께 저장해야 다시 계산할 수 있다.

SeaORM의 순간 타입은 SQLx와 다르다. 생성된 Entity가 DateTimeWithTimeZone이면 도메인 DateTime<Utc>와 읽을 때 .with_timezone(&Utc), 쓸 때 Utc::now().fixed_offset()로 변환한다.

실측(2026-09-25 · sea-orm 1.1.19 · sqlx 0.8.6 · chrono 0.4.44 · 오프라인 컴파일): SeaORM의 DateTimeWithTimeZone과 DateTimeUtc는 TimestampWithTimeZone, DateTime은 DateTime, Time은 Time으로 추론됐다.

같은 실측에서 SQLx의 DateTime<Utc> · NaiveDateTime · NaiveTime은 차례로 TIMESTAMPTZ · TIMESTAMP · TIME이었다. SeaORM 2.x는 재지 않았다.

시간대와 나라를 코드 상수나 한 나라 기본값으로 박지 않는다. 이 기준은 RFC 요구가 아니라 이 킷의 규칙이다.

안티패턴

실패하기 쉬운 구현과 원본이 권하는 교정 방향을 나란히 비교한다.

Bad · query! 매크로를 CI 없이 사용

query!는 실제 DB 연결이 있어야 컴파일된다. SQLX_OFFLINE=true 없이 CI에서 빌드하면 DB가 없는 환경에서 실패한다.

// .sqlx/ 캐시 없이 매크로만 사용
sqlx::query!(
    "SELECT * FROM users WHERE id = $1",
    id
);
Good · 오프라인 캐시 생성

cargo sqlx prepare로 .sqlx/ 캐시를 만들고 저장소에 커밋해 CI가 DB 없이 검증할 수 있게 한다.

cargo sqlx prepare
git add .sqlx/

# CI 스펙 드리프트 검증
cargo sqlx prepare --check
Bad · fetch_all로 무제한 행 조회

페이지네이션 없는 fetch_all은 대용량 테이블의 모든 행을 메모리에 올려 OOM을 일으킬 수 있다.

let all_users = sqlx::query_as!(
    UserRow,
    "SELECT * FROM users"
)
.fetch_all(pool)
.await?;
Good · LIMIT + 커서 페이지네이션

LIMIT와 커서 조건을 함께 써 한 번에 가져오는 행 수를 제한한다.

let users = sqlx::query_as!(
    UserRow,
    "SELECT * FROM users
     WHERE id > $1
     ORDER BY id
     LIMIT $2",
    cursor_id, page_size
)
.fetch_all(pool)
.await?;
Bad · 트랜잭션에서 다른 풀 연결 사용

트랜잭션 컨텍스트 밖의 쿼리는 해당 트랜잭션에 참여하지 않아 원자성을 깨뜨린다.

let mut tx = pool.begin().await?;

sqlx::query!("UPDATE accounts ...")
    .execute(pool)
    .await?;

tx.commit().await?;
Good · &mut *tx를 executor로 전달

모든 관련 쿼리에 &mut *tx를 전달해 같은 트랜잭션 안에서 실행한다.

let mut tx = pool.begin().await?;

sqlx::query!("UPDATE accounts ...")
    .execute(&mut *tx)
    .await?;

tx.commit().await?;
Bad · 벽시계를 TIMESTAMPTZ 하나로 저장

반복 일정이나 알림 시각을 순간 하나로만 바꾸면 시간대 변경이나 서머타임 진입·해제 때 사용자가 정한 현지 시각과 어긋난다.

-- 원래 지역 정보가 사라짐
scheduled_at TIMESTAMPTZ NOT NULL
Good · 벽시계와 시간대 이름을 분리

원칙 6의 구분대로 벽시계 열과 IANA 시간대 식별자 열을 함께 저장해 미래 순간을 다시 계산한다.

local_time TIMESTAMP NOT NULL,
time_zone  TEXT NOT NULL
-- 예: Asia/Seoul
Checklist

Gotchas

컴파일 오류와 트랜잭션 이탈을 막기 위해 구현·리뷰 때 확인할 네 항목이다.

  • ✓ query_as!에서 nullable 컬럼은 Option<T>로 받는다. DB 컬럼이 nullable인데 Rust 타입이 T이면 컴파일 에러가 발생한다. Option<T>로 선언하거나 SELECT COALESCE(col, default)로 처리한다.
  • ✓ query! 매크로에서 $N 바인딩은 1-indexed다. PostgreSQL 파라미터는 $1, $2부터 시작하며 MySQL 스타일 ?는 사용하지 않는다.
  • ✓ cargo sqlx prepare에는 DATABASE_URL이 필요하다. .env나 환경변수로 설정한다. cargo sqlx prepare --workspace는 워크스페이스 전체 쿼리를 캐시한다.
  • ✓ tx.execute()에는 &mut *tx 패턴이 필요하다. sqlx 0.8에서 트랜잭션을 executor로 전달할 때 역참조해야 하며 &tx는 Executor를 구현하지 않는다.
