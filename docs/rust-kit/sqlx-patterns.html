SQLx 패턴

sqlx 0.8.x는 컴파일 타임 SQL 검증을 지원하는 비동기 Rust DB 라이브러리다. 매크로 기반 쿼리(query!, query_as!)와 런타임 쿼리(query, QueryBuilder) 두 방식을 상황에 맞게 조합한다.

핵심 원칙

SQLx 사용 시 지켜야 할 쿼리 패턴, 타입 매핑, 트랜잭션, 풀 설정 원칙 5가지.

1

정적 SQL은 query_as!, 동적 SQL은 QueryBuilder

query_as!는 컴파일 타임에 SQL과 Rust 타입을 검증한다. 동적으로 조건이 붙는 쿼리는 QueryBuilder를 사용한다.

// 컴파일 타임 검증 — 정적 쿼리
pub async fn find_by_id(
    pool: &PgPool, id: Uuid,
) -> Result<Option<UserRow>, sqlx::Error> {
    sqlx::query_as!(
        UserRow,
        "SELECT id, email, name, created_at FROM users WHERE id = $1",
        id
    )
    .fetch_optional(pool)
    .await
}

// 동적 쿼리 — QueryBuilder
pub async fn search_users(
    pool: &PgPool,
    email_like: Option<&str>,
) -> Result<Vec<UserRow>, sqlx::Error> {
    let mut qb = QueryBuilder::new(
        "SELECT id, email, name, created_at FROM users WHERE 1=1"
    );
    if let Some(email) = email_like {
        qb.push(" AND email ILIKE ").push_bind(format!("%{email}%"));
    }
    qb.build_query_as::<UserRow>().fetch_all(pool).await
}

2

FromRow + 컬럼 rename

#[derive(FromRow)]로 DB 컬럼을 Rust 구조체에 매핑한다. 컬럼명이 필드명과 다를 때는 #[sqlx(rename = "...")]을 사용한다.

#[derive(Debug, Clone, FromRow)]
pub struct UserRow {
    pub id: Uuid,
    pub email: String,
    #[sqlx(rename = "display_name")]
    pub name: String,
    pub created_at: DateTime<Utc>,
    pub deleted_at: Option<DateTime<Utc>>,
}

// 주의: query_as! 매크로는 FromRow를 무시하고
// SELECT 컬럼 순서로 매핑한다.
// 구조체 필드 순서 = SELECT 컬럼 순서 일치 필요

타입 매핑 feature 활성화

Uuid, DateTime<Utc>, Decimal 등 확장 타입은 Cargo.toml feature로 활성화해야 한다.

sqlx = { version = "0.8", features = [
    "postgres",
    "runtime-tokio-native-tls",
    "uuid",          # Uuid 타입 지원
    "chrono",        # DateTime<Utc> 지원
    "json",          # serde_json::Value 지원
    "rust_decimal",  # Decimal 타입 지원
] }

4

트랜잭션 — 명시적 commit

트랜잭션 객체를 drop하면 자동 rollback된다. 성공 경로에서 반드시 commit()을 호출해야 한다. &mut *tx 패턴으로 executor를 전달한다.

pub async fn transfer_credits(
    pool: &PgPool,
    from_id: Uuid, to_id: Uuid, amount: i64,
) -> Result<(), sqlx::Error> {
    let mut tx = pool.begin().await?;

    sqlx::query!(
        "UPDATE accounts SET credits = credits - $1 WHERE id = $2",
        amount, from_id
    )
    .execute(&mut *tx)  // &mut *tx 패턴 필수
    .await?;

    sqlx::query!(
        "UPDATE accounts SET credits = credits + $1 WHERE id = $2",
        amount, to_id
    )
    .execute(&mut *tx)
    .await?;

    tx.commit().await?;  // 명시적 commit 필수
    Ok(())
}

PgPool 설정

앱 시작 시 한 번 생성하고 axum State로 공유한다. max_connections는 DB 서버 설정의 1/5 이하를 권장한다.

let pool = PgPoolOptions::new()
    .max_connections(20)
    .min_connections(2)
    .acquire_timeout(Duration::from_secs(5))
    .max_lifetime(Duration::from_secs(1800))   // 30분
    .idle_timeout(Duration::from_secs(600))    // 10분
    .connect(&database_url)
    .await?;

안티패턴

SQLx 사용 시 반복되는 실수와 올바른 대안.

Bad — CI 없이 query! 매크로 사용
// .sqlx/ 캐시 없이 query! 사용
// CI에서 DB 연결 없으면 컴파일 실패 ❌
sqlx::query!(
    "SELECT * FROM users WHERE id = $1", id
)

// SQLX_OFFLINE=true 없이 빌드 시
// DATABASE_URL 필요 → CI 환경에서 실패
Good — .sqlx/ 캐시 커밋
# 개발 환경에서 캐시 생성
cargo sqlx prepare

# .sqlx/ 디렉토리를 git에 커밋
git add .sqlx/
git commit -m "chore: sqlx offline cache"

# CI에서 DB 없이 빌드 가능 ✅
# SQLX_OFFLINE=true 자동 감지
Bad — fetch_all로 무제한 조회
// 페이지네이션 없이 전체 조회
let all_users = sqlx::query_as!(UserRow,
    "SELECT * FROM users"
)
.fetch_all(pool)
.await?;
// 수백만 행 → OOM ❌
Good — LIMIT + 커서 페이지네이션
let users = sqlx::query_as!(UserRow,
    "SELECT * FROM users
     WHERE id > $1
     ORDER BY id
     LIMIT $2",
    cursor_id, page_size
)
.fetch_all(pool)
.await?; // ✅ 안전한 페이지네이션
Bad — 트랜잭션 밖에서 풀 연결 사용
let mut tx = pool.begin().await?;

// pool을 executor로 전달 — tx 범위 밖 ❌
sqlx::query!("UPDATE accounts ...")
    .execute(pool)  // 트랜잭션에 참여 안 함
    .await?;

tx.commit().await?; // 원자성 보장 안 됨
Good — &mut *tx 패턴
let mut tx = pool.begin().await?;

// &mut *tx로 같은 트랜잭션 내 실행 ✅
sqlx::query!("UPDATE accounts ...")
    .execute(&mut *tx)
    .await?;

tx.commit().await?; // 원자성 보장 ✅
Gotchas 체크리스트

SQLx 작업 시 반복적으로 실수하는 포인트.

  • ✓ nullable 컬럼은 Option<T> — DB 컬럼이 nullable인데 Rust 타입이 T이면 컴파일 에러가 발생한다. Option<T>로 선언하거나 SELECT COALESCE(col, default)로 처리한다.
  • ✓ $N 바인딩은 1-indexed — PostgreSQL 파라미터 바인딩은 $1, $2로 시작한다. MySQL 스타일 ?는 사용하지 않는다.
  • ✓ cargo sqlx prepare는 DATABASE_URL 필요 — .env 파일이나 환경변수로 DATABASE_URL을 설정해야 한다. cargo sqlx prepare --workspace는 워크스페이스 전체 쿼리를 캐시한다.
  • ✓ tx.execute()에 &mut *tx 패턴 — sqlx 0.8에서 트랜잭션을 executor로 전달할 때 &mut *tx로 역참조해야 한다. &tx는 Executor를 구현하지 않는다.
  • ✓ query_as!는 FromRow 무시 — query_as! 매크로는 FromRow의 rename 설정을 무시하고 SELECT 컬럼 순서로 직접 매핑한다. SELECT 컬럼 순서와 구조체 필드 순서를 일치시켜야 한다.
