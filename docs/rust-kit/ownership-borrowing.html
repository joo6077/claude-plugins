소유권과 빌림 원칙

Rust의 메모리 안전성은 런타임 GC 없이 컴파일 타임 소유권 규칙으로 보장된다. 값은 하나의 소유자를 갖고, 소유자가 스코프를 벗어나면 해제된다. 불변 빌림과 가변 빌림은 동시에 존재할 수 없다. 이 규칙을 이해하면 불필요한 .clone() 없이 안전한 코드를 작성할 수 있다.

핵심 원칙
1

불필요한 .clone()을 피한다

Ownership Transfer

.clone()은 힙 할당 데이터를 완전히 복사한다. String은 평균 ~40ns, Vec은 길이에 비례한다. 함수에 소유권이 필요하지 않다면 참조를 넘긴다.

// 비효율 — 호출마다 String 복사
fn greet(name: String) { println!("Hello, {name}"); }
greet(user.name.clone());

// 효율 — 참조만 빌림
fn greet(name: &str) { println!("Hello, {name}"); }
greet(&user.name);

Arc::clone()처럼 복사 비용이 작은 경우(~5ns atomic op)나 소유권 이전이 실제로 필요한 경우는 허용.

↗ Rust Book Ch.4 — Understanding Ownership
2

&String 대신 &str을 사용한다

Slice Types

&String은 String에서만 빌릴 수 있다. &str은 String, &str 리터럴, 슬라이스 모두에서 빌릴 수 있어 더 범용적이다. 같은 이유로 &Vec<T> 대신 &[T], &PathBuf 대신 &Path를 사용한다.

fn process(name: &str) { ... }    // ✅
fn process(name: &String) { ... } // ❌ Clippy: ptr_arg

3

빌림 범위를 최소화한다

Borrow Scope

빌림이 길수록 가변 접근이 차단되는 범위가 넓어진다. 값이 필요한 시점 직전에 빌리고, 필요가 끝나면 즉시 해제한다. 중간에 소유권을 이전할 필요가 있으면 빌림을 먼저 끝낸다.

// 빌림을 블록으로 제한
let len = {
    let s = &data.name;
    s.len()
};
data.name.push_str(" Jr."); // ✅ 가변 접근 가능

4

lifetime 명시는 컴파일러가 추론 못할 때만

Lifetime Elision

lifetime 생략 규칙(elision rules)이 대부분의 경우를 자동 처리한다. 명시가 필요한 경우: 반환값이 여러 입력 중 하나에서 빌려오는 경우, 구조체가 참조를 필드로 가지는 경우.

// 명시 불필요 — 컴파일러가 추론
fn first_word(s: &str) -> &str { ... }

// 명시 필요 — 반환값이 두 입력 중 하나
fn longer<'a>(x: &'a str, y: &'a str) -> &'a str { ... }

// 구조체 필드에 참조
struct Excerpt<'a> { part: &'a str }

5

Arc/Rc 사용 기준을 명확히 한다

Smart Pointers

용도에 맞는 스마트 포인터를 선택한다. 가변 접근이 필요하면 Mutex 또는 RwLock을 조합한다.

Rc<T>
단일 스레드 공유 소유권. ~2ns clone. 순환 참조는 Weak<T>로 방지.
Arc<T>
멀티 스레드 공유 소유권. ~5ns atomic clone. tokio::spawn에서 필수.
// 멀티 스레드 — Arc 사용
let shared: Arc<Config> = Arc::new(Config::load());
let clone = Arc::clone(&shared); // ~5ns
tokio::spawn(async move { use_config(&clone) });

수치 기준

빌림과 복사 작업의 실제 비용. 참조 전달과 스마트 포인터 간의 트레이드오프를 수치로 확인한다.

작업 비용 비고
&str 빌림 전달~0ns포인터 + 길이만 복사 (fat pointer 16바이트)
String::clone() (빈 문자열)~40ns힙 할당 + memcpy. 길이에 비례해 증가
Vec::clone() (요소 n개)O(n)요소별 clone 호출. 힙 재할당 포함
Arc::clone()~5nsatomic fetch_add. 멀티 스레드 안전
Rc::clone()~2ns비원자적 ref count. 단일 스레드만
Mutex::lock() 비경쟁~10ns경쟁 시 수십 µs로 급증
안티패턴

흔히 저지르는 소유권 실수 패턴과 올바른 대안.

Bad — 방어적 .clone() 남용
// 컴파일 에러를 회피하려고 clone 추가
fn process(items: Vec<Item>) {
    store(items.clone()); // ❌ 불필요한 복사
    render(items.clone());
    items
}
Good — 소유권 이전 또는 빌림
// 소유권 이전이 필요한지 먼저 파악
fn process(items: &[Item]) {
    store(items); // ✅ 참조만 전달
    render(items);
}
Bad — &String 함수 인자
fn greet(name: &String) {  // ❌ ptr_arg
    println!("Hello, {name}");
}
// String 에서만 호출 가능
Good — &str 범용 슬라이스
fn greet(name: &str) {  // ✅
    println!("Hello, {name}");
}
// String, &str, 슬라이스 모두 수용
Bad — 구조체에 &str 필드 남용
struct User<'a> {  // ❌ lifetime 복잡도 증가
    name: &'a str,
    email: &'a str,
}
Good — 구조체는 소유 데이터
struct User {  // ✅ 유지보수 단순
    name: String,
    email: String,
}
// 함수 인자에서만 &str 사용
Gotchas

반복적으로 발생하는 실수와 컴파일러가 알려주지 않는 함정.

  • !
    NLL 이후에도 구조체 필드 빌림 충돌이 발생할 수 있다
    컴파일러가 구조체 전체를 빌린 것으로 판단하는 경우가 있다. 빌림 대상 필드를 지역 변수에 분리하거나, 메서드 대신 함수로 분리한다.
  • !
    fn make_greeting() -> &str은 컴파일 에러
    반환되는 참조가 어디서 빌려오는지 알 수 없다. String을 반환하거나, static 데이터라면 &'static str을 명시한다.
  • !
    Deref 강제 변환을 명시적 역참조로 방해하지 않는다
    Box<String>을 &str로 넘길 때 자동 Deref 체인이 동작한다. &*box_val처럼 명시적 역참조보다 &box_val로 Deref 강제 변환에 맡긴다.
  • !
    tokio::spawn은 'static을 요구한다
    클로저 캡처를 Arc::clone으로 공유하거나 move로 넘긴다. unsafe transmute로 lifetime을 지우는 것은 사용 금지.
