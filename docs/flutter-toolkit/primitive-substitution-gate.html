Precondition

적용 조건 — HAS_DS = true 일 때만

HAS_DS = true (references/project-detection.md 감지 결과) 일 때만 발동한다. 디자인 시스템이 없는 프로젝트에 이 게이트를 걸면 대체 후보가 존재하지 않아 노이즈만 생긴다.

project-detection Step 7 패턴감지 결과이 게이트

(위 폴더 없음) HAS_DS = false, 디자인 시스템 규칙 스킵 발동하지 않는다
감지 규칙 자체는 project-detection (flutter-toolkit/references/project-detection.md) 이 정한다. 이 게이트는 그 결과만 읽는다.

Out of scope

게이트 대상이 아닌 layout primitive — 금지하지 않는다

Text · Row · Column · Padding · SizedBox 같은 layout primitive 는 이 게이트의 대상이 아니다. 이들까지 금지하면 과잉 규칙이 되어 게이트가 통째로 무시된다 — 우회된 게이트는 없는 게이트보다 나쁘다. Stack · Expanded · Flexible · Align · Center · Spacer 도 같다.

대상 — 먼저 검색한다
  • Divider · Button 계열 · Chip 계열
  • Card · ListTile · Switch
  • TextField / TextFormField
  • CircularProgressIndicator / LinearProgressIndicator
대상 아님 — 금지하지 않는다
  • Text · Row · Column
  • Padding · SizedBox
  • Stack · Expanded · Flexible
  • Align · Center · Spacer
예외 하나 — 프로젝트가 Text 를 감싸는 타이포 컴포넌트(예: AppText)를 이미 전면 사용 중이라 Text( 직접 호출이 코드베이스에 사실상 없으면, 그때만 프로젝트 관습을 따른다. 그 판정은 이 게이트가 아니라 기존 코드 관찰로 한다.
Procedure

절차 — quick 검색과 deep 검색

생성 스킬은 쓰려는 위젯 한 종만 한 번 찾는다. 감사 모드는 변경 파일 전체를 훑는다.

quick

생성 스킬 — flutter-widget · flutter-screen

생성 시간을 늘리지 않도록 대상 위젯 한 종에 대해서만 1 회 검색한다.

# 예: Divider 를 쓰려 한다
rg -n "class .*Divider|Divider\(" lib/ --glob '!**/*.g.dart' | head -20

검색 경로 우선순위:

1 lib/**/design_system → 2 lib/**/components → 3 lib/**/widgets → 4 lib/**/ui
deep

flutter-audit deep 모드 · widget-inspector deep 모드

변경 파일 전체를 훑어 게이트 대상 8 종의 직접 사용을 열거하고, 각 사용처마다 DS 대체 후보가 실재하는지 확인한다. 

# 게이트 대상 직접 사용 열거 (zsh · bash 동일)
grep -rnE '\b(Divider|ElevatedButton|TextButton|OutlinedButton|IconButton|Chip|Card|ListTile|Switch|TextField|TextFormField|CircularProgressIndicator|LinearProgressIndicator)\(' \
  lib/ --include='*.dart' | grep -v '\.g\.dart:'

0 매치 판정 — 이 순서를 거친 0 만 "위반 없음"

  1. 대상 파일 수부터 센다검색 범위의 .dart 파일 수를 먼저 적는다 (예: 42 개).
  2. 알려진 위치에서 1 회 이상 맞는지 본다그 패턴이 알려진 위치에서 최소 1 회 매치한다는 것을 확인한다.
  3. 그 뒤의 0 만 "위반 없음"경로가 틀려서 나온 0 은 [미검증] 이다.
Artifact

E2 아티팩트 — 대체 후보 표

게이트가 발동하면 아래 표를 응답에 채워서 남긴다. 채우지 않고 진행하지 않는다.

후보 있음

후보가 있는데 기본 위젯을 쓰려면 근거 한 줄이 필수다.

"스타일이 달라서" 는 근거가 아니다 — DS 컴포넌트의 파라미터로 표현 가능한지 먼저 소스를 읽는다.

후보가 없으면 "없음" 이라고 적고 진행한다.

Anti-patterns

게이트를 무력하게 만드는 쓰임새

원본의 각 절이 막으려는 행동을 한자리에 모았다.

Bad
  • 프로젝트 컴포넌트를 찾아보지 않고 Divider 를 바로 넣는다
  • DS 후보가 있는데 "스타일이 달라서" 를 근거로 기본 위젯을 쓴다
  • 대체 후보 표를 채우지 않고 완료를 선언한다
  • 경로가 틀린 검색의 0 을 "위반 없음" 으로 읽는다
  • Text · Row · Column 까지 막아 게이트 전체를 노이즈로 만든다
  • 대상 목록을 스킬 문서에 복사해 두 곳에서 따로 고친다
Good
  • 쓰려는 위젯 한 종을 rg 로 1 회 찾고 표에 적는다
  • DS 컴포넌트 소스를 읽고 파라미터로 표현되는지 확인한 뒤 결정한다
  • 후보가 없으면 "없음" 과 근거를 적고 기본 위젯을 쓴다
  • 대상 파일 수와 알려진 위치의 매치를 확인한 뒤의 0 만 믿는다
  • 게이트 대상 8 종에만 걸고 layout primitive 는 그대로 둔다
  • 스킬 문서는 이 파일을 인용만 한다

왜 E2 인가 — 등급 근거

E1 · 문장 규칙

서술문으로 적은 조항

§Enumerate-before-Act · "기존 위젯 수정이 기본값" 이 이 등급이었다.

RE-02 는 이 조항들이 있는 상태에서 났다.

E2 · 현재

아티팩트를 남기는 등급

문장을 또 다듬지 않고, 대체 후보 표를 응답에 남기게 한다.

표가 없으면 진행하지 않는다.

E3 · 다음 단계

스크립트로 막는 등급

표 없이 완료 선언이 반복되면 다음 사이클에 게이트 대상 grep 을 실행하는 E3 스크립트로 승급한다.

승급 규칙 원문 — 기존 E1 조항(§Enumerate-before-Act · "기존 위젯 수정이 기본값")이 있는 상태에서 RE-02 가 발생했으므로 문장을 또 다듬지 않고 아티팩트를 남기는 등급으로 올린다. 등급 정의: skill-design-guide §3.7
Gotchas

Gotchas 체크리스트

게이트를 걸기 전과 표를 채운 뒤에 한 번씩 대조한다.

  • ✓
    HAS_DS = false 면 걸지 않는다 디자인 시스템이 없으면 대체 후보가 없다. 게이트를 걸면 노이즈만 생긴다.
  • ✓
    목록을 자기 문서에 복제하지 않는다 대상 · 면제 목록과 검색 명령은 이 파일 하나에만 둔다. 네 인용처는 이 파일을 가리키기만 한다.
  • ✓
    layout primitive 까지 금지하지 않는다 Text · Row · Column · Padding · SizedBox 와 Stack · Expanded · Flexible · Align · Center · Spacer 는 대상이 아니다.
  • ✓
    생성 스킬은 한 종만 1 회 찾는다 quick 검색은 생성 시간을 늘리지 않으려는 절차다. 전수 열거는 deep 모드의 몫이다.
  • ✓
    검증 안 된 0 은 "위반 없음" 이 아니다 대상 파일 수를 세고, 알려진 위치에서 최소 1 회 매치하는지 본 뒤의 0 만 유효하다. 경로가 틀려서 나온 0 은 [미검증] 이다.
  • ✓
    "스타일이 달라서" 는 근거가 아니다 DS 컴포넌트의 파라미터로 표현 가능한지 소스를 먼저 읽는다. 읽지 않고 기본 위젯으로 돌아가면 RE-02 가 그대로 다시 난다.
Summary

한 문장 요약

금지하는 게이트가 아니라, 검색과 근거를 남기게 하는 게이트

HAS_DS = true 인 프로젝트에서 의미 있는 UI 위젯 8 종을 새로 꺼내 쓰기 전에 DS 컴포넌트를 검색하고, 그 결과를 대체 후보 표로 남긴다. 후보가 없으면 "없음" 이라고 적고 기본 위젯을 쓰면 된다. layout primitive 는 대상이 아니고, 검증되지 않은 0 매치는 "위반 없음" 이 아니라 [미검증] 이다. 표 없이 완료 선언이 반복되면 다음 사이클에 E3 스크립트로 올린다.
