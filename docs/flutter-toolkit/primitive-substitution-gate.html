Flutter Toolkit · SSOT · Enforcement E2

Primitive Substitution Gate

"Flutter 기본 위젯 대신 프로젝트 디자인 시스템 컴포넌트를 써야 하는가" 를 판정하는 게이트다. 기본 위젯 사용을 금지하는 규칙이 아니라 검색 없이 쓰는 것을 금지하고, 판정 근거를 대체 후보 표라는 아티팩트로 남기게 한다.

등급 E2 (아티팩트 강제) 적용 조건 HAS_DS = true 게이트 대상 8종 신규 2026-08-13
SSOT. 이 정의가 유일한 정본이다. flutter-widget · flutter-screen · flutter-audit · widget-inspector 는 이 문서를 인용만 하고 아래 목록을 자기 문서에 복제하지 않는다. 현재 등급은 E2 (skill-design-guide §3.7 Enforcement 3 등급).
Why

왜 이 게이트가 있는가

문장 규칙(E1)만으로는 재발했다. 아래가 그 실측 근거다.

실측 REJECT

RE-02: B5(클러스터 묶음) 구분선이 Flutter 기본 Divider 사용, 기존 IFDivider 컴포넌트 미재사용

2026-08-12 · fit-pal
규칙 사이의 빈틈

기존 조항이 있었는데도 재발한 이유

flutter-widget 은 이미 §Enumerate-before-Act (디자인 토큰 전수 나열)와 "기존 위젯 수정이 기본값" 조항을 갖고 있었다. 그런데도 재발한 이유는 두 조항 모두 "프로젝트 위젯을 고칠 때" 를 전제하고, "Flutter 기본 위젯을 새로 꺼내 쓸 때" 를 막지 않기 때문이다. Divider 는 토큰이 아니고 기존 위젯 수정도 아니다 — 규칙 사이의 빈틈으로 빠져나간다.

Precondition

적용 조건

디자인 시스템이 없는 프로젝트에 이 게이트를 걸면 대체 후보가 존재하지 않아 노이즈만 생긴다.

  • HAS_DS = true (project-detection 감지 결과) 일 때만 발동한다.
  • HAS_DS = false 면 게이트를 발동시키지 않는다 — 표를 채울 후보 자체가 없다.
Scope

게이트 대상 — 의미 있는 UI 위젯 8종

아래 Flutter 기본 위젯을 새로 작성하는 코드에 넣기 전에 프로젝트 컴포넌트를 먼저 검색한다.

#기본 위젯흔한 DS 대체물
1Divider프로젝트 구분선 컴포넌트
2Button 계열 (ElevatedButton · TextButton · OutlinedButton · IconButton)프로젝트 버튼 컴포넌트
3Chip 계열프로젝트 태그/칩 컴포넌트
4Card프로젝트 카드/서피스 컴포넌트
5ListTile프로젝트 리스트 아이템 컴포넌트
6Switch프로젝트 토글 컴포넌트
7TextField / TextFormField프로젝트 입력 컴포넌트
8CircularProgressIndicator / LinearProgressIndicator프로젝트 로딩/스켈레톤 컴포넌트
Out of scope

게이트 대상이 아닌 layout primitive

이들까지 금지하면 과잉 규칙이 되어 게이트가 통째로 무시된다 — 우회된 게이트는 없는 게이트보다 나쁘다.

게이트 대상 — 검색 필요
  • Divider · Button 계열 · Chip 계열
  • Card · ListTile · Switch
  • TextField / TextFormField
  • Progress indicator 2종
대상 아님 — 금지하지 않는다
  • Text · Row · Column
  • Padding · SizedBox
  • Stack · Expanded · Flexible
  • Align · Center · Spacer
예외 하나 — 프로젝트가 Text 를 감싸는 타이포 컴포넌트(예: AppText)를 이미 전면 사용 중이라 Text( 직접 호출이 코드베이스에 사실상 없으면, 그때만 프로젝트 관습을 따른다. 그 판정은 이 게이트가 아니라 기존 코드 관찰로 한다.
Procedure

절차 — quick / deep

생성 스킬은 얕게 한 번, 감사 스킬은 변경 파일 전체를 훑는다.

quick

생성 스킬 — flutter-widget · flutter-screen

생성 시간을 늘리지 않도록 대상 위젯 한 종에 대해서만 1회 검색한다.

# 예: Divider 를 쓰려 한다
rg -n "class .*Divider|Divider\(" lib/ --glob '!**/*.g.dart' | head -20

검색 경로 우선순위: lib/**/design_system → lib/**/components → lib/**/widgets → lib/**/ui.

deep

flutter-audit deep 모드 · widget-inspector deep 모드

변경 파일 전체를 훑어 게이트 대상 8종의 직접 사용을 열거하고, 각 사용처마다 DS 대체 후보가 실재하는지 확인한다. 

# 게이트 대상 직접 사용 열거 (zsh · bash 동일)
grep -rnE '\b(Divider|ElevatedButton|TextButton|OutlinedButton|IconButton|Chip|Card|ListTile|Switch|TextField|TextFormField|CircularProgressIndicator|LinearProgressIndicator)\(' \
  lib/ --include='*.dart' | grep -v '\.g\.dart:'
0 매치 판정 — 대상 .dart 파일 수를 먼저 세고(예: 42 개), 그 패턴이 알려진 위치에서 최소 1회 매치한다는 것을 확인한 뒤의 0 만 "위반 없음" 이다. 경로가 틀려서 나온 0 은 [미검증] 이다.
Artifact

E2 아티팩트 — 대체 후보 표

게이트가 발동하면 아래 표를 응답에 채워서 남긴다. 채우지 않고 진행하지 않는다.

## Primitive Substitution Gate
검색 경로: <실제로 검색한 경로>
| 사용하려는 기본 위젯 | 검색 명령 | DS 후보 | 결정 |
| --- | --- | --- | --- |
| Divider | rg -n "Divider" lib/ | IFDivider (lib/design_system/…) | IFDivider 사용 |
| Card    | rg -n "Card" lib/    | 없음                          | 기본 Card 사용 (근거: DS 미제공) |
  • 후보가 있는데 기본 위젯을 쓰려면 근거 한 줄이 필수다. "스타일이 달라서" 는 근거가 아니다 — DS 컴포넌트의 파라미터로 표현 가능한지 먼저 소스를 읽는다.
  • 후보가 없으면 "없음" 이라고 적고 진행한다. 게이트는 기본 위젯 사용을 금지하는 것이 아니라 검색 없이 쓰는 것을 금지한다.
Enforcement

왜 E2 인가 — 등급 근거

같은 위반이 2회 이상 재발하면 E1 → E2 로 승급한다는 규칙의 적용 결과다.

E1

문장 규칙

"기존 위젯 수정이 기본값", "토큰을 전수 나열하라" 같은 서술 조항. RE-02 는 이 상태에서 발생했다.

E2 · 현재

아티팩트 강제

대체 후보 표를 응답에 남기지 않으면 진행 불가. 문장을 또 다듬는 대신 남는 증거를 요구한다.

E3 · 승급 조건

스크립트 검증

표 없이 완료 선언이 반복되면 게이트 대상 grep 을 실행하는 E3 스크립트로 승급한다.

승급 규칙 — 기존 E1 조항(§Enumerate-before-Act · "기존 위젯 수정이 기본값")이 있는 상태에서 RE-02 가 발생했으므로 문장을 또 다듬지 않고 아티팩트를 남기는 등급으로 올렸다. 근거: skill-design-guide §3.7
Gotchas

Gotchas 체크리스트

게이트를 무력화시키는 네 가지 패턴.

  • ✓
    목록을 다른 스킬 문서에 복제하지 마라 이 문서가 SSOT 다. 복제본은 반드시 드리프트하며, 그 시점부터 어느 쪽이 정본인지 알 수 없게 된다. 인용만 하라.
  • ✓
    layout primitive 까지 금지하지 마라 Text·Row·Column·Padding·SizedBox 를 막으면 과잉 규칙이 되어 게이트 전체가 무시된다. 우회된 게이트는 없는 게이트보다 나쁘다.
  • ✓
    "0 매치" 를 검증 없이 위반 없음으로 읽지 마라 대상 파일 수를 세고, 알려진 위치에서 최소 1회 매치하는지 확인한 뒤의 0 만 유효하다. 경로 오타로 나온 0 은 [미검증] 이다.
  • ✓
    "스타일이 달라서" 는 근거가 아니다 DS 컴포넌트의 파라미터로 표현 가능한지 소스를 먼저 읽어라. 읽지 않고 기본 위젯으로 우회하면 RE-02 가 그대로 재발한다.
Summary

한 문장 요약

금지하는 게이트가 아니라, 검색과 근거를 남기게 하는 게이트

HAS_DS = true 인 프로젝트에서 의미 있는 UI 위젯 8종을 새로 꺼내 쓰기 전에 DS 컴포넌트를 검색하고, 그 결과를 대체 후보 표로 남긴다. 후보가 없으면 "없음" 이라고 적고 기본 위젯을 쓰면 된다. layout primitive 는 대상이 아니며, 검증되지 않은 0 매치는 "위반 없음" 이 아니라 [미검증] 이다. 표 없이 완료 선언이 반복되면 다음 사이클에 E3 스크립트로 승급한다.
