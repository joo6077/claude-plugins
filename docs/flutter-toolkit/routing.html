라우팅

GoRouter vs auto_route vs Navigator 2.0 선택 기준, 중첩 라우트, 가드, 딥링크, URL 전략, 전환 애니메이션을 하나의 의사결정 프레임으로 정리한 리서치 문서.

Principles

다섯 가지 원칙

라우팅 패키지 선택과 구조 설계를 좌우하는 기본 원칙. 각 원칙에는 Flutter 공식 문서와 pub.dev 패키지 페이지에서 직접 확인한 근거를 링크한다.

PRINCIPLE 01

복잡한 딥링크·웹 URL·다중 Navigator가 있으면 Router 기반 필수

단순 push/pop만 있는 앱은 Navigator 1로 충분하지만, 딥링크·웹 URL 동기화·중첩 Navigator가 필요하면 Router API(go_router, auto_route) 기반으로 전환해야 한다.

Flutter Navigation Overview
PRINCIPLE 02

go_router는 Flutter team 공식 배포, 선언형 URL + redirect + ShellRoute

공식 권장 라우팅 패키지. URL 기반 선언형 라우팅, redirect로 가드, ShellRoute로 중첩 네비게이션, 딥링크를 기본 제공하며 웹·모바일 경로 통합이 쉽다.

go_router on pub.dev
PRINCIPLE 03

auto_route는 코드 생성 기반 strongly-typed

build_runner 기반 코드 생성으로 type-safe 라우트 인자를 얻는다. 중첩 라우팅, 가드, 탭 라우팅을 제공하며 대규모 앱의 라우트 수백 개를 타입 안전하게 관리할 수 있다.

auto_route on pub.dev
PRINCIPLE 04

중첩 네비게이션은 ShellRoute 또는 AutoTabsRouter

BottomNavigationBar처럼 탭별 독립 back stack이 필요할 때 go_router의 ShellRoute 또는 auto_route의 AutoTabsRouter를 사용한다. 단일 Navigator로는 탭별 스택 독립을 구현할 수 없다.

go_router auto_route
PRINCIPLE 05

웹 URL 전략은 기본 hash, PathUrlStrategy 시 서버 rewrite 필수

usePathUrlStrategy()로 #를 제거하면 모든 경로를 index.html로 rewrite하도록 서버 설정이 반드시 따라와야 한다. 미설정 시 새로고침·직접 URL 접근 모두 404가 발생한다.

Anti-patterns

피해야 할 패턴

라우트와 상태의 경계를 오용했을 때 발생하는 전형적 버그. 코드 리뷰에서 이 증상이 보이면 구조를 다시 본다.

안티패턴 문제
auth 상태를 build 안에서 imperative push/pop 상태-라우트 불일치, race condition, 로그아웃 시 중복 navigation
딥링크 필요한데 Navigator 1 named routes 사용 URL 동기화 및 딥링크 불가, 푸시 알림·웹 공유 링크 구현 막힘
탭별 독립 back stack 필요한데 단일 Navigator 탭 전환 시 스택이 공유되어 사용자 UX 붕괴
PathUrlStrategy만 켜고 서버 rewrite 미설정 새로고침·직접 URL 접근 시 404
Gotchas

실무 주의사항

패키지 선택 후 개발·배포 과정에서 반복적으로 부딪히는 두 함정.

!
go_router는 active feature development가 크지 않다 메이저 신기능보다 안정화 위주로 업데이트된다. 최신 변경사항은 CHANGELOG로 직접 확인하고, 기능이 부족하다고 느끼면 패키지 이슈 트래커를 먼저 확인한다.
!
auto_route는 코드생성 의존 CI에 build_runner 단계가 반드시 필요하고, 생성 파일을 커밋할지 여부를 프로젝트 시작 시점에 명확히 정해야 한다. 후행 변경은 merge conflict의 주요 원인이다.
