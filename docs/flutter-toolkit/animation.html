Principles

다섯 가지 핵심 원칙

단순한 프로퍼티 보간부터 정밀 제어, shared element transition까지 — 상황에 맞는 도구를 선택하는 기준.

1

Implicit vs Explicit — 상황 기반 선택

단순 property 변화는 AnimatedContainer 같은 implicit 애니메이션으로 충분하다. 정밀 제어가 필요하면 AnimationController를 쓴다. 선택 기준은 단 하나: "직접 컨트롤, 다른 값과의 동기화, 역재생이 필요한가?"

docs.flutter.dev/ui/animations/implicit-animations docs.flutter.dev/ui/animations/tutorial
2

AnimationController는 vsync + dispose 필수

AnimationController는 vsync를 요구하며 반드시 dispose()해야 한다. SingleTickerProviderStateMixin을 State에 믹스인하거나, HookWidget의 useAnimationController로 생명주기를 자동 관리한다. dispose 누락은 메모리 릭과 좀비 ticker의 대표 원인.

api.flutter.dev/flutter/animation/AnimationController-class.html
3

Tween = 값, Curve = 속도 — 분리해 조합

Tween은 값 범위(예: 0.0 → 1.0, Offset 보간)를 담당하고, Curve는 속도 곡선(ease, bounce, elastic 등)을 담당한다. 둘을 분리해 조합하면 동일 animation 객체에 서로 다른 interpolation을 여러 개 붙일 수 있다.

api.flutter.dev/flutter/animation/Curves-class.html
4

Hero는 shared element transition 전용

Hero는 route 간 "동일한 semantic element가 공간을 이동하는" 경우에만 쓴다. 단순 fade나 slide에는 사용하지 마라 — 적합한 경우는 상세 페이지로 이동할 때 썸네일이 확대되어 대표 이미지가 되는 상황 등이다.

docs.flutter.dev/ui/animations/hero-animations
5

CustomPainter는 shouldRepaint를 정확히

CustomPainter 기반 애니메이션은 shouldRepaint를 엄밀하게 구현해야 한다. 애니메이션 값이 실제로 바뀔 때만 true를 반환하라. 항상 true를 반환하면 매 프레임 전체 repaint가 발생해 비용이 심각해진다.

api.flutter.dev/flutter/rendering/CustomPainter/shouldRepaint.html

Anti-patterns

안티패턴 vs 권장

일상적으로 반복되는 실수와 그 대체안.

Avoid
  • 단순 색/크기 변경에 AnimationController를 직접 만든다
  • AnimatedBuilder 내부에서 불변 subtree까지 매 프레임 rebuild
  • 같은 route 안에서 Hero tag가 충돌하도록 방치 — 런타임 assertion
  • CustomPainter의 shouldRepaint를 항상 true로 반환
  • Lottie/Rive를 플랫폼 테스트 없이 프로덕션에 투입
Prefer
  • AnimatedContainer, AnimatedOpacity 등 implicit 위젯으로 대체
  • AnimatedBuilder의 child 파라미터로 불변 subtree를 hoisting
  • route 내에서 Hero tag의 유일성을 보장 (key 또는 id 기반)
  • shouldRepaint는 이전 instance의 animation 값과 비교해 판정
  • iOS/Android/Web 각 렌더러에서 QA 단계 검증 후 릴리스
Decision

Implicit vs Explicit 결정표

어느 도구가 맞는지 빠르게 판단하기 위한 참고 매트릭스.

Implicit을 선택해야 하는 상황

단일 위젯의 프로퍼티 하나 또는 둘이 변화하는 경우. 예: 카드 탭 시 높이 증가, 버튼 상태 변경 시 색상 전환, 상태 플래그에 따른 정렬 변경. AnimatedContainer, AnimatedOpacity, AnimatedAlign, AnimatedPositioned, TweenAnimationBuilder가 기본 선택지다.

Explicit이 필요한 상황

여러 위젯의 값이 동기화되어 움직이거나, 역재생/반복/시퀀싱이 필요한 경우. 제스처 입력과 연동되어 사용자가 직접 진행률을 조절해야 하는 경우. 이때 AnimationController + Tween + Curve 조합이 적합하다.

Snippet

예시 · AnimationController + Curve

vsync, dispose, Curve 분리의 전형적 패턴.

class _FadeDemoState extends State<FadeDemo>
    with SingleTickerProviderStateMixin {
  late final AnimationController _ctrl;
  late final Animation<double> _fade;

  // Tween은 값 범위, CurvedAnimation은 속도 곡선 — 분리해 조합
  @override
  void initState() {
    super.initState();
    _ctrl = AnimationController(
      vsync: this,
      duration: const Duration(milliseconds: 300),
    );
    _fade = CurvedAnimation(parent: _ctrl, curve: Curves.easeOutCubic);
    _ctrl.forward();
  }

  @override
  void dispose() {
    _ctrl.dispose(); // 필수 — ticker 릭 방지
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return FadeTransition(
      opacity: _fade,
      child: const Text('Hello animation'), // child hoisting
    );
  }
}
Gotchas

Gotchas 체크리스트

렌더러, CPU/GPU 부담, 플랫폼 차이에서 반복되는 함정들.

  • ✓
    Rive는 렌더러와 Impeller 사용 환경에 따라 다르게 보일 수 있다 iOS/Android/Web에서 동일하게 보이는지 QA 단계에서 반드시 확인하라. Skia와 Impeller 간 blend mode/shader 차이가 있을 수 있다.
  • ✓
    Lottie는 CPU/GPU 부담이 누적될 수 있다 반복 재생되는 경우 LottieOptions.enableMergePaths, renderCache 옵션을 검토하라. 큰 JSON은 앱 시작 시 프리로드해 첫 재생 지연을 없앨 수 있다.
  • ✓
    AnimationController dispose 누락 State가 dispose될 때 controller도 함께 dispose하지 않으면 ticker 좀비가 남는다. SingleTickerProviderStateMixin + 명시적 dispose() 호출을 습관화하라.
  • ✓
    Hero tag 유일성 같은 route에 동일 tag가 두 개 이상 존재하면 assertion이 터진다. 리스트 아이템에는 고유 id를 tag에 포함하라 (예: 'hero-$itemId').
  • ✓
    AnimatedBuilder의 child 파라미터 builder 안에서 새로 만드는 위젯은 매 프레임 재생성된다. 변하지 않는 부분은 반드시 child로 hoisting하여 구조를 재사용하라.
  • ✓
    CustomPainter의 shouldRepaint 비교 대상 이전 painter instance의 필드와 현재 값을 비교해야 한다. 단순히 return true나 return false로 끝내지 마라.
Summary

한 문장 요약

프레임 예산 안에서 부드럽게

implicit으로 해결되면 implicit으로, 제어가 필요하면 explicit으로 간다. Tween은 값, Curve는 속도 — 분리해 조합한다. Hero는 shared element에만, CustomPainter의 shouldRepaint는 정확히 구현한다. 플랫폼별 렌더러 차이(Skia/Impeller)는 QA 단계에서 반드시 확인한다. Rive/Lottie 반복 재생은 CPU/GPU 누적 비용을 계산하고 튜닝한다.
