Principles

다섯 가지 핵심 원칙

implicit/explicit 선택, vsync·dispose, Tween과 Curve 분리, Hero 용도 한정, shouldRepaint 정확성.

1

단순 property 변화는 implicit, 정밀 제어는 explicit

단순 property 변화는 implicit(AnimatedContainer 등), 정밀 제어가 필요하면 explicit(AnimationController)을 쓴다. 선택 기준은 "직접 컨트롤/동기화/역재생이 필요한가"다.

docs.flutter.dev/ui/animations/implicit-animations docs.flutter.dev/ui/animations/tutorial
2

AnimationController는 vsync를 요구하고 반드시 dispose

AnimationController 는 vsync 를 요구하며 반드시 dispose() 해야 한다. SingleTickerProviderStateMixin 또는 HookWidget 의 useAnimationController 로 자동 관리하라.

api.flutter.dev/flutter/animation/AnimationController-class.html
3

Tween은 값 범위, Curve는 속도 곡선

Tween 은 값 범위, Curve 는 속도 곡선을 담당한다. 둘을 분리해 조합하면 동일 animation 에 다양한 interpolation 을 붙일 수 있다.

api.flutter.dev/flutter/animation/Curves-class.html
4

Hero는 shared element transition 전용

Hero 는 shared element transition 전용이다. route 간 "동일한 semantic element 가 이동하는" 경우에만 쓰고, 단순 fade/slide 에는 쓰지 마라.

docs.flutter.dev/ui/animations/hero-animations
5

CustomPainter의 shouldRepaint를 정확히 구현

CustomPainter 기반 애니메이션은 shouldRepaint 를 정확히 구현한다. 애니메이션 값이 바뀔 때만 true 를 반환해야 하며, 항상 true 는 비용이 심각하다.

api.flutter.dev/flutter/rendering/CustomPainter/shouldRepaint.html

Anti-patterns

안티패턴 vs 권장

과한 컨트롤러, 불필요한 rebuild, tag 충돌, 무조건 repaint.

Avoid
  • 단순 색/크기 변경에 AnimationController 를 직접 생성
  • AnimatedBuilder 내부에서 불변 subtree 까지 rebuild
  • Hero tag 충돌 방치 — route 하나에 동일 tag 가 둘 이상
  • CustomPainter 의 shouldRepaint 를 항상 true 로 반환
Prefer
  • AnimatedContainer / AnimatedOpacity 로 충분
  • child 파라미터로 불변 subtree 를 hoisting
  • route 별로 유일한 Hero tag 를 부여 (런타임 assertion 회피)
  • 애니메이션 값이 바뀔 때만 true 를 반환
Decision

Implicit vs Explicit 결정표

어느 도구가 맞는지 빠르게 판단하기 위한 참고 매트릭스.

Implicit 을 선택해야 하는 상황

단일 위젯의 프로퍼티 하나 또는 둘이 변화하는 경우. 예: 카드 탭 시 높이 증가, 버튼 상태 변경 시 색상 전환, 상태 플래그에 따른 정렬 변경. AnimatedContainer, AnimatedOpacity, AnimatedAlign, AnimatedPositioned, TweenAnimationBuilder 가 기본 선택지다.

Explicit 이 필요한 상황

여러 위젯의 값이 동기화되어 움직이거나, 역재생/반복/시퀀싱이 필요한 경우. 제스처 입력과 연동되어 사용자가 직접 진행률을 조절해야 하는 경우. 이때 AnimationController + Tween + Curve 조합이 적합하다.

Snippet

예시 · AnimationController + Curve

vsync, dispose, Curve 분리, child hoisting 의 전형적 패턴.

class _FadeDemoState extends State<FadeDemo>
    with SingleTickerProviderStateMixin {
  late final AnimationController _ctrl;
  late final Animation<double> _fade;

  // Tween은 값 범위, CurvedAnimation은 속도 곡선 — 분리해 조합
  @override
  void initState() {
    super.initState();
    _ctrl = AnimationController(
      vsync: this,
      duration: const Duration(milliseconds: 300),
    );
    _fade = CurvedAnimation(parent: _ctrl, curve: Curves.easeOutCubic);
    _ctrl.forward();
  }

  @override
  void dispose() {
    _ctrl.dispose(); // 필수 — ticker 릭 방지
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return FadeTransition(
      opacity: _fade,
      child: const Text('Hello animation'), // child hoisting
    );
  }
}
Pattern

Staggered Animation

여러 위젯이 순차적으로 등장하는 패턴. Interval 로 각 요소의 시작/끝 시점을 배분한다.

0.0 – 0.5
0.0 – 0.6
0.3 – 0.8
전체 duration 을 0.0~1.0 으로 보고 각 요소가 차지하는 구간을 나눈다.
// Interval(0.0, 0.5) → 전체 duration의 전반부에서 실행
// Interval(0.3, 0.8) → 30%~80% 구간에서 실행
final slideAnim = Tween<Offset>(begin: Offset(0, 0.3), end: Offset.zero)
    .animate(CurvedAnimation(parent: controller, curve: Interval(0.0, 0.6, curve: Curves.easeOut)));
  • 출처: docs.flutter.dev/ui/animations/staggered-animations
Patterns

교체 vs 전환, 그리고 격리

같은 위치의 위젯 교체와 route 전환은 다른 도구를 쓴다.

AnimatedSwitcher vs PageRouteBuilder

같은 위치에서 위젯을 교체할 때는 AnimatedSwitcher, route 전환은 PageRouteBuilder / CustomTransitionPage 를 쓴다. 혼동하면 layout shift 가 발생한다.

api.flutter.dev/flutter/widgets/AnimatedSwitcher-class.html

RepaintBoundary 활용

애니메이션되는 위젯을 RepaintBoundary 로 감싸면 해당 서브트리만 별도 레이어로 분리되어 나머지 UI 의 repaint 를 방지한다.

Profiling

성능 프로파일링

UI thread 와 Raster thread 를 함께 본다. 렌더러가 무엇인지 먼저 확정한다.

  • DevTools 의 "Performance Overlay" 에서 UI thread 와 Raster thread 모두 16ms 이내인지 확인한다.
  • Timeline.startSync('animation_label') 로 특정 애니메이션의 비용을 측정한다.
  • Impeller 환경에서는 shader compilation jank 가 사라지므로 first-frame 성능이 개선된다 — iOS 필수 · Android API 29+ 기본 · macOS/Linux/Windows 는 Flutter 3.47 부터 기본 · Web 은 Skia. 플랫폼별 상태는 성능 문서 §Impeller 성능 특성 참조.
  • 출처: docs.flutter.dev/perf/ui-performance
Gotchas

Gotchas 체크리스트

Rive/Lottie 런타임 차이, hook 파라미터 변경, listener 해제.

  • ✓
    Rive 는 렌더러 환경에 따라 동작이 다르다 renderer 선택과 Impeller 사용 환경에 따라 차이가 있다 — iOS/Android/웹에서 동일하게 보이는지 QA 단계에서 반드시 확인하라.
  • ✓
    Lottie 는 CPU/GPU 부담이 커질 수 있다 반복 재생되는 경우 LottieOptions.enableMergePaths, renderCache 등 옵션을 검토하라.
  • ✓
    useAnimationController 의 duration 변경은 hot reload 로 안 잡힌다 HookWidget 에서 useAnimationController 의 duration 파라미터 변경은 hot reload 에서 반영되지 않을 수 있다 — restart 가 필요하다.
  • ✓
    addStatusListener 는 반드시 해제 dispose 에서 제거하지 않으면 메모리 릭이 발생한다. useEffect 의 cleanup 에서 반드시 제거하라.
Summary

한 문장 요약

필요한 만큼만 제어하고, 나머지는 프레임워크에 맡긴다

property 하나둘이면 implicit 으로 끝내고, 동기화·역재생·제스처 연동이 필요할 때만 AnimationController 를 꺼낸다. Tween 과 Curve 를 분리하고, child hoisting 과 RepaintBoundary 로 rebuild·repaint 범위를 좁힌다. Hero 는 shared element 전용이며, shouldRepaint 는 값이 바뀔 때만 true 여야 한다. 프로파일링 수치를 볼 때는 렌더러(Impeller/Skia)가 무엇인지 먼저 확정한다.
