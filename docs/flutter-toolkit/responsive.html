MediaQuery와 LayoutBuilder 선택, breakpoint, SafeArea, NavigationRail vs BottomNavigationBar를 다룬다.

Principles

다섯 가지 원칙

폰·태블릿·폴더블·데스크톱 모든 창 크기에서 동작하려면 디바이스가 아닌 window size class를 기준으로 레이아웃을 결정해야 한다.

01

Responsive와 Adaptive는 다르다

Responsive는 주어진 공간에 맞춰 레이아웃을 늘리고 줄이는 것, Adaptive는 그 공간에서 usable한 UI 패턴을 선택하는 것이다.

adaptive-responsive
02

MediaQuery.sizeOf vs LayoutBuilder

창 전체 크기는 MediaQuery.sizeOf(context), 지역 레이아웃은 LayoutBuilder를 쓴다. LayoutBuilder는 부모 constraints 기준이라 중첩 컨테이너에 정확하다.

adaptive-responsive/general
03

Device가 아니라 Window size

디바이스 종류가 아니라 window size로 브랜치한다. "폰이냐 태블릿이냐"가 아니라 "현재 width class가 무엇이냐"로 결정하라.

adaptive-responsive/general
04

내비게이션 패턴을 교체하라

작은 창에는 BottomNavigationBar, 넓은 창에는 NavigationRail을 쓴다. 내비게이션 패턴 자체를 width class에 따라 교체하는 것이 adaptive의 핵심.

adaptive-responsive/general
05

SafeArea와 system inset

SafeArea와 system UI inset을 항상 고려한다. 노치·상태바·제스처 영역을 무시하면 기기마다 레이아웃이 어긋난다.

Numbers & Boundaries

수치·경계값

Material Design width size class의 경계값. 모든 분기는 logical pixel(dp) 기준이다.

항목값
내비게이션 경계 600dp 미만: BottomNavigationBar, 600dp 이상: NavigationRail.
Compact 0–599dp — 폰 portrait 일반.
Medium 600–839dp — 소형 태블릿·폰 landscape·폴더블 unfolded.
Expanded 840dp+ — 태블릿·데스크톱.
단위 기준 breakpoint는 물리 inch가 아니라 logical pixel(dp)로 판단한다.
Anti-patterns

하지 말아야 할 것 vs 해야 할 것

디바이스 종류·OS·기기명을 기준으로 분기하는 순간 foldable과 desktop resize에서 무너진다.

Anti-patterns
  • Platform.isAndroid/Platform.isIOS로 레이아웃을 분기 — OS가 아니라 창 크기 문제다.
  • 기기명(iPhone 15 Pro 등) 하드코딩 — foldable, desktop resize에서 즉시 깨진다.
  • MediaQuery.of(context)를 전역 남발 — 필요 없는 속성 변화에도 전부 rebuild된다.
  • portrait lock으로 responsive 이슈를 숨기기 — 태블릿/폴더블/데스크톱 사용자 경험이 망가진다.
Preferred
  • width size class(Compact/Medium/Expanded)로 분기한다.
  • 창 크기 기반의 breakpoint helper를 한 곳에 정의해 재사용한다.
  • MediaQuery.sizeOf/paddingOf 등 필요한 속성만 읽는다.
  • 모든 orientation에서 레이아웃이 동작하도록 설계한다.
Gotchas

반복되는 함정

Flutter 3.10+에서 추가된 세분화된 MediaQuery selector를 쓰면 rebuild 범위가 크게 줄어든다.

✓

"폰/태블릿만" 분기는 반드시 깨진다. "폰/태블릿만" 분기하는 코드는 foldable의 접힘 상태 변화와 desktop window resize에서 반드시 깨진다 — width class 기반으로 작성하라.

✓

세분화된 selector를 쓰면 rebuild가 줄어든다. MediaQuery.of(context) 전체 대신 MediaQuery.sizeOf(context), MediaQuery.paddingOf(context) 등 필요한 속성만 읽으면 rebuild 범위가 크게 줄어든다 (Flutter 3.10+).
