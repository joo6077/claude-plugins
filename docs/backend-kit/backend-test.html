백엔드 테스트 자동 생성

스택 무관 테스트 코드 자동 생성. 프로젝트를 감지하여 pytest, Jest, JUnit, go test, ExUnit 등 적합한 프레임워크로 unit, integration, API 테스트를 생성한다. Arrange-Act-Assert 패턴, 에러 경로 커버, 테스트 격리를 기본 원칙으로 따른다.

Step 0

스택 감지

프로젝트 루트의 설정 파일을 탐색하여 스택과 테스트 프레임워크를 자동 결정한다. Rust와 Dart는 전용 스킬로 리다이렉트한다.

추가로 ORM(SQLAlchemy, TypeORM, Prisma, Django ORM, JPA, GORM, Ecto), API 프레임워크(FastAPI, Express, NestJS, Spring Boot, Gin, Echo, Phoenix), 기존 테스트 디렉토리(tests/, __tests__/, src/test/), 설정 파일(pytest.ini, jest.config.*, vitest.config.*)을 감지한다.

Step 1

테스트 유형 자동 추론

대상 파일의 특성을 분석하여 테스트 유형을 자동 결정한다. 사용자가 유형을 명시하면 그것을 우선한다.

대상 특성 테스트 유형 설명
순수 함수, 유틸리티, 도메인 로직 unit 외부 의존성 없이 격리 실행, 밀리초 단위
DB 모델, 리포지토리, 쿼리 integration 실제 DB(Testcontainers)로 검증, 스키마 드리프트 방지
API 핸들러, 라우터, 컨트롤러 api 프레임워크 test client로 요청/응답 검증
외부 서비스 연동, 전체 플로우 e2e 핵심 플로우 중심, 최소 범위로 유지
Step 3

스택별 생성 가이드

공통 규칙: Arrange-Act-Assert 패턴, public 함수당 최소 1개 테스트, happy path + error path 모두 커버, 행위 서술형 테스트 이름.

Py

Python (pytest)

tests/test_{module}.py 구조. 클래스 기반 그루핑, pytest.raises로 에러 검증. DB 의존 시 conftest.py에 fixture 정의 + Testcontainers 또는 트랜잭션 롤백.

class TestUserService: def test_create_user_with_valid_data(self): # Arrange payload = {"name": "Alice", "email": "a@b.com"} # Act user = service.create(payload) # Assert assert user.name == "Alice" def test_create_user_duplicate_raises(self): with pytest.raises(DuplicateError): service.create(duplicate_payload)
JS

Node.js (Jest / Vitest)

__tests__/{module}.test.ts 구조. describe/it 블록, expect 체이닝. API 테스트는 supertest(Express) 또는 inject(Fastify) 사용.

describe('UserService', () => { it('should create user with valid data', () => { const user = service.create(validPayload) expect(user.name).toBe('Alice') }) it('should throw on duplicate email', () => { expect(() => service.create(dup)) .toThrow(DuplicateError) }) })
Jv

Java (JUnit 5)

src/test/java/{pkg}/{Target}Test.java 구조. AssertJ fluent assertions, @DisplayName 행위 서술. Spring Boot API는 MockMvc / WebTestClient 사용.

@Test @DisplayName("valid input creates user") void happyPath() { var user = service.create(validInput); assertThat(user.getName()) .isEqualTo("Alice"); } @Test @DisplayName("duplicate throws exception") void errorCase() { assertThatThrownBy(() -> service.create(dup)) .isInstanceOf(DuplicateException.class); }
Go

Go (testing + testify)

{module}_test.go 같은 패키지 내 배치. testify의 assert/require 사용. API 테스트는 httptest로 서버 기동 없이 검증.

func TestCreateUser_HappyPath(t *testing.T) { user, err := service.Create(validInput) require.NoError(t, err) assert.Equal(t, "Alice", user.Name) } func TestCreateUser_Duplicate(t *testing.T) { _, err := service.Create(dupInput) assert.ErrorIs(t, err, ErrDuplicate) }
Step 4

Integration 테스트 보강

DB 의존 코드나 API 핸들러가 감지되면 자동으로 통합 테스트 인프라를 구성한다.

1

Testcontainers로 실제 DB 테스트

Docker로 실제 DB를 테스트 시 자동 생성/폐기한다. Mock DB는 스키마 드리프트를 놓치므로 실제 DB를 원칙으로 한다.

스택패키지
Pythontestcontainers
Node.jstestcontainers
Javaorg.testcontainers
Gotestcontainers-go

마이그레이션 자동 실행 포함. 격리는 트랜잭션 롤백 또는 테이블 truncate로 보장한다.

2

API Test Client 우선 사용

실제 포트 바인딩 없이 프레임워크의 내장 test client를 사용한다. OpenAPI spec이 있으면 요청/응답 스키마를 대조하고, 인증 헤더 fixture를 포함시킨다.

Gotchas

체크리스트

테스트 코드 생성 시 반복되는 실수 10가지. Claude가 매번 확인해야 하는 항목들이다.

  • 1. 스택 감지 없이 테스트 코드 생성 금지 Step 0의 프로젝트 감지를 반드시 먼저 수행하라. Python 프로젝트에 Jest 테스트를 생성하거나 Node 프로젝트에 pytest를 생성하면 안 된다.
  • 2. DB 의존 테스트에 실제 DB 사용 원칙 가능하면 Testcontainers/Docker Compose로 실제 DB를 띄워라. Mock DB는 스키마 드리프트를 놓친다.
  • 3. API 테스트에서 서버 기동 방식 확인 프레임워크의 test client를 우선 사용하라 (FastAPI: TestClient, Express: supertest, Spring: MockMvc, Go: httptest). 실제 포트 바인딩은 integration/e2e에서만.
  • 4. 테스트 격리 필수 각 테스트는 독립 실행 가능해야 한다. 공유 상태(전역 변수, DB 레코드)에 의존하면 순서 의존성이 생긴다. 트랜잭션 롤백 또는 테스트별 시드 데이터를 사용하라.
  • 5. 에러 경로 테스트 누락 금지 happy path만 테스트하면 프로덕션에서 깨진다. 최소한 400/401/404/500 응답 경로를 각각 테스트하라. RFC 9457 problem+json 응답 형식도 검증 대상이다.
  • 6. Mock 남용 금지 외부 서비스(결제 API, 이메일 발송)만 mock하라. 내부 서비스/리포지토리를 mock하면 리팩토링 시 테스트가 깨지고 실제 동작과 괴리가 생긴다.
  • 7. 기존 테스트 패턴 무시 금지 프로젝트에 이미 테스트가 있으면 그 패턴(디렉토리 구조, 네이밍, fixture 방식, assert 라이브러리)을 먼저 파악하고 따르라. 새로운 패턴을 무단 도입하지 마라.
  • 8. 환경 변수 하드코딩 금지 DB URL, API 키를 테스트 파일에 직접 넣지 마라. .env.test 또는 fixture/conftest에서 주입하라.
  • 9. 비동기 테스트에서 타임아웃 미설정 금지 async 테스트는 적절한 타임아웃을 설정하라. 무한 대기는 CI를 멈춘다.
  • 10. ORM 쿼리 테스트 시 N+1 검증 포함 리스트 조회 API 테스트에서 쿼리 수를 assert하라. Django: assertNumQueries, SQLAlchemy: connection.execute 카운트, JPA: Hibernate statistics.
Anti-patterns

안티패턴

테스트 생성 시 가장 빈번하게 발생하는 3가지 안티패턴. Bad vs Good 비교로 올바른 접근법을 제시한다.

Mock 남용 (가짜 그린)
Bad
# 내부 리포지토리까지 전부 mock def test_create_user(mock_repo, mock_validator): mock_repo.save.return_value = User(id=1) mock_validator.validate.return_value = True result = service.create(data) mock_repo.save.assert_called_once() # 구현 변경 시 테스트 깨짐, 실제 DB 오류 미탐지
Good
# 실제 DB + 외부 서비스만 mock def test_create_user(db_session, mock_email): result = service.create(data) assert result.id is not None assert result.name == "Alice" user_in_db = db_session.get(User, result.id) assert user_in_db is not None # 실제 DB 동작 검증, 이메일만 mock
환경 변수 하드코딩
Bad
// DB URL을 테스트 파일에 직접 하드코딩 const DB_URL = "postgres://user:pass@localhost:5432/testdb" const API_KEY = "sk-test-12345" describe('UserRepo', () => { beforeAll(async () => { db = await connect(DB_URL) }) })
Good
// .env.test에서 주입, 테스트 setup에서 로드 import { loadEnv } from './test-helpers' describe('UserRepo', () => { beforeAll(async () => { const env = loadEnv('.env.test') db = await connect(env.DATABASE_URL) }) }) // 시크릿 미노출, CI에서도 동작
에러 경로 테스트 누락
Bad
// happy path만 테스트 func TestGetUser(t *testing.T) { user, _ := handler.GetUser(1) assert.Equal(t, "Alice", user.Name) } // 404? 401? 500? 전부 미검증 // 프로덕션에서 에러 응답이 빈 body로 나감
Good
func TestGetUser_NotFound(t *testing.T) { w := httptest.NewRecorder() req := httptest.NewRequest("GET", "/users/999", nil) router.ServeHTTP(w, req) assert.Equal(t, 404, w.Code) // RFC 9457 problem+json 검증 var problem ProblemDetail json.Unmarshal(w.Body.Bytes(), &problem) assert.Equal(t, "not_found", problem.Type) }
Step 5

실행 검증

생성된 테스트를 실행하고 결과를 확인한다. 실패 시 원인 분석 후 수정하며, 의존성 미설치는 설치를 안내한다.

스택 실행 명령
Python pytest {test_file} -v
Node.js npx vitest run {test_file} 또는 npx jest {test_file}
Java ./gradlew test --tests {TestClass} 또는 mvn test -Dtest={TestClass}
Go go test -v -run {TestFunc} ./{pkg}/...
Elixir mix test {test_file}
