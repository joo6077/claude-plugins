Schema — Reflect Kit

파이프라인이 주고받는 데이터의 정본. Reflection 엔트리 YAML · Promotion Ledger · 훅 에러 로그 태그 · project_id 포맷 네 가지를 한 페이지에 모은다.

YAML 스키마 · Ledger · 에러 태그 · project_id
1 · Reflection Entry

log-reflection.sh 출력 YAML

경로: ~/.claude/logs/<project_id>/reflections-YYYY-MM.md — 각 타임스탬프 헤더 아래 여러 YAML 블록이 올 수 있다. no issues 한 줄이면 블록 없음.

primary_category: misunderstanding | repeated_error | wrong_approach | tool_failure
also_applies: []                      # multi-label: 추가 해당 카테고리
mistake_tag: <kebab-case 영문 태그>   # 같은 패턴이면 같은 태그 (집계 키)
trigger: <str>                        # 사용자 프롬프트/상황 스니펫 1줄
undesired_behavior: <str>             # Claude가 한 잘못 1줄
desired_behavior: <str>               # 사용자가 원한 것 1줄
severity: low | medium | high
# Surface 결정 4축
scope: session | project | global
risk_class: low | medium | high
procedurality: single_rule | multi_step_procedure
enforcement_need: soft_reminder | hard_gate
evidence_turns: <int>                 # 교정이 드러난 턴 수
tools_used:
  skills: []                          # invoke된 slash command
  agents: []                          # spawn된 subagent type
  mcp_servers: []                     # 사용한 MCP 서버 prefix
approach_note: <str>                  # 시도한 접근법 1줄
카테고리

4종 (상호배타 아님)

misunderstanding
사용자 의도 오해 — 엉뚱한 파일 수정, 범위 오해, 잘못된 가정
repeated_error
같은 세션 내 또는 사용자 교정 뒤에도 반복된 같은 실수
wrong_approach
더 적절한 스킬/에이전트/MCP가 있었는데 비효율적으로 시도
tool_failure
도구 호출 실패 중 맥락이 의미 있는 것 (단순 exit code-only는 제외)
primary_category에 지배적인 하나, also_applies에 추가 해당 카테고리를 배열로. 단일 필드 surface_candidate는 스키마에서 제거됐다 — 4축 precedence로만 계산한다.
2 · Promotion Ledger

reflect-promote 승격 이력

경로: ~/.claude/logs/<project_id>/promotions-ledger.md — 승격마다 한 엔트리 append. 30일 뒤 kaizen이 post_freq를 채운다.

- rule_id: <uuid>                       # uuidgen
  mistake_tag: <tag>
  promoted_to: project_claude_md | project_memory | global_claude_md |
               global_memory | skill | path_scoped_rule | hook
  target_path: <실제 수정된 파일 절대경로>
  promoted_at: <ISO8601 with TZ>
  source_evidence:
    - path: ~/.claude/logs/<id>/reflections-YYYY-MM.md
      anchor: <타임스탬프 헤더>
  initial_freq: <int>                   # 승격 시점 빈도
  calibration_window_days: 30
  post_freq: <int | null>               # 30일 뒤 kaizen이 업데이트
  status: active | demoted | removed
  demotion_reason: <str>                # 강등 시만

회귀 판정 규칙

조건판정
post_freq == 0 AND risk_class == lowstatus: demoted 후보 (과잉제약)
post_freq >= initial_freq효과 없음 → 프롬프트/surface 재검토
post_freq < initial_freq효과 있음 → 유지
3 · Error Log Tags

.errors.log — 훅 실패 사유 태그

구조: 한 줄당 <ISO8601+TZ> [<hook-name>] <reason>. log-reflection.sh가 사용하는 태그:

skip:cli-missing
codex CLI 없음
skip:transcript-path-empty
stdin에 transcript_path 없음
skip:transcript-file-missing path=<>
transcript 파일 없음
skip:transcript-too-short lines=<N>
10줄 미만
skip:transcript-empty-after-tail
tail 결과 빈 값
fail:codex-exit-<N> session=<>
codex exec 비정상 종료
fail:codex-empty-output session=<>
codex 빈 응답
/reflect-digest가 .errors.log를 읽어 훅 실패 요약도 리포트에 포함한다. 특정 태그가 반복되면 인프라 문제 신호다.
4 · Project ID (v0.3.0 Hybrid)

로그 분리 식별자

기본:         <basename(git-root)>
충돌 fallback: <basename>-<6자 md5 hex>
  • v0.3.0 Hybrid — basename 기본 사용, .project-root 마커로 충돌 감지 시 자동 hash fallback + stderr 1회 경고
  • 기존 <basename>-<hash6> 디렉토리는 glob union 으로 read 지원 (backward-compatible · 마이그레이션 불필요)
  • git root 없으면 cwd basename 사용 (기존 fallback 유지)
  • 헬퍼: ${CLAUDE_PLUGIN_ROOT}/hooks/_lib-project-id.sh — compute_project_id (쓰기 id), normalize_project_query (읽기 glob union), is_internal_logs_dir (_cron/dot/underscore 제외)
  • 예: claude-plugins (basename), fit-pal-a3b4f9 (충돌 감지 또는 v0.2.0 레거시)
버전 관리
스키마 변경 시 이 페이지와 reflect-kit/docs/DESIGN.md, reflect-kit/docs/SCHEMA.md를 동시에 업데이트한다. 호환되지 않는 변경(필드 삭제·의미 변경)은 log-reflection.sh 프롬프트도 함께 수정해야 한다.
