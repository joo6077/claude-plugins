01 · Reflection Entry

1. Reflection 엔트리 (hooks/log-reflection.sh 출력)

저장 경로~/.claude/logs/<project_id>/reflections-YYYY-MM.md

각 타임스탬프 헤더 ## <ISO8601+TZ> 아래 여러 YAML 블록이 올 수 있다. 결과가 no issues 한 줄이면 기록할 블록이 없다는 뜻이다.

primary_category: misunderstanding | repeated_error | wrong_approach | tool_failure
also_applies: []                      # multi-label: 추가로 해당하는 카테고리
mistake_tag: <kebab-case 영문 태그>   # 같은 패턴이면 같은 태그 (집계 키)
trigger: <str>                        # 사용자 프롬프트/상황 스니펫 1줄
undesired_behavior: <str>             # Claude가 한 잘못 1줄
desired_behavior: <str>               # 사용자가 원한 것 1줄
severity: low | medium | high
actionability: claude_behavior | user_environment
# Surface 결정 4축 (단일 surface_candidate 필드는 쓰지 않음)
scope: session | project | global
risk_class: low | medium | high
procedurality: single_rule | multi_step_procedure
enforcement_need: soft_reminder | hard_gate
evidence_turns: <int>                 # 교정이 드러난 턴 수
tools_used:
  skills: []                          # invoke된 slash command
  agents: []                          # spawn된 subagent type
  mcp_servers: []                     # 사용한 MCP 서버 prefix
approach_note: <str>                  # 시도한 접근법 1줄

카테고리 정의

misunderstanding

사용자 의도를 오해한 경우. 엉뚱한 파일 수정, 범위 오해, 잘못된 가정이 포함된다.

repeated_error

같은 세션 안에서, 또는 사용자 교정 뒤에도 같은 실수를 반복한 경우다.

wrong_approach

더 적절한 스킬·에이전트·MCP가 있었지만 비효율적인 접근을 시도한 경우다.

tool_failure

맥락이 의미 있는 도구 호출 실패다. 단순 exit code-only 실패는 제외한다.

카테고리는 상호 배타적이지 않다. 지배적인 하나를 primary_category에, 추가 해당 카테고리를 also_applies 배열에 기록한다.

4축 필드 의미

scope

규칙이 적용될 범위: session / project / global

risk_class

위반 시 피해 정도: low / medium / high

procedurality

단일 규칙인지 절차인지: single_rule / multi_step_procedure

enforcement_need

안내로 충분한지 차단이 필요한지: soft_reminder / hard_gate

/reflect-promote는 이 4축과 빈도를 precedence table에 넣어 최종 surface를 계산한다. 단일 surface_candidate 필드는 사용하지 않는다.

actionability

값의미파이프라인 취급
claude_behaviorClaude가 다르게 행동했다면 피할 수 있었던 사건. 기본값이다.precedence 대상
user_environment없는 훅 참조, 실행 권한 없음, CLI 미설치, 포트 점유처럼 사용자 환경만 고쳐야 해소되는 사건precedence 제외. digest의 ## 환경 액션 아이템으로만 보고하고 반복 로깅을 억제한다.
  • 필드가 없는 레거시 엔트리는 claude_behavior로 간주하는 fail-open 방식이다.
  • user_environment의 desired_behavior에는 환경 수정 지시가 아니라 Claude가 무엇을 보고 판단했어야 하는지를 쓴다.
  • 도입 근거는 2026-07 실측이다. 760개 엔트리 중 351건, 즉 40%가 단일 환경 오설정의 반복 기록이었다.

mistake_tag 정규화

열린 어휘를 유지한다

태그는 닫힌 집합이 아니다. 새로운 사건에는 새 태그를 허용해 드문 신호가 catch-all로 흡수되는 것을 막는다.

출처 · arXiv 2605.06940

반복은 묶고 주기적으로 재노출한다

환경 이슈는 태그별로 그룹화하고 7일 억제 창 뒤 다시 노출한다. 구조는 Alertmanager의 group_by와 repeat_interval에 대응한다.

출처 · Prometheus Alertmanager
  • 근본원인 1개 = 태그 1개. 증상·파일명·도구명을 태그에 넣지 않는다.
  • 형태는 <행동동사>-<대상> kebab-case다.
  • Stop 훅은 기존 태그 중 빈도 2 이상인 상위 40개를 프롬프트에 주입해 stateless 분석기의 재사용을 유도한다.
  • 이미 파편화된 태그는 /reflect-digest가 canonical_tag와 aliases 클러스터로 복구한다.
02 · Promotion Ledger

2. Promotion Ledger 엔트리 (reflect-promote 기록)

저장 경로~/.claude/logs/<project_id>/promotions-ledger.md

/reflect-promote가 승격마다 한 엔트리를 append하고, 30일 뒤 /reflect-kaizen이 canonical과 aliases를 합산한 post_freq를 채운다.

- rule_id: <uuid>                       # 고유 ID (uuidgen)
  mistake_tag: <canonical_tag>          # 클러스터 대표 태그
  aliases: []                           # 같은 근본원인의 다른 표기들
  promoted_to: project_claude_md | project_memory | global_claude_md |
               global_memory | skill | path_scoped_rule | hook
  enforcement_level: E1 | E2 | E3       # skill-design-guide §3.7 등급
  target_path: <실제 수정된 파일 절대경로>
  promoted_at: <ISO8601 with TZ>
  source_evidence:
    - path: ~/.claude/logs/<id>/reflections-YYYY-MM.md
      anchor: <타임스탬프 헤더>
  initial_freq: <int>                   # 승격 시점 cluster_freq
  calibration_window_days: 30
  post_freq: <int | null>               # canonical + aliases 합산
  status: active | demoted | removed
  demotion_reason: <str>                # 강등 시만
                                          # 상향이면 escalated-to-E<N> (rule_id: <새 uuid>)

enforcement_level

등급 정의와 승급 임계의 SSOT는 harness/docs/guides/skill-design-guide.md §3.7 “Enforcement 3 등급”이다. 여기서는 동의어나 별도 정의를 만들지 않고 surface 대응만 기록한다.

§3.7 등급reflect-kit surface
E1project/global memory, CLAUDE.md 한 줄
E2path_scoped_rule, skill의 Process 체크리스트
E3hook, 검증 스크립트

Regression 측정 규칙

관측값판정
post_freq == 0 AND risk_class == lowstatus: demoted 후보. 과잉제약일 수 있다.
post_freq == 1문구 명확화 후보. enforcement 등급은 유지한다.
post_freq >= 2효과 없음. 2회 이상 E2, 3회 이상 또는 비가역·신뢰 손상이면 E3 상향 후보로 본다.
post_freq < initial_freq AND post_freq <= 1효과 있음. 현재 규칙을 유지한다.
측정 단위 주의: promoted_at + calibration_window_days 시점의 mistake_tag와 aliases 전체 재발 횟수를 합산한다. canonical 단독 count는 태그 파편화 상황에서 구조적으로 과소집계된다.
03 · Hook Error Log

3. 훅 에러 로그 (.errors.log)

저장 경로~/.claude/logs/<project_id>/.errors.log

한 줄은 <ISO8601+TZ> [<hook-name>] <reason> 포맷이며, 파싱할 수 있도록 key=value 쌍을 공백으로 구분한다.

사유 태그 (log-reflection.sh)

skip:cli-missing
codex CLI가 없다.
skip:transcript-path-empty
stdin에 transcript_path가 없다.
skip:transcript-file-missing path=<>
transcript 파일이 없다.
skip:transcript-too-short lines=<N>
transcript가 10줄 미만이다.
skip:transcript-empty-after-tail
tail 결과가 빈 값이다.
fail:codex-exit-<N> session=<> err=<한 줄>
codex exec가 비정상 종료했다.
fail:codex-empty-output session=<>
codex가 빈 응답을 냈다.
fallback:claude-used session=<>
codex 실패 뒤 claude -p 대체 경로로 기록했다.
fallback:claude-exit-<N> session=<> err=<한 줄>
대체 경로도 비정상 종료해 기록 없이 끝났다.
fallback:claude-empty-output session=<>
대체 경로가 빈 응답을 냈다.
skip:fallback-unavailable session=<>
claude CLI가 없다.
fail:tag-field-unresolved session=<>
태그 필드 이름을 읽지 못해 분석 전에 멈췄다.
env-dedup:kept=<N> dropped=<M> drop=<tag>... session=<>
환경 오설정 블록을 억제했다.
skip:env-dedup-all <요약> session=<>
모든 블록이 억제되어 append 자체를 생략했다.
warn:env-dedup-failed exit=<N> session=<>
dedup 게이트가 실패해 fail-open으로 원본을 기록했다.
warn:lemma-map-unreadable path=<> session=<>
정규화 사전을 못 읽어 사전 없이 묶었지만 실행은 계속된다.
vocab:raw_distinct/clusters/entries/singletons/fold/singleton_share/epc=<일곱 값> session=<>
태그 파편화 지표다. 실패가 아니므로 collect_status는 세지 않는다.
err=는 공백을 포함해 줄 끝까지다. stderr에서 error 또는 ERROR로 시작하는 첫 줄을 고르고, 없으면 비어 있지 않은 첫 줄을 가린 뒤 200자로 자른다. codex가 성공해도 stderr에 프롬프트 전문을 쓰므로 전문은 남기지 않는다. 대체 경로는 stderr가 비면 stdout에서 고른다.

/reflect-digest의 collect_status는 대체 경로 실패 셋, skip:cli-missing, fail:tag-field-unresolved를 기록 없이 끝난 실행으로 센다.

03-1 · Environment Rollup

3-1. 환경 오설정 롤업 (.env-issues.tsv)

저장 경로~/.claude/logs/<project_id>/.env-issues.tsv
tag <TAB> first_seen <TAB> last_seen <TAB> count
# first_seen, last_seen 시각은 epoch 초

Stop 훅의 dedup 게이트가 actionability: user_environment 블록을 억제할 때마다 count를 올린다. REFLECT_ENV_REPEAT_DAYS 기본값인 7일 안에 같은 태그가 다시 오면 reflections 본문에는 쓰지 않고 이 파일만 갱신한다.

빈도 해석: reflections 본문만 보면 환경 이슈 규모를 과소평가한다. /reflect-digest의 ## 환경 액션 아이템은 이 TSV를 근거로 작성한다.
  • 7일은 hypothesis다. digest 기본 period가 7d이므로 사이클마다 최대 1회 재노출된다.
  • 게이트는 LLM을 호출하지 않는 순수 판정이며 fail-open이다.
  • actionability 누락, 파싱 실패, awk 비정상 종료 시 원본 블록을 보존한다.
  • claude_behavior 블록은 어떤 경우에도 억제하지 않는다.
04 · Surface Decision

4. Surface Precedence Table (판정 규칙)

표에 들어가기 전 세 가지 전제를 먼저 확인한다.

actionability == user_environment이면 precedence 대상이 아니다. 환경 액션 아이템으로만 보고한다.

freq는 canonical과 aliases를 합산한 cluster_freq다. 원시 태그 빈도로 임계를 판정하지 않는다.

ledger의 같은 canonical/alias가 status: active이고 post_freq ≥ 2이면 재승격 대신 enforcement 등급을 올린다.

아래 규칙을 위에서 아래로 적용하고, 먼저 맞는 하나만 선택한다.

#조건승격 surface
0user_stated_constraint == true — freq ≥ 1, 임계값 우회매 세션 자동 로드 surface로 fast-track. global이면 글로벌 CLAUDE.md, 아니면 project CLAUDE.md. 200줄 초과 시 path-scoped rule. hard_gate면 hook 후보 병기.
1enforcement_need == hard_gate — 빈도 무관hook 검토. 다른 축은 무시한다.
2procedurality == multi_step_procedure AND freq ≥ 2skill 신설 또는 보강
3scope == global AND 복수 프로젝트 freq ≥ 3risk_class=high면 글로벌 CLAUDE.md, 나머지는 글로벌 memory
4scope == project AND freq ≥ 3project CLAUDE.md. 200줄 초과 예상 시 .claude/rules/<tag>.md
5scope == project AND freq ≥ 2project memory의 feedback 타입
6risk_class == low AND freq == 1관망 — no action
7그 외수동 review 후보
임계값은 hypothesis다. /reflect-kaizen이 30일 운영 데이터로 calibration한다.

05 · Project Identity

5. Project ID 포맷

기본:          <basename(본 레포 root)>
충돌 fallback: <basename>-<6자 md5 hex>
버전:          Hybrid, v0.3.0부터
  • 본 레포 root는 project_root가 정한다.
  • 링크된 워크트리에서 git-dir과 common-dir이 다르고 공통 git 폴더 이름이 .git이면 그 부모를 root로 쓴다.
  • 그 밖에는 git rev-parse --show-toplevel, git 밖이면 cwd를 쓴다.
  • 따라서 같은 레포의 로그가 워크트리 폴더 이름별로 갈라지지 않는다.
  • 충돌 판정 마커 .project-root와 hash 입력도 같은 root를 쓴다.
  • 헬퍼는 ${CLAUDE_PLUGIN_ROOT}/hooks/_lib-project-id.sh의 project_root, compute_project_id, normalize_project_query다.
  • 워크트리 이름으로 이미 만들어진 폴더는 옮기지 않는다. 자세한 내용은 DESIGN.md 결정 #3의 ### 워크트리 절을 따른다.
Practice · Bad / Good

안티패턴과 올바른 기록

BAD · 신호를 파편화한다
  • 증상·파일명·도구명마다 새 mistake_tag를 만든다.
  • canonical만 세어 aliases의 재발을 누락한다.
  • 환경 오설정을 행동 신호와 함께 precedence에 넣는다.
  • 같은 등급에서 문구만 고치고 enforcement 개선으로 간주한다.
GOOD · 근본원인과 행동을 보존한다
  • 근본원인 하나를 <행동동사>-<대상> 태그 하나로 묶는다.
  • canonical_tag + aliases를 합산해 회귀를 측정한다.
  • user_environment는 TSV 롤업과 환경 액션 아이템으로 분리한다.
  • 재발 임계에 도달하면 E1 → E2 → E3 surface를 검토한다.
Checklist · Gotchas

Gotchas 체크리스트

  • 레거시 fail-open: actionability가 없으면 claude_behavior로 읽는다.
  • 환경 지시 분리: user_environment의 desired_behavior에는 환경 수정 명령을 쓰지 않는다.
  • 클러스터 빈도: precedence와 회귀 측정은 raw tag가 아니라 canonical과 aliases 합산값을 쓴다.
  • 환경 빈도: reflections만 세지 말고 .env-issues.tsv의 count를 확인한다.
  • dedup 안전성: 파싱이나 awk 실패 시 원본 Reflection을 버리지 않고 보존한다.
  • stderr 절삭: 프롬프트 전문을 남기지 말고 선별한 오류 한 줄만 200자로 자른다.
  • SSOT 유지: E1·E2·E3 정의는 skill-design-guide §3.7에서만 관리한다.
  • 워크트리 안정성: Project ID root는 워크트리 이름이 아니라 공통 레포 root를 기준으로 한다.
