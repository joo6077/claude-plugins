Codex Kaizen

Codex 위임 방법론과 전역 프롬프트 템플릿을, 훅이 verbatim 자동수집한 위임 로그를 신호로 주 1회 점진 강화하는 카이젠 루프. 신호는 내가 손으로 매긴 점수가 아니라 codex 세션 rollout에서 그대로 떠온 원문이며, 모든 템플릿 반영은 사용자 승인 게이트를 거친다.

reflect-kit · /codex-kaizen · 승인 게이트
왜 만들었나

수동 로깅 · 자가채점은 신뢰도가 0이다

기존 프로토콜은 매 Codex 위임 후 내가 직접 로그를 쓰고, 5축 루브릭으로 0~5점 자체 채점을 매겼다. 문제는 두 가지다 — (1) 내가 시킨 출력을 내가 다시 옮겨 적으면 요약·과장이 끼어든다, (2) 같은 모델 계열이 자기 출력을 평가하면 self-preference 편향으로 점수가 부풀려진다. 실제 로그에는 거의 모든 위임이 25/25로 기록돼 있었다.

🪞

Self-preference 편향

LLM 평가자는 자기 출력을 인간 평가자보다 높게 매긴다. 자기 출력을 인식하는 능력과 편애 강도 사이에 인과가 실증됐다.

arXiv:2404.13076 →
🔁

Self-refine가 bias 증폭

6개 LLM(GPT-4·Gemini·LLaMA2·Mixtral 등)에서 자기 출력 재평가 기반 self-refine이 fluency는 올려도 bias를 키운다.

arXiv:2402.11436 →
📉

채점 ≠ 신호

자가채점은 training signal로 쓰면 drift를 강화한다. 평가는 리뷰 시점에 다른 모델 family가 독립적으로 해야 의미가 있다.

arXiv:2306.05685 →
정공법 — 자동 수집

Codex가 이미 남긴 rollout을 훅이 verbatim으로 떠온다

Codex CLI는 모든 위임을 ~/.codex/sessions/.../rollout-*.jsonl에 완전 기록한다. 손으로 옮겨 적을 이유가 없다 — Stop 훅이 새로 끝난 rollout을 찾아 프롬프트와 응답을 원문 그대로 월간 로그에 붙인다. 멱등(중복 방지)이고, 첫 실행 시 과거를 쏟지 않도록 시드한다.

[ codex-rescue 위임 ] → codex가 rollout-*.jsonl 기록 (prompt + response 전부) │ [ turn 종료 ] → Stop 훅 → harvest-codex-log.sh │ · 새 rollout 탐지 (멱등: 이미 떠온 건 skip) │ · task_complete 확인 (진행 중이면 다음 Stop으로 미룸) │ · prompt / response / web_search 수 추출 ▼ ~/.claude/codex-research-log/YYYY-MM.md (verbatim, 점수 없음)
인플레이션 불가 — 로그가 codex 원본에서 그대로 복사되므로 요약·과장이 끼어들 여지가 없다. 채점 칸 자체가 사라졌다.

가드레일 — Gotchas

완료 전 전수 대조 항목

  • 위임 시점 self-score를 부활시키지 않았다 — 평가는 리뷰 시점 독립 평가만.
  • 전역 자산(codex-prompt-template.md · CLAUDE.md)을 승인 없이 편집하지 않았다.
  • codex에 --model을 넘기지 않았다 — gpt-5.5 게이트 실패 시 1회 재시도 → WebSearch fallback(미검증 명시).
  • 단일 실패 1건 patch가 아니라 반복 패턴을 줄이는 generalized instruction이다.
  • 모든 변경에 로그 또는 1차 출처 근거가 있다 — 추측 기반 강화 금지.
  • 새 인용은 WebFetch로 제목·저자 1회 검증 후 추가했다 (codex ID 오매핑 방지).
  • 템플릿 변경 시 template_version 스탬프를 올리고 변경이력 한 줄을 남겼다.
안티패턴

흔한 잘못 vs 정공법

✕ 거대 기계

수동 자가채점 위에 kaizen 스킬 생태계 + sprint-contract + QA + 스핀오프 세션을 얹는다. 신호는 신뢰 못 할 self-score.

✓ 훅 + 직접 갱신

훅이 verbatim 로그를 깨끗이 쌓고, 단일 스킬이 주 1회 그 로그를 신호로 템플릿 diff를 승인 게이트로 제안한다.

✕ 추측 강화

"이러면 더 좋을 것 같다"로 템플릿을 키운다. 로그 1건에 과적합한 특수 지시를 박는다.

✓ 근거 + 일반화

로그 반복 패턴 또는 1차 출처 근거가 있을 때만. 반복 패턴을 줄이는 generalized instruction으로, 작은 diff로.

도메인 경계

reflect-kaizen과 무엇이 다른가

reflect-kaizen은 reflect 파이프라인(분류·승격 품질)을 개선하고 신호는 reflection 로그·ledger다. codex-kaizen은 codex 위임 방법/템플릿을 개선하고 신호는 codex rollout 로그다. 신호원도 대상 자산도 다르므로 두 리포트를 섞지 않는다.
