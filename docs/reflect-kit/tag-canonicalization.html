§1 확장 — 필드 이름도 SSOT 다

수집면과 집계면이 각자 리터럴을 박으면 조용히 0 건이 된다

필드 이름(mistake_tag)과 그 줄 패턴도 이 SSOT 에 포함된다. 훅 프롬프트가 분석기에게 "이 키로 출력하라" 고 지시하는 문자열(수집면)과, 추출기·환경 dedup 게이트가 파싱하는 문자열(집계면)이 각자 리터럴을 갖고 있으면 한쪽만 바뀌는 순간 추출이 0 건이 되고 어휘 주입이 통째로 빈다 — 에러 한 줄 없이.

접근자내는 값쓰임
tag_canon_field필드 이름훅 프롬프트가 분석기에게 지시할 키
tag_canon_line_regrep / sed BRE줄 매칭 · 추출
tag_canon_awk_reawk 동적 정규식집계 파이프라인 내부 파싱
정본은 hooks/_lib-tag-canon.sh 의 위 세 접근자이고, 훅은 접근자로만 참조한다 (§6.1 규칙 8). 문자열을 한 곳으로 옮기면 "1 곳에만 존재" 가 문서상의 주장이 아니라 grep -F 로 곧바로 확인되는 사실이 된다.
§2 — 용어 분리

raw / lemma / canonical / aliases / family

이름정의쓰임
raw_tag 분석기가 실제로 쓴 원문 표기 감사·재현용. 절대 버리지 않는다

canonical_tag 같은 lemma_key 안에서 최빈 raw_tag (동률이면 최근) 사람이 읽는 대표 이름 · 훅 프롬프트 주입
aliases 같은 lemma_key 의 나머지 raw_tag + 개별 freq 감사표
family 병합하지 않은 채 묶어 보고만 하는 상위 계열 §4

✕ aliases 를 손으로 고른다

"관련 있어 보이는 것만" 골라 ledger 에 적는다. 빠진 표기의 재발은 0 으로 집계되고, 실패한 규칙이 살아남는다.

✓ 클러스터 멤버 전체가 곧 aliases

tag_canon_groups 가 낸 lemma_key 클러스터의 멤버를 그대로 옮긴다. 손으로 고르면 비워지고, 비면 post_freq 가 과소집계된다.

canonical 은 최빈 표기를 쓴다. 최빈이 아닌 표기를 canonical 로 강제하려면 ledger 엔트리에 수동 override 사유를 남긴다 — 실사용과 맞는 대신 나중에 이름을 바꾸기 어렵다는 트레이드오프가 있다.

§4 — family

표기가 닮았다고 합치면 안 되는 묶음

alias 조건: undesired_behavior 와 desired_behavior 가 둘 다 같을 때만 alias 로 묶는다. remediation 이 다르면 alias 가 아니라 family 로만 보고한다 — 합산 금지, post_freq 반영 금지. family 판별은 결정론적 문자열 규칙이다: 태그를 - 로 쪼갠 세그먼트에 stale 이 있으면 stale-context-reference family.

§6.1 — 무증상 실패 전례

셸·cwd 무관성은 주장이 아니라 검증 대상이다

정규화 라이브러리가 자기 위치를 cwd 로 추측하면, 같은 입력이 셸·작업 디렉토리 조합마다 다른 답을 낸다. 에러가 나지 않고 숫자만 달라지므로 눈으로는 잡히지 않는다.

규칙 6

규칙 7

"0 건 = PASS" grep 은 -F

substring 오탐(거짓 양성)만 조심하면 된다고 생각하기 쉬운데, 반대 방향인 거짓 음성이 더 위험하다 — "0 건" 이 곧 PASS 인 조건에서 패턴이 잘못되면 위반이 있어도 통과한다.

전례 — 이 환경의 grep 은 ugrep 7.5.0 이고 패턴 중간의 $ 를 앵커로 해석한다. Phase 12 계약 RE-02 의 측정문이 그 경로였다: grep -c 'source "$SCRIPT_DIR/_lib-' 는 0, grep -cF 와 grep -c '...\$...' 는 3 (참값 3).

규칙 8

"N 곳에만 존재" 는 문자열을 지워서 증명

규칙 7 의 -F 는 거짓 음성만 막는다. 패턴이 너무 넓으면 거짓 양성이 나서 중복이 아닌 것을 중복으로 센다.

전례 — grep -rlF 'mistake_tag:' reflect-kit/hooks 가 2 행을 냈는데 두 번째 매치는 추출 규칙이 아니라 LLM 프롬프트 안의 YAML 스키마 예시였다. 오라클을 '^[[:space:]]*mistake_tag:' 로 좁히면 측정은 통과하지만 리터럴은 여전히 두 곳에 남는다. 두 방향을 한 번에 없애는 방법은 문자열 자체를 접근자(§1) 한 곳으로 옮기는 것이다.

양성 · 음성 대조

tag_canon_selftest 가 게이트의 시작점이다

selftest 는 접힘 4→2 + canonical 최빈형 + 추출 4 건을 함께 단정하고, 실패하면 사유를 출력한다. 이것이 통과하지 않으면 그 뒤의 모든 수치는 근거가 되지 않는다. 

. "<repo>/reflect-kit/hooks/_lib-tag-canon.sh" && tag_canon_selftest
SELFTEST_OK raw=4 clusters=2 canonical=edit-before-read

# selftest 의 판별력을 확인할 때는 반드시 export 로 넘긴다
( export REFLECT_TAG_LEMMA_MAP=/nonexistent; . "<repo>/reflect-kit/hooks/_lib-tag-canon.sh"
  tag_canon_selftest )   # SELFTEST_FAIL fold raw=4 clusters=4
주의 — VAR=x . lib; func 로 음성 대조를 돌리지 마라. 명령 앞 변수 할당은 그 명령에만 붙는다. .(source)는 특수 빌트인이라 셸에 따라 할당이 남기도 하고 남지 않기도 해서, 뒤이어 호출하는 함수는 그 변수를 못 볼 수 있다. 2026-08-13 재검증에서 실제로 REFLECT_TAG_LEMMA_MAP=/nonexistent . lib; tag_canon_selftest 가 SELFTEST_OK 를 냈고, "맵이 없어도 통과한다 = selftest 가 오라클이 아니다" 로 잘못 읽힐 뻔했다. export 로 넘기면 같은 조건이 정상적으로 SELFTEST_FAIL 이다. 음성 대조가 통과하면 구현을 의심하기 전에 대조 자체가 성립했는지 확인하라.

§7 — 운영 절차

새 alias 를 추가하는 5 단계

  1. /reflect-digest 의 ## 병합 보류 또는 ## 원인 계열 (family) 에서 후보를 고른다.
  2. 두 태그의 undesired_behavior / desired_behavior 를 원문 인용해 같은지 확인한다.
  3. 같으면 tag-lemma-map.tsv 에 alias 행을 추가하고 reason 열에 실측 근거(건수 포함)를 적는다.
  4. tag_canon_groups 를 재실행해 클러스터가 실제로 합쳐졌는지 출력으로 확인한다.
  5. 다르면 추가하지 말고 family 로만 남긴다.
안티패턴

흔한 잘못 vs 정공법

✕ 원시 태그 빈도로 승격 판단

같은 근본원인이 표기별로 흩어져 개별 빈도가 임계 미달로 떨어진다. 최상위 이슈가 아무것도 승격되지 않는다.

skipped-required-api-doc-check  71
# 임계 미달 → 승격 없음

✓ 클러스터 합산 후 판단

결정론적 pass 로 먼저 묶고 나서 precedence 를 적용한다. 39 건(55%)이 되살아난다.

lemma cluster                   110
# tag_canon_groups 출력 그대로

✕ 눈대중 클러스터링

리포트 안에서만 합치고 tag-lemma-map.tsv 에 남기지 않는다. 다음 주기에 같은 판단을 처음부터 다시 한다.

✓ 맵에 기록 + 재실행 확인

병합 판단은 TSV 에 reason 과 함께 남기고, tag_canon_groups 재실행 출력으로 합쳐졌음을 확인한다.

✕ cd hooks && . ./lib

우연히 cwd 가 맞을 때만 통과한다. 라이브러리의 cwd 의존 결함을 가리고, 셸이 바뀌면 숫자가 조용히 달라진다.

✓ 절대경로 source + selftest

. "<repo>/reflect-kit/hooks/_lib-tag-canon.sh" 후 tag_canon_selftest 로 양성 대조부터 통과시킨다.

가드레일

완료 전 전수 대조 체크리스트

  • 집계 키는 lemma_key — canonical_tag 단독으로 post_freq 를 세지 않았다.
  • aliases 는 클러스터 멤버 전체 — 손으로 고르거나 비워두지 않았다.
  • 파편화 판정은 singleton_share — fold_ratio 로 "정상" 판정하지 않았다.
  • tag_canon_selftest 를 먼저 돌렸다 — SELFTEST_OK 가 아니면 그 뒤 수치를 근거로 쓰지 않았다.
  • 음성 대조는 export 로 — VAR=x . lib; func 형태로 판별력을 확인하지 않았다.
  • 절대경로 source — cd 로 cwd 를 맞춘 관용구를 쓰지 않았다.
  • 회귀는 set -u 유/무 × 3 셸 × cwd 4 종 — 같은 cwd 반복으로 대체하지 않았다.
  • "0 건 = PASS" grep 에 -F — 메타문자를 이스케이프하지 않은 패턴으로 거짓 음성을 만들지 않았다.
  • 중복 리터럴은 접근자로 제거 — 패턴을 좁혀 측정만 조용하게 만들지 않았다.
  • 프로브는 mktemp -d 복제 버킷 — 실 로그 버킷을 log_dir 로 넘기지 않았다.
  • 정리 확인은 ~/.claude/logs 전체 — 한 버킷 감사를 전역 결론으로 쓰지 않았다.
  • remediation 이 다르면 family — 표기 유사성만으로 alias 병합하지 않았다.
  • hard enum 을 만들지 않았다 — 새 tag 는 new_tag_reason 과 함께 허용했다.
  • 확인 실패한 직접 인용을 쓰지 않았다 — 재확인 안 되는 문구는 근거에서 뺐다.
