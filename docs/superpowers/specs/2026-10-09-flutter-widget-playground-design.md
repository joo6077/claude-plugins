# flutter-toolkit — 공용 위젯 놀이터와 기본기 검사 설계

작성 2026-10-09. 대상 킷 flutter-toolkit (현재 v0.12.0). 시험 대상 앱은 핏팰.

## 1. 왜 만드나

사용자가 원한 것은 두 가지다.

1. 앱에서 쓰는 **진짜 위젯**을 골라 속성 값을 바꿔 보며 결과를 보고, 그 위젯에 **어떤 속성이 있는지** 한눈에 보는 화면. 사람과 클로드가 같이 본다.
2. 위젯이 **기본기**를 지키는 것. 안쪽 여백, 크기 동작, 아이콘과 글자 위아래 정렬, 넘침.

손으로 적는 카탈로그는 낡는다. 핏팰 카탈로그는 `IFButton` 속성 7개 중 2개만 노출했고, 일부 항목은 진짜 위젯 대신 모양을 흉내 낸 상자였다. 기본기도 사람이 지적할 때마다 그 화면 하나만 고쳐서 다음 화면에서 다시 터졌다.

### 1.2 이미 기각한 것

- **위젯북 4판**: 생성자에서 조절 장치를 자동으로 만드는 원리는 좋다(시험으로 확인). 하지만 별도 앱이라 앱 글꼴이 안 넘어와 Roboto 로 그려졌고, 위젯이 미리보기를 꽉 채웠고, 사용자가 직접 보고 「많이 별로, 보기도 불편」이라고 했다. 원리만 가져온다.

## 2. 범위

### 2.1 1단계 (이 문서): 킷

- 위젯 기본 규칙 문서
- 생성자를 읽어 카탈로그 항목을 만드는 생성기
- 놀이터 화면
- 공용 위젯을 전부 띄워 재는 기본기 검사 묶음
- 기존 스킬(`flutter-widget`, `flutter-extract`, `flutter-preflight`, `flutter-audit`)과의 연결

### 2.2 2단계 (별도 계약): 핏팰

1단계 검사를 핏팰에 돌려 위반 목록을 숫자로 뽑은 뒤 고친다. 순서는 `IFButton`·`GlassPressBox` 여백과 크기 동작 → 버튼 높이 토큰 → 아이콘·글자 정렬 방식 → 넘치기 쉬운 102곳과 17곳. 이 문서는 2단계의 입력(검사 결과)까지만 다룬다.

**범위 밖**: 위젯북 연동, 웹에 올려 함께 보기, 화면(페이지) 단위 카탈로그, 시안(목업) 관리.

## 3. 구성

### 3.1 위젯 기본 규칙 — `flutter-toolkit/references/widget-fundamentals.md`

규칙마다 강도(MUST / SHOULD)와 자동 검사 여부를 적는다. 수치는 고정하지 않고 **프로젝트 토큰을 가리킨다**. 바깥 기준 수치는 출처로만 남긴다.

| # | 규칙 | 강도 | 자동 검사 |
| --- | --- | --- | --- |
| 1 | 내용을 감싸는 위젯(버튼·칩·배지·탭·입력칸)은 안쪽 여백을 직접 가진다. 부르는 쪽에 맡기지 않는다 | MUST | 예 |
| 2 | 크기 동작을 선언한다: 내용 맞춤 / 꽉 채움. 내용 맞춤이면 부모 폭을 다 먹지 않는다(`Center` 단독 금지, `widthFactor` 또는 `Row(min)`) | MUST | 예 |
| 3 | 꽉 채움이 필요하면 부르는 쪽이 명시한다(풀폭 속성 또는 감싸기). 위젯이 몰래 늘어나지 않는다 | MUST | 예 (2번과 같이) |
| 4 | 같은 역할은 크기 단계(작게/보통/크게)가 높이·여백·아이콘 크기·글자 크기를 함께 정한다 | MUST | 예 |
| 5 | 상태(눌림·비활성·선택·로딩)가 바뀌어도 크기는 같다 | MUST | 예 |
| 6 | 보이는 크기와 터치 영역을 나눈다. 터치 영역은 프로젝트 하한(핏팰 44) 이상 | MUST | 예 |
| 7 | 아이콘 크기와 아이콘–글자 간격은 크기 단계 토큰으로 위젯이 갖는다 | MUST | 예 |
| 8 | 아이콘과 글자를 나란히 둘 때 정렬 기준을 하나로 정한다(3.6 참고) | MUST | 예 |
| 9 | 글자 스타일은 프로젝트 글자 토큰(`AppTypo` 등)으로만 만든다. 글꼴 이름을 직접 쓰지 않는다 | MUST | 예 (코드 검사) |
| 10 | 줄 안의 바뀌는 글자에는 폭 한계를 준다(`Flexible`/`Expanded`) | MUST | 예 |
| 11 | 글자가 넘칠 때 줄 바꿈·말줄임·자라기 중 무엇을 할지 위젯이 정한다 | MUST | 예 |
| 12 | 큰 글자(최대 2.0배)에서 고정 높이 대신 자라거나 다시 배치한다 | MUST | 예 |
| 13 | 여백·간격은 토큰 값만 쓴다 | SHOULD | 예 (코드 검사) |
| 14 | 화면 바깥 여백(SafeArea·화면 좌우 여백)은 화면이, 안쪽 여백은 위젯이 맡는다 | SHOULD | 아니오 |
| 15 | 탭 대상에는 읽어 줄 이름, 글자는 대비 기준을 지킨다 | SHOULD | 예 (Flutter 내장 검사) |

출처: Flutter 기본 버튼(좌우 24, 최소 64×40, 설치본 `elevated_button.dart` 에서 확인), Flutter 터치 크기 검사(48/44, `flutter_test/accessibility.dart`), Material Web 토큰, Carbon 버튼·간격 규격, Apple HIG 배치·접근성. 상세 URL 은 조사 기록에 남기고 문서에는 한 줄씩만 적는다.

### 3.2 위젯 목록 파일 — 프로젝트의 `catalog/widgets.yaml`

생성기와 검사가 같이 읽는 한 벌의 목록이다. 운영 코드에 표시를 박지 않으려고 따로 둔다.

```yaml
widgets:
  - class: IFButton
    file: lib/shared/presentation/widgets/buttons/if_button.dart
    sizing: hug            # hug(내용 맞춤) | fill(꽉 채움)
    min_padding: AppPadding.h16   # 안쪽 좌우 여백 하한 (토큰 이름)
    view: phone            # 놀이터가 처음 여는 보기: phone | content
    labels:
      new: primary         # 기본 생성자 표시 이름
    ranges:
      width: [0, 400]
      radius: [0, 40]
    samples:
      child: "Text('버튼')" # 위젯·콜백처럼 자동으로 못 만드는 속성의 예시 값
```

- 공용 위젯 폴더의 공개 위젯이 목록에 없으면 검사가 실패한다(빠진 위젯을 조용히 넘기지 않음). 일부러 뺄 위젯은 `skip: 이유` 로 적는다.
- 목록에 적었는데 코드에 없는 위젯·속성 이름도 실패한다.

### 3.3 생성기 — `tool/catalog_gen.dart` (킷이 틀을 깔아 줌)

시제품에서 동작을 확인했다(`IFButton` 생성자 5개, 속성 7개·11개 전부, 속성 추가 시 저절로 생김, `EdgeInsets` 를 넣으면 실패).

- Dart 공식 분석 도구 `analyzer` 로 목록의 위젯 생성자를 전부 읽는다.
- 타입별 조절 장치: 참/거짓 → 스위치, 글자 → 입력칸, 정수·실수 → 슬라이더(빈 값 허용이면 켜고 끄는 스위치 포함), enum → 드롭다운, 위젯 자식 → 글자 입력을 `Text` 로 감쌈, 콜백 → 고정값.
- 그 밖의 타입은 `samples` 에 예시가 없으면 **실패**한다. 무엇이 걸렸는지 위젯·생성자·속성 이름으로 찍는다.
- 기본값은 상수 값을 계산해 넣는다(다른 파일의 상수도 됨). 생성물은 `lib/catalog/generated/*.catalog.g.dart`.
- 생성물에는 속성마다 타입·기본값·문서 주석이 함께 들어간다. 클로드는 이 파일만 읽어도 위젯 속성을 안다.
- 시제품에서 고친 함정: 실패하면 파일을 쓰지 않는다(시제품은 쓰고 나서 실패했음).

### 3.4 놀이터 화면

사용자가 「그나마 낫다」고 한 배치를 기준으로 한다.

```text
┌──────────┬────────────────────────────┬────────────────────┐
│ 위젯 목록 │ 이름 · 설명                 │ 종류  [primary ▾]   │
│ (작은     │ 보기[휴대폰|내용] 폭 배경 초기화│ 속성 6             │
│ 미리보기  │                            │ child   [버튼    ]  │
│ + 이름)   │     큰 미리보기             │ height  ──●── 54   │
│          │     영역 선 + 크기 숫자      │ width   ○ ── null  │
└──────────┴────────────────────────────┴────────────────────┘
```

- 왼쪽: 위젯마다 작은 미리보기와 이름. 누르면 바로 바뀐다. 뒤로 가는 단계 없음.
- 가운데: 진짜 위젯. 보기 두 가지 — 휴대폰 화면(폭 320/375/390/430, 앱 배경, 좌우 16) / 내용 크기. 위젯이 차지한 영역을 선으로 두르고 크기를 숫자로 보인다. 처음 보기는 `widgets.yaml` 의 `view`.
- 오른쪽: 맨 위 「종류」 드롭다운(생성자), 그 아래 한 줄에 한 속성. 바꾼 속성에는 점과 되돌리기. 조절 못 하는 속성은 「예시 값으로 고정」 묶음으로 아래에. 코드 칸은 없다(사용자: 「필요 없다」).
- 생성자를 오가도 바꾼 값은 남는다.
- 프로젝트에 카탈로그 앱이 있으면 그 안에 붙인다(핏팰 `main_catalog.dart`). 없으면 킷이 최소 카탈로그 진입 파일을 만든다. **반드시 앱 패키지 안에서 띄운다** — 별도 패키지로 띄우면 글꼴·그림 경로가 바뀌어 진짜 모습이 아니다.

### 3.5 기본기 검사 묶음 — `test/widget_fundamentals_test.dart` (생성)

`widgets.yaml` 의 위젯마다, 생성자마다, 기본 속성으로 띄워서 잰다. 경우마다 테스트를 따로 둔다(한 테스트에서 여러 번 띄우면 넘침 예외가 겹쳐 결과가 흔들린다).

| 검사 | 방법 | 규칙 |
| --- | --- | --- |
| 넘침 | 폭 320·360·393 × 글자 1.0·1.3·1.6·2.0 × 한국어·영어 × 짧은/긴/띄어쓰기 없는 글자. 예외가 나면 실패. 예외 없이 잘리는 경우는 글자 상자가 위젯 상자 안에 드는지 잰다 | 10, 11, 12 |
| 안쪽 여백 | 글자(또는 아이콘) 상자와 위젯 테두리 사이 좌우 거리 ≥ `min_padding` | 1 |
| 크기 동작 | 폭 한계 390 의 느슨한 자리에 놓고 잰다. `hug` 인데 390 이면 실패, `fill` 인데 390 이 아니면 실패 | 2, 3 |
| 크기 단계 | 같은 단계 위젯끼리 높이가 토큰과 같은지 | 4 |
| 상태 불변 | 상태 속성(참/거짓 중 상태 이름: `enabled`·`selected`·`isLoading` 등, `widgets.yaml` 에 지정)을 바꿔 가며 크기가 같은지 | 5 |
| 터치 영역 | Flutter 내장 `meetsGuideline(iOSTapTargetGuideline)` 또는 프로젝트 하한 | 6 |
| 아이콘·글자 정렬 | 아이콘 상자 가운데와 글자 기준점(3.6) 차이 ≤ 1px | 8 |
| 이름·대비 | `labeledTapTargetGuideline`, `textContrastGuideline` | 15 |

- 실제 글꼴(핏팰 KIMM·WantedSans)을 테스트에 등록하고 잰다. 테스트 기본 글꼴로 재면 화면과 다르다(메모리: 테스트는 통과했는데 크롬에서만 11px 넘침).
- 코드 검사(규칙 9, 13): 글꼴 이름 직접 사용, 토큰에 없는 여백 숫자를 공용 위젯 폴더에서 찾는다. 분석 규칙(custom lint)까지는 1단계에서 하지 않고 스크립트로 시작한다.
- 결과는 표로도 남긴다(`build/widget_fundamentals.csv`). 2단계의 입력이 된다.
- 넘침 검사는 공용 위젯만 덮는다. 화면 단위 넘침(키보드, 긴 목록)은 범위 밖이고, 규칙 문서에 적어 둔다.

### 3.6 아이콘·글자 정렬 기준 — 측정 후 확정

조사 결과 방법은 셋이다. 줄 상자 가운데(간단하지만 줄 높이 1.6 의 위아래 여유 때문에 통과해도 어긋나 보일 수 있음), 기준선(Flutter 문서 권장, 서로 다른 글자끼리), 글자 모양 가운데(가장 정확, Flutter 가 대문자 높이 등을 바로 주지 않아 근사). 핏팰 기록에는 `height: 1` 로 고쳤다가 작은 배지에서 글자 윗부분이 잘린 일이 있어 그 방법은 일반 규칙이 될 수 없다.

**결정 방법**: 구현 첫 단계에서 KIMM·WantedSans 로 「가」「A」「1」 의 글자 모양 상자와 줄 상자를 재고, 세 방법으로 아이콘을 배치한 캡처를 사용자에게 보여 고르게 한다. 고른 방법을 규칙 8 과 검사에 넣는다.

### 3.7 기존 스킬과의 연결

| 스킬 | 바뀌는 점 |
| --- | --- |
| `flutter-widget` | 새 공용 위젯을 만들면 `widgets.yaml` 에 항목을 추가하고, 규칙 1~12 를 지킨 틀로 만든다 |
| `flutter-extract` | 공용으로 뺄 때 같은 일. `_` 비공개로 남기지 않는다 |
| `flutter-preflight` | 생성기 다시 돌린 결과가 커밋된 생성물과 다르면 실패 + 기본기 검사 실행 |
| `flutter-audit` | 기본기 검사 표를 감사 결과에 넣는다 |
| 새 스킬 `flutter-catalog` | 처음 깔기(목록 파일·생성기·놀이터·검사), 다시 생성, 놀이터 띄우기 |

## 4. 흐름

```text
위젯 코드 ──analyzer──▶ 생성기 ──▶ *.catalog.g.dart ──▶ 놀이터 화면
   ▲                     ▲                    │
   │                widgets.yaml ─────────────┼──▶ 기본기 검사 ──▶ 실패 / 표
   └──── 사람·클로드가 고침 ◀──────────────────┘
```

## 5. 실패 처리

- 분류 못 한 속성 타입 → 생성 실패, 무엇인지 찍음. 파일은 안 씀.
- 목록에 없는 공개 위젯, 목록에만 있는 이름 → 실패.
- 혼자 못 띄우는 위젯(상태 저장소·번역이 필요) → `widgets.yaml` 에 감싸개(예: 핏팰 `catalogSessionOverrides`)를 적는다. 감싸개 없이 실패하면 「감싸개가 필요하다」고 알려 준다.
- 실제 글꼴 등록 실패 → 검사 실패(대체 글꼴로 재고 통과시키지 않음).

## 6. 검증 계획

- 핏팰 **복사본**에서 돌린다. 원본은 2단계에서만 고친다.
- 처음 돌린 결과가 오늘 실측과 맞는지 대조한다: `IFButton` 5종 「hug 선언인데 390」 실패, 여백 0 실패. 맞지 않으면 검사가 틀린 것이다.
- 막는지 확인: 일부러 여백을 0 으로, `Center` 를 넣어, 줄 안 글자의 `Flexible` 을 빼서 각각 실패하는지 본다.
- 놀이터는 사용자가 쓰는 구글 크롬으로 배포용 빌드(`--pwa-strategy=none`, 새 포트)를 띄워 확인한다. 디버그 서버와 서비스 워커 때문에 옛 화면이 뜬 일이 두 번 있었다.
- 킷 레포 검사: `python3 scripts/validate-plugin.py flutter-toolkit`, `sync-docs.py`.

## 7. 열린 질문

1. 아이콘·글자 정렬 기준 — 3.6 의 측정 뒤 사용자가 고른다.
2. 목록에 남은 흉내 낸 시안 카드 8장(`Submit Disabled A·B·C`, `Aqua 3D …`) — 시안 칸으로 옮길지 숨길지 사용자 답 대기.
3. 크기 단계 토큰이 없는 프로젝트 — 킷이 토큰을 만들지, 검사만 「토큰 없음」으로 알릴지. 기본안: 알리기만 하고 `design-kit:design-system` 으로 넘긴다.
