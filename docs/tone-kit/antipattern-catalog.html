Antipattern Catalog — A~J 판정 카탈로그

tone-guide 와 tone-campaign 이 위반을 판정할 때 참조하는 카탈로그 SSOT. 코드가 이미 말한 것을 다시 말하는 주석, 계산 과정을 이름에 박은 변수, 그리고 정리하다가 함께 지워지면 안 되는 주석을 잡는다. 10개 카테고리 중 H 는 위반이 아니라 보존 대상이다. v0.1.0 · 최종 갱신 2026-09-02

🛡️ H 만 방향이 반대다 — 위반이 아니라 보존이다

A~G · I · J 는 after 에서 주석과 구조가 줄어드는 것이 정답이다. H 는 after 에서 주석이 남아 있는 것이 정답이다. H 를 위반 목록에 넣고 A~J 를 일괄 삭제하는 것이 이 카탈로그의 최대 오용이며, H 는 정확히 그 사고를 막기 위해 존재하는 방어 카테고리다.

이 페이지에서 MUST 보존 배지와 보존 처리 배지, 그리고 초록 좌측선이 붙은 블록은 전부 H 다. 나머지 아홉은 경고 계열(마젠타 · 노랑 · 파랑) 좌측선을 쓴다.

종합 예시 — 6종이 한 화면에 겹쳐 있다

실제 코드에서 카테고리는 하나씩 오지 않는다. 아래 before 아홉 줄에는 F 구분선 · B 마커 · C 번역투 doc · A 이름 번역 · E 접두사가 동시에 들어 있고, 그 사이에 섞인 마지막 한 줄이 H 다. after 에서 다섯 종은 사라졌고 H 한 줄만 남았다.

before F 구분선 B 마커 C 번역투 doc A 이름 번역 E 접두사

다섯 종의 위반과 한 줄의 H 가 구분 없이 섞여 있다. 정규식 일괄 삭제가 위험한 이유가 여기 있다.

// ------------------------------------------------------------
//위젯 구현부
// ------------------------------------------------------------
/// 눌림 시작 상태를 처리합니다.
void handlePressStart() {
  final effectiveGradient = props.gradient ?? {TokenClass}.defaultGradient; // 기본 그라디언트
  // 안 끄면 M3 tonal overlay 가 이 색 위에 덧칠돼 더 밝아진다
  _tint = Colors.transparent;
}
after 4종 삭제 · 1종 개명 H 1줄 보존

배너 · 마커 · 번역투 doc · 인라인 번역 주석은 지웠고, effectiveGradient 는 역할명으로 개명했다. 초록 줄은 코드로 복원되지 않으므로 남는다.

void handlePressStart() {
  final toolbarGradient = props.gradient ?? {TokenClass}.defaultGradient;
  // 안 끄면 M3 tonal overlay 가 이 색 위에 덧칠돼 더 밝아진다
  _tint = Colors.transparent;
}

규칙마다 강도(MUST / SHOULD / 관측 컨벤션)와 축(스택 무관 코어인지 특정 스택 전용인지 표시하는 라벨)이 붙는다. 관측 컨벤션은 공개 출처 없이 프로젝트 실측만 있는 규칙이라는 뜻이며, 준수 강도가 낮다는 뜻이 아니다. 해당은 E 하나뿐이다.

카테고리 한눈에 — 10종 · 강도 · 처리

라벨만 붙이고 처리 방침을 구분하지 않는 것이 이 카탈로그의 흔한 오용이다. 삭제(B·D·F) · 개명(A·E) · 흡수(G) · 보존(H) · 재구성(I·J)은 서로 다른 작업이다.

B 템플릿 마커 파일마다 같은 자리에 박히는 고정 라벨은 지운다 삭제 MUST [코어]

D 프레임워크 기본 설명 공식 문서 첫 문단에 있는 내용은 코드 옆에 옮겨 적지 않는다 삭제 MUST [코어]

원칙 A~G — 주석과 이름의 위반

일곱 카테고리 전부 before/after 쌍으로 판정한다. 왼쪽 카드가 위반이고 오른쪽이 정답이며, 각 카드 하단의 판정 신호는 후보 수집용 grep 이지 위반 건수 집계기가 아니다.

A

이름 번역 주석

MUST 삭제 삭제또는 개명 [코어][한국어]

식별자 이름과 타입이 이미 담고 있는 의미를 한국어로 되풀이하는 주석은 지운다.

beforeA 위반 · 3줄
const {widget_prefix}SliderWidget({
  String? text,   // 버튼 텍스트
  bool isChecked, // 체크 여부
  double v,       // 최소 눈금 값
  Color bg,       // 0x66 = alpha 40%
});
after삭제 + 개명 + 메타 유지
const {widget_prefix}SliderWidget({
  String? text,
  bool isChecked,
  double minTick,
  Color bg,       // 0x66 = alpha 40%
});
왜 — 주석을 지워도 정보 손실이 0이다. v 처럼 이름이 약해서 주석이 필요했던 자리는 주석이 아니라 이름을 고쳐야 하며, 주석만 지우고 이름을 그대로 두면 원래보다 나빠진다.
예외 — hex 값의 alpha 퍼센트처럼 값에서 사람이 곧바로 읽어낼 수 없는 메타 정보는 A 가 아니다. 위 0x66 = alpha 40% 가 after 에서도 남은 이유다.

판정 신호 — 선언 뒤에 붙은 한국어 인라인 주석

grep -rnE '^[[:space:]]*[A-Za-z_].*[a-zA-Z0-9_?],[[:space:]]*//[[:space:]]*[가-힣]' --include='*.dart' .

Effective Dart 의 등급은 AVOID 이고 이 카탈로그는 이를 MUST 로 승격했다. 승격 사유는 실측 최다 빈도(48파일 전역, 약 85건)와 제거 시 손실 0 이다.

B

템플릿 마커

MUST 삭제 삭제 [코어]

파일마다 같은 위치에 기계적으로 반복되는 고정 라벨은 지운다.

beforeB 위반 · 고정 라벨 2종
class {widget_prefix}DeviceRowWidget extends StatelessWidget {
  //상태
  final {widget_prefix}DeviceRowWidgetProps props;

  //위젯 구현부
  @override
  Widget build(BuildContext context) => Row(children: [...]);
}
after선언이 스스로 말한다
class {widget_prefix}DeviceRowWidget extends StatelessWidget {
  final {widget_prefix}DeviceRowWidgetProps props;

  @override
  Widget build(BuildContext context) => Row(children: [...]);
}
왜 — 그 파일이 무엇인지는 클래스 선언이 이미 말한다. 파일 구조를 알려주는 역할이 필요하면 그것은 파일 분할이나 이름으로 해결할 문제이지 마커로 해결할 문제가 아니다.
예외 — 없다.

판정 신호 — 동일 주석 줄의 코퍼스 전역 빈도

생성 파일을 반드시 제외하고, 빈도 상위에 뜨는 짧은 라벨을 후보로 본다.

grep -rhoE '^[[:space:]]*//[[:space:]]*[^[:space:]/*].*$' --include='*.dart' \
  --exclude='*.g.dart' --exclude='*.freezed.dart' . \
  | sed 's/^[[:space:]]*//' | sort | uniq -c | sort -rn | head -20

C

메서드명 반복 doc

SHOULD 삭제 삭제 [코어]

메서드 이름을 한국어 문장으로 풀어 쓴 doc 주석은 지운다. 남길 이유가 있으면 이름 대신 계약을 쓴다.

beforeC 위반 · 번역투 종결형
/// 눌림 시작 상태를 처리합니다.
void handlePressStart() { ... }

/// 값을 초기화하도록 합니다.
void reset() { ... }
after삭제 · 그리고 계약으로 재작성

이름의 반복은 삭제한다. public API 는 doc 을 남기되 이름이 아니라 계약과 부수효과 순서를 적는다.

void handlePressStart() { ... }

/// 진행 중인 반복 타이머를 취소하고 오프셋을 0 으로 되돌린다.
/// 취소 시점에 `onChanged` 가 마지막 값으로 한 번 더 불린다.
void reset() { ... }
왜 — 번역투 종결형(~을 처리합니다, ~하도록 합니다)이 따라붙는 doc 은 이름을 두 번 읽게 만들 뿐이다. 호출자가 코드를 열지 않고 알아야 하는 것은 이름이 아니라 계약과 부수효과 순서다.
예외 — public API 계약, 그리고 부수효과 순서가 호출자에게 중요한 경우. 파라미터·반환값 블록의 표기 형식(- 반환값: 없음 을 유지할지 등)은 이 카탈로그가 아니라 어댑터 슬롯(코어 규칙을 특정 스택 문법에 결속하는 값 — 주석 기호, doc 라벨 형식 등)이 정한다. 어댑터가 유지를 지시하면 C 로 판정하지 않는다.

판정 신호 — 번역투 doc 후보 필터

과수집되므로 히트를 위반으로 세지 말고 후보 목록으로만 쓴다.

grep -rnE '^[[:space:]]*///.*(합니다|됩니다|하도록)' --include='*.dart' .

D

프레임워크 기본 설명

MUST 삭제 삭제 [코어]

프레임워크 공식 문서에 이미 적힌 기본 동작을 코드 옆에 옮겨 적지 않는다.

beforeD 위반 · 공식 문서 재서술
// 크기 지정
const SizedBox(height: 12),
// borderRadius 클리핑
ClipRRect(borderRadius: BorderRadius.circular(8), child: child),
// 배경색 지정
Material(color: {TokenClass}.surface, child: child),
after기본 동작 삭제 · 이유는 H 로 승격
const SizedBox(height: 12),
ClipRRect(borderRadius: BorderRadius.circular(8), child: child),
// 안 끄면 M3 tonal overlay 가 이 색 위에 덧칠돼 더 밝아진다
Material(
  color: {TokenClass}.surface,
  surfaceTintColor: Colors.transparent,
  child: child,
),
왜 — 프레임워크 기본 동작 서술은 정보량이 0일 뿐 아니라 버전이 오르면 거짓이 되므로 유지 비용이 음수다.
경계 — 남는 한 줄, 즉 그 선택을 한 이유는 D 가 아니라 H 로 승격된다. 같은 API 를 언급한다고 같은 카테고리가 아니다.

판정 신호 — grep 없음

정규식으로 분리되지 않는다. 판정은 리뷰로 한다: 주석이 설명하는 내용이 그 API 문서 첫 문단에 있으면 D 다.

E

접두사 fallback 변수명

관측 컨벤션 — 실측 9건 / 4파일 개명 [코어]

effective* / resolved* 접두사는 지우는 게 아니라 도메인·역할명으로 개명한다.

beforeE 위반 · 계산 과정이 이름에
final effectiveGradient = props.gradient ?? {TokenClass}.defaultGradient;
final resolvedChildren = props.children.isNotEmpty ? props.children : fallback;
after역할명으로 개명 · 호출부 전수 동반
final toolbarGradient = props.gradient ?? {TokenClass}.defaultGradient;
final visibleChildren = props.children.isNotEmpty ? props.children : fallback;
왜 — ?? 연산자가 이미 fallback 을 표현하므로 접두사는 역할이 아니라 계산 과정을 드러낸다. 읽는 사람이 알아야 하는 것은 "기본값이 적용됐다"가 아니라 "이게 툴바 그라디언트다"다.
근거 한계 — 이 카테고리는 공개 통계 근거가 없다. 2026-08 조사에서 접두사별 LLM 과대표집 통계는 공개 1차 문헌 어디에도 확인되지 않았다. 그래서 강도를 관측 컨벤션 으로 낮춰 표기하고 각주를 붙이지 않는다. 실측은 유효한 국지 근거이므로 규칙을 지우지도 않는다.

판정 신호

grep -rnE '\b(effective|resolved)[A-Z]' --include='*.dart' .

F

구분선 블록

MUST 삭제 삭제 [코어]

// --- 를 늘여 만든 시각적 구획은 지우고 빈 줄과 이름으로 대체한다.

beforeF 위반 · 배너 2블록
// ------------------------------------------------------------
// 빌드
// ------------------------------------------------------------
@override
Widget build(BuildContext context) => Row(children: [...]);

// ============================================================
// 핸들러
// ============================================================
void handleTap() { ... }
after빈 줄과 이름으로 대체
@override

void handleTap() { ... }
왜 — 한 파일에 14개까지 쌓이면 구분 기능 자체가 사라진다. 구분선이 필요하다고 느껴진다면 그것은 파일이 너무 길다는 신호이지 선이 필요하다는 신호가 아니다.
예외 — 코드 생성기가 만드는 배너. 생성 파일은 대상에서 제외한다.

G

자명 구조 라벨

SHOULD 흡수 코드 구조로 흡수 [코어][한국어]

바로 아래 코드가 그대로 말하는 라벨은 이름으로 흡수한 뒤 지운다. 지우기만 하면 안 된다.

beforeG 위반 · 선언 1개짜리 라벨
Column(children: [
  // 제목
  Text(props.title, style: {TokenClass}.titleM),
  // 서버 이름
  Text(state.name),
]),
after이름으로 옮긴 뒤 라벨 삭제
Column(children: [
  Text(props.title, style: {TokenClass}.titleM),
  Text(serverNameText),
]),
남는 예외섹션 라벨의 경제성

선언 2개 이상을 묶고, 그 묶음의 축을 이름으로 못 쓰는 경우에만 라벨이 남는다.

// 좌측: leading 또는 기본 뒤로가기
final leading = props.leading ?? const {widget_prefix}BackButtonWidget();
final leadingWidth = props.leadingWidth ?? 48.0;
여전히 G라벨 = 변수명

선언 1개짜리 섹션 라벨, 그리고 라벨과 변수명이 같은 뜻인 경우는 예외가 아니라 그대로 G 다.

// 좌측 위젯
final leading = props.leading ?? const {widget_prefix}BackButtonWidget();

오른쪽 패널은 별도 사례가 아니라 왼쪽 예외를 선언 1개로 줄여 본 것이다. 카탈로그가 규정한 경제성 규칙("2개 이상을 묶을 때만 남긴다")이 어디서 깨지는지를 보여준다.

왜 — 라벨을 그냥 지우면 구획 정보가 이름으로 옮겨가지 않고 그냥 없어진다. 라벨이 담던 의미는 변수명이나 추출한 위젯 이름이 받아야 한다.

  • !E 는 선언만 고치면 컴파일이 깨진다 — 개명이므로 호출부 전수를 함께 바꾼다. 삭제 카테고리와 작업 형태가 다르다.
  • →[한국어] 라벨은 규칙이 아니라 신호에 붙는다 — A 와 G 의 규칙은 언어 무관이고, 한국어에 묶인 것은 grep 패턴뿐이다. 다른 언어 코퍼스에서는 패턴을 다시 만들어야 하며, 규칙이 적용 불가해지는 것은 아니다.
  • →"위반 0" 과 "규칙 적용 불가" 는 다르다 — 어떤 스택에서 실측이 0이라고 해서 코어 규칙이 그 스택에 안 맞는 것이 아니다. 이 카탈로그는 기존 코드 정리용이 아니라 새 코드 작성 표준이다.
  • ✓카테고리 경계에서는 D 가 H 로 승격된다 — 프레임워크 기본 동작 서술은 D 지만, 그 동작 때문에 이 코드를 이렇게 쓸 수밖에 없었다는 이유는 H 다. 같은 API 를 언급한다고 같은 카테고리가 아니다.
