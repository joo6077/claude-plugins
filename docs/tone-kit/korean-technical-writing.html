Korean Technical Writing — 한국어 축 SSOT

한국어로 쓰는 주석·doc 의 문체 규칙. 번역투 제거, 종결형 고정, 외래어 처리, 용어 번역표 작성이 대상이다. 이 문서가 "한국어 의존" 축의 SSOT 다 — 다른 문서는 한국어 규칙을 다시 정의하지 말고 여기를 가리킨다. v0.1.0 · 최종 갱신 2026-09-02

⚠️ 이 문서를 스택 어댑터로 복사하지 마라 · 라벨은 부분 변경 금지

규칙의 의존성은 스택 축(Dart/Flutter · Rust · TypeScript)과 언어 축(한국어 · 영어) 둘로 나뉘고, 두 축은 서로를 결정하지 않는다. Rust 나 TypeScript 어댑터가 필요해지면 라벨 상수와 주석 문법만 그쪽에 정의하고 문체는 이 문서를 참조한다. 복사하는 순간 두 벌이 갈라지고, 갈라진 사실을 아무도 모른다.

언어 의존 상수는 부분 변경이 금지다. - 반환값: 을 - 리턴: 이나 - 결과: 로 다듬고 싶어지는 순간이 온다. 이것은 자유 서술이 아니라 상수다 — 원본 코드베이스에서 - 반환값: 은 80개 파일에 577건, - [param]: 은 788건 나왔다. 이 규모에서 표기가 둘로 갈리면 커버리지 측정과 일괄 치환이 모두 깨진다. 표기를 바꾸려면 전수 치환을 같이 한다.

같은 이유로 - 반환값: 없음 을 노이즈로 보고 지우는 것도 금지이고, void 반환에 N/A 같은 새 표기를 도입하는 것도 금지다. 있고 없음이 섞이면 "doc 이 없는 것" 과 "반환값이 없는 것" 을 구분할 수 없다.

이 문서가 잡는 것 — 세 가지 오염

세 가지가 각각 다른 층위에서 생긴다. 종결형은 어미 층위, 번역투는 문장 구조 층위, 군더더기는 정보 설계 층위다. 한 층위를 고쳐도 나머지 둘은 그대로 남는다 — 그래서 따로 잡는다.

번역투

~에 의해 · ~하도록 합니다 처럼 영어 구문을 그대로 옮긴 문장. 문장 구조 문제라서 종결어미 치환으로는 잡히지 않는다.

종결형 혼용

한 코드베이스에 합니다체와 한다체가 섞이는 것. grep 기준이 무너지고 파일마다 톤이 달라진다.

군더더기 한국어

이름을 되풀이하는 번역 주석(// 버튼 텍스트)과 음역(보더 라디우스). 주석이 정보를 0 만큼 더한다.

★

Bad 수동태 + 사역 + 음역

원칙 1 — 한국어 규칙은 이 문서에만 쓴다
MUST [코어] [한국어] 킷 구조 결정

한국어 문체는 스택과 무관하다. 스택 어댑터 문서는 라벨 상수와 주석 문법만 갖고, 문체는 여기를 참조한다. 언어를 바꾸면 라벨 문자열만 바뀌고 "파라미터·반환값을 doc 하단 라벨 블록으로 붙인다"는 골격과 커버리지 기준은 남는다. 반대로 Dart 에서 Rust 로 옮기면 주석 문법과 링크 문법([param] → `param`)만 바뀌고 한국어 문체는 한 줄도 안 바뀐다.

언어 축 한국어 · 영어 → 라벨 문자열만 교체
×
스택 축 Dart/Flutter · Rust · TypeScript → 주석 문법·링크 문법만 교체
=
불변 골격 + 커버리지 기준 → 두 축 어느 쪽도 안 바꾼다

같은 규칙, 언어만 교체 — 골격은 그대로다

한국어 프로젝트: /// - 반환값: 연결되어 있으면 true
영어 프로젝트:   /// - Returns: true when connected
⚠

어댑터 슬롯에 문체를 복사하면 두 벌이 갈라진다

SSOT 붕괴
Bad
dart-flutter 어댑터 문서에
"종결형은 한다체" 를 다시 적는다

● 개정 시 SSOT 가 갈라져 한쪽만 갱신된다. 갈라진 사실을 아무도 모른다.

Good
dart-flutter 어댑터 문서는
`- 반환값:` 라벨과 `///` 문법만 정의하고,
문체는 이 문서를 링크한다

● 어댑터 슬롯은 스택마다 갈아 끼우는 문서 자리이고, 라벨 상수와 주석 문법만 담는다.

원칙 4 — 종결형은 한다체 하나로 고정한다
관측 컨벤션 [코어] [한국어] 실측 근거만 존재 · 공개 문헌 없음

원칙 5 — 외래어는 3원칙으로 가른다
SHOULD [한국어]

공식 API 이름은 영어 원문, 일반 명사는 한국어, 음역은 금지. surface tint · BoxDecoration · strokeAlign 은 문서·검색·자동완성이 전부 원문 기준으로 움직여서 번역하면 찾을 수 없다. 반대로 보더 라디우스 는 한국어도 영어도 아니라 검색이 안 되고 공식 이름과도 어긋난다.

1

세 갈래가 각각 어떻게 어긋나는가

Bad
/// 보더 라디우스와 박스 데코레이션을 적용합니다.
///     ← 음역
/// 표면 색조 값을 계산합니다.
///     ← 공식 API 이름을 번역
/// 백그라운드 컬러를 덮어씁니다.
///     ← 일반 명사를 음역
Good
/// {TokenClass}.radiusM 을 테두리 반경으로 쓴다.
/// surface tint 가 배경 위에 얹히는 양을 계산한다.
/// 배경색을 덮어쓴다.

● 공식 이름은 원문, 일반 명사는 한국어, 음역은 0건.

정착 외래어 — 허용

한국어 표기가 이미 정착해 검색이 되는 어휘는 그대로 쓴다.

다운로드 · 업로드 · 파싱 · 파일 · 폴더

치환 대상 — 일반 명사

공식 API 이름이 아니면서 한국어 대응어가 명확한 어휘는 옮긴다.

잡(job)   → 작업
큐(queue) → 대기열
!

코드 식별자는 이 규칙의 대상이 아니다

타입·함수·변수·메서드 이름은 영어를 그대로 둔다. 번역하면 doc 링크가 끊긴다. 음역 금지는 한국어 본문만 겨냥한다. 정착 여부 판정은 팀이 하고, 결과는 용어 번역표에 적는다(원칙 8).

원칙 6 — 이름 번역 주석은 지운다
SHOULD [코어] [한국어] 단일 최대 카테고리 · 전체 안티패턴의 약 30%

이름·타입이 이미 말하는 내용을 한국어로 되풀이하지 마라. 지우거나, 이름·타입에서 안 읽히는 계약만 남긴다. 식별자가 영어이고 주석이 한국어라서 번역 주석이 정보를 더하는 것처럼 보이지만, 실제로는 같은 내용의 반복이다. 영어 단일 언어 프로젝트라면 // button text 는 누구도 안 쓴다 — 번역이라는 명분이 붙어야 생기므로 한국어 축에 속한다.

1

이름을 한국어로 되풀이한다

Bad
String? text,        // 버튼 텍스트
bool isChecked,      // 체크 여부
double min,          // 최소값

● text 가 이미 '텍스트', isChecked 가 이미 '체크 여부', min 이 이미 '최소값'이다.

Good
String? text,
bool isChecked,
double min,          // step 의 배수로 올림된다.
                     // min 자체는 후보에서 빠진다

● 남길 것은 값의 우선순위, 무효화 조건, 허용 범위처럼 이름·타입에서 안 읽히는 계약뿐이다.

2

이름이 약해서 주석으로 때운다

주석이 아니라 이름을 고칠 자리
Bad
int t,               // 타임아웃 초
Good
int timeoutSeconds,

● 주석 대신 이름을 고치면 호출부에서도 읽힌다.

실측 — 왜 단일 최대 카테고리인가

원본 코드베이스 진단(57파일 스캔)에서 이 유형이 48개 파일에 약 85건으로 가장 컸고, 전체 안티패턴 약 275건의 약 30% 를 차지했다.

이름 번역 주석
약 85건
나머지 9 카테고리
약 190건
메서드명 반복 doc
약 7건

총계 약 275건 / 10 카테고리. 메서드명 반복 doc 은 약 7건 / 2파일로 별도 집계된다.

원칙 7 — doc 라벨은 상수다, 표기를 쪼개지 마라
관측 컨벤션 [어댑터:dart-flutter] [한국어]

파라미터·반환값 라벨은 자유 서술이 아니다. - [param]: 설명 과 - 반환값: 설명 두 형태로 고정하고, void 반환은 - 반환값: 없음 으로 쓴다. 상수로 다루는 이유는 검색성이다.

1

표기가 갈리고 void 에 새 표기를 도입한다

부분 변경
Bad
/// - 리턴: 연결되어 있으면 true
/// - 결과: 연결 여부
/// - 반환값: N/A

● 세 표기가 공존하면 커버리지 측정과 일괄 치환이 둘 다 깨진다.

Good 두 형태로 고정
/// 네트워크 연결 상태를 확인하고,
/// 끊긴 경우 안내 다이얼로그를 띄운다.
///
/// - [context]: 다이얼로그 표시용 빌드 컨텍스트
/// - [ref]: 네트워크 모니터 상태 조회용 ref
/// - 반환값: 연결되어 있으면 true, 끊겨 있으면 false

/// 입력 버퍼를 비운다.
///
/// - 반환값: 없음

● void 도 라벨을 지우지 않는다.

2

doc 본문에 섹션 헤더와 알고리즘 단계를 늘어놓는다

Bad
/// 정책: 캐시는 5분마다 만료된다.
/// 참고: 백그라운드 진입 시 타이머가 멈춘다.
/// 주의: 1) 키 생성 2) 조회 3) 없으면 원격 호출
Good
/// 캐시에서 먼저 찾고, 5분이 지났으면
/// 원격에서 다시 받아 채운다.

● 한두 문장으로 끝내고 나머지는 설계 문서로 보낸다.

원칙 8 — 용어 번역표는 프로젝트가 소유한다
관측 컨벤션 [코어] [한국어]

판정 결과를 누적하는 표를 프로젝트 저장소에 하나 둔다. 킷 공용 문서로 올리지 않는다. 원칙 5 의 3원칙만으로는 매번 판정이 갈리고, 도메인 어휘와 정착 외래어 판정은 프로젝트마다 다르다. 공용 문서로 올리면 다른 프로젝트에 잘못된 번역을 강제한다.

1

어디에 두고, 무엇을 채우나

Bad 킷 공용 문서 + 자명한 단어
| button | 버튼   |
| color  | 색상   |
| text   | 텍스트 |

● 원칙 5 로 자명하게 갈리는 단어를 전부 나열하면 표가 규칙을 대체해 버린다.

Good 프로젝트 저장소 + 판정이 갈렸던 행만
| 용어 (영어 원문) | 주석 표기    | 비고 (판정 근거) |
|-----------------|-------------|----------------|
| surface tint    | surface tint| Material 3 API |
| border radius   | 테두리 반경   | 음역 금지       |
| job             | 작업         | 일반 명사       |
| parsing         | 파싱         | 정착 외래어      |

기준 코드베이스: {widget_prefix} 위젯 디렉토리
(정리 이력 없는 영역)

표 작성 규칙 5가지

  • 13열 고정 — 용어(영어 원문) / 주석에서 쓸 표기 / 비고(판정 근거). 비고에는 Material 3 API, 일반 명사, 음역 금지 처럼 원칙 5 의 어느 갈래인지 적는다.
  • 2판정이 갈렸던 것만 올린다. 자명한 단어를 전부 나열하면 표가 규칙을 대체한다. 초기 규모는 6행 안팎이면 충분하다.
  • 3새 케이스가 생길 때 한 행씩 늘린다. 표를 미리 채우지 않는다.
  • 4기준 코드베이스를 명시한다. 애매하면 어느 디렉토리의 네이밍을 따를지 표 하단에 적는다. AI 톤 오염이 진행된 영역은 기준으로 삼지 않는다 — 오염된 표기가 표를 통해 정식 규칙으로 승격된다.
  • 5표 내용은 이관 대상이 아니다. 킷이 옮기는 것은 "표를 어떻게 만들고 유지하는가"이고, 행 자체는 각 프로젝트가 자기 도메인으로 채운다.

규칙 강도 — 세 등급, 어길 때 무엇이 깨지나

각 원칙 끝에 붙는 강도는 세 단계다. 등급은 "얼마나 지켜야 하나"가 아니라 "근거가 어디서 오나"를 말한다 — 관측 컨벤션이 SHOULD 보다 느슨하다는 뜻이 아니다.

MUST

킷 구조를 결정하는 규칙. 어기면 문서 체계가 깨진다.

어길 때: 개정 시 SSOT 가 갈라져 한쪽만 갱신된다.

안티패턴 — 9가지

문체 자체의 안티패턴과 규칙 운영의 안티패턴이 섞여 있다. 후자(마지막 세 줄)가 더 위험하다 — 문장 하나가 아니라 규칙 체계를 무너뜨린다.

안티패턴문제유형
~을 처리합니다 로 doc 본문 종결 동사가 비어 메서드명을 한국어로 반복하는 데 그친다. 주석이 정보를 0 만큼 더한다 문체
종결어미만 한다체로 바꾸고 끝내기 ~에 의해 · ~되어 있는 경우 는 종결형과 무관하다. 문장 구조가 그대로면 번역투도 그대로다 문체
보더 라디우스 같은 음역 한국어도 영어도 아니라 검색이 안 되고 공식 API 이름과도 어긋난다 문체
코드 식별자를 한국어로 번역 doc 링크가 끊기고 코드와 문서가 어긋난다. 음역 금지는 본문에만 적용된다 문체
이름 번역 주석 (String? text, // 버튼 텍스트) 타입과 이름이 이미 담은 의미의 반복. 이름이 약하면 이름을 고칠 자리다 문체
void doc 에 N/A 표기 도입 언어 의존 상수를 프로젝트 안에서 두 표기로 쪼갠다. 커버리지 측정과 일괄 치환이 깨진다 상수 훼손
- 반환값: 없음 을 노이즈로 보고 삭제 "doc 이 없는 것"과 "반환값이 없는 것"을 구분할 수 없게 된다 상수 훼손
용어 번역표를 공용 킷 문서로 승격 도메인 어휘는 프로젝트 소유다. 공용화하면 다른 프로젝트에 잘못된 번역을 강제한다 범위 침범
한국어 규칙을 스택 어댑터 문서에 다시 정의 SSOT 가 무너져 개정 때 한쪽만 갱신된다. 어댑터는 라벨 상수와 주석 문법만 갖는다 SSOT 붕괴
Gotchas — 반복되는 실수 6가지

규칙을 외우는 것보다 이 6가지를 피하는 게 실효가 크다. 1번이 가장 흔하고, 4번은 이 문서를 쓰는 사람 자신에게 걸린다.

  • 1 번역투는 종결어미 문제가 아니라 문장 구조 문제다 — 합니다 를 한다 로 바꾸는 치환은 30초면 끝나고, 그래서 그것만 하고 완료로 보고하게 된다. 킬러 패턴 6종은 종결형과 독립이므로 치환 후에 6종을 따로 grep 한다.
  • 2 라벨을 "더 자연스럽게" 다듬으면 grep 이 깨진다 — - 반환값: 을 - 리턴: 이나 - 결과: 로 바꾸고 싶어지는 순간이 온다. 이것은 상수다. 표기를 바꾸려면 전수 치환을 같이 하고, 부분 변경은 금지다.
  • 3 정착 외래어와 음역의 경계는 팀이 한 번 정하고 끝낸다 — 파싱 은 허용이고 보더 라디우스 는 금지라는 판정에 일반 규칙은 없다. 매번 재논쟁하지 말고 판정을 용어 번역표에 적어 다음 세션이 그것을 읽게 한다.
  • 4 규칙 문서 자신이 번역투를 쓴다 — 규칙을 설명하는 문장에서 ~하도록 합니다 와 ~에 대해 가 특히 잘 나온다. 문서를 다 쓴 뒤 자기 본문에 6종을 grep 하는 자기모순 검사를 한 번 돌린다.
  • 5 다른 스택 어댑터가 생길 때 이 문서를 복사하지 마라 — Rust 나 TypeScript 어댑터가 필요해지면 라벨 상수와 주석 문법만 그쪽에 정의하고 문체는 이 문서를 참조한다. 복사하는 순간 두 벌이 갈라지고, 갈라진 사실을 아무도 모른다.
  • 6 AI 톤이 낀 영역을 번역 기준으로 삼으면 오염이 승격된다 — "기존 코드가 이렇게 쓰니까" 로 표기를 정하면, 정리 대상이던 표기가 표를 통해 정식 규칙이 된다. 기준 디렉토리는 정리 이력이 없는 쪽으로 명시한다.
