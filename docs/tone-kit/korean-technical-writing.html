한국어 기술 문서·주석 문체

한국어로 쓰는 주석·doc의 문체 규칙. 번역투 제거, 종결형, 외래어 처리, 용어 번역표 작성이 대상이다. 한국어 의존 축의 SSOT이며 다른 문서는 이 규칙을 다시 정의하지 않는다. v0.1.0 · 최종 갱신 2026-09-25

문체는 한곳에, 라벨은 상수로

스택 축과 언어 축은 서로를 결정하지 않는다. 스택 어댑터에는 라벨 상수와 주석 문법만 두고 한국어 문체는 이 문서를 참조한다. - 반환값: 같은 라벨을 일부 파일에서만 바꾸면 grep과 커버리지 측정이 깨진다.

이 문서가 잡는 것
  • 번역투~에 의해·~하도록 합니다처럼 영어 구문을 그대로 옮긴 문장
  • 종결형 혼용한 코드베이스에 합니다체와 한다체가 섞이는 것
  • 군더더기 한국어이름을 되풀이하는 번역 주석과 보더 라디우스 같은 음역
  • 새로 붙인 이름처음 읽는 사람이 뜻을 짐작할 수 없는 합성어·비유인 차례칸 같은 이름
Bad
/// 값이 설정되어 있는 경우 라벨이
/// 오버레이에 의해 표시되도록 합니다.
Good
/// 값이 있으면 라벨을 그린다.
/// surface tint가 얹혀 배경보다 밝아 보인다.

강도는 MUST, SHOULD, 관측 컨벤션 세 단계다. 관측 컨벤션은 공개 출처 없이 프로젝트 실측만 있다는 뜻이지 준수 강도가 낮다는 뜻이 아니다.

원칙

아홉 원칙은 한국어 문체의 소유권, 문장 구조, 종결형, 외래어, 주석 경제, 라벨, 용어표, 새 이름을 함께 다룬다.

지운 자리를 능동형·주체·원인으로 채운다

한국어SHOULD

패턴을 지우는 데서 멈추지 않는다. 주체와 결과를 직설로 밝히고 원인과 결과를 구체적으로 잇는다. 주석의 값어치는 what보다 why에서 나온다.

외래어는 3원칙으로 가른다

한국어SHOULD

공식 API 이름은 영어 원문, 일반 명사는 한국어, 음역은 금지한다. 코드 식별자는 대상이 아니며 영어 그대로 둔다. 정착 여부는 팀이 판정해 용어 번역표에 적는다.

Bad

6

이름 번역 주석은 지운다

코어한국어SHOULD

이름·타입이 이미 말하는 내용을 한국어로 되풀이하지 않는다. 지우거나 값의 우선순위, 무효화 조건, 허용 범위처럼 이름과 타입에서 읽히지 않는 계약만 남긴다. 이름이 약하면 주석 대신 이름을 고친다.

Bad
String? text,   // 버튼 텍스트
bool isChecked, // 체크 여부
double min,     // 최소값
int t,          // 타임아웃 초
Good
String? text,
bool isChecked,
double min, // step의 배수로 올림된다.
int timeoutSeconds,

실측에서 이름 번역 주석은 48파일 약 85건으로 두 번째로 큰 카테고리였고, 전체 안티패턴 약 275건의 30%를 차지했다. 1위는 템플릿 마커 약 90건이었다.

8

용어 번역표는 프로젝트가 소유한다

코어한국어관측 컨벤션

판정 결과 표는 프로젝트 저장소에 하나 두고 공용 킷으로 올리지 않는다. 판정이 갈렸던 항목만 3열로 쌓고, 초기 6행 안팎에서 새 사례가 생길 때 한 행씩 늘린다.

Bad
| button | 버튼 |
| color  | 색상 |
| text   | 텍스트 |
Good
| 영어 원문    | 주석 표기    | 판정 근거       |
| surface tint | surface tint | Material 3 API |
| border radius| 테두리 반경   | 음역 금지       |
| job          | 작업         | 일반 명사       |
| parsing      | 파싱         | 정착 외래어     |
  • 1용어 원문 / 주석 표기 / 판정 근거의 3열을 고정한다.
  • 2자명한 단어는 빼고 판정이 갈렸던 것만 올린다.
  • 3표를 미리 채우지 않고 새 사례가 생길 때 늘린다.
  • 4정리 이력이 없는 기준 코드베이스를 명시한다. AI 톤 오염 영역은 기준으로 삼지 않는다.
  • 5킷은 표 유지 방법만 옮긴다. 표의 행 자체는 이관하지 않는다.

9

새 이름을 만들지 않는다

한국어관측 컨벤션

이미 있는 이름을 쓰고, 없으면 하는 일을 문장으로 풀어 쓴다. 글쓴이가 새로 붙인 합성어·비유는 쓴 사람만 뜻을 안다. 판정 기준은 사전 등재 여부가 아니라 처음 읽는 사람이 뜻을 짐작할 수 있는가다.

Bad — 새 합성어
// 차례칸이 비면 첫 세트로 돌아간다
Good — 동작 또는 원래 이름
// 다음에 할 세트가 없으면 첫 세트로 돌아간다
// pendingSets가 비면 첫 세트로 돌아간다

새 이름이 꼭 필요하면 처음 나올 때 괄호로 뜻을 붙인다. 표시훅처럼 음역까지 섞이면 원칙 5와 원칙 8도 함께 적용한다. 한국어 근거는 2026-09-19 세션 관찰 1건이며, 새 합성어 때문에 사용자가 뜻을 되물었다.

Good — 소유권이 선명하다

라벨은 전수 변경 전까지 고정하고, 한국어 문체는 이 문서가, 용어 판정은 각 프로젝트가 소유한다.

Gotchas
  • 1번역투는 종결어미가 아니라 문장 구조 문제다. 합니다를 한다로 바꾼 뒤에도 킬러 패턴 6종을 따로 grep한다.
  • 2라벨을 자연스럽게 다듬으면 grep이 깨진다. 표기를 바꾸려면 전수 치환을 함께 하며 부분 변경은 금지한다.
  • 3정착 외래어와 음역의 경계는 팀이 한 번 정한다. 판정을 용어 번역표에 남겨 다음 세션이 읽게 한다.
  • 4규칙 문서 자신도 번역투를 쓸 수 있다. 완성 뒤 자기 본문에 킬러 패턴 6종을 grep해 자기모순을 검사한다.
  • 5새 스택 어댑터에 이 문서를 복사하지 않는다. 라벨 상수와 주석 문법만 정의하고 이 문서를 참조한다.
  • 6AI 톤이 낀 영역을 번역 기준으로 삼지 않는다. 정리 대상이던 표기가 용어표를 통해 정식 규칙으로 승격될 수 있다.
