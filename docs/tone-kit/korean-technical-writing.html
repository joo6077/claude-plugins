한국어 기술 문서·주석 문체

한국어로 쓰는 주석·doc 의 문체 규칙을 정의한다. 번역투 제거, 종결형, 외래어 처리, 용어 번역표 작성이 대상이다. 이 문서가 "한국어 의존" 축(규칙이 무엇에 의존하는지 가르는 기준 — 스택 축과 언어 축 둘이 있다)의 SSOT 다 — 다른 문서는 한국어 규칙을 다시 정의하지 말고 여기를 가리킨다. v0.1.0 · 최종 갱신 2026-09-25

문체는 한곳에, 라벨은 상수로

스택 축과 언어 축은 서로를 결정하지 않는다. 스택 어댑터에는 라벨 상수와 주석 문법만 두고 한국어 문체는 이 문서를 참조한다. - 반환값: 같은 라벨을 일부 파일에서만 바꾸면 grep과 커버리지 측정이 깨진다.

이 문서가 잡는 것
  • 번역투~에 의해 · ~하도록 합니다 처럼 영어 구문을 그대로 옮긴 문장
  • 종결형 혼용한 코드베이스에 합니다체와 한다체가 섞이는 것
  • 군더더기 한국어이름을 되풀이하는 번역 주석(// 버튼 텍스트)과 음역(보더 라디우스)
  • 새로 붙인 이름읽는 사람이 뜻을 짐작할 수 없는 합성어·비유로 대상을 부르는 것(차례칸)
Bad
/// 값이 설정되어 있는 경우 라벨이 오버레이에 의해 표시되도록 합니다.
Good
/// 값이 있으면 라벨을 그린다. surface tint 가 얹혀 배경보다 밝아 보인다.

1

한국어 규칙은 이 문서에만 쓴다

[코어][한국어]MUST

한국어 문체는 스택과 무관하다. 스택 어댑터 문서는 라벨 상수와 주석 문법만 갖고, 문체는 여기를 참조한다.

같은 규칙, 언어만 교체 — 골격은 그대로다
한국어 프로젝트: /// - 반환값: 연결되어 있으면 true
영어 프로젝트:   /// - Returns: true when connected
Bad

dart-flutter 어댑터 문서에 "종결형은 한다체" 를 다시 적는다

Good

dart-flutter 어댑터 문서는 - 반환값: 라벨과 /// 문법만 정의하고, 문체는 이 문서를 링크한다

왜. 규칙의 의존성은 스택 축(Dart/Flutter · Rust · TypeScript)과 언어 축(한국어 · 영어) 둘로 나뉘고, 두 축은 서로를 결정하지 않는다. 언어를 바꾸면 라벨 문자열만 바뀌고 "파라미터·반환값을 doc 하단 라벨 블록으로 붙인다"는 골격과 커버리지 기준은 남는다. 반대로 Dart 에서 Rust 로 옮기면 주석 문법과 링크 문법([param] → `param`)만 바뀌고 한국어 문체는 한 줄도 안 바뀐다. 그래서 어댑터 슬롯(스택마다 갈아 끼우는 문서 자리 — 라벨 상수와 주석 문법만 담는다)에 문체를 복사하면 두 벌이 갈라진다.

강도: MUST (킷 구조 결정)

번역투 킬러 패턴 6종을 제거한다

[한국어]SHOULD

아래 6개 구문을 주석에서 지운다. 종결어미만 한다체로 바꾸면 6종은 그대로 남는다.

패턴문제대체형
~을 처리합니다 / ~을 관리합니다동사가 비어 있어 메서드명을 한국어로 되풀이하는 데 그친다실제 동작 동사: 길게 누르기 반복을 시작한다
~에 대해서 / ~에 대해about / for 직역. 목적격 조사면 충분하다서버 이름을 보여 준다
~하도록 합니다사역 구문 직역. 주체가 사라진다단정형 ~한다: 키보드 입력을 이어 간다
~에 의해by 직역 수동태주어를 되살린 능동형: surface tint 가 배경색을 덮는다
~되어 있는 경우if ... is set 직역. 조건 서술이 두 배로 길어진다값이 없으면 …
과한 수동태 (표시됩니다 · 적용됩니다)행위 주체가 사라져 원인을 추적할 수 없다주체 + 능동: 이 위젯이 …를 그린다

1) ~을 처리합니다 → 실제 동작 동사

Bad
/// 캐시 만료를 처리합니다.
void evictExpired() { }
Good
/// 마지막 갱신에서 5분이 지난 항목을 캐시에서 지운다.
void evictExpired() { }

2) ~에 대해 → 목적격 조사

Bad
/// 입력값에 대해 검증합니다.
Good
/// 입력값의 길이와 허용 문자를 검증한다.

3) ~하도록 합니다 → 단정형 ~한다

Bad
// 재시도 횟수를 3회로 제한하도록 합니다.
Good
// 재시도는 3회까지만 한다. 넘으면 마지막 실패를 그대로 올린다.

4) ~에 의해 → 주어를 되살린 능동형

Bad
// 스크롤 위치가 컨트롤러에 의해 복원됩니다.
Good
// 탭으로 되돌아오면 이 컨트롤러가 이전 스크롤 위치를 복원한다.

5) ~되어 있는 경우 → ~면

Bad
/// 아이콘이 지정되어 있는 경우 라벨 왼쪽에 배치합니다.
Good
/// 아이콘이 있으면 라벨 왼쪽에 붙인다.

6) 과한 수동태 → 주체 + 능동

Bad
/// 스크롤이 끝에 닿으면 다음 페이지가 요청됩니다.
Good
/// 스크롤이 끝에 닿으면 이 위젯이 다음 페이지를 요청한다.

왜. 6종은 종결형 규칙과 독립이다. 합니다 → 한다 치환은 30초면 끝나지만 ~에 의해, ~되어 있는 경우 는 문장 구조라서 치환에 걸리지 않는다. 각각 따로 grep 해서 잡는다.

강도: SHOULD (국립국어원·번역투 연구 근거, 프로젝트가 MUST 로 승격 가능)

지운 자리를 능동형·주체·원인으로 채운다

[한국어]SHOULD

패턴을 지우는 것으로 끝내지 마라. 능동형으로 쓰고, 주체와 결과를 직설로 밝히고, 원인과 결과를 구체적으로 잇는다.

#BadGood
1/// 눌림 시작을 처리합니다.// 길게 누르기 반복을 시작한다.
2// 서버 이름에 대해 표시합니다.// 선택된 서버 이름을 그대로 보여 준다.
3// 배경색이 오버레이에 의해 변경됩니다.// Material 3 surface tint 가 배경색을 덮어 실제 색이 더 밝아 보인다.
4// 포커스를 잃지 않도록 합니다.// 드롭다운을 닫은 뒤에도 키보드 입력을 이어 가야 한다.
5// 값이 설정되어 있는 경우에만 표시되도록 합니다.// 값이 없으면 빈 영역을 만들지 않는다.

왜. 세 번째 Bad 줄은 번역투(~에 의해)와 음역(오버레이)이 함께 걸린 사례다. 한 문장이 두 규칙을 동시에 어기는 일이 흔하므로 고칠 때 둘 다 본다. 문장 수사보다 정보 설계가 먼저이고, 주석의 값어치는 what 이 아니라 why 에서 나온다.

강도: SHOULD

종결형은 한다체 하나로 고정한다

[코어][한국어]관측 컨벤션

doc 본문 동사는 한다체로 쓴다. 합니다체와 명사형 종결을 섞지 않는다.

Bad — 한 파일 안에서 종결형이 셋으로 갈린다
/// 설정값을 반환합니다.
/// 캐시를 비운다.
/// 재시도 횟수 초기화.
Good — 전부 한다체
/// 설정값을 반환한다.
/// 캐시를 비운다.
/// 재시도 횟수를 0 으로 되돌린다.
// 예외 — 인라인 주석은 파편형·단문 허용, 코드로 읽히면 아예 지운다
final expiresAt = issuedAt.add(ttl); // UTC 기준

왜. 한 코드베이스에 두 종결형이 공존하면 grep 기준이 무너지고 파일마다 톤이 달라진다. 종결형 고정은 문장을 쓰기로 한 자리에만 적용되고, 인라인 // 는 대상이 아니다. 근거는 실측이다 — 동일 모노레포의 공용 패키지 한 곳에서 반환합니다 종결 doc 이 125건 나왔다. 고정하지 않으면 이런 덩어리가 조용히 쌓인다.

강도: 관측 컨벤션 (실측 근거만 존재)

프로젝트 실측 — 공용 패키지 번역투 doc 129건(반환합니다 125건), 2026-08-28 전수 감사. 공개 문헌 근거 없음
5

외래어는 3원칙으로 가른다

[한국어]SHOULD

공식 API 이름은 영어 원문, 일반 명사는 한국어, 음역은 금지.

Bad
/// 보더 라디우스와 박스 데코레이션을 적용합니다.  ← 음역
/// 표면 색조 값을 계산합니다.                    ← 공식 API 이름을 번역
/// 백그라운드 컬러를 덮어씁니다.                  ← 일반 명사를 음역
Good
/// {TokenClass}.radiusM 을 테두리 반경으로 쓴다.
/// surface tint 가 배경 위에 얹히는 양을 계산한다.
/// 배경색을 덮어쓴다.
정착 외래어는 허용: 다운로드 · 업로드 · 파싱 · 파일 · 폴더
치환 대상:        잡(job) → 작업 · 큐(queue) → 대기열

왜. surface tint, BoxDecoration, strokeAlign 은 문서·검색·자동완성이 전부 원문 기준으로 움직여서 번역하면 찾을 수 없다. 반대로 보더 라디우스 는 한국어도 영어도 아니라 검색이 안 되고 공식 이름과도 어긋난다. 정착 여부는 팀이 판정하고 결과를 용어 번역표에 적는다(원칙 8).

코드 식별자는 이 규칙의 대상이 아니다. 타입·함수·변수·메서드 이름은 영어를 그대로 둔다. 번역하면 doc 링크가 끊긴다. 음역 금지는 한국어 본문만 겨냥한다.

강도: SHOULD

이름 번역 주석은 지운다

[코어][한국어]SHOULD

이름·타입이 이미 말하는 내용을 한국어로 되풀이하지 마라. 지우거나, 이름·타입에서 안 읽히는 계약만 남긴다.

Bad — 이름을 한국어로 되풀이
String? text,        // 버튼 텍스트   ← text 가 이미 '텍스트'
bool isChecked,      // 체크 여부     ← isChecked 가 이미 '체크 여부'
double min,          // 최소값        ← min 이 이미 '최소값'
Good — 지우고, 남길 것은 계약뿐
String? text,
bool isChecked,
double min,          // step 의 배수로 올림된다. min 자체는 후보에서 빠진다
Bad — 이름이 약해서 주석으로 때운다
int t,               // 타임아웃 초
Good — 주석 대신 이름을 고친다
int timeoutSeconds,

왜. 식별자가 영어이고 주석이 한국어라서 번역 주석이 정보를 더하는 것처럼 보이지만 실제로는 같은 내용의 반복이다. 원본 코드베이스 진단에서 이 유형이 48개 파일에 약 85건으로 두 번째로 큰 카테고리였고 (1위는 템플릿 마커 약 90건), 전체 안티패턴 약 275건의 30% 를 차지했다. 영어 단일 언어 프로젝트라면 // button text 는 누구도 안 쓴다 — 번역이라는 명분이 붙어야 생기므로 한국어 축에 속한다. 남길 것은 값의 우선순위, 무효화 조건, 허용 범위처럼 이름·타입에서 안 읽히는 계약뿐이다.

강도: SHOULD

7

doc 라벨은 상수다 — 표기를 쪼개지 마라

[어댑터:dart-flutter][한국어]관측 컨벤션

파라미터·반환값 라벨은 자유 서술이 아니다. - [param]: 설명 과 - 반환값: 설명 두 형태로 고정하고, void 반환은 - 반환값: 없음 으로 쓴다.

Bad — 표기가 갈리고 void 에 새 표기를 도입한다
/// - 리턴: 연결되어 있으면 true
/// - 결과: 연결 여부
/// - 반환값: N/A
Good — 두 형태로 고정
/// 네트워크 연결 상태를 확인하고, 끊긴 경우 안내 다이얼로그를 띄운다.
///
/// - [context]: 다이얼로그 표시용 빌드 컨텍스트
/// - [ref]: 네트워크 모니터 상태 조회용 ref
/// - 반환값: 연결되어 있으면 true, 끊겨 있으면 false
Good — void 도 라벨을 지우지 않는다
/// 입력 버퍼를 비운다.
///
/// - 반환값: 없음
Bad — doc 본문에 섹션 헤더와 알고리즘 단계를 늘어놓는다
/// 정책: 캐시는 5분마다 만료된다.
/// 참고: 백그라운드 진입 시 타이머가 멈춘다.
/// 주의: 1) 키 생성 2) 조회 3) 없으면 원격 호출
Good — 한두 문장으로 끝내고 나머지는 설계 문서로 보낸다
/// 캐시에서 먼저 찾고, 5분이 지났으면 원격에서 다시 받아 채운다.

왜. 상수로 다루는 이유는 검색성이다. 원본 코드베이스에서 - 반환값: 은 80개 파일에 577건, - [param]: 은 788건 나왔다. 이 규모에서 표기가 둘로 갈리면 커버리지 측정과 일괄 치환이 모두 깨진다. - 반환값: 없음 을 노이즈로 보고 지우는 것도 금지다 — 있고 없음이 섞이면 "doc 이 없는 것"과 "반환값이 없는 것"을 구분할 수 없다.

강도: 관측 컨벤션

Effective Dart documentation 프로젝트 실측 — - 반환값: 577건 / 80파일, - [param]: 788건 (2026-08-28)
8

용어 번역표는 프로젝트가 소유한다

[코어][한국어]관측 컨벤션

판정 결과를 누적하는 표를 프로젝트 저장소에 하나 둔다. 킷 공용 문서로 올리지 않는다.

Bad — 킷 공용 문서에 올리고, 원칙 5 로 자명한 단어까지 채운다
| button | 버튼 |
| color  | 색상 |
| text   | 텍스트 |
Good — 프로젝트 저장소에 두고, 판정이 갈렸던 행만 3열로 쌓는다
| 용어 (영어 원문) | 주석 표기     | 비고 (판정 근거)      |
|-----------------|--------------|---------------------|
| surface tint    | surface tint | Material 3 API      |
| border radius   | 테두리 반경    | 음역 금지            |
| job             | 작업          | 일반 명사            |
| parsing         | 파싱          | 정착 외래어           |
기준 코드베이스: {widget_prefix} 위젯 디렉토리 (정리 이력 없는 영역)

표 작성 규칙은 다음과 같다.

  • 13열 고정 — 용어(영어 원문) / 주석에서 쓸 표기 / 비고(판정 근거). 비고에는 Material 3 API, 일반 명사, 음역 금지 처럼 원칙 5 의 어느 갈래인지 적는다.
  • 2판정이 갈렸던 것만 올린다. 원칙 5 로 자명하게 갈리는 단어를 전부 나열하면 표가 규칙을 대체해 버린다. 초기 규모는 6행 안팎이면 충분하다.
  • 3새 케이스가 생길 때 한 행씩 늘린다. 표를 미리 채우지 않는다.
  • 4기준 코드베이스를 명시한다. 애매하면 어느 디렉토리의 네이밍을 따를지 표 하단에 적는다. AI 톤 오염이 진행된 영역은 기준으로 삼지 않는다 — 오염된 표기가 표를 통해 정식 규칙으로 승격된다.
  • 5표 내용은 이관 대상이 아니다. 킷이 옮기는 것은 "표를 어떻게 만들고 유지하는가"이고, 행 자체는 각 프로젝트가 자기 도메인으로 채운다.

왜. 원칙 5 의 3원칙만으로는 매번 판정이 갈린다. 도메인 어휘와 정착 외래어 판정은 프로젝트마다 다르므로, 공용 문서로 올리면 다른 프로젝트에 잘못된 번역을 강제한다.

강도: 관측 컨벤션

9

새 이름을 만들지 않는다

[한국어]관측 컨벤션

대상을 부를 이름이 이미 있으면 그 이름을 쓴다. 없으면 하는 일을 문장으로 풀어 쓴다. 글쓴이가 새로 붙인 합성어·비유로 부르지 않는다.

Bad — 글쓴이가 새로 붙인 이름. 무엇을 가리키는지 코드를 읽어야 안다
// 차례칸이 비면 첫 세트로 돌아간다
Good — 하는 일을 문장으로
// 다음에 할 세트가 없으면 첫 세트로 돌아간다
Good — 원래 이름을 그대로
// pendingSets 가 비면 첫 세트로 돌아간다

왜. 새 이름은 쓴 사람만 뜻을 안다. 읽는 사람은 그 이름이 무엇을 가리키는지부터 되물어야 하고, 되묻지 못하면 짐작으로 읽는다. 실측은 세션 1건이다(2026-09-19) — 훅의 동작을 표시훅 이라는 새 합성어로 부르자 사용자가 뜻을 몰라 되물었다.

판정 기준은 사전에 실렸는지가 아니다. 한글 맞춤법 제50항 해설은 국어사전에 모든 전문 용어를 실을 수는 없다며 사전에 없는 전문 용어도 정당한 말로 다룬다. 그래서 처음 읽는 사람이 뜻을 짐작할 수 있는가 로 가른다. 새 이름이 꼭 필요하면 처음 나올 때 괄호로 뜻을 붙인다 — Google 문서 스타일 가이드가 권하는 순서(그 말을 피해 쓸 수 있는가 → 더 구체적인 말로 바꿀 수 있는가 → 꼭 써야 하면 처음 나올 때 풀어 쓴다)와 같다.

표시훅 의 훅 처럼 음역이 섞이면 원칙 5 의 음역 금지에도 걸릴 수 있다. 정착 외래어인지는 원칙 8 의 용어 번역표로 판정하고, 둘 다 걸리면 두 규칙을 함께 적는다.

강도: 관측 컨벤션 (한국어 쪽 근거는 세션 1건 관찰뿐이다. 영어권 문서 가이드는 새 말 만들기를 피하라고 하지만 한국어 규범은 새 말 만들기를 금하지 않는다)

Gotchas
  • 1번역투는 종결어미 문제가 아니라 문장 구조 문제다 — 합니다 를 한다 로 바꾸는 치환은 30초면 끝나고, 그래서 그것만 하고 완료로 보고하게 된다. 킬러 패턴 6종은 종결형과 독립이므로 치환 후에 6종을 따로 grep 한다.
  • 2라벨을 "더 자연스럽게" 다듬으면 grep 이 깨진다 — - 반환값: 을 - 리턴: 이나 - 결과: 로 바꾸고 싶어지는 순간이 온다. 이것은 상수다. 표기를 바꾸려면 전수 치환을 같이 하고, 부분 변경은 금지다.
  • 3정착 외래어와 음역의 경계는 팀이 한 번 정하고 끝낸다 — 파싱 은 허용이고 보더 라디우스 는 금지라는 판정에 일반 규칙은 없다. 매번 재논쟁하지 말고 판정을 용어 번역표에 적어 다음 세션이 그것을 읽게 한다.
  • 4규칙 문서 자신이 번역투를 쓴다 — 규칙을 설명하는 문장에서 ~하도록 합니다 와 ~에 대해 가 특히 잘 나온다. 문서를 다 쓴 뒤 자기 본문에 6종을 grep 하는 자기모순 검사를 한 번 돌린다.
  • 5다른 스택 어댑터가 생길 때 이 문서를 복사하지 마라 — Rust 나 TypeScript 어댑터가 필요해지면 라벨 상수와 주석 문법만 그쪽에 정의하고 문체는 이 문서를 참조한다. 복사하는 순간 두 벌이 갈라지고, 갈라진 사실을 아무도 모른다.
  • 6AI 톤이 낀 영역을 번역 기준으로 삼으면 오염이 승격된다 — "기존 코드가 이렇게 쓰니까" 로 표기를 정하면, 정리 대상이던 표기가 표를 통해 정식 규칙이 된다. 기준 디렉토리는 정리 이력이 없는 쪽으로 명시한다.
