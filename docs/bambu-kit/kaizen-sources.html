Anti-pattern · 잘못된 폴링 전략

MakerWorld을 매시간 스크래핑하지 마라

MakerWorld는 공식 API/RSS가 없어 DOM 스크래핑에 의존한다. 짧은 주기로 폴링하면 차단되거나 첫 DOM 변경 한 번에 깨진다. 주 1회로 낮추고, 실패 시 codex-rescue WebFetch fallback으로 우회하는 게 안전하다.

✗ Anti-pattern

MakerWorld을 매시간 스크래핑

cron 0 * * * *로 trending 페이지를 매시간 GET. DOM 변경 한 번에 파서 전체 깨짐. Cloudflare 차단 시 전체 cycle 실패. Reddit RSS도 동일 주기로 돌리면 403 누적.

✓ 권장

주 1회 + WebFetch fallback

cron 0 9 * * 1 (월 09:00 1회). 스크래핑 실패 시 codex-rescue에 WebFetch 위임으로 우회. Reddit은 UA 지정 + 실패 시 JSON endpoint로 재시도, 그래도 실패하면 다음 주로 미룬다.

Gotchas · 폴링 자동화 주의사항

cron 등록 전 체크리스트

5가지 폴링 함정. 자동화 첫 cycle에서 한 번이라도 걸리면 references 갱신이 조용히 멈춘다.

  • ✓ GitHub unauth 60/h — 5개 repo 폴링하면 시간당 5 요청. 충분하지만 If-None-Match ETag 헤더로 변동분만 가져와 quota를 보존한다.
  • ✓ Reddit RSS 403 backoff — User-Agent를 bambu-kit-kaizen/1.0 (contact: ...)로 명시. 403 시 5분 대기 후 1회 재시도, 그래도 실패하면 다음 주기로 미루고 로그만 남긴다.
  • ✓ MakerWorld DOM 변경 리스크 — 셀렉터를 한 곳에 모으고 (parsers/makerworld.ts) 응답에 핵심 셀렉터가 0개일 때 즉시 알림. 침묵 실패 금지.
  • ✓ Bambu Blog Ghost RSS 첫 응답 검증 — /rss/ endpoint가 200 + valid XML인지 첫 cron에서 확인. Ghost 사이트 구조에 따라 /feed/나 /rss일 수도 있다.
  • ✓ 지역 스토어 결정 (US/EU/JP/KR) — Shopify endpoint가 지역별로 SKU/가격이 다르다. 기준 지역을 US로 잡고, KR/JP는 추후 별도 cycle로 분리. 한 endpoint로 다 해결하려 하지 말 것.
  • ✓ Discord 채널은 references 소스 X — 빠른 신호는 있지만 공개 RSS/API 없음. 권한·초대·검색 문제로 자동화 reference 갱신 소스로는 비추천. 수동 검증 채널로만 사용.

⚠ Q1 / Bambu Blog RSS

⚠ Q2 / Bambu Store Shopify
지역별 endpoint 노출 / 차단 차이
US/EU/JP/KR 중 어느 region을 references 기준으로 잡을지 결정 필요. US가 가장 안정적이지만 KR 한정 SKU 누락 가능. 1차는 US, 2차로 KR mirror 검토.
⚠ Q3 / MakerWorld API
공식 API / RSS 미확인
스크래핑 또는 비공식 reverse-engineered endpoint 의존. 장기 자동화 안정성 ↓. references 핵심 소스보다 "트렌드 후보 수집"으로 격하 권장.
