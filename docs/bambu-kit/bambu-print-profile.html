Bambu Print Profile — H2S 자동 JSON 생성 워크플로우

MakerWorld URL 또는 로컬 모델 → 모델 분석 → 소재 추천 → seam 전략 → Bambu Studio용 process+filament JSON + zip 번들. H2S + AMS HT + AMS 2 Pro + Bambu Studio v2.6.0+ 환경 가정. 4건의 Codex research run과 실측 피드백으로 references 4종을 채워 silent skip을 유발하는 메타필드 누락 패턴을 회피한다.

v2 정책 추가 (2026-05-16): Phase 3에 Surface-first 모드 분기 추가. 회전체 default를 random + entire_loop(분산)에서 Auto-select 결정 트리(spiral → painted → random fallback)로 전환. 6개 형상 enumerate + 8개 소재 ironing 매트릭스 + PETG HF 건조 경고. 자세한 정책 → Surface Recipes. Codex run a25261e23b21252b2 (score 24/25).
트리거 조건 (Triggers)

스킬은 H2S + Bambu Studio 환경에 한정된다. 다른 프린터(X1/P1/A1)나 다른 슬라이서(OrcaSlicer/PrusaSlicer) 요청에는 트리거되지 않는다. 단순 1필드 변경에도 트리거되지 않는다 — 그건 Bambu Studio UI에서 직접 처리하는 게 빠르다.

트리거함 — 워크플로우 실행
  • MakerWorld URL이 메시지에 포함 (makerworld.com/en/models/...)
  • 로컬 모델 파일 경로 언급 (.3mf / .stl / .step)
  • "삼프 설정", "Bambu 프로파일 만들어줘", "출력 셋팅", "프린트 셋팅"
  • "MakerWorld 모델 출력하려고" 같은 출력 의도 표현
  • "원기둥 seam 안 보이게", "회전체 표면 깔끔하게" 같은 형상 + seam 결합 요청
  • 모델명 + 소재 + 품질 요구가 묶여서 들어오는 경우
트리거 안 함 — 다른 도구 사용
  • 단순 1필드 변경 ("온도 245로 해줘", "색만 바꿔줘") → Studio UI 직접
  • 기존 프로파일 리뷰만 요청 ("이 설정 어때?")
  • 다른 프린터 / 다른 슬라이서 언급 (X1C, P1S, A1, OrcaSlicer, PrusaSlicer)
  • 슬라이싱 결과 분석만 요청 ("이 출력 어땠어?")
  • 하드웨어 트러블슈팅 ("벨트 텐션", "노즐 막힘")
  • 장비 펌웨어/메인보드 관련 질문
Why H2S만? Bambu Studio의 시스템 프리셋은 프린터별로 inherit chain이 완전히 다르다. compatible_printers가 정확히 매칭되지 않으면 import는 성공해도 드롭다운에 안 보이는 silent skip이 발생한다. 멀티 프린터 지원은 v2 카이젠 백로그.
워크플로우 5단계 (Phase 1~5)

입력(URL/파일/대화 컨텍스트) → 모델 컨텍스트 추출 → 소재 추천 → JSON 생성 → zip 번들 → 검증 + (선택) coupon test. 각 Phase는 references 4종 중 어느 파일을 로드해야 하는지 명시되어 있다.

Phase 5 (선택, 강력 권장)

Coupon Test

De-risk Print

본 출력 전에 작은 cylinder primitive로 빠른 검증. coupon은 본 process의 scarf 설정만 동일하게 두고 나머지를 lean하게 깎는다.

대상 케이스

  • 필요 출력 시간 > 4시간
  • 필요 회전체 + seam-critical
  • 필요 새 소재 또는 새 scarf 조합 첫 시도

coupon-process.json 차이

  • top/bottom_shell_layers = 0
  • sparse_infill_density = 0%
  • scarf 관련 필드는 본 process와 동일

Studio에서 cylinder primitive 30×30×9mm 추가 → coupon process 적용 → 짧게 출력 → 결과 평가 후 본 출력 결정.

↗ Bambu Studio (primitive 모델)
필수 메타필드 (Silent Skip 회피)

Bambu Studio는 메타필드가 빠지거나 잘못된 JSON을 import해도 에러를 띄우지 않는다. 드롭다운에 preset이 보이지 않을 뿐. Codex run a2a01770a87626167으로 검증된 7종 필드는 절대 누락하지 말 것.

필드값비고
type "process" 또는 "filament" JSON 분류 결정. 잘못 쓰면 그 카테고리 드롭다운에 안 뜸.
name "<모델명> - <변종> 0.12mm" 사용자 인지 가능한 이름. UI에 그대로 노출되므로 식별성 우선.
version "2.6.0.2" Semver parseable 필수. Studio v2.6.0과 호환되는 값.
from "User" 대문자 U — "user" 소문자는 silent skip된다.
inherits 시스템 프리셋명 정확 일치 못 찾으면 silent skip. 셸로 사전 검증 권장 (ls ~/Library/Application Support/BambuStudio/system/BBL/...).
print_settings_id / filament_settings_id name과 동일. filament은 배열 형태 빠지면 "Preset type is unknown" 에러 또는 silent skip.
compatible_printers ["Bambu Lab H2S 0.4 nozzle"] H2S 고정. 다른 프린터 문자열은 매칭 실패 → silent skip.
왜 silent skip인가? Bambu Studio는 사용자 데이터 손상을 막기 위해 의심스러운 preset을 조용히 무시한다. 에러 다이얼로그 없음, 로그도 거의 없음. 이 스킬의 가장 큰 실패 모드이며 Codex run a2a01770a87626167이 7종 필드 조합을 모두 시험하여 도출한 baseline이다.
JSON 튜닝 정책 (Override Scope)

"무엇을 만지고 무엇을 안 만지는가"가 명확해야 한다. 기본 원칙: 모델 형상/seam 전략에 직결되는 필드만 override. 사용자 영역(노즐 온도, retraction, fan)은 base profile 또는 .3mf creator 튜닝에 맡긴다.

P

Process JSON — Override 대상

Print Geometry & Strategy
  • + layer_height, initial_layer_print_height — 사용자 요구
  • + wall_loops, sparse_infill_density, top/bottom_shell_layers, wall_sequence — 모델 형상 기반
  • + seam_position, seam_slope_*, scarf_angle_threshold, override_filament_scarf_seam_setting — seam 전략
  • + outer_wall_speed, inner_wall_speed — 소재별
  • + enable_arc_fitting — 원통 모델
  • + 멀티컬러: enable_prime_tower, prime_tower_width/brim_width/flat_ironing, flush_into_*
  • + enable_support, raft_layers
↗ Codex run aab7cad186e9523af (멀티컬러 필드)
F

Filament JSON — Override 대상 (좁다)

Scarf Only

seam-recipes.md에서 결정된 scarf 필드만 override한다. 그 외는 base profile에 위임.

Override 허용

  • + filament_scarf_seam_type (none/external/all)
  • + filament_scarf_height, filament_scarf_gap, filament_scarf_length

절대 안 건드림 (DO NOT touch)

  • × nozzle_temperature, nozzle_temperature_initial_layer
  • × retraction / fan / cooling 관련 모든 필드

사용자 명시 요청 (2026-05-16): .3mf creator 튜닝 값 또는 base profile 기본값을 유지한다.

↗ Codex run a06a8ac153247d901 (wipe_on_loops 부재 검증)
Seam 전략 결정 트리

모델 형상이 seam 전략의 1차 결정 인자다. seam-recipes.md의 형상×소재 매트릭스 + Real-world findings에서 도출. PETG HF + entire_loop 콤보는 stringing에 민감하므로 사전/연속 건조 필수.

회전체/원기둥 (전방향 노출)?
  YES → seam_position: random + seam_slope_type: external + seam_slope_entire_loop: 1
        + seam_slope_inner_walls: 0     # 내벽 scarf 불필요 — 안 보이는 곳
        + wall_sequence: inner-outer-inner wall
        + 소재별 scarf 파라미터:
            PETG  → gap 8%  / length 12
            PLA   → gap 10% / length 20

  NO  → 형상 분기:
       박스/직육면체    → seam_position: back    + 일반 seam (scarf 짧게 또는 none)
       유기적/피규어    → seam_position: aligned + painted seam 가이드 (Studio UI)
       얇은 벽/미세    → seam_position: aligned + scarf length 짧게 (5-10mm)
경고 — PETG HF + entire_loop: seam-recipes.md Finding 4 참조. stringing이 발생하면 거의 확실히 필라멘트 흡습이 원인이다. 사용자에게 AMS HT 65°C 8h 사전 건조 + continuous drying 필수임을 강조한다. 실측 H2D Vent Pipe 케이스에서 동일 패턴 재현됨.
Gotcha 자기 검증 체크리스트 (생성 직후 7항)

JSON 생성 직후 사용자에게 zip을 넘기기 전에 7항을 self-verify한다. 한 항이라도 실패하면 그 자리에서 수정. silent skip은 사용자가 Studio에서 import한 뒤에야 발견되므로 비용이 크다.

  • 1
    version이 "2.6.0.2" (또는 현재 Bambu Studio 버전 매칭). semver parseable이어야 함.
  • 2
    from이 "User" (대문자 U). 소문자 "user"는 실패한다.
  • 3
    print_settings_id / filament_settings_id 존재. filament은 배열 형태 (["..."]).
  • 4
    inherits가 시스템 프리셋에 실제 존재. 필요 시 셸 검증: ls ~/Library/Application\ Support/BambuStudio/system/BBL/{process,filament,machine}/ | grep
  • 5
    compatible_printers에 H2S 명시 ("Bambu Lab H2S 0.4 nozzle").
  • 6
    filament JSON의 scarf 필드는 모두 배열 (["..."]). 스칼라로 두면 silent skip.
  • 7
    nozzle_temperature 등 사용자 영역 필드 안 건드렸는지. 무심코 base 값을 복사해 넣지 말 것.
