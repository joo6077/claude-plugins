Failure Recipes — 실측 실패를 프로파일 키로 되돌린다

실물을 출력했고 실패했을 때 그 실패 표현(“곡면이 계단처럼 보인다”, “실이 늘어진다”, “바닥이 떴다”)을 Bambu Studio process / filament 키로 역매핑하는 사후 레시피. Surface Recipes 가 사전 정책이라면 이 문서는 사후 대응이다. 키 이름 · 단위 · default 의 정본은 Fields Baseline §10 이며 이 문서는 판정 절차 · 게이트 순서 · 권장 방향 · 부작용 · 금지만 갖는다.

Last updated 2026-08-13 카이젠 Phase 13 evidence Bambu Studio 2.6.0 (v02.06.00.51) 실패 모드 L1 · L2 · L3 Codex foreground · read-only
Section 0 — 이 문서의 위치 · 실패 모드 3종

surface-recipes.md 는 사용자가 처음부터 표면을 원할 때 쓰는 사전 정책이다. 이 문서는 반대 방향 — 이미 출력했고 실패한 결과물을 손에 든 상태에서 시작한다. 두 문서는 같은 키를 다루지만 진입 조건이 다르다.

BAD — 수치를 두 문서에 중복 기재
  • 이 문서에도 brim_width default 5 를 적어 둔다
  • Fields Baseline §10 에도 같은 값이 있다
  • Bambu 가 default 를 바꾸면 한쪽만 고쳐진다
  • 생성 JSON 에 틀린 값이 박힌 채 사용자에게 나간다
선례: xy_hole_compensation 2× 오해 (tolerance.md §1.1). 중복 기재는 정정 사이클을 반드시 반쪽으로 만든다.
GOOD — SSOT 분리
  • 키 이름 · 단위 · default → Fields Baseline §10 단독
  • 판정 절차 · 게이트 순서 · 부작용 · 금지 → 이 문서 단독
  • 이 문서는 값이 필요하면 §10.x 를 참조만 한다
  • 정정이 한 곳에서 끝난다
이 페이지에 숫자가 보이면 그것은 방향(하향/상향)과 범위이지 default 사본이 아니다.

Section 1 — 사용자 실측 실패 보고의 취급

규칙 정본은 harness/docs/guides/skill-design-guide.md §3.8 User-Reported Failure Gate 다. 요지만 인용한다: 사용자 관측은 반증 대상이 아니라 재현 대상이고, 상태는 PASS 가 아니라 REOPENED 이며, 재현 전에 “정상입니다” 를 다시 말하지 않는다. 이 문서가 단독으로 갖는 것은 §3.8 의 재현 6 축을 3D 프린팅 도메인으로 치환한 대응표뿐이다.

Section 2 — L1 곡면 계단현상 (curved surface stair-stepping)

계단현상의 가장 직관적인 대응은 “레이어를 얇게” 지만, 자동화 관점에서 가장 먼저 확인해야 하는 것은 무엇이 이 스킬의 산출물 범위 밖인가다. variable / adaptive layer height 는 범위 밖이며, 조용히 생략하지 말고 명시 보고한다.

Section 3 — L2 스트링잉 (voronoi 인필 · travel stringing)

L2 의 지배 변수는 프로파일이 아니라 습도다. 커뮤니티 사례는 PETG/stringing 에서 “retraction 기본값이면 충분, 건조가 우선” 이라는 답과, 다중 retraction 파트에서 wipe-while-retract 및 노즐 온도 −5~−10 °C 가 도움 된다는 보고가 같이 존재한다. 그래서 게이트가 필요하다.

3.1. 진단 게이트 — 건조가 먼저다

L2 감지
  │
  ├─ (0) 소재 상태 확인 — 이 단계에서 대부분 끝난다
  │      · AMS HT 건조 이력 (소재별 시간/온도는 materials.md)
  │      · 스풀 개봉 시점 / 보관 상태
  │      · 같은 스풀로 다른 모델에서도 났는가
  │      → 건조 미충족이면 JSON 변경 없이 건조 후 재출력 권고로 종료
  │
  ├─ (1) 건조 충족인데도 travel stringing → filament wipe 만 opt-in
  │      filament_wipe = 1 · filament_wipe_distance = 2 (기본값 §10.2)
  │      → 이 2 키가 L2 의 유일한 무조건 허용 override 다
  │
  └─ (2) (1) 로도 남으면 retraction 소량 상향 — coupon 통과 후에만
         filament_retraction_length 를 기준값(§10.2)에서 1.0–1.2 까지만
         → Phase 5 coupon 으로 검증한 뒤 본 출력에 반영
“nil” 은 미설정이 아니다. 공통 filament profile 기본은 대체로 "nil" 이고, 이는 printer / extruder 기본에 위임된 상태다. "nil" 을 “설정 안 됨” 으로 읽고 임의 숫자로 채우면 프린터 기본 튜닝을 통째로 덮어쓴다. 위임 상태의 실효값은 Fields Baseline §10.2 의 underlying default 열을 본다.

Section 4 — L3 바닥 박리 · 첫 레이어 들림 · warping

L3 는 3종 중 가장 먼저 처리한다 (Section 6). 첫 레이어가 안 붙으면 나머지 관측은 신뢰할 수 없기 때문이다. process JSON 자동 대응의 1 순위는 brim 이고, 첫 레이어 보강은 바닥면 품질을 포기할 수 있을 때만 조건부다.

4.1. process JSON 자동 대응 — brim 우선

키값비고
brim_typeouter_only 또는 auto_brimenum 전체 · default 는 Fields Baseline §10.3
brim_width5–8fdm_process_common 기본과의 차이는 §10.3
brim_object_gap0–0.1ASA / ABS / PC 는 0 (접착 우선)
첫 레이어 보강은 조건부다. initial_layer_print_height 상향 · initial_layer_line_width 상향 · initial_layer_speed 하향은 사용자가 바닥면 품질을 포기할 수 있을 때만. 두꺼운 첫 레이어가 adhesion 을 개선할 수 있다는 것은 source tooltip 근거가 있다 (§10.3). 단 H2S standard 의 initial_layer_speed 는 source/common 보다 높게 잡혀 있으므로 “기본값보다 낮춘다” 를 계산 없이 말하지 마라 — 상속 체인의 실효값을 먼저 확인한다.

Section 6 — 3 종 동시 보고 시 우선순위

실측에서는 3 종이 한 출력에서 같이 나온다. 순서를 지켜라 — 뒤 항목부터 만지면 앞 항목이 원인일 때 증거가 오염된다.

1. L3 먼저  — 첫 레이어가 안 붙으면 나머지 관측은 전부 신뢰할 수 없다
      │
2. L2 다음  — 건조 문제면 L1 튜닝(느린 외벽 · 낮은 layer)이 stringing 을 더 키운다
      │        (surface-recipes.md §6.5 PETG HF 경고와 같은 구조)
      │
3. L1 마지막 — 시간 비용이 가장 크고, 위 둘이 원인이면 효과가 없다
      │
4. L2 ∧ L3 동시 — fan 방향이 상충한다 (§4.3). 어느 쪽을 우선할지 사용자에게 명시적으로 물어라
순서 1

L3 — 관측 신뢰성 확보

바닥이 떠 있으면 그 위 모든 레이어가 왜곡된다. 계단현상처럼 보이는 것이 실제로는 박리로 인한 층 밀림일 수 있다. brim 부터 잡고 재출력해야 L1/L2 관측이 유효해진다.
fdm_process_common.json — brim default
순서 2

L2 — 건조 게이트

L1 대응(외벽 감속 · 얇은 layer)은 노즐 체류 시간을 늘려 stringing 을 악화시킨다. 습한 소재 상태를 먼저 배제하지 않으면 L1 튜닝이 L2 를 키우는 역효과가 난다.
Surface Recipes §6.5 — 속도 무시 부작용
순서 3

L1 — 마지막, 가장 비싸다

0.20 → 0.12 만으로 레이어 수가 약 1.67 배다. 앞의 두 원인을 배제하지 않은 채 여기부터 손대면 시간만 쓰고 증상이 남는다.

Section 8 — Gotchas 체크리스트 + 출처

L1 / L2 / L3 대응 시 자주 빠지는 함정. 프로파일을 생성하기 전에 전부 통과했는지 확인한다.

  • ✓수치를 이 문서에 적지 않는다 — 키 이름 · 단위 · default 는 Fields Baseline §10 이 정본. 중복 기재하면 한쪽만 고쳐진다.
  • ✓재현 6 축을 먼저 대조한다 — 모델 리비전 / preset 이름 / 슬라이서 버전 / plate·chamber / 소재 lot·건조 / AMS 슬롯. 하나라도 다르면 키를 만지기 전에 보고.
  • ✓adaptive_layer_height 를 JSON 에 넣지 않는다 — 켜진다는 근거가 없다. 대신 notes.md §1.2 에 “UI 직접 적용” 을 명시한다 (조용한 생략 금지).
  • ✓0.08 을 자동으로 밀어넣지 않는다 — H2S 공식 process 프로파일 근거는 [미확인]. 0.12 가 1 차값이고, 레이어 수 배수를 고지한 뒤 사용자 선택을 받는다.
  • ✓enable_arc_fitting 을 계단 대응 카드로 제시하지 않는다 — 품질 기능이 아니라 G-code encoding 변경이며 firmware arc segmentation 리스크가 있다.
  • ✓resolution 을 Z 계단 해결책으로 말하지 않는다 — XY 세그먼트 해상도 전용이다.
  • ✓L2 는 건조부터 — 게이트 (0) 을 통과하지 않으면 JSON 을 변경하지 않는다. filament_wipe · filament_wipe_distance 만 무조건 허용 override.
  • ✓"nil" 을 임의 숫자로 채우지 않는다 — 위임 상태이며, 채우면 프린터 기본 튜닝을 덮어쓴다.
  • ✓온도를 건드리지 않는다 — nozzle_temperature* 자동 하향 금지 (사용자 명시 요청 2026-05-16).
  • ✓raft_layers > 0 과 elefant_foot_compensation 을 같이 쓰지 않는다 — 공차 보정이 조용히 무효화된다.
  • ✓plate 온도는 plate-specific 키로만 — bed_temperature* 는 게이트 금지 목록이다.
  • ✓순서는 L3 → L2 → L1 — 역순으로 만지면 증거가 오염된다. L2 ∧ L3 동시면 fan 방향 상충을 먼저 알린다.
