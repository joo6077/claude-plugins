플러그인 검증 가이드

scripts/validate-plugin.py 의 8-카테고리 자동 검증. 릴리스 전 품질 게이트 + 카이젠 베이스라인을 제공하며, 7개 킷 전체의 스킬 · 에이전트 · 템플릿 · 훅 무결성을 보장한다.

1 · 목적 · 적용 범위

플러그인 모노레포는 7개 킷, 100여 개 스킬, 10여 개 에이전트로 구성된다. 킷 수가 늘어날수록 다음 문제가 발생한다.

자동 탐지 대상 5종

  • 숨은 깨진 링크 — SKILL.md 가 references/xxx.md 참조하나 파일 없음
  • Frontmatter 누락 — name/description 없어 Claude 가 스킬 미인식
  • 트리거 중복 — 두 킷이 동일 키워드 선언 → 의도치 않은 스킬 실행
  • Placeholder 노출 — TODO · TBD · FIXME 사용자에게 노출
  • 버전 불일치 — plugin.json vs marketplace.json 태그 diff

적용 범위

.claude-plugin/plugin.json 을 가진 모든 디렉토리. 현재 7개 킷:

harness/          flutter-toolkit/
design-kit/       backend-kit/
infra-kit/        rust-kit/
react-kit/

킷 목록은 .claude-plugin/marketplace.json plugins 배열에서 자동 읽기. 새 킷 등록 시 자동 포함.

2 · 실행 명령

모든 킷 전수 또는 특정 킷/체크만 선택 실행. CI 파이프라인에는 --json 출력 사용.

# 전체 킷 검증
python3 scripts/validate-plugin.py

# 특정 킷만
python3 scripts/validate-plugin.py react-kit

# 특정 체크만 (쉼표 구분)
python3 scripts/validate-plugin.py --check=frontmatter,refs

# JSON 출력 (CI 파이프라인용)
python3 scripts/validate-plugin.py --json

# 자동 수정 (V5 placeholders + V6 code-fence)
python3 scripts/validate-plugin.py --fix
3 · V1 ~ V8 검증 카테고리

8가지 카테고리. 각 카테고리는 PASS / WARNING / FAIL 판정 + 구체적 라인 번호를 보고한다.

V1
Frontmatter 무결성
SKILL.md — name · description · user-invocable. 에이전트 — name · description · tools · model. YAML 파싱 성공 + 필수 필드 존재.
V2
Templates 구문
templates/ 내 JSON · YAML · TOML 파서 검증. .ts/.js 는 외부 도구 의존으로 SKIP. .template 확장자는 내부 확장자로 판별.
V3
Cross-reference 링크
SKILL.md 마크다운 링크 [text](path) 가 실제 파일로 해소. 절대 URL · 앵커 · <!-- novalidate --> 주석은 제외.
V4
Trigger 키워드
description 의 따옴표 키워드 추출. 킷 간 exact-match 중복 시 WARNING. KIT_CONTEXT_TOKENS 로 "flutter"/"react" 같은 kit-specific 단어 있으면 disambiguation.
V5
Placeholders
TODO · TBD · FIXME 0건. 단어 경계(\b) 기준 대소문자 무관 매칭. --fix 로 중립 주석 자동 교체.
V6
Code fence 언어 힌트
여는 fence (```) 뒤 언어 힌트 필수. 상태 머신으로 in_block 추적. --fix 로 ```text 자동 보강.
V7
plugin.json ↔ marketplace.json 정합성
name · version 일치 + marketplace description 의 [vX.Y.Z · YYYY-MM-DD] 태그가 plugin.json 버전과 일치. 정규식 \[v(\d+\.\d+\.\d+)\s*·\s*\d{4}-\d{2}-\d{2}\] 로 추출.
V8
Hook 스크립트 실행 비트
hooks/hooks.json 이 인터프리터 없이 직접 실행하는 ${CLAUDE_PLUGIN_ROOT}/x.sh 스크립트가 실행 비트(mode 0755)를 가지는지 검증. git 이 추적하는 파일 모드가 100644(비실행)이면 marketplace clone · plugin cache 등 모든 설치본에서 hook 이 Permission denied 로 실패한다. bash · sh · source 경유 호출은 읽기 권한만 필요하므로 V8 대상에서 제외. hooks.json 없는 킷 또는 직접 실행 참조 0건이면 OK.

V1 · V3 설계 근거

Frontmatter 와 링크 무결성은 Claude 플러그인 로딩의 최소 전제. 스킬 로더가 YAML 파싱 실패 시 전체 스킬 미로드.

docs.anthropic.com · Claude Code Plugins

V4 Context Disambiguation

"테스트 만들어줘" 같은 공통 키워드가 여러 킷에서 겹쳐도, description 에 kit-specific 단어(Flutter/React/Rust)가 있으면 disambiguation 성공.

docs.anthropic.com · Claude Skills

V8 회귀 방지 근거

2026-06 reflect 30일 집계에서 hook permission-denied 가 24개 프로젝트 957건(전체 friction 의 38%)으로 단일 최대 마찰원. 100644 로 커밋된 직접 실행 스크립트가 전 설치본에 누적 실패를 일으켰다.

plugin-validation-guide.md §3.8

V7 릴리스 태깅

scripts/release.sh 가 plugin.json 버전 bump + marketplace.json description 의 [vX.Y.Z · 날짜] 태그 자동 갱신. 수동 수정은 V7 FAIL 위험.

semver.org · SemVer 2.0

V8 직접 실행 vs 경유

${CLAUDE_PLUGIN_ROOT}/x.sh 가 command 첫 토큰이면 직접 실행 → exec 비트 필수. bash ${CLAUDE_PLUGIN_ROOT}/x.sh 처럼 인터프리터가 앞서면 PASS.

docs.anthropic.com · Claude Code Hooks

V8 수정 흐름

chmod +x <script> 후 커밋하면 git mode 가 100755 로 추적된다. release.sh 로 새 버전을 배포해야 기존 설치본 cache 가 갱신된다.

7 · 자동 수정 · 수동 수정

--fix 는 V5 · V6 만 안전 수정. 나머지는 파일 삭제/링크 재배선 같은 의미 분석이 필요하므로 수동.

자동 수정 (--fix)

체크동작
V5TODO: → <설명 필요>
TBD → <내용 추가>
FIXME: → <수정 필요>
V6빈 ``` → ```text

수동 수정

  • V1 — frontmatter 누락 필드 추가
  • V2 — templates/ JSON/YAML/TOML 구문 오류
  • V3 — 참조 파일 생성 또는 링크 경로 수정
  • V4 — description 중복 키워드 제거 또는 구체화
  • V7 — plugin.json 또는 marketplace.json 버전 태그
  • V8 — chmod +x <script> 후 커밋 (git mode 100755)

카이젠 위임 기준

다음 경우 해당 킷의 *-kaizen 스킬로 위임:

  • ✓
    V3 FAIL 3건 이상 — 참조 구조 재설계 수준
  • ✓
    V4 중복 5건 이상 — 킷 간 트리거 키워드 체계 재정의 필요
  • ✓
    V1 FAIL 3건 이상 — 스킬 템플릿 자체가 잘못된 경우
8 · 카이젠 연동 — SSOT

이 가이드 §7(원본) 은 9개 카이젠 스킬의 "Plugin Validation 결과 반영" 단계의 SSOT. 각 카이젠 스킬은 킷 특화 규칙만 로컬에 유지하고, 공통 규칙은 이 가이드를 참조한다.

실행 패턴

# 세션 시작 — 현재 상태
python3 scripts/validate-plugin.py <kit>

# 자동 수정 (V5 + V6)
python3 scripts/validate-plugin.py <kit> \
  --fix --check=placeholders,code-fence

# 세션 종료 — 회귀 없음 확인
python3 scripts/validate-plugin.py <kit>

우선순위 매핑

결과처리
ERROR개선 우선순위 높음. 이 세션에서 반드시 수정
WARNING우선순위 중간. description 보강으로 해소 권장
PASSskip. 변경으로 FAIL 생기지 않도록 주의
9 · 킷별 예외 카탈로그

templates/ 없는 킷은 V2 전체 SKIP. TS/JS 파일은 외부 도구(tsc) 의존으로 V2 SKIP.

킷V2 templates비고
harnesstemplates/ 없음 — SKIPQA 프레임워크. 코드 템플릿 대상 아님
flutter-toolkittemplates/ 없음 — SKIP스킬 지시문 기반. 별도 템플릿 파일 없음
design-kittemplates/ 없음 — SKIP디자인 가이드 중심. 코드 템플릿 없음
backend-kittemplates/ 없음 — SKIP스택 무관 가이드
infra-kittemplates/ 없음 — SKIP스택 무관 가이드
rust-kittemplates/ 없음 — SKIP스킬에서 인라인 생성. 향후 templates/ 추가 가능
react-kittemplates/ 9 파일 — TS 4개 SKIP, 5개 파싱.ts/.js 4개 SKIP, Cargo.toml.template 등 5개 파싱
10 · Gotchas 체크리스트

validate-plugin 실행 전/후에 확인할 항목.

  • ✓
    커밋 전 전수 실행 — python3 scripts/validate-plugin.py PASS 확인. CI 보다 먼저.
  • ✓
    --fix 우선 — V5 · V6 자동 수정으로 쉬운 오류 제거 → 남은 FAIL 집중.
  • ✓
    새 킷 등록 순서 — marketplace.json 등록 → plugin.json 생성 → SKILL.md 작성 → validate 확인.
  • ✓
    V3 링크 상대경로 — SKILL.md 위치 기준. 절대 경로 · 프로젝트 root 기준 금지.
  • ✓
    V4 context disambiguation — "테스트 만들어줘" 처럼 공통 키워드는 "Flutter"/"React" 같은 kit-specific 단어 description 에 포함.
  • ✓
    V7 릴리스 흐름 — scripts/release.sh 가 plugin.json + marketplace.json 동시 업데이트. 수동 수정 지양.
  • ✓
    V8 hook 실행 비트 — 직접 실행 .sh 추가 시 chmod +x 후 커밋. git mode 100755 확인. 누락 시 전 설치본에서 Permission denied.
  • ✓
    카이젠 세션 시작/종료 필수 — 세션 시작 시 현재 상태 파악, 종료 시 회귀 없음 확인.
  • ✓
    Exit code 2 차단 — CI 에서 exit 2 를 빌드 실패로 처리. WARN(1) 은 통과시킬지 팀 정책.
  • ✓
    V1 frontmatter 즉시 수정 — 1줄 수정이므로 발견 즉시 처리. 카이젠 위임 대상 아님.
  • ✓
    novalidate 주석 제한 — <!-- novalidate --> 는 의도적 미해소 링크에만. 남용 시 V3 가치 상실.
  • ✓
    JSON 출력 스키마 — CI 통합 시 --json 출력 포맷 버전 고정 확인.
