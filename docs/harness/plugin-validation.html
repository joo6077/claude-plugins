1 · 목적

플러그인 모노레포는 여러 킷과 100여 개 스킬, 10여 개 에이전트로 이뤄진다. 킷이 늘수록 아래 다섯 문제가 생긴다. 이 문서는 그 문제를 자동으로 찾는 검사 10 종을 정하고, 검사마다 기준 · 방법 · 예외 · FAIL 예시를 적는다. 카이젠 주기마다 이 문서를 기준으로 전체 킷을 점검해 품질이 떨어지는 것을 막는다.

5 · V8 Hook 스크립트 실행 비트

hooks/hooks.json 이 인터프리터 없이 직접 실행하는 .sh 스크립트("command": "${CLAUDE_PLUGIN_ROOT}/scripts/x.sh")가 실행 비트(mode 0755)를 가지는지 본다. git 은 파일 모드를 추적하므로, 스크립트가 100644(비실행)로 커밋되면 marketplace clone · 플러그인 설치본 등 모든 설치본에서 그 훅이 Permission denied 로 실패한다.

왜 중요한가

2026-06 reflect 로그 30 일 집계에서 훅 permission-denied 계열이 24 개 프로젝트 957 건(전체 마찰의 38%)으로 가장 큰 마찰 하나였다. 원인은 harness/scripts/{env-check,run-guard,sdk-guard}.sh 와 design-kit/scripts/env-check.sh 4 종이 100644 로 커밋된 것이었다. SessionStart · PreToolUse 훅은 매 세션 · 매 Bash 호출마다 돌아, 비실행 스크립트 하나가 전 프로젝트에 실패를 쌓는다.

code.claude.com · Hooks

직접 실행 vs 인터프리터 경유

${CLAUDE_PLUGIN_ROOT}/x.sh 가 명령의 첫 토막이면 직접 실행이라 실행 비트가 꼭 있어야 한다. bash ${CLAUDE_PLUGIN_ROOT}/x.sh 처럼 인터프리터(bash · sh · source)가 앞서면 읽기 권한만 있으면 되므로 V8 대상이 아니다 — reflect-kit 의 log-prompt.sh 는 bash 경유라 PASS.

고치는 흐름

chmod +x <script> 후 커밋하면 git 이 모드를 100755 로 추적한다. 기존 설치본에 남은 옛 사본은 release.sh 로 새 버전을 배포해야 바뀐다.

6 · V9 스킬 본문의 인자 치환 위험

무엇을 · 어떻게 판정하나

  • 검사 이름 — arg-substitution (--check=arg-substitution)
  • 대상 — 각 킷의 skills/*/SKILL.md
  • 판정 — 이스케이프하지 않은 $ + 숫자가 1 건이라도 있으면 FAIL. 파일:줄과 고치는 법을 함께 출력한다
  • --fix 없음 — awk 인지 bash 인지 판단이 필요해 자동으로 바꾸면 위험하다

왜

Claude Code 는 스킬 본문의 $N 을 $ARGUMENTS[N] 으로 바꿔 넣는다. 인자와 함께 부르면 본문 코드의 $0 · $1 이 그 순번(0 부터)에 들어온 인자 낱말로 바뀌어 awk · 셸 스니펫이 깨진 채 로드된다.

고치는 법 — 자리마다 다르다

자리이렇게 쓴다주의
awk 필드$(0) · $(2)awk 에서 괄호형은 같은 필드 참조다
bash 위치 인자 · 스크립트 이름${1} · ${0}$(0) 을 순수 bash 에 쓰면 명령 치환이라 0: command not found 로 깨진다
데이터베이스 질의문의 자리표시자처럼 문법상 $ + 숫자여야 하는 곳역슬래시로 이스케이프로드할 때 역슬래시가 빠져 Claude 는 원래 형태를 본다

고친 뒤 실행으로 확인한다. $ + 숫자 0 건은 「형태만 바꾼 오류」($(1) 을 bash 에 쓴 경우)를 못 잡는다. 고친 함수를 실제로 한 번 실행해 같은 결과가 나오는지 본다.

어떻게 — 고립 행 판정

표 행(| 로 시작) 가운데 바로 위가 표 행이 아니고, 바로 아래도 헤더 구분선(| 로 시작하고 파이프 · 붙임표 · 콜론 · 공백만으로 이뤄진 줄)이 아닌 행을 고립으로 본다. 정상 표는 헤더 행 다음에 구분선이 오므로 걸리지 않는다.

표 행은 왼쪽 공백을 벗겨서 판정한다. 표는 목록 · 인용 안에서 들여쓰여 쓰이고, 왼쪽 끝만 보면 그것이 전부 검사에서 빠진다.

13 · 카이젠 연동 (원본 §7)

각 킷의 카이젠 스킬(*-kaizen)이 이 문서를 비교 기준으로 쓴다. 원본 §7 이 카이젠 스킬마다 있는 「Plugin Validation 결과 반영」 단계의 기준 원본이다. 카이젠 스킬은 킷에만 해당하는 규칙만 자기 파일에 두고, 공통 규칙은 이 절을 따른다.

§7.1 실행 패턴 — 시작과 끝 둘 다

# 세션 시작 시 현재 상태 파악
python3 scripts/validate-plugin.py <kit-name>

# 자동 수정 가능한 항목 먼저 (V5 placeholders, V6 code-fence)
python3 scripts/validate-plugin.py <kit-name> --fix --check=placeholders,code-fence

# 세션 종료 시 다시 망가진 것 없는지 확인
python3 scripts/validate-plugin.py <kit-name>

§7.2 우선순위 매핑

결과의미처리
ERROR (FAIL)V1 ~ V10 중 하나 이상 실패개선 우선순위 「높음」 에 자동으로 들어간다. 이 세션에서 반드시 고친다
WARNINGV4 트리거 키워드 겹침 등우선순위 「중간」. description 을 보강해 없애기를 권한다
PASS모든 검사 통과그 항목은 건너뛴다. 이번 변경으로 FAIL 이 생기지 않게 주의

§7.3 통합 규칙

  • --fix 자동 모드는 V5 placeholders 와 V6 code-fence 만 고친다. 다른 검사는 손으로 고친다
  • V3 refs BROKEN 은 링크 경로나 참조 파일을 손으로 확인한 뒤 고친다
  • V1 frontmatter 누락은 한 줄 수정이라 바로 고친다
  • V7 plugin-json 불일치가 릴리스 흐름 문제라면 카이젠이 아니라 scripts/release.sh (릴리스 스킬)에서 다룬다

§7.4 카이젠 스킬이 이 문서를 가리키는 방식

카이젠 스킬의 「Step N: Plugin Validation 결과 반영」 절은 아래 형식을 따른다. 킷에만 해당하는 규칙(예외 동작, Library Policy 원칙 등)만 스킬 파일에 남긴다.

카이젠 세션 시작/종료 시 `scripts/validate-plugin.py <kit-name>` 을 실행하여
전 카테고리 상태를 확인하고 결과를 개선 우선순위에 반영한다.

**실행 패턴, 우선순위 매핑, 통합 규칙**은
`harness/docs/guides/plugin-validation-guide.md §7` 에서 정의한다 (SSOT).

§7.5 이 문서를 고치는 때

  • 새 킷을 더하면 — 킷별 예외 카탈로그(원본 §6)에 더한다
  • 새 검사를 들이면 — V11 부터의 번호로 원본 §3 에 더한다 (V10 까지는 이미 쓰였다)
  • 기존 검사 기준을 바꾸면 — 그 V 번호 절을 고치고 last_updated 를 갱신한다
  • 통합 규칙을 바꾸면 — §7.3 을 고친다

이 문서 갱신은 harness-kaizen 스킬이 맡는다.

  • ✓새 킷은 marketplace.json 에 먼저 등록 — 등록해야 검사 목록에 들어간다. 등록 전 킷은 V7 을 포함해 아무 검사도 받지 않는다.
  • ✓V1 은 발견 즉시 — 한 줄 수정이다. 3 건 이상이면 스킬 템플릿을 의심하고 카이젠으로 넘긴다.
  • ✓V3 링크는 SKILL.md 위치 기준 — 그 파일이 있는 자리에서 경로를 풀어 찾는다. <!-- novalidate --> 는 일부러 잇지 않는 링크에만 단다.
  • ✓V4 공통 키워드엔 킷 낱말을 — 「테스트 만들어줘」 처럼 여러 킷이 쓰는 말은 description 에 Flutter · React 같은 킷 고유 낱말을 함께 적는다.
  • ✓V7 은 릴리스 흐름에서 — scripts/release.sh 가 plugin.json 과 marketplace.json 을 같이 올린다. 손으로 한쪽만 고치면 V7 FAIL 이 난다.
  • ✓V8 직접 실행 .sh 는 chmod +x 후 커밋 — git 모드 100755 를 확인한다. 빠지면 모든 설치본에서 Permission denied.
