Model
모델 선택 전략

Patterns
6가지 에이전트 디자인 패턴

Anthropic이 식별한 핵심 패턴. 에이전트를 설계할 때 이 중 하나를 기반으로 한다.

Pattern 1
프롬프트 체이닝
LLM A → Gate → LLM B → 결과
순차 단계 + 중간 검증 게이트. 정확도가 중요한 작업.
Pattern 2
라우팅
입력 → 분류기 → 전문가 A/B/C
이질적인 요청을 전문 핸들러로 분배.
Pattern 3
병렬화
입력 → [A | B | C] → 합성
독립적 하위 작업을 동시 실행.
Pattern 4
오케스트레이터-워커
오케스트레이터 → 동적 분해 → 워커들
하위 작업이 사전 정의되지 않고 동적 결정.
Pattern 5
평가자-최적화자
생성 LLM ↔ 평가 LLM (반복)
명확한 평가 기준 + 반복 개선. qa-evaluator가 이 패턴.
Pattern 6
계획-실행 분리
계획 에이전트 → 실행 에이전트
계획(Read only)과 실행(Edit/Write)을 분리하여 안전성 확보.
Gotchas
에이전트에서 반복되는 실수
  • × 서브에이전트는 다른 서브에이전트를 생성할 수 없다 — 중첩 위임 불가
  • × 플러그인 에이전트는 hooks, mcpServers, permissionMode 미지원
  • × 과도한 병렬화는 토큰 낭비 — 관련 작업을 묶어라
  • × 순차 체이닝에서 이전 결과를 다음 에이전트에 전달하지 않으면 의존성 체인 붕괴
  • × 백그라운드 에이전트는 사용자에게 질문 불가 — 권한 미리 승인
  • × 많은 에이전트가 상세 결과를 반환하면 메인 컨텍스트 빠르게 소진
Summary
핵심 원칙 요약
  • ✓ 단순함 우선 — 스킬로 충분하면 에이전트 불필요
  • ✓ description은 트리거 — "언제 위임할지" 구체적 명시
  • ✓ 최소 권한 — 필요한 도구만 부여
  • ✓ 모델 최적화 — 작업 복잡도에 맞는 모델 선택
  • ✓ 호출 품질 — 컨텍스트, 범위, 파일참조, 성공기준
  • ✓ 독립 컨텍스트 — 생성과 평가는 분리
  • ✓ 영속 메모리 — 대화를 넘어서 학습시켜라
  • ✓ 6가지 패턴 — 작업에 맞는 패턴 선택
