Overview
피드백 시스템 개요

매번 sprint-contract 와 qa-evaluator 가 실행될 때마다 결과 + 자가진단 + 교차진단을 YAML 파일로 글로벌 저장한다. 피드백은 카이젠 (harness/contract/evaluator-kaizen) 의 입력으로 소비된다.

sprint-contract 실행 → 자기진단 → 교차진단 (qa-evaluator) → YAML 저장 → 카이젠 입력
저장 위치
~/.harness/feedback/ └── {project_hash}-{timestamp}.yaml

프로젝트 경로 SHA-256 앞 8자 + ISO-8601 타임스탬프. save-feedback.sh 가 스키마 검증 후 저장.

저장 보존 정책

최근 6 개월 + 최대 500 건. 글로벌 피드백이 무한 누적되면 카이젠 입력 토큰이 과부하되므로, 오래된 피드백은 자동 정리된다.

Skill-Specific
스킬별 전용 필드 (contract / evaluator)

실행한 스킬에 따라 전용 필드가 추가된다. contract 는 sprint-contract 에서, evaluation 은 qa-evaluator 에서 사용.

contract 필드 (sprint-contract)
contract: condition_count: 8 category_count: 4 category_coverage: 0.8 anti_pattern_count: 3 complexity: medium

category_coverage 는 0.0~1.0 (project.yaml 카테고리 대비 비율). anti_pattern_count 는 최소 2.

evaluation 필드 (qa-evaluator)
evaluation: verdict: APPROVE # or REJECT / BLOCKED conditions_total: 10 conditions_passed: 9 l3_coverage: 0.95 reject_reasons: - "DG-02 fenced fence 누락"

l3_coverage 는 L3 검증 도달 비율. REJECT 시 사유 목록 필수.

Diagnosis
자기진단 + 교차진단 — diagnosis 필드

실행 후 자가 점검 (checklist) + 교차 진단 (cross_diagnosis) 결과가 모두 저장된다. 카이젠은 이 데이터를 분석해 가이드 문서를 개선한다.

sprint-contract checklist
diagnosis: checklist: ambiguous_conditions: false missing_error_paths: true untestable_conditions: false category_coverage_gap: false complexity_underestimate: false

5 개 boolean 필드. 하나라도 true 면 다음 iteration 에서 개선 필요.

qa-evaluator checklist

교차진단 (cross_diagnosis)
diagnosis: cross_diagnosis_by: qa-evaluator # 또는 sprint-contract cross_diagnosis_notes: "조건 3번 경계값 누락 가능성" improvement_suggestions: - "에러 경로 조건을 별도 카테고리로 분리"

sprint-contract 를 실행했으면 qa-evaluator 가 교차진단, qa-evaluator 를 실행했으면 sprint-contract 가 교차진단. 각자의 시야 한계를 보완한다.

Phase 4 New Fields
누적 분석 필드 — repeat_count / first_seen_at / regression_link

Phase 4 카이젠의 핵심 추가. 2026 agentic regression detection 트렌드 (Sauce Labs, ContextQA, GrowthBook 의 "Feedback Loops are the Next Breakthrough in Agentic Coding") 에 맞춰 신설된 optional 필드. save-feedback.sh 의 required 리스트에는 포함되지 않으며, 없어도 검증 PASS.

repeat_count v1+

동일 diagnosis.checklist 시그니처가 글로벌 피드백에서 반복된 횟수. contract-kaizen / evaluator-kaizen 의 "최근 10건 중 3 회 이상" 임계치 판단에 사용.

repeat_count: 2 Sauce Labs Agentic Regression
first_seen_at v1+

동일 시그니처가 처음 발견된 타임스탬프. 만성 이슈 vs 신규 이슈 구분에 사용. 2 주 이상 지속되면 만성 이슈로 분류.

first_seen_at: "2026-03-28T09:15:00+09:00" ContextQA Agentic Testing
regression_link v1+

이전 APPROVE 피드백 파일명. APPROVE 후 같은 영역에서 다시 REJECT 발생 시 회귀 추적용. null 이면 회귀 아님.

regression_link: "a1b2c3d4-2026-04-10T120000.yaml" GrowthBook Feedback Loops

Common Mistakes
피드백 작성 안티패턴

save-feedback.sh 가 검증을 통과하더라도, 카이젠 입력으로는 쓸모없는 피드백이 발생할 수 있는 안티패턴.

Bad — 모호한 진단
diagnosis: checklist: ambiguous_conditions: false # ... 전부 false cross_diagnosis_by: qa-evaluator cross_diagnosis_notes: "OK" improvement_suggestions: []

모든 항목이 false + 빈 suggestions = 카이젠이 분석할 정보 없음. 진짜 OK 인지 점검을 안 했는지 구분 불가.

Good — 구체적 진단
diagnosis: checklist: ambiguous_conditions: false missing_error_paths: true untestable_conditions: false category_coverage_gap: false complexity_underestimate: false cross_diagnosis_by: qa-evaluator cross_diagnosis_notes: > UI-03 의 "사용자에게 적절히 표시" 가 모호. [goal] 태그 추가 권장. improvement_suggestions: - "에러 경로 카테고리 신설" - "UI-03 [goal] 태그 추가"

구체적 항목 + 인용 + 제안 ≥ 1.

Gotchas Checklist
피드백 시스템 운영 체크리스트

피드백 저장·소비 시 점검 항목.

  • ✓ save-feedback.sh 가 schema_version, timestamp, project_hash 등 7 개 필수 필드를 검증
  • ✓ project_hash 는 프로젝트 경로 SHA-256 앞 8자 — 여러 PC 에서 동일 프로젝트면 동일 해시
  • ✓ diagnosis.checklist 는 스킬별 고정 필드 (sprint-contract 5개, qa-evaluator 5개) — 임의 추가 금지
  • ✓ improvement_suggestions 가 빈 배열이면 카이젠 입력 가치 없음 — 최소 1 개 작성
  • ✓ Phase 4 누적 필드 repeat_count/first_seen_at/regression_link 는 optional 이지만 카이젠 효율을 크게 높임
  • ✓ regression_link 가 non-null 이면 동일 영역의 회귀 — 우선순위 높게 다룸
  • ✓ repeat_count ≥ 3 이면 만성 패턴 — 가이드 문서 갱신 필요
  • ✓ 글로벌 피드백 디렉토리 정리 정책: 최근 6 개월 + 최대 500 건
  • ✓ 사용자 시그널 (user_rating, user_comment) 은 optional 이지만 가이드 우선순위 가중에 사용
  • ✓ outcome: blocked 는 외부 차단 (네트워크, 도구 권한 등) — 스킬 자체 품질 문제 아님

Phase 4 Kaizen 변경 요약

Phase 4 에서 harness 의 피드백 시스템에 누적 분석 트랙이 추가되었다. 핵심 변경: ① repeat_count — 동일 진단 시그니처 반복 횟수, "최근 10 건 중 3 회 이상" 임계치 판단에 사용, ② first_seen_at — 첫 발견 타임스탬프, 만성 vs 신규 이슈 구분, ③ regression_link — 이전 APPROVE 피드백 파일명, 회귀 추적용. 세 필드 모두 optional 이며 save-feedback.sh 의 required 리스트에는 포함되지 않는다 (기존 피드백과 호환). harness-kaizen / contract-kaizen / evaluator-kaizen 의 Triage 단계가 이 필드를 소비해 우선순위를 매긴다. Phase 4 는 또한 글로벌 피드백 보존 정책 (6 개월 + 최대 500 건) 을 명문화하고, save-feedback.sh / verify-feedback.sh 스크립트의 동작을 schema 와 정합시켰다.
