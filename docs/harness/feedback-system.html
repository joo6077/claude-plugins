피드백 시스템

원본 제목: 피드백 스키마 v1

sprint-contract 와 qa-evaluator 가 실행을 마칠 때마다 남기는 피드백 파일의 모양이다. 키 41 개를 묶음별 표로 옮기고, 원본 예시와 전문을 함께 싣는다.

공통 필수 일곱

schema_version · timestamp · project_hash · project_name · skill · skill_version · outcome 은 모든 파일에 있어야 한다.

스킬별 필드

계약 쪽은 contract 에 조건 수 · 카테고리 · 복잡도를, 평가 쪽은 evaluation 에 판정 · 통과 수 · 반려 사유를 적는다.

true 는 문제

diagnosis.checklist 의 항목은 모두 true 가 「문제가 있다」 는 뜻이다. 카이젠이 되풀이 횟수를 셀 수 있게 뜻을 한쪽으로 맞췄다.

누적 분석

repeat_count · first_seen_at · regression_link 는 선택 필드다. 만성 문제와 회귀를 가려낼 때 쓴다.

§ 01

저장 흐름

sprint-contract 와 qa-evaluator 가 끝날 때마다 결과 · 자기진단 · 교차 진단을 YAML 파일 하나로 홈 폴더 아래 ~/.harness/feedback/ 에 저장한다. 카이젠(harness-kaizen · contract-kaizen · evaluator-kaizen)이 이 파일들을 읽어 가이드와 스킬을 고친다.

  • 1.
    스킬 실행 — sprint-contract 또는 qa-evaluator
  • 2.
    자기진단 — 스킬마다 정한 checklist 를 true · false 로 채운다
  • 3.
    교차 진단 — 다른 쪽 관점으로 되짚고 cross_diagnosis_by 에 누가 했는지 적는다
  • 4.
    저장 — bash harness/scripts/save-feedback.sh <contract|evaluator> <초안 파일> 이 스키마를 검사하고 저장한다
  • 5.
    검증 — bash harness/scripts/verify-feedback.sh <저장 경로> 가 PASS 를 내야 끝난다
  • 6.
    카이젠 입력 — 최근 피드백에서 같은 checklist 모양이 되풀이되면 개선 후보가 된다
text
~/.harness/feedback/
├── contract/
│   └── {project_hash}-{timestamp}-{세션 앞 8 자}-{고유 번호}.yaml
└── evaluator/
    └── {project_hash}-{timestamp}-{세션 앞 8 자}-{고유 번호}.yaml

project_hash 는 계약 폴더(CONTRACT_ROOT) 경로의 SHA-256 앞 8 자다. 초안에 다른 값을 적어도 save-feedback.sh 가 다시 계산해 덮어쓰고 원래 값은 draft_project_hash 로 남긴다.

공통 필수 — 필드 6 개

모든 피드백 파일에 들어가는 필드다. save-feedback.sh 가 이 필드가 있는지 검사한다.

contract 전용 — 필드 6 개

skill 이 sprint-contract 일 때만 쓴다.

evaluator 전용 — 필드 6 개

skill 이 qa-evaluator 일 때만 쓴다.

자기진단 — 필드 17 개

두 스킬 모두 쓴다. checklist 의 모든 항목은 true 가 「문제가 있다」 는 뜻이다.

사용자 시그널 — 필드 2 개

선택 필드다. 사용자가 평가를 남기면 적는다.

누적 분석 필드 — 필드 3 개

선택 필드다. save-feedback.sh 의 필수 목록에 없어 빠져도 검사를 통과한다. 카이젠의 먼저 볼 것 고르기 단계가 읽는다.

§ 03

cross_diagnosis_by 값

값
뜻
sprint-contract
계약 작성자 관점으로 되짚었다 (구현 판정의 교차 진단이 끝난 상태)
qa-evaluator
평가자 관점으로 되짚었다 (계약 문서 검토의 교차 진단)
pending-parent
평가자가 저장한 시점 값. 교차 진단은 부모가 하므로 아직 끝나지 않았다.
none
끝내 못 했다 — 사유와 오류 출력을 cross_diagnosis_notes 에 적는다
none
과 pending-parent 를 섞지 마라. none 은 "못 했다" 이고 그 집계가 개선 근거가 된다.

none 과 pending-parent 를 섞지 않는다. none 은 「끝내 못 했다」 이고 그 집계가 개선 근거가 된다. 「부모가 할 예정」 을 none 에 넣으면 다음 카이젠이 개선 효과를 읽지 못한다.

§ 04

예시

원본 example 블록을 그대로 옮겼다. 이 블록을 YAML 로 읽으면 원본의 example 값과 같다.

yaml
example:
  schema_version: 1
  timestamp: "2026-03-30T14:00:00+09:00"
  project_hash: "a1b2c3d4"
  project_name: "my-flutter-app"
  skill: sprint-contract
  skill_version: "0.3.3"
  outcome: completed
  contract:
    condition_count: 8
    category_count: 4
    category_coverage: 0.8
    anti_pattern_count: 3
    complexity: medium
  diagnosis:
    checklist:
      ambiguous_conditions: false
      missing_error_paths: true
      untestable_conditions: false
      category_coverage_gap: false
      complexity_underestimate: false
    cross_diagnosis_by: qa-evaluator
    cross_diagnosis_notes: "조건 3번 경계값 누락 가능성"
    improvement_suggestions:
      - "에러 경로 조건을 별도 카테고리로 분리"
  # 누적 분석 필드 (optional)
  repeat_count: 2
  first_seen_at: "2026-03-28T09:15:00+09:00"
  regression_link: null
  user_rating: null
  user_comment: null
§ 05

원본 전문

주석까지 포함한 원본 파일이다. 키 표에 옮기지 못한 설명(누적 분석 필드의 배경 등)은 여기서 읽는다.

yaml
# 피드백 스키마 v1
# sprint-contract와 qa-evaluator 실행 후 글로벌 저장되는 피드백 파일 포맷
# save-feedback.sh가 이 스키마로 검증한다

schema_version: 1

# --- 공통 필수 ---
# timestamp: ISO-8601 (예: "2026-03-30T14:00:00+09:00")
# project_hash: string(8) — 프로젝트 경로 SHA-256 앞 8자
# project_name: string — 사람이 읽을 수 있는 프로젝트 식별자
# skill: enum [sprint-contract, qa-evaluator]
# skill_version: semver (예: "1.3.0")
# outcome: enum [completed, failed, blocked]

# --- contract 전용 (skill=sprint-contract일 때) ---
# contract:
#   condition_count: int
#   category_count: int
#   category_coverage: float (0.0-1.0)
#   anti_pattern_count: int (>= 2)
#   complexity: enum [simple, medium, complex]

# --- evaluator 전용 (skill=qa-evaluator일 때) ---
# evaluation:
#   verdict: enum [APPROVE, REJECT, BLOCKED]
#   conditions_total: int
#   conditions_passed: int
#   l3_coverage: float (0.0-1.0)
#   reject_reasons: list[string]

# --- 자기진단 (공통) ---
# diagnosis:
#   checklist: (고정 필드 — 스킬별 정의)
#     # sprint-contract 필수 필드:
#     #   ambiguous_conditions: bool
#     #   missing_error_paths: bool
#     #   untestable_conditions: bool
#     #   category_coverage_gap: bool
#     #   complexity_underestimate: bool
#     #   measure_premise_unrun: bool
#     #   known_answer_missing: bool
#     #   모든 항목의 true 는 「문제가 있다」 는 뜻이다. 나머지 항목과 문항 전체는 harness/skills/sprint-contract/SKILL.md Step 7 에 있다
#     # qa-evaluator 필수 필드:
#     #   l3_unreached: bool
#     #   bias_detected: bool
#     #   evidence_missing: bool
#     #   contract_misinterpret: bool
#     #   perspective_gap: bool
#   cross_diagnosis_by: enum [sprint-contract, qa-evaluator, pending-parent, none]
#     sprint-contract  계약 작성자 관점으로 되짚었다 (구현 판정의 교차 진단이 끝난 상태)
#     qa-evaluator     평가자 관점으로 되짚었다 (계약 문서 검토의 교차 진단)
#     pending-parent   평가자가 저장한 시점 값. 교차 진단은 부모가 하므로 아직 끝나지 않았다.
#                      부모가 마친 뒤 sprint-contract 로 갱신한다 (2026-09-22 신규)
#     none             끝내 못 했다 — 사유와 오류 출력을 cross_diagnosis_notes 에 적는다
#     none 과 pending-parent 를 섞지 마라. none 은 "못 했다" 이고 그 집계가 개선 근거가 된다.
#     "부모가 할 예정" 을 none 에 넣으면 다음 카이젠이 개선 효과를 읽지 못한다.
#     (2026-09 이전 기록에는 unavailable · null 같은 비표준 값이 섞여 있다)
#   cross_diagnosis_notes: string
#   improvement_suggestions: list[string]

# --- 사용자 시그널 (optional) ---
# user_rating: enum [good, bad] | null
# user_comment: string | null

# --- 누적 분석 필드 (v1 extension, optional) ---
# 2026 agentic regression detection 트렌드 (Sauce Labs, ContextQA, GrowthBook "Feedback Loops
# are the Next Breakthrough in Agentic Coding") 에 맞춰 추가된 optional 필드.
# save-feedback.sh 의 required 리스트에는 포함되지 않으며, 없어도 검증 PASS.
# harness-kaizen / contract-kaizen / evaluator-kaizen 의 Triage 단계가 이 필드를 소비한다.
#
# repeat_count: int — 동일 diagnosis.checklist 시그니처가 글로벌 피드백에서 반복된 횟수.
#                    contract-kaizen / evaluator-kaizen 의 "최근 10건 중 3회 이상" 임계치 판단에 사용.
# first_seen_at: ISO-8601 — 동일 시그니처가 처음 발견된 타임스탬프. 만성 이슈 vs 신규 이슈 구분.
# regression_link: string | null — 이전 APPROVE 피드백 파일명 (예: "a1b2c3d4-2026-04-10T120000.yaml").
#                                  APPROVE 후 같은 영역에서 다시 REJECT 발생 시 회귀 추적용.
#                                  null 이면 회귀 아님.

# 예시:
example:
  schema_version: 1
  timestamp: "2026-03-30T14:00:00+09:00"
  project_hash: "a1b2c3d4"
  project_name: "my-flutter-app"
  skill: sprint-contract
  skill_version: "0.3.3"
  outcome: completed
  contract:
    condition_count: 8
    category_count: 4
    category_coverage: 0.8
    anti_pattern_count: 3
    complexity: medium
  diagnosis:
    checklist:
      ambiguous_conditions: false
      missing_error_paths: true
      untestable_conditions: false
      category_coverage_gap: false
      complexity_underestimate: false
    cross_diagnosis_by: qa-evaluator
    cross_diagnosis_notes: "조건 3번 경계값 누락 가능성"
    improvement_suggestions:
      - "에러 경로 조건을 별도 카테고리로 분리"
  # 누적 분석 필드 (optional)
  repeat_count: 2
  first_seen_at: "2026-03-28T09:15:00+09:00"
  regression_link: null
  user_rating: null
  user_comment: null
