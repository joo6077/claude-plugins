글로벌 저장 경로

피드백은 프로젝트가 아닌 사용자 홈 디렉토리에 글로벌로 저장되어, 여러 프로젝트의 피드백을 종합 분석할 수 있다.

~/.harness/feedback/

프로젝트는 project_hash (경로 SHA-256 앞 8자)로 구분된다. 스키마 버전: v1

Self-Diagnosis

자기진단 체크리스트

각 스킬은 실행 완료 후 고정된 boolean 체크리스트를 자가 점검하여 피드백에 기록한다.

sprint-contract 체크리스트
  • ambiguous_conditions — 모호한 조건이 있는가?
  • missing_error_paths — 에러 경로 조건이 누락되었는가?
  • untestable_conditions — 테스트 불가능한 조건이 있는가?
  • category_coverage_gap — 카테고리 커버리지에 갭이 있는가?
  • complexity_underestimate — 복잡도를 과소평가했는가?
qa-evaluator 체크리스트
  • l3_unreached — L3 검증에 미도달한 조건이 있는가?
  • bias_detected — 편향 징후가 감지되었는가?
  • evidence_missing — 증거 없이 판정한 조건이 있는가?
  • contract_misinterpret — 계약 조건을 오해석했을 가능성이 있는가?
  • perspective_gap — 단일 관점에서만 평가한 조건이 있는가?
Cross-Diagnosis

교차 진단 프로세스

qa-evaluator 실행 후 sprint-contract 서브에이전트를 호출하여 해석 정확성을 검증한다.

1 전달 내용

평가 판정 결과 (출력만 전달). 평가 과정의 추론이나 중간 메모는 전달하지 않는다.

2 핵심 질문

"계약 조건의 원래 의도를 정확히 해석했는가?" — 계약 작성자 관점의 검증

3 결과 기록

피드백 YAML의 cross_diagnosis_by, cross_diagnosis_notes 필드에 기록

Example

피드백 YAML 예시

sprint-contract 실행 후 저장되는 피드백 파일의 전체 구조

schema_version: 1
timestamp: "2026-03-30T14:00:00+09:00"
project_hash: "a1b2c3d4"
project_name: "my-flutter-app"
skill: sprint-contract
skill_version: "0.3.3"
outcome: completed

contract:
  condition_count: 8
  category_count: 4
  category_coverage: 0.8
  anti_pattern_count: 3
  complexity: medium

diagnosis:
  checklist:
    ambiguous_conditions: false
    missing_error_paths: true
    untestable_conditions: false
    category_coverage_gap: false
    complexity_underestimate: false
  cross_diagnosis_by: qa-evaluator
  cross_diagnosis_notes: "조건 3번 경계값 누락 가능성"
  improvement_suggestions:
    - "에러 경로 조건을 별도 카테고리로 분리"

user_rating: null
user_comment: null
