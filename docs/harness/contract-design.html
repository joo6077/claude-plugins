계약 설계 원칙

Design by Contract, Given-When-Then, 검증 가능성, NASA 표준 기반 조건 작성법

Core Principles
핵심 원칙

모든 조건은 제3자가 코드만 보고 PASS/FAIL을 판정할 수 있어야 한다.

1 검증 가능성

모든 조건은 제3자가 코드만 보고 PASS/FAIL을 판정할 수 있어야 한다.

"로그인 실패 시 HTTP 401을 반환한다"

"로그인이 적절히 처리된다"

2 단일 해석

조건은 단 하나의 해석만 가능해야 한다. IEEE 29148 기반 품질 기준.

  • • 능동태 사용 ("시스템이 반환한다")
  • • 단일 조건 (복합은 분리)
  • • 모호 형용사 금지 ("빠르게" → 수치)
3 측정 가능성

조건의 충족 여부를 파일, 코드, 실행 결과로 증명할 수 있어야 한다.

자기 점검: "이 조건을 코드와 실행 결과만으로 PASS/FAIL 판정할 수 있는가?"

Structure
Given-When-Then 구조

BDD(Behavior-Driven Development) 패턴으로 조건을 구조화한다. 복잡도 "중간" 이상에서 모든 핵심 조건에 필수.

Given등록된 사용자가 없을 때
When신규 사용자 등록 요청을 보낸다
Then성공 응답을 반환하고 사용자 목록에 1명이 존재한다
Design by Contract

Precondition: 구현 전 충족 조건 (환경, 의존성)
Postcondition: 구현 후 반드시 참인 조건 (핵심 기능)
Invariant: 전후로 불변인 조건 (기존 기능 보전)

NASA 표준

각 조건은 하나의 "~한다"만 포함. 부정보다 긍정 선호. "and/or" 금지 — 각각 별도 조건으로.

External Observables
외부 관찰 가능성

조건은 시스템이 무엇을 하는지(외부 행동)만 기술한다. 어떻게 하는지(내부 구현)는 기술하지 않는다.

Bad - 구현 누수

"UserService의 userRepository가 비어있을 때"

"POST /api/users 호출 시 201을 반환한다"

Good - 외부 관찰

"등록된 사용자가 없을 때"

"신규 사용자 등록 요청 시 성공 응답을 반환한다"

유형설명예시수정
어휘적단어 자체가 여러 의미"처리한다", "관리한다"구체 동사 ("반환한다")
구문적문장 구조가 여러 해석 허용"A와 B를 포함하는 C"분리하여 각각 명시
의미적도메인 맥락 없이 해석 불가"적절한 응답"상태 코드/값으로 명시
Red Flags
안티패턴 체크리스트

계약 작성 시 반드시 피해야 하는 패턴. 자가 진단 체크리스트로 사용한다.

!
모호한 조건
"적절히 처리한다" → 구체적 행동과 결과로 재작성
!
복합 조건
"A이고 B이며 C이다" → 각각 독립 조건으로 분리
!
카테고리 편중
모든 조건이 UI에만 집중 → GQM으로 균형 확인
!
테스트 불가 조건
"사용자 경험이 좋다" → 측정 가능한 지표로 변환
!
구현 누수
조건에 클래스명/메서드명 포함 → 외부 행동으로 재작성
!
NFR 누락
기능 조건만 존재 → 성능/보안/접근성 항목 추가
!
복잡도 과소평가
파일 수로만 판단 → 영향 범위(레이어, API)로 판단
!
과소 안티패턴
0-1개 안티패턴 → 최소 2개 필수
Self-Check
구조화 진단 체크리스트

sprint-contract 실행 완료 후 자가 점검 항목. Consumer-Driven 원칙: 계약의 소비자는 qa-evaluator이다.

  • ✓ ambiguous_conditions — 모호한 표현이 포함된 조건이 있는가?
  • ✓ missing_error_paths — 에러/예외 경로에 대한 조건이 누락되었는가?
  • ✓ untestable_conditions — 코드만으로 검증 불가능한 조건이 있는가?
  • ✓ category_coverage_gap — project.yaml 카테고리 중 미커버 항목이 있는가?
  • ✓ complexity_underestimate — 복잡도를 과소평가하여 조건 수가 부족한가?
  • ✓ implementation_leakage — 내부 구현 용어가 조건에 포함되었는가?
  • ✓ nfr_coverage — 비기능 요구사항이 조건에 반영되었는가?
