Archetypes
9가지 스킬 유형

Anthropic이 내부 스킬 수백 개를 분석하여 발견한 패턴. 좋은 스킬은 하나의 유형에 명확히 속하고, 나쁜 스킬은 여러 유형에 걸친다.

#유형설명예시
1라이브러리 레퍼런스내부 라이브러리 사용법 및 함정 정리사내 SDK 가이드
2제품 검증Playwright 등 도구로 코드 자동 확인E2E 테스트 스킬
3데이터 조회모니터링/분석 스택 연결Grafana 대시보드 조회
4비즈니스 자동화반복 업무 자동화스탠드업 리포트
5코드 스캐폴딩보일러플레이트 자동 생성프로젝트 초기 설정
6코드 리뷰스타일 강제 또는 자동 리뷰PR 리뷰 스킬
7CI/CDPR 모니터링 및 자동 롤백배포 파이프라인 스킬
8런북(Runbook)장애 시 자동 조사 및 보고서인시던트 대응 스킬
9인프라 운영리소스 정리 및 비용 분석미사용 리소스 정리
Gotchas
Gotchas - 스킬에서 가장 가치 있는 섹션

Claude가 이미 아는 뻔한 내용은 넣지 마라. 스킬에 담아야 할 것은 Claude가 추론만으로 절대 알 수 없는 정보다.

반복 실패 기록

Claude가 반복적으로 실패하는 지점을 모아 놓은 목록이다. 신입 사원에게 매뉴얼보다 선배의 "이거 조심해" 조언이 더 유용한 것과 같다.

점진적 성장

대부분의 스킬은 몇 줄의 지시문 + 하나의 Gotchas로 시작하여 점진적으로 성장한다. 처음부터 완벽하게 만들지 마라.

검증 가능한 기준

스킬이 산출물을 생성할 때, Claude가 스스로 결과를 검증할 수 있는 기준을 포함해야 한다. 검증 없으면 "그럴듯하지만 동작하지 않는" 결과가 나온다.

Claude가 실수 → 실수 패턴 식별 → Gotchas에 한 줄 추가 → 다음부터 같은 실수 방지
Trigger
Description은 트리거 조건이다

스킬의 description 필드는 사람을 위한 요약이 아니라 Claude가 스킬을 선택하는 트리거 조건이다. "언제 이 스킬을 켜라"를 명시해야 한다.

Bad
description: 배포 관련 스킬

무엇을 하는지만 한 줄 — Claude가 언제 쓸지 판단 불가

Good
description: > 사용자가 서비스를 프로덕션에 배포하려 하거나, PR 머지 후 배포 상태를 확인하려 할 때 사용한다.

트리거 키워드 + 비트리거 조건까지 명시

Architecture
폴더로 설계하라

스킬은 마크다운 파일 하나가 아니라 폴더 단위로 설계한다. 점진적 공개(Progressive Disclosure) 원칙: 메인 파일에는 개요만, 상세는 별도 파일로 분리.

my-skill/ ├── my-skill.md # 메인 지시문 ├── references/ # API 문서, 코드 스니펫 │ └── api.md ├── scripts/ # 헬퍼 함수, 검증 스크립트 │ └── validate.sh └── templates/ # 출력 템플릿 └── report.md
밀키트 비유

레시피(지시문)뿐 아니라 재료(레퍼런스)와 도구(스크립트)까지 제공한다. Claude는 필요한 것만 꺼내 쓴다.

컨텍스트 효율

메인 파일에 모든 정보를 넣으면 컨텍스트 과부하. 폴더 내 파일 목록을 명시하면 Claude가 필요한 파일만 선택적으로 읽는다.

Growth
스킬 성장 사이클

처음부터 완벽하게 만들지 마라. 몇 줄로 시작해서 실패를 관찰하며 한 줄씩 추가한다.

버전상태트리거
1지시문 3줄 + Gotchas 1개시작
2Gotchas에 호출 순서 규칙 추가Claude가 API 호출 순서를 틀림
3references/api.md 분리같은 API 문서를 매번 설명해야 함
4scripts/validate.sh 추가반복되는 검증 로직 발생
5templates/report.md 추가출력 형식이 매번 다름

"스킬은 문서가 아니라, 에이전트의 실패를 관찰하며 경험치를 쌓는 살아 있는 시스템이다."

Summary
핵심 원칙 요약
  • ✓ 폴더로 설계 — 마크다운 하나가 아닌 폴더 하나를 설계한다
  • ✓ 뻔한 말 금지 — Claude가 이미 아는 것은 넣지 않는다
  • ✓ Gotchas 최우선 — 반복 실패 지점을 기록하는 것이 가장 높은 가치
  • ✓ 점진적 공개 — 메인 파일에는 개요만, 상세는 별도 파일로 분리
  • ✓ 트리거 조건 명시 — description은 "언제 켜라"를 구체적으로 쓴다
  • ✓ 헬퍼 제공 — 스크립트로 보일러플레이트를 줄인다
  • ✓ 검증 가능한 기준 — Claude가 스스로 결과를 확인할 수 있는 기준 포함
  • ✓ 점진적 발전 — 몇 줄로 시작해서 실패를 관찰하며 한 줄씩 추가
