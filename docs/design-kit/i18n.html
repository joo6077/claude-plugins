Internationalization (i18n)

design-kit HTML 산출물에 적용할 한국어 / 영어 다국어 패턴. standalone HTML(빌드 도구 없이 브라우저에서 바로 열리는 단일 파일)에서 data-i18n 속성과 인라인 딕셔너리로 구현한다.

1 · 핵심 패턴 — data-i18n + 인라인 딕셔너리

HTML 요소에 data-i18n="key.path" 속성을 달고, JS 딕셔너리에서 현재 언어 값을 찾아 textContent 로 치환. 번들 도구 없이 동작한다.

<h1 data-i18n="hero.title">디자인 시스템</h1>
<p data-i18n="hero.desc">색상, 타이포그래피, 간격의 기초</p>
const translations = {
  ko: { hero: { title: "디자인 시스템", desc: "색상, 타이포그래피, 간격의 기초" } },
  en: { hero: { title: "Design System", desc: "Foundations of color, typography, and spacing" } }
};

function applyTranslations(lang) {
  document.querySelectorAll("[data-i18n]").forEach(el => {
    const text = el.dataset.i18n.split(".").reduce((obj, k) => obj?.[k], translations[lang]);
    if (text) el.textContent = text;
  });
  document.documentElement.lang = lang;
  localStorage.setItem("lang", lang);
}

속성 번역 접미사

텍스트 노드 외에 속성값을 번역하려면 접미사 사용: data-i18n-placeholder="form.email", data-i18n-aria-label="nav.menu". 각각 placeholder, aria-label 속성으로 주입.

2 · lang 속성 — 스크린 리더 기반

<html lang=""> 은 스크린 리더 음성 엔진 선택에 직접 영향한다. Googlebot 은 JS 동적 변경도 인식. i18n 스크립트는 반드시 document.documentElement.lang 을 함께 업데이트한다.

ko
디자인 시스템
VoiceOver · TalkBack · NVDA 가 한국어 음성 엔진으로 읽는다. :lang(ko) 선택자 트리거.
en
Design System
English voice engine. :lang(en) selector activates English-specific fonts/rules.
3 · 폰트 스택 — Pretendard 통합

Pretendard = Inter 기반 로마자 + Noto Sans KR 한글 통합. 단일 폰트 스택으로 한/영을 커버하면 폰트 사이의 baseline/크기 차이로 인한 시각 불일치가 없다.

:root {
  font-family:
    "Pretendard Variable", Pretendard,
    -apple-system, BlinkMacSystemFont, system-ui,
    "Segoe UI", Roboto,
    "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic",
    sans-serif;
}

/* 언어별 최적화 (선택) */
:lang(en) { font-family: Inter, system-ui, sans-serif; }
:lang(ko) { font-family: "Pretendard Variable", "Noto Sans KR", sans-serif; }

Pretendard Variable

가변 서체 — 100~900 무게 단일 파일. 한글 자소 너비 최적화. 웹 폰트 1개로 한/영 완결.

github.com/orioncactus/pretendard

시스템 폴백

-apple-system (SF Pro) · Segoe UI · system-ui 로 CDN 실패 시 OS 기본 폰트.

:lang() 선택자

같은 요소라도 lang 속성에 따라 다른 폰트 적용 가능. 영문 전용 서체 브랜딩에 유용.

4 · 레이아웃 영향 방지

한국어 CJK 문자는 영어 대비 글자 폭 약 2배. 텍스트 길이 변화로 레이아웃이 깨지지 않도록 유동 레이아웃과 word-break 규칙을 설정한다.

문제해결CSS
버튼 폭 불규칙최소 폭 + 중앙 정렬min-width: 6rem; text-align: center
한국어 단어 중간 개행단어 단위 유지:lang(ko) { word-break: keep-all }
네비 항목 overflowFlex wrapdisplay: flex; flex-wrap: wrap; gap: 0.5rem
제목 한 줄 강제유동 사이즈font-size: clamp(18px, 4vw, 32px)
긴 텍스트 컨테이너max-width 제한max-width: 40ch (CJK 한 줄 최대)

W3C 권고 — CJK 한 줄 최대 40자. 영어는 65~75자. 다국어 페이지의 공통 상한은 max-width: 40ch 로 잡는 것이 안전.

5 · 날짜 / 숫자 / 통화 포맷 — Intl API

ECMAScript Intl API 는 빌드 도구 없이 모든 모던 브라우저에서 동작. 로케일별 날짜 · 숫자 · 통화 · 상대 시간 포맷을 제공한다.

const locale = lang === "ko" ? "ko-KR" : "en-US";

// 날짜
new Intl.DateTimeFormat(locale, { dateStyle: "long" }).format(new Date());
// ko-KR → "2026년 4월 17일"
// en-US → "April 17, 2026"

// 숫자 · 통화
new Intl.NumberFormat(locale, { style: "currency", currency: "KRW" }).format(1234567);
// ko-KR → "₩1,234,567" / en-US → "₩1,234,567"

// 상대 시간
new Intl.RelativeTimeFormat(locale, { numeric: "auto" }).format(-1, "day");
// ko-KR → "어제" / en-US → "yesterday"

6 · 토글 UI — 우상단 고정

전환 대상 언어를 그 언어로 표기. 한국어 페이지에서는 "English" 를, 영어 페이지에서는 "한국어" 를 표시. 국기 아이콘 사용 금지 — 언어와 국적이 1:1 매칭 아님(영어는 미국뿐 아니라 영국·호주·인도 등).

<div class="lang-toggle" role="navigation" aria-label="언어 선택">
  <button onclick="switchLang()">
    <span lang="en">English</span>
  </button>
</div>

<script>
function switchLang() {
  const next = document.documentElement.lang === "ko" ? "en" : "ko";
  applyTranslations(next);
  const btn = document.querySelector(".lang-toggle span");
  btn.textContent = next === "ko" ? "English" : "한국어";
  btn.lang = next === "ko" ? "en" : "ko";
}
</script>

왜 국기를 쓰지 않는가

국기는 국가(political entity)를 상징하지 언어를 상징하지 않는다. "스페인어 = 스페인 국기"는 남미 사용자에게 소외감, "영어 = 미국 국기"는 영국/호주 사용자에게 이질감. 언어 선택 UI 는 언어 이름 그 자체로 표기.

7 · 접근성 · SEO

접근성

  • html lang="ko" 필수 — 스크린 리더 음성 엔진 선택
  • 언어 토글 버튼에 aria-label="언어 선택"
  • 혼합 언어 콘텐츠는 요소별 lang 속성 분리
  • RTL 언어 지원 시 dir="rtl" 전환

SEO

  • <link rel="alternate" hreflang="en" href="...">
  • URL 구조 — /ko/..., /en/... 또는 ?lang=en
  • Googlebot 은 JS 동적 lang 변경도 인식
  • 메타 description 도 언어별 전환
8 · 안티패턴 vs 올바른 패턴
✗ Bad — innerHTML 번역

el.innerHTML = translations[lang] 로 HTML 직접 주입. XSS 위험 + 내부 자식 요소 손실.

✓ Good — textContent

el.textContent = text 로 텍스트만 안전 치환. HTML 구조 필요 시 별도 요소로 분리.

✗ Bad — 국기 버튼

🇰🇷 / 🇺🇸 이모지로 언어 표시. 국적 ≠ 언어, 문화적 소외감 유발.

✓ Good — 언어명

"한국어" / "English" 텍스트 그 자체. ARIA 레이블과 함께.

✗ Bad — 고정 폭 버튼

width: 100px 하드코딩. "Save" (4자) → "저장하기" (4자)에선 OK 지만 "Configure settings" → "설정 구성하기"는 오버플로우.

✓ Good — min-width

min-width: 6rem; padding: 0 1rem. 콘텐츠에 따라 유동 확장.

✗ Bad — 영어 word-break

word-break: break-all 을 모든 언어에 적용. 영어 단어가 중간에서 깨짐.

✓ Good — :lang(ko) 분기

:lang(ko) { word-break: keep-all } 로 한국어에만 단어 단위 유지.

✗ Bad — 문자열 연결

"You have " + count + " items". 언어에 따라 단복수 · 어순 · 조사 달라 번역 불가능.

✓ Good — ICU 메시지

{count, plural, one {# item} other {# items}}. Intl.PluralRules 로 로케일별 처리.

9 · Gotchas 체크리스트

다국어 구현 시 design-audit 에서 자주 지적되는 항목.

  • ✓
    html lang 업데이트 — document.documentElement.lang 동기 변경. 스크린 리더 음성 엔진 전환.
  • ✓
    localStorage 저장 — lang 선택을 세션 간 유지. 재방문 시 즉시 적용.
  • ✓
    초기 언어 감지 — localStorage → navigator.language → 기본값 순서.
  • ✓
    textContent 사용 — innerHTML 금지 (XSS · 자식 요소 손실).
  • ✓
    속성 번역 — data-i18n-placeholder, data-i18n-aria-label 접미사로 속성값 번역.
  • ✓
    min-width 유동 레이아웃 — 고정 폭 금지. CJK/로마자 글자 폭 차이 대응.
  • ✓
    :lang(ko) word-break: keep-all — 한국어 단어 중간 개행 방지.
  • ✓
    max-width: 40ch — CJK 한 줄 최대. 가독성 확보.
  • ✓
    Intl.DateTimeFormat — 직접 문자열 조립 금지. 로케일별 포맷 자동.
  • ✓
    ICU Plural — 단복수 문자열 연결 금지. Intl.PluralRules 또는 별도 키.
  • ✓
    국기 이모지 금지 — 언어명 텍스트로 표기. aria-label="언어 선택" 필수.
  • ✓
    SEO hreflang — <link rel="alternate" hreflang="..."> 로 검색엔진에 언어 버전 고지.

11 · 실무 팁 · FAQ

다국어 구현 시 자주 부딪히는 경계 케이스.

Q. 언어별 URL 구조 어느 게 좋은가?

SEO 관점에서 서브디렉토리 (/ko/, /en/) 권장. 서브도메인(en.site.com)은 별개 사이트 취급되어 SEO 권한 분산. 쿼리 (?lang=en)는 검색엔진이 인덱싱 어려움.

Q. RTL(아랍어/히브리어) 지원은?

dir="rtl" + CSS Logical Properties 사용. margin-left → margin-inline-start. text-align: left → text-align: start. 레이아웃이 거울 반전되지 않도록 로직 속성 우선.

Q. 번역 파일 관리 스케일업?

인라인 딕셔너리는 소규모 standalone HTML 에 적합. 규모 커지면 react-i18next · next-intl · FormatJS · Lingui 도입. 번역 플랫폼(Crowdin · Lokalise · Phrase)과 연동해 번역가 워크플로우 통합.

Q. 이미지 내 텍스트는 어떻게?

이미지 내 텍스트는 번역 불가. 아이콘 + HTML 텍스트 오버레이로 분리 설계. 피할 수 없으면 언어별 이미지를 <picture> <source srcset> 로 분기. OCR 로 번역 가능한 대체 텍스트 제공.
