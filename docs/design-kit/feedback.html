피드백 수단 선택

정보 유형에 맞는 피드백 수단

NNGroup은 피드백 수단을 세 가지로 분류한다. 잘못된 수단을 선택하면 효과가 사라진다. 긴급도에 비례하여 침투도를 조절한다.

토스트 vs 스낵바 인터랙티브 데모

토스트는 순수 정보 전달, 스낵바는 정보 + 선택적 액션. 버튼을 눌러 차이를 확인하라.

모달 다이얼로그 데모

모달은 치명적 에러 방지, 필수 정보 요청, 워크플로우 분리에만 사용한다. 남용하면 "양치기 소년" 효과가 발생한다.

✅ 올바른 사용
파괴적 액션 확인
되돌릴 수 없는 행동 전 사용자를 일시 정지시키고 구체적 라벨로 확인을 받는다.
❌ 잘못된 사용
비필수 정보에 모달
뉴스레터 구독, 프로모션 같은 비필수 콘텐츠에 모달을 사용하면 사용자가 짜증낸다.

"양치기 소년" 효과

비필수 콘텐츠에 모달을 남용하면, 사용자가 모든 모달을 반사적으로 닫게 되어 정말 중요한 모달도 무시한다.

에러 상태

에러 메시지 4대 원칙

NNGroup의 에러 메시지 가이드라인 4가지 핵심 원칙을 인터랙티브하게 확인한다.

👁
1. 가시성 (Visibility)
에러가 발생한 UI 요소 바로 옆에 배치. 굵은 글씨 + 높은 대비 + 아이콘 조합. 색상만으로 표시하면 안 된다.
💬
2. 커뮤니케이션 (Communication)
평이한 언어로 구체적으로 설명. "오류가 발생했습니다" 대신 "이메일 주소에 @ 기호가 필요합니다"로 교체한다.
⚡
3. 효율성 (Efficiency)
사전 예방, 데이터 보존, 가이드된 복구. 사용자 입력을 유지하여 수정만 하면 되게 한다.
⏰
4. 시기 (Timing)
조기 에러 표시 금지. 대부분의 필드는 onBlur 시점에 검증. 탐색 중 에러를 표시하지 않는다.

인라인 검증 타이밍 데모

이메일 필드에 입력하며 조기 검증(Premature)과 올바른 검증(onBlur)의 차이를 체험하라.

❌ 조기 검증 (Premature)

타이핑 중 즉시 에러 표시 — 사용자가 짜증남

✅ 올바른 검증 (onBlur)

필드를 떠난 후 검증 — 탐색을 방해하지 않음

알림 등급

알림 등급 체계

알림 피로(notification fatigue)를 방지하려면 심각도에 따라 침투도를 차등 적용한다. Critical이 아닌 알림에 소리/진동을 넣지 않는다.

Progressive

📍
제한적 사용
Coach Marks

브랜드 전달
Slides
