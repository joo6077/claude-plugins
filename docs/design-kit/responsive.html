2 · Grid auto-fill / auto-fit + minmax

브레이크포인트 없이 카드 그리드가 자동 조절. 미디어 쿼리 0개로 1/2/3/4 컬럼 전환이 매끄럽게 이루어진다.

.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: clamp(12px, 2vw, 24px);
}

auto-fill

빈 트랙을 유지한다. 컨테이너에 공간이 남으면 보이지 않는 빈 트랙이 자리. 요소 수가 적어도 너비가 예측 가능.

auto-fit

빈 트랙을 접음. 요소가 적으면 기존 요소가 남은 공간까지 늘어남. 카드가 화면 가득 펼쳐지는 효과.

3 · clamp() — 유체 타이포 / 스페이싱

clamp(min, preferred, max). 뷰포트 크기에 비례해 값이 유동 변화하되, 최소/최대 한계 내에 머문다. 미디어 쿼리 단계 없이 매끄러운 스케일.

:root {
  --text-base: clamp(14px, 1.5vw, 18px);
  --text-lg:   clamp(18px, 2.5vw, 28px);
  --text-xl:   clamp(24px, 4vw,   48px);
  --space-md:  clamp(16px, 3vw,   32px);
  --space-lg:  clamp(24px, 5vw,   56px);
}

3인자의 의미

min — 작은 뷰포트에서의 하한. preferred — vw/rem 기반 선호값. max — 큰 뷰포트에서의 상한. 뷰포트 320px 에서는 1.5vw = 4.8px 이지만 min 14px 로 클램프. 1920px 에서는 1.5vw = 28.8px 이지만 max 18px 로 클램프.

4 · 컨테이너 쿼리 — 부모 기반 반응형

뷰포트가 아닌 부모 컨테이너 기준 반응형. 2025 기준 전 주요 브라우저 지원(Chrome 105+ · Safari 16+ · Firefox 110+). 재사용 컴포넌트의 내부 레이아웃을 컨테이너 크기에 맞춰 변환.

.card-wrapper { container-type: inline-size; }

@container (min-width: 400px) {
  .card { flex-direction: row; }
  .card-image { width: 40%; }
}

@container (min-width: 600px) {
  .card { padding: 24px; }
  .card-title { font-size: 20px; }
}

컨테이너 쿼리가 해결하는 문제

사이드바 안의 카드 vs 메인 영역의 카드가 같은 컴포넌트여도 주변 너비에 따라 레이아웃이 달라야 함. 뷰포트 미디어 쿼리로는 불가.

page-size vs container-size

단일 컬럼(뷰포트=컨테이너) 레이아웃에서는 @media 가 간단. 컴포넌트 재사용성 높은 프로젝트는 @container 우선.

5 · 레이아웃 패턴 3종

실무에서 반복되는 구조 3가지. 각각 grid 또는 flex + 미디어 쿼리 조합으로 구현.

01사이드바 + 콘텐츠

.layout {
  display: grid;
  grid-template-columns: 1fr;
}
@media (min-width: 1024px) {
  .layout {
    grid-template-columns: 260px 1fr;
  }
}

모바일에서는 세로 스택, 데스크톱에서는 사이드바 + 메인 분할.

02풀블리드 히어로

.page {
  display: grid;
  grid-template-columns:
    1fr min(65ch, 100%) 1fr;
}
.full-bleed { grid-column: 1 / -1; }
.content { grid-column: 2; }

본문 폭 65ch 제한, 히어로는 전체 폭. min() 으로 모바일 안전.

03반응형 카드 그리드

.grid {
  display: grid;
  grid-template-columns:
    repeat(auto-fill, minmax(280px, 1fr));
  gap: clamp(12px, 2vw, 24px);
}

미디어 쿼리 없이 1/2/3/4 컬럼 자동 전환.

04적응형 타이포

h1 {
  font-size: clamp(28px, 5vw, 56px);
  line-height: 1.1;
}
p {
  font-size: clamp(14px, 1.2vw, 17px);
  max-width: 65ch;
}

clamp 로 유동. max-width: 65ch 로 긴 행 방지.

7 · 안티패턴 vs 올바른 패턴
✗ Bad — max-width 방향

@media (max-width: 768px) 데스크톱 퍼스트. 작은 기기가 CSS 오버라이드 누적 → 성능 저하, 디버깅 어려움.

✓ Good — min-width

@media (min-width: 768px). 모바일 기본에서 큰 화면일수록 기능 추가. 캐스케이드 단방향.

✗ Bad — 고정 px

font-size: 16px; padding: 20px 32px 하드코딩. 모바일에서 너무 크거나 데스크톱에서 너무 작음.

✓ Good — clamp

font-size: clamp(14px, 1.5vw, 18px). 뷰포트에 비례 유동, 상하한 내 머무름.

✗ Bad — 미디어 4단계

sm/md/lg/xl 4개 브레이크포인트 각각 조건 작성. grid-template-columns 를 4번 재정의.

✓ Good — auto-fill

repeat(auto-fill, minmax(280px, 1fr)) 한 줄로 전 브레이크포인트 대응.

✗ Bad — user-scalable=no

viewport 에 user-scalable=no. 시력 약자의 확대 불가 → 접근성 위반.

✓ Good — 표준 meta

<meta name="viewport" content="width=device-width, initial-scale=1">. 사용자 확대 허용.

✗ Bad — 뷰포트 단위 남용

height: 100vh. iOS Safari 에서 주소창 애니메이션으로 레이아웃 점프.

✓ Good — dvh/svh

height: 100dvh (dynamic) 또는 100svh (small). iOS 주소창 고려.

✗ Bad — 컴포넌트에 뷰포트 기준

사이드바 안의 카드가 @media (min-width: 1024px) 로 레이아웃 변경. 실제 카드 너비와 무관.

✓ Good — 컨테이너 쿼리

@container (min-width: 400px) 로 카드 자체 너비 기준. 사이드바 너비가 바뀌어도 일관.

8 · Gotchas 체크리스트

반응형 구현 시 design-audit 에서 자주 지적되는 항목.

  • ✓
    viewport meta 필수 — <meta name="viewport" content="width=device-width, initial-scale=1">. user-scalable=no 금지.
  • ✓
    모바일 퍼스트 방향 — 기본 CSS = 모바일, min-width 로 큰 화면 확장. max-width 는 예외 케이스만.
  • ✓
    brekapoint 최소화 — 640/1024/1536px 3단계. 필요 시에만 확장. 과도한 분기 지양.
  • ✓
    clamp 유체 타이포 — 고정 px 금지. clamp(min, vw, max) 패턴.
  • ✓
    auto-fill + minmax — 카드 그리드는 미디어 쿼리 없이 자동 분기.
  • ✓
    max-width: 65ch — 본문 가독성. CJK 는 40ch.
  • ✓
    dvh / svh — iOS Safari 주소창 대응. 100vh 대신.
  • ✓
    터치 타겟 44×44pt — 모바일 UI 버튼/링크 최소 크기. 8pt 간격.
  • ✓
    컨테이너 쿼리 활용 — 재사용 컴포넌트는 @container 우선, 레이아웃 프레임은 @media.
  • ✓
    이미지 반응형 — srcset, sizes, <picture> 로 기기별 최적 해상도.
  • ✓
    DevTools 기기 에뮬레이션 — iPhone SE (375) · iPad (768) · 1080p (1920) 최소 3단계 확인.
  • ✓
    가로 스크롤 0 — overflow-x: hidden 으로 감추지 말고 근본 원인(고정 폭 요소) 제거.

10 · 실무 팁 · FAQ

반응형 구현 시 자주 부딪히는 경계 케이스.

Q. 모바일 퍼스트 vs 데스크톱 퍼스트?

모바일 퍼스트가 표준. 캐스케이드가 단방향이라 디버깅 쉬움 + 작은 기기 성능 최적. 데스크톱 퍼스트는 max-width 오버라이드 누적으로 CSS 파싱 비용 증가, 모바일 기기가 불필요한 스타일 계산.

Q. 컨테이너 쿼리 지원 안 되면?

2025 기준 전 주요 브라우저 지원(Chrome 105+ · Safari 16+ · Firefox 110+). 레거시 IE/구형 Safari 는 JS 폴백(resize 이벤트 + classList)으로 대응. 새 프로젝트는 컨테이너 쿼리 기본 채택 안전.

Q. 이미지 srcset 어떻게 쓰나?

<img srcset="a-320.webp 320w, a-640.webp 640w, a-1280.webp 1280w" sizes="(min-width:640px) 50vw, 100vw" src="a-640.webp">. 브라우저가 뷰포트 + 픽셀 밀도에 맞는 해상도 자동 선택. <picture> 는 WebP/AVIF 폴백과 아트 디렉션에 사용.

Q. 반응형 테스트 자동화?

Playwright 의 page.setViewportSize 또는 Percy/Chromatic 시각 회귀 테스트. 주요 breakpoint(375/768/1024/1920) 스냅샷 비교. CI 에서 회귀 자동 감지.
