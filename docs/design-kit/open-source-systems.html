오픈소스 디자인 시스템

Radix UI, Shadcn/ui, Tailwind CSS 에 더해 Ant Design, Chakra UI, Mantine 비교 분석. React/웹 프로젝트에서 선택 가능한 6종 시스템의 철학 · API · 장단점 · 적합한 프로젝트 기준.

1 · Radix UI — 헤드리스 접근성 프리미티브

비스타일(unstyled) React 프리미티브 라이브러리. Shadcn/ui 의 기반이며, Node.js/Vercel/Supabase 팀이 채택했다. WAI-ARIA 구현의 어려운 세부사항을 라이브러리가 자체 처리한다.

접근성 우선

aria-*, role 자동 관리. 포커스 이동(AlertDialog 열리면 Cancel 로 자동). Tab · Arrow · Enter · Escape 키보드 패턴 내장. 스크린 리더 테스트 완료.

radix-ui.com/.../accessibility

스타일 자유도

CSS · Tailwind · CSS-in-JS 무엇이든 적용 가능. 구조적 토대만 제공하고 시각 표현은 완전 위임. "스타일 아닌 행동을 제공"이 핵심 가치.

radix-ui.com/.../introduction

asChild · 트리 셰이킹

렌더링 요소 완전 교체 가능. 개별 @radix-ui/react-* 패키지로 설치 → 사용 컴포넌트만 번들에 포함.

radix-ui.com/primitives 
// Radix 는 구조 · 동작만 제공, 스타일은 자유
import * as Dialog from '@radix-ui/react-dialog';

<Dialog.Root>
  <Dialog.Trigger className="my-button">열기</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay className="my-overlay" />
    <Dialog.Content className="my-dialog">
      <Dialog.Title>제목</Dialog.Title>
      <Dialog.Close>닫기</Dialog.Close>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>

3 · Tailwind CSS — 유틸리티 우선

미리 정의된 단일 목적 클래스를 HTML 에서 직접 조합. 2025 기준 사실상의 표준 CSS 프레임워크. Shadcn/ui 의 기본 스타일링 엔진.

핵심 장점

  • 빠른 개발 — 클래스명 고민 불필요
  • 안전한 변경 — 해당 요소에만 영향
  • 쉬운 유지보수 — 스타일시트 추적 불필요
  • CSS 성장 억제 — 재사용률 높음
  • 이식성 — UI 청크 통째로 복사 가능

6 · 선택 가이드

프로젝트 성격에서 역산한 조합 권장. Radix + Tailwind 또는 Shadcn/ui 가 2025 기본값이지만, 도메인에 따라 Ant / Chakra / Mantine 이 더 적합할 수 있다.

디자인 시스템을 처음부터?

Radix UI + Tailwind 또는 Shadcn/ui. 구조는 Radix 가 접근성 보장, 시각 표현은 자유롭게 설계. Shadcn 은 한 단계 위 — 복사된 소스를 프로젝트가 소유.

관리자 패널 · B2B 대시보드?

Ant Design. ProComponents 의 Form/Table/Layout 로우코드 구현이 생산성 압도. 번들 크기는 트리 셰이킹으로 대응.

접근성 최우선?

Chakra UI 또는 Radix UI. 둘 다 WAI-ARIA 기본 내장. Chakra 는 Props API 로 빠르게, Radix 는 커스텀 스타일 자유도로.

폼 · 날짜 · 차트까지 한 생태계?

Mantine. @mantine/core + hooks + form + dates + charts + notifications + spotlight(Cmd+K). 한 생태계에서 UI 전체 커버.

7 · 안티패턴 vs 올바른 패턴

오픈소스 디자인 시스템 도입 시 자주 발생하는 실수.

✗ Bad — 전체 import

import { Button, Modal } from 'antd' 만으로도 번들에 전체 antd 포함되는 실수(구 버전). 1MB+ JS 증가.

✓ Good — 개별 import

import Button from 'antd/es/button' 또는 babel-plugin-import 로 트리 셰이킹. v5 는 기본적으로 트리 셰이킹 친화.

✗ Bad — Radix 통 래핑

Radix Dialog 전체를 <MyDialog> 로 래핑 후 children 만 받음. asChild · 파트별 props 주입 불가.

✓ Good — 파트 조합

사용 측에서 Dialog.Root / Trigger / Content 직접 조립. 유연한 스타일링과 이벤트 핸들러 부착.

✗ Bad — Shadcn 고정 유지

Shadcn 으로 복사한 Button 을 "업스트림 변경" 우려로 수정 기피. 프로젝트 디자인과 어긋나도 그대로 사용.

✓ Good — 자유 편집

Shadcn 철학은 "당신이 소유". 프로젝트 톤 맞게 variant 추가 · 스타일 수정 · 심지어 Radix 대신 다른 프리미티브 교체까지 가능.

✗ Bad — Tailwind 임의 값 남용

bg-[#316ff6] p-[13px] mt-[23px] 로 임의 값 남용. 디자인 토큰 무시.

✓ Good — 테마 확장

tailwind.config.js 에 브랜드 토큰 등록 후 bg-brand p-md mt-lg. 일관성 유지.

  • ✓
    테마 토큰 매핑 — 선택한 시스템의 토큰과 프로젝트 디자인 토큰 1:1 매핑 문서화. 추후 교체 가능성 대비.
  • ✓
    커스터마이징 전략 — 스타일 오버라이드(Ant) vs 복사 편집(Shadcn) vs Props(Chakra) 중 팀 컨벤션 명시.

  • ✓

  • ✓
    국제화(i18n) — RTL 대응 · 날짜 포맷 locale · 키보드 단축키 충돌 확인. Ant/Mantine 은 locale package 제공.
  • ✓

9 · 실무 팁 · FAQ

오픈소스 DS 도입 시 자주 부딪히는 경계 케이스.

Q. Shadcn/ui 업스트림 변경은 어떻게 반영?

수동 반영 원칙. 업스트림이 Radix 업데이트 또는 접근성 개선을 배포하면 diff 를 참고해 로컬 파일에 선별 적용. Git 으로 변경 이력을 추적하므로 리베이스가 가능하다. 대규모 변경은 별도 브랜치에서 실험 후 merge.

Q. Tailwind + CSS-in-JS 동시 사용?

기술적으로는 가능하지만 권장 안 함. 두 시스템의 특이성(specificity) 충돌로 디버깅 지옥. Next.js App Router 는 CSS-in-JS 런타임 오버헤드로 RSC 이점 상실. Tailwind 단일 채택이 안전.

Q. Radix 를 Solid/Vue 에서 쓰려면?

Radix Primitives 는 React 전용. 대안: Headless UI(React/Vue 모두) · Ark UI(프레임워크 무관, Zag.js 기반) · Kobalte(Solid). Shadcn/ui 도 Solid/Vue 포크 존재.

Q. Ant Design v5 번들 크기 줄이기?

v5 는 기본적으로 트리 셰이킹 친화. import { Button } from 'antd' 만으로도 해당 컴포넌트 + 의존성만 포함. Moment.js 제거로 약 200KB 감소. 추가로 CSS-in-JS 추출 시 SSR 에서 FOUC 주의.

2025 트렌드 — AI-Native UI 라이브러리

LLM 이 코드를 직접 읽고 개선하는 시대에 맞춰 Shadcn/ui 의 "복사형" 모델이 부상. 블랙박스 npm 패키지 대신 프로젝트가 소유하는 투명한 코드가 AI 도구 친화적. Radix + Tailwind + Shadcn 조합이 2025 기준 사실상 표준.

ui.shadcn.com — AI-Ready 원칙

TL;DR — 2025 기준 추천 조합

Radix UI (구조 · 접근성) + Tailwind CSS (스타일) + Shadcn/ui (복사형 베이스라인). 이 조합이 커스터마이징 자유도 · AI 친화성 · 성능 · 접근성을 동시에 확보한다. B2B/관리자는 Ant Design, 폼/날짜/차트 중심은 Mantine 을 대안으로.
