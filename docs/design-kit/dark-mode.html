Dark / Light Mode

design-kit HTML 산출물 템플릿에 적용할 다크/라이트 테마 전환 패턴. CSS 변수 + data-theme 속성 + prefers-color-scheme 조합으로 기본 구현한다.

1 · 라이트 vs 다크 시각 비교

단순 반전이 아닌 역할별 독립 설계가 핵심. 같은 accent(파랑)도 다크에서는 밝기를 올려 같은 인지 중요도를 유지한다.

LIGHT
디자인 시스템
색상 · 타이포그래피 · 간격의 기초를 정의하는 토큰 체계. 라이트 모드의 기본 배경은 #ffffff, 텍스트는 #1a1a1a.

DARK

2 · 테마 전환 우선순위

localStorage → 시스템 설정 → 기본값(라이트) 순서로 해석한다. 사용자가 수동 전환한 선택을 가장 우선시하고, 아직 선택 전이면 OS 설정을 따르며, 없으면 라이트.

1순위

localStorage

localStorage.getItem('theme') 값이 있으면 최우선 적용. 사용자가 명시적 선택한 상태.

2순위

prefers-color-scheme

OS/브라우저 설정. matchMedia('(prefers-color-scheme: dark)') 로 감지. macOS · iOS · Windows 11 · Android 다크모드 반영.

3순위

기본값 라이트

둘 다 정보 없으면 라이트. 처음 방문자의 오탐 방지 — 사용자가 인지하지 못한 채 다크로 시작하면 배경 깜빡임 경험.

3 · CSS 변수 토큰 체계

MD3 + Apple HIG 기반. 단순 반전이 아닌 역할(role)별 독립 값 정의. --color-bg 는 #fff ↔ #121212, --color-accent 는 #1a73e8 ↔ #82b4ff.

역할라이트다크비고
bg#ffffff#121212#000 금지 (할레이션)
surface#f5f5f5#1e1e1e카드 · 패널 배경
surface-high#eeeeee#2a2a2a높은 elevation
text-primary#1a1a1a#e8e8e8#fff 금지
text-secondary#666666#aaaaaa보조 텍스트
border#e0e0e0#333333구분선
shadowrgba(0,0,0,.08)rgba(0,0,0,.4)강도 증가
accent#1a73e8#82b4ff밝기 ↑

다크 모드에서 elevation 은 그림자가 배경에 묻히므로, tonal overlay(더 밝은 surface)로 표현한다. --color-surface-high 가 그 역할.

4 · CSS 구현 — 3단 선택자

:root 기본값 → @media (prefers-color-scheme: dark) → [data-theme="dark"] 명시 오버라이드. 시스템 다크 + 사용자 라이트 선택 케이스도 :root:not([data-theme="light"]) 로 처리.

:root {
  --color-bg: #ffffff;
  --color-surface: #f5f5f5;
  --color-surface-high: #eeeeee;
  --color-text-primary: #1a1a1a;
  --color-text-secondary: #666666;
  --color-border: #e0e0e0;
  --color-shadow: rgba(0, 0, 0, 0.08);
  --color-accent: #1a73e8;
}

/* 시스템 다크 모드, 단 명시적 라이트 선택 아닐 때 */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --color-bg: #121212;
    --color-surface: #1e1e1e;
    --color-surface-high: #2a2a2a;
    --color-text-primary: #e8e8e8;
    --color-text-secondary: #aaaaaa;
    --color-border: #333333;
    --color-shadow: rgba(0, 0, 0, 0.4);
    --color-accent: #82b4ff;
  }
}

/* 사용자 명시 다크 선택 (시스템 설정 무시) */
[data-theme="dark"] {
  --color-bg: #121212;
  --color-surface: #1e1e1e;
  --color-surface-high: #2a2a2a;
  --color-text-primary: #e8e8e8;
  --color-text-secondary: #aaaaaa;
  --color-border: #333333;
  --color-shadow: rgba(0, 0, 0, 0.4);
  --color-accent: #82b4ff;
}
5 · 토글 JS — 최소 구현

standalone HTML 권장 패턴. 프레임워크 없이 10줄 이내로 구현. FOUC 방지를 위해 <head> 내 인라인 스크립트에서 먼저 data-theme 를 결정한다.

<script>
  // 페이지 로드 즉시 — FOUC 방지
  const saved = localStorage.getItem('theme')
    ?? (matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
  document.documentElement.dataset.theme = saved;

  function toggleTheme() {
    const next = document.documentElement.dataset.theme === 'dark' ? 'light' : 'dark';
    document.documentElement.dataset.theme = next;
    localStorage.setItem('theme', next);
  }
</script>

FOUC 방지 왜 필요한가

<body> 이후에 JS 가 실행되면 라이트로 그려진 후 다크로 재렌더링되어 화면이 깜빡인다. 반드시 HTML 파싱 첫 순간에 data-theme 를 설정해야 한다. <head> 끝 인라인 스크립트가 표준 패턴.

6 · 이미지 · 미디어 대응

다크 모드에서 이미지의 흰 배경이 튀거나, 컬러 일러스트 채도가 과하게 진동하는 문제. 유형별 처리법이 다르다.

일반 이미지

filter: brightness(0.85) 로 살짝 어둡게. 사진 톤 유지하면서 눈부심 감소.

Inline SVG

fill: currentColor · stroke: currentColor. CSS 변수 전환 시 아이콘 색 자동 대응.

배경 사진

opacity: 0.8 또는 다크 오버레이 (rgba(0,0,0,.3)) 레이어. 텍스트 가독성 유지.

7 · 접근성 기준

라이트 대비 다크에서는 색상 진동 · 대비 저하 문제가 동시에 발생할 수 있다. WCAG 2.1 기준으로 검증해야 한다.

8 · 안티패턴 vs 올바른 패턴
✗ Bad — 단순 반전

filter: invert(1) 로 전체 반전. 보더 · 그림자 · 이미지가 모두 깨진다. 사진도 음화 효과.

✓ Good — 역할별 토큰

CSS 변수로 역할(bg · surface · text · accent)별 독립 값. 라이트/다크 각각 최적 설계.

✗ Bad — 순검정 배경

background: #000. 밝은 텍스트와 극단적 대비로 할레이션(halo) 발생, 눈 피로 증가.

✓ Good — #121212

Material Design 권장. 충분히 어둡되 할레이션을 일으키지 않는 절제된 검정.

✗ Bad — 고채도 그대로

라이트용 #0066FF accent 를 다크에서 그대로 사용. 어두운 배경에서 색 진동.

✓ Good — Tone 상승

다크에서 tone 을 40 → 80 근처로 올림 (#82b4ff). 채도는 낮추고 밝기 증가.

✗ Bad — FOUC

JS 를 <body> 끝에서 실행. 라이트로 그려진 후 다크로 재렌더링 → 깜빡임.

✓ Good — head 인라인

<head> 끝 인라인 스크립트가 data-theme 먼저 설정. 첫 페인트 전에 결정.

✗ Bad — 시스템 무시

다크 토글 구현 안 하거나, 첫 방문에도 라이트 강제. OS 다크모드 사용자에게 불편.

✓ Good — 3단 우선순위

localStorage → prefers-color-scheme → 라이트. 사용자 선택을 존중하되 시스템 설정도 반영.

9 · Gotchas 체크리스트

다크/라이트 구현 시 design-audit 에서 자주 지적되는 항목.

  • ✓
    CSS 변수 필수 — 모든 색상이 var(--color-*) 참조. 하드코딩 hex 금지.
  • ✓
    FOUC 방지 — <head> 인라인 스크립트로 data-theme 선설정. 첫 페인트 전 결정.
  • ✓
    localStorage 우선 — 사용자 명시 선택 > 시스템 설정. 매 세션 유지.
  • ✓
    대비 WCAG AA — 텍스트 4.5:1, 대형 3:1, UI 3:1. 둘 다 라이트/다크 각각 검증.
  • ✓
    #000 · #fff 회피 — 순검정/순흰색 대신 #121212 · #e8e8e8 사용.
  • ✓
    Accent 밝기 보정 — 다크에서 brand 컬러 tone 을 올려 동일 인지 중요도 유지.
  • ✓
    Elevation = tonal overlay — 그림자 대신 더 밝은 surface로 높이 표현.
  • ✓
    이미지 필터 — 일반 이미지 brightness(0.85), SVG 는 currentColor.
  • ✓
    포커스 링 가시성 — 배경과 3:1 이상 대비. accent 컬러 2px solid 권장.
  • ✓
    상태 색상 + 보조 신호 — 성공/경고/오류를 색상 단독이 아닌 아이콘 · 텍스트 병행 (색맹 대응).
  • ✓
    다크모드 스크린샷 — 디자인 검증 시 라이트/다크 각각 캡처해서 비교.

11 · 실무 팁 · FAQ

다크/라이트 구현 시 자주 부딪히는 경계 케이스.

Q. 테마 전환 애니메이션은 어떻게?

:root { transition: background 0.3s, color 0.3s; } 정도면 충분. 너무 긴 transition(0.5s+)은 체감 성능 저하. prefers-reduced-motion 대응으로 transition 끄기 옵션 필수.

Q. 다크모드에서 일러스트 어떻게?

이상적인 건 라이트/다크 각각 일러스트 제작. 현실적으로는 SVG inline + currentColor 로 자동 전환. 사진/그래픽 일러스트는 <picture> + prefers-color-scheme 미디어 쿼리로 소스 분기.

Q. "시스템 따라가기" 옵션이 필요한가?

UX 관점으로 필요. 3옵션 토글(라이트/다크/시스템)을 제공하면 사용자 선택권 증가. 구현: localStorage 값이 "auto"일 때 prefers-color-scheme 감지 + 리스너 등록해 실시간 반영.

Q. SSR 에서 FOUC 가 여전히 발생?

Next.js App Router 는 next-themes · script dangerouslySetInnerHTML 로 first paint 전 테마 주입. 일반 SSR 은 쿠키로 서버에서 data-theme 를 HTML 에 미리 찍어 보냄.

TL;DR — 다크 모드를 한 문장으로

"CSS 변수로 역할별 토큰을 정의하고, data-theme 속성으로 스위치하며, localStorage → prefers-color-scheme → 라이트 우선순위로 초기값을 결정한다. FOUC 방지를 위해 <head> 내 인라인 스크립트가 필수." — 이 패턴이 표준.
