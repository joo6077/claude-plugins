Design Test

디자인 품질 테스트
자동 생성

디자인 토큰 일관성, 접근성(WCAG 2.2 AA), 시각 회귀(Playwright), 반응형 레이아웃 검증까지 -- UI 코드를 분석하여 디자인 품질 테스트를 자동으로 생성합니다.

Step 1
테스트 유형 자동 추론
대상 파일이나 디렉토리의 특성을 분석하여 적합한 테스트 유형을 자동으로 선택합니다. 명시적으로 유형을 지정할 수도 있습니다.
대상 특성 테스트 유형 설명
토큰 파일, 테마 설정 token 디자인 토큰 일관성 검증 -- 포맷 통일, 스케일 검증, 하드코딩 탐지
컴포넌트, 페이지 a11y + visual 접근성 테스트(WCAG 2.2 AA) + 시각 회귀 테스트(Playwright 스크린샷)
레이아웃, 그리드 responsive 반응형 레이아웃 -- breakpoint별 오버플로, 가독성, 이미지 반응성
전체 프로젝트 ALL 모든 유형의 테스트를 생성
사용법

Step 3
토큰 일관성 테스트
디자인 토큰 파일을 분석하여 포맷 일관성, 스케일 규칙, 하드코딩 여부, 다크 모드 커버리지를 검증하는 테스트를 자동 생성합니다.
컬러 포맷 통일

모든 컬러 토큰이 동일한 포맷(hex/oklch/hsl)을 사용하는지 검증합니다. 포맷이 혼재되면 테스트가 실패합니다.

it('all color tokens use consistent format', () => { const formats = new Set( colorTokens.map(([, , value]) => { if (value.startsWith('#')) return 'hex' if (value.startsWith('oklch')) return 'oklch' if (value.startsWith('hsl')) return 'hsl' }) ) expect(formats.size).toBeLessThanOrEqual(1) })
스페이싱 스케일 검증

스페이싱 토큰이 base * multiplier 규칙을 따르는지 확인합니다. 각 단계의 비율이 1보다 커야 합니다.

it('spacing tokens follow scale', () => { const spacings = tokens .filter(([, name]) => name.includes('spacing')) .map(([, , v]) => parseFloat(v)) .sort((a, b) => a - b) for (let i = 1; i < spacings.length; i++) { expect(spacings[i] / spacings[i-1]) .toBeGreaterThan(1) } })
하드코딩 탐지

컴포넌트 CSS에서 raw 컬러값(#ff0000)이나 raw 픽셀값(16px)을 탐지합니다. reset/normalize와 외부 라이브러리는 자동 제외됩니다.

it('no hardcoded values in components', () => { const css = fs.readFileSync('src/components/Button.css') const rawColors = [...css.matchAll(/#[0-9a-fA-F]{3,8}/g)] const rawPx = [...css.matchAll(/:\s*\d+px/g)] // reset, normalize, 외부 라이브러리 제외 expect(rawColors).toEqual([]) expect(rawPx).toEqual([]) })
다크 모드 커버리지

라이트 모드 토큰에 대응하는 다크 모드 토큰이 모두 존재하는지 검증합니다. 누락된 토큰이 있으면 테스트가 실패합니다.

it('dark mode covers all light tokens', () => { const lightNames = tokens .filter(([, n]) => !n.includes('dark')) .map(([, n]) => n.replace('light-', '')) const darkNames = tokens .filter(([, n]) => n.includes('dark')) .map(([, n]) => n.replace('dark-', '')) const missing = lightNames .filter(n => !darkNames.includes(n)) expect(missing).toEqual([]) })
Step 4
접근성 테스트
axe-core 기반 WCAG 2.2 AA 자동 검증. 페이지별 위반 사항, 인터랙티브 요소의 accessible name, 색상 대비, 터치 타겟 크기, 다크 모드 대비를 테스트합니다.

Dark Mode
생성되는 테스트 코드
import { test, expect } from '@playwright/test' import AxeBuilder from '@axe-core/playwright' test('should pass axe-core WCAG 2.2 AA', async ({ page }) => { await page.goto('/') const results = await new AxeBuilder({ page }) .withTags(['wcag2a', 'wcag2aa', 'wcag22aa']) .analyze() expect(results.violations).toEqual([]) }) // 다크 모드 (토큰에 다크 모드가 있을 때) test('dark mode passes color contrast', async ({ page }) => { await page.emulateMedia({ colorScheme: 'dark' }) await page.goto('/') const results = await new AxeBuilder({ page }) .withRules(['color-contrast']) .analyze() expect(results.violations).toEqual([]) })

금지

픽셀 단위 비교는 anti-aliasing, 서브픽셀 렌더링, 폰트 힌팅 차이로 OS/브라우저마다 미세한 차이가 발생합니다. threshold 없이 비교하면 CI에서 false positive가 빈번하게 발생합니다.

Storybook 연동

.storybook/ 디렉토리와 *.stories.* 파일이 감지되면 컴포넌트별 시각 테스트를 추가로 생성합니다. Storybook이 없으면 Playwright 페이지 스크린샷으로 대체합니다.

Step 6
반응형 레이아웃 테스트
프로젝트 디자인 시스템의 breakpoint를 기준으로 수평 오버플로, 텍스트 가독성, 이미지 반응성을 검증합니다.
Breakpoint Width 검증 항목
sm 640px 수평 오버플로 없음 (scrollWidth ≤ clientWidth + 2px)
md 768px 수평 오버플로 없음
lg 1024px 수평 오버플로 없음
xl 1280px 수평 오버플로 없음
텍스트 가독성

모바일 뷰포트(375px)에서 본문 font-size가 최소 14px 이상인지 검증합니다.

const bodyFontSize = await page.evaluate(() => { return parseFloat( getComputedStyle(document.body).fontSize ) }) expect(bodyFontSize) .toBeGreaterThanOrEqual(14)
이미지 반응성

모바일 뷰포트에서 모든 <img> 요소가 뷰포트 너비를 초과하지 않는지 검증합니다.

const images = await page .locator('img').all() for (const img of images) { const box = await img.boundingBox() if (box) { expect(box.width) .toBeLessThanOrEqual(375) } }
Gotchas
체크리스트
design-test 스킬이 반복하기 쉬운 9가지 실수입니다. 테스트를 생성하기 전에 모두 확인하세요.
Anti-patterns
안티패턴
테스트 생성 시 가장 흔한 3가지 안티패턴과 올바른 대안입니다.

1 Threshold 없는 시각 회귀 테스트

Anti-pattern

threshold 없이 픽셀 비교하면 CI에서 false positive가 빈발합니다.

await expect(page).toHaveScreenshot( 'home.png' // threshold 없음! )
Correct

maxDiffPixelRatio를 설정하여 미세한 렌더링 차이를 허용합니다.

await expect(page).toHaveScreenshot( 'home.png', { maxDiffPixelRatio: 0.01 } )

2 APCA를 PASS/FAIL 판정 기준으로 사용

Anti-pattern

APCA Lc 값으로 합격/불합격을 판정합니다. APCA는 아직 법적 기준이 아닙니다.

// APCA Lc >= 60 이면 PASS? const lc = calcAPCA(fg, bg) expect(lc).toBeGreaterThanOrEqual(60) // WCAG 2.2에 APCA는 없다!
Correct

WCAG 2 공식(4.5:1)으로 판정하고, APCA는 informational로만 출력합니다.

// WCAG 2 contrast ratio 기준 const results = await new AxeBuilder({ page }) .withRules(['color-contrast']) .analyze() expect(results.violations).toEqual([]) // APCA는 로그에 참고용으로만 출력

3 임의 하드코딩 breakpoint

Anti-pattern

프로젝트 디자인 시스템을 무시하고 임의의 breakpoint 값을 사용합니다.

// 프로젝트 토큰과 무관한 임의 값 const breakpoints = [320, 768, 1024] // Tailwind는 640/768/1024/1280인데 // 320은 어디서 온 거지?
Correct

프로젝트의 디자인 시스템에 정의된 breakpoint를 읽어서 사용합니다.

// tailwind.config.ts 또는 토큰 파일에서 추출 const breakpoints = [ { name: 'sm', width: 640 }, { name: 'md', width: 768 }, { name: 'lg', width: 1024 }, { name: 'xl', width: 1280 }, ]
