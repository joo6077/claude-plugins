핵심 원칙

테스트가 증거가 되기 위한 조건

스냅샷 파일이나 초록색 실행 결과만으로 품질을 증명할 수 없습니다. 판정 기준, 활성화 실패, 콘텐츠 존재, 사용자 관측 채널을 함께 묶어야 합니다.

baseline은 통과가 아니다

첫 실행은 비교 대상이 없으므로 현재 화면을 baseline으로 기록합니다. 의도적 변형이 실제로 실패하는 negative control과 복원 후 통과를 모두 확인해야 합니다.

Playwright Visual Comparisons ↗
두 임계값을 분리한다

maxDiffPixelRatio는 다른 픽셀의 비율이고, threshold는 같은 좌표 픽셀의 YIQ 색차입니다. 색상 회귀에는 두 축을 각각 점검합니다.

Playwright Screenshot Options ↗
reduced motion은 대체다

prefers-reduced-motion: reduce는 모든 전환을 제거하라는 뜻이 아닙니다. scale·translate 같은 이동감을 opacity·dissolve 같은 온건한 표현으로 바꿉니다.

Gotchas

생성 전에 확인할 체크리스트

15개 가드레일을 모두 확인합니다. 특히 10~15번은 시각 회귀 결과가 실제 사용자 관측을 증명하도록 만드는 규칙입니다.

  1. 1
    스택 감지. React·Vue·Svelte·Angular·Flutter·정적 HTML을 먼저 구분하고 Flutter에 Playwright 테스트를 생성하지 않습니다.
  2. 2
    WCAG 2.2 AA. 본문 4.5:1, 큰 텍스트와 비텍스트 UI 3:1, 터치 타겟 AA 24×24px와 AAA 44×44px를 구분합니다.
  3. 3
    axe-core 버전. 설치된 @axe-core/playwright 또는 axe-core 룰셋 버전을 확인합니다.
  4. 4
    시각 회귀 임계값. maxDiffPixelRatio: 0.01 같은 threshold를 설정해 렌더링 차이의 false positive를 제어합니다.
  5. 5
    하드코딩 탐지 범위. raw value를 무조건 실패시키지 않고 reset·normalize CSS와 외부 라이브러리를 제외합니다.
  6. 6
    breakpoint 출처. 임의의 320·768·1024가 아니라 프로젝트 디자인 시스템의 값을 사용합니다.
  7. 7
    다크 모드. 토큰에 다크 매핑이 있으면 밝은 모드와 어두운 모드 양쪽에서 테스트합니다.
  8. 8
    Storybook 선택 사용. Storybook이 없으면 Playwright 페이지 스크린샷으로 대체합니다.
  9. 9
    APCA는 정보용. PASS/FAIL은 WCAG 2.2 AA의 WCAG2 공식으로 판정하고 APCA Lc는 부가 정보로만 제공합니다.
  10. 10
    negative control. baseline 기록 직후 green을 통과로 보고하지 않습니다. 변형 시 실패, 복원 시 통과를 모두 남깁니다.
  11. 11
    빈 화면 방지. 핵심 요소 visible, 목록 count ≥ 1, 컨테이너 height > 0 assertion을 스냅샷보다 먼저 실행합니다.
  12. 12
    부분 변경 격리. 대상 locator와 주변 영역의 scoped 스냅샷을 분리합니다. 주변 실패는 회귀입니다.
  13. 13
    온건한 모션 대체. animation 개수 0을 요구하지 않고 이동 모션이 opacity·dissolve로 바뀌었는지 봅니다.
  14. 14
    결정 전파 커버리지. .design/decisions.yaml이 있으면 required surface마다 golden과 visible·count·height assertion을 생성합니다.
  15. 15
    증거 채널. 채널, viewport, route/state, visible locator, count/height, screenshot/golden id가 없으면 [미검증]입니다.

Step 4

  await page.goto('/')
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag22aa'])
    .analyze()
  expect(results.violations).toEqual([])
})

test('touch targets are at least 24x24px', async ({ page }) => {
  await page.setViewportSize({ width: 375, height: 812 })
  const targets = await page.locator(
    'button, a, input, select, [role="button"], [role="link"]'

  for (const target of targets) {
    const box = await target.boundingBox()
    if (box) {
      expect(box.width).toBeGreaterThanOrEqual(24)
      expect(box.height).toBeGreaterThanOrEqual(24)
    }
  }
})

Step 5-b · 조건부

결정 전파 테스트 생성

.design/decisions.yaml이 있을 때만 실행합니다. 없으면 “해당 없음”이 아니라 NO_MANIFEST와 exit 3의 의미를 보존해 “manifest 부재”로 보고합니다.

1셋업

route_or_entry, state, viewport_or_container를 테스트에 그대로 옮깁니다.

2assertion 우선

assertions[]를 golden 비교보다 먼저 실행해 빈 렌더가 기준으로 굳는 것을 막습니다.

3영역 분리

selectors[]는 대상 locator에, 바깥은 주변 영역 스냅샷에 사용합니다.

test('DEC-20260813-001 → dashboard.desktop.main', async ({ page }) => {
  await page.setViewportSize({ width: 1440, height: 900 })
  await page.goto('/dashboard')

  const main = page.locator('main').first()
  await expect(main).toBeVisible()
  await expect(page.locator("[data-surface='group-list'] > *"))
    .not.toHaveCount(0)
  expect((await main.boundingBox())?.height ?? 0).toBeGreaterThan(0)

  await expect(main).toHaveScreenshot(
    'DEC-20260813-001/dashboard.desktop.main.png',
    { maxDiffPixelRatio: 0.01 }
  )
})
golden만 있고 assertions가 빈 surface는 FAIL입니다. excluded_surfaces는 테스트에서 제외하되 결과 보고에 이유와 함께 열거합니다.

반응형 레이아웃 테스트 생성

Anti-patterns

실패를 통과로 오인하는 패턴

왼쪽은 증거가 약하거나 잘못된 테스트, 오른쪽은 원본이 요구하는 교정 방식입니다.

1baseline 생성 직후 green

Bad

새 스냅샷을 기록한 실행이 성공했으므로 시각 회귀 테스트가 작동한다고 보고합니다.

--update-snapshots ✓ passed → "회귀 테스트 통과"
Good

의도적 변형으로 실패를 확인하고, 변형을 되돌린 다음 통과 결과까지 인용합니다.

baseline 기록 → 변형 후 FAIL → 복원 후 PASS → 두 출력 인용

2빈 페이지의 동일 스냅샷

Bad

스크린샷 비교만 수행합니다. 렌더가 깨져 빈 화면이어도 baseline과 같으면 통과할 수 있습니다.

await expect(page) .toHaveScreenshot('home.png')
Good

visible, count, height assertion을 먼저 실행한 뒤 golden을 비교합니다.

await expect(main).toBeVisible() expect(count).toBeGreaterThanOrEqual(1) expect(height).toBeGreaterThan(0) await expect(main).toHaveScreenshot(...)

3전체 페이지 하나로 부분 변경 검증

Bad

“보더만 변경”을 전체 페이지 스냅샷 하나로 판정해 배경 같은 의도 외 변화를 구분하지 못합니다.

await expect(page) .toHaveScreenshot('all.png')
Good

대상 locator와 주변 panel을 분리합니다. 주변 스냅샷 실패를 명시적인 회귀로 처리합니다.

target.toHaveScreenshot('target.png') surrounding.toHaveScreenshot('around.png')

4APCA로 합격 판정

Bad

APCA Lc 값을 유일한 PASS/FAIL 기준으로 사용합니다.

expect(apcaLc) .toBeGreaterThanOrEqual(60)
Good

WCAG 2.2 AA를 판정 기준으로 쓰고 APCA는 informational 출력으로만 제공합니다.

withTags(['wcag2a','wcag2aa','wcag22aa']) // APCA: 참고 정보만 출력

5reduced motion에서 전환 0개 요구

Bad

사용자 설정을 모든 애니메이션 제거로 해석하고 animation 개수 0을 assert합니다.

expect(animationCount).toBe(0)
Good

scale·translate 같은 이동감이 사라지고 opacity·dissolve 같은 온건한 대안으로 바뀌었는지 검사합니다.

expect(transformMotion).toBe(false) expect(opacityAlternative).toBe(true)

시각 회귀 baseline 검증 루프

단계행동기대 결과
1. baseline 기록--update-snapshots 실행파일 생성. 통과 증거가 아님
2. negative control대상에 의도적 변형 후 일반 실행실패해야 함
3. 되돌리기변형을 revert하고 동일 명령 실행통과
4. 증거 인용2와 3의 출력을 보고에 첨부판별력과 정상 상태를 함께 증명
maxDiffPixelRatio

달라도 되는 픽셀의 비율입니다. 범위는 0~1이고 기본값은 unset입니다. 크게 잡으면 국소 변경이 묻힙니다.

threshold

같은 좌표 픽셀 간 YIQ 색차입니다. 0은 엄격, 1은 관대하며 기본값은 0.2입니다. 미묘한 색상 회귀에는 이 값을 낮춥니다.
