2 · 핵심 설계 원칙

M3 의 세 기둥 — 개인화 · 적응형 · 접근성. 각 원칙이 다이내믹 컬러 · 반응형 그리드 · 토널 팔레트로 구체화된다.

01

개인화 (Personalization)

사용자 배경화면에서 알고리즘으로 색상 추출 → 앱 · 시스템 UI 에 개인 맞춤 팔레트 적용. 브랜드 컬러와 사용자 선호를 동시에 반영하는 유연한 색상 체계.

02

적응형 (Adaptive)

폰 · 태블릿 · 폴더블 · 데스크톱 · Wear OS 까지 다양한 폼팩터에 적응. 반응형 그리드 + Canonical layouts(목록-상세, 피드, 보조 패널) 활용.

m3.material.io/foundations
03

접근성 우선 (A11y)

토널 팔레트 시스템으로 대비 있는 색상 조합 자동 생성. WCAG 기준 충족 색상 역할(role) 체계. Tone 차이가 곧 대비비를 결정.

m3.material.io/foundations
3 · 디자인 토큰 3계층

Reference → System → Component 계층 구조. 각 수준이 하위 수준에서 값을 상속받아, 라이트/다크 전환 시 상위 참조만 바꾸면 전체 테마가 변경된다.

계층역할예시
Reference Tokens원시 값 (HEX · px · 폰트)md.ref.palette.primary40 = #6750A4
System Tokens역할 · 의미 (테마 전환 지점)md.sys.color.primary = md.ref.palette.primary40
Component Tokens개별 UI 속성md.comp.filled-button.container.color = md.sys.color.primary
 
// System Token 예시 — 라이트/다크 전환은 여기서 교체
md.sys.color.primary     = md.ref.palette.primary40
md.sys.color.on-primary  = md.ref.palette.primary100
md.sys.color.surface     = md.ref.palette.neutral99
md.sys.typescale.body-large = { font: Roboto, size: 16sp, weight: 400 }
md.sys.shape.corner.medium  = 12dp
m3.material.io/foundations/design-tokens
4 · 다이내믹 컬러 · HCT 색상 공간

Google 이 M3 를 위해 개발한 HCT(Hue · Chroma · Tone) 색상 공간. 기존 HSL/HSV 와 달리 인지적 균일성을 보장하여 Tone 차이만으로 WCAG 대비비를 계산할 수 있다.

Hue (색조)

빨강 · 파랑 등. 0 ~ 360°. HSL 과 동일 차원이지만 HCT 에서는 채도/밝기와 독립적으로 변화.

Chroma (채도)

색의 선명도. 0 ~ 120+. Primary 는 chroma 48(선명), Secondary 는 chroma 16(차분).

Tone (밝기)

WCAG 대비 계산에 직접 사용 가능. 0(검정) ~ 100(흰색). Tone 40 vs Tone 100 = 대비비 7:1 (AAA).

색상 역할용도Tone (라이트)
Primary주요 버튼 · 활성 상태40
Secondary필터 칩 · 보조 컴포넌트40
Tertiary대비 악센트 · 강조40
Error오류 상태 표시40
Surface배경 · 카드 · 시트99
On-*역할 위 콘텐츠 (대비 보장)100 / 10
*-Container해당 역할의 컨테이너90

5 · 주요 컴포넌트 패턴

FAB · 네비게이션(Bar/Rail/Drawer) · 카드 · 칩. 네 컴포넌트가 M3 앱의 레이아웃 기준을 만든다.

1FAB 4종

Small 40 · Standard 56 · Large 96 · Extended(가변). 화면당 하나만 사용. M3 에서 M2 대비 각진 형태로 전환, 코너 반경 FAB 16 · Small 12 · Large 28dp.

m3.material.io/.../fab

2적응형 네비게이션

<600dp Bar · 600~1240 Rail · >1240 Drawer. 화면 크기에 따라 다른 네비 컴포넌트 자동 전환. Rail 은 M3 Expressive 에서 접힘/펼침 상태 지원.

m3.material.io/.../navigation

3카드 3종

Elevated · Filled · Outlined. 시각적 분리 강도 순. 코너 반경 12dp medium. 전체 카드를 탭 타겟으로 만들거나 내부 버튼 배치 가능.

m3.material.io/components/cards

4칩 4종

Assist · Filter · Input · Suggestion. 높이 32dp, 코너 반경 8dp. Filter/Input 은 선택 상태 표시, Input 은 삭제(x) 버튼 포함 가능.

m3.material.io/components/chips
6 · M3 Expressive (2025, Android 16)

M3 의 미니멀 톤에서 벗어나 과감한 색상 · 형태 · 모션을 도입. 기존 M3 와 하위 호환 — Expressive 컴포넌트를 점진적 도입 가능.

영역M3 기존M3 Expressive
색상5가지 키 컬러6번째 키 컬러 + 고채도 변형
Shape코너 4단계Squircle + 더 큰 반경
타이포그래피5역할 × 3크기가변 서체 축 강화 + Expressive 스케일
모션7 이징 + 16 듀레이션스프링 물리 기반
컴포넌트표준 크기XL 변형 추가 (FAB XL · Button XL)

Squircle (스퀴클)

원과 사각형의 중간 형태. CSS border-radius 와 달리 모서리에서 직선→곡선 전환이 연속 곡률로 부드럽다. iOS 는 오래전부터 앱 아이콘에 사용했으며, M3 Expressive 가 Android 에 도입했다.

material.io/blog/m3-expressive
7 · 구현 — Jetpack Compose · Flutter

Android Jetpack Compose 는 MaterialTheme 으로, Flutter 는 ColorScheme.fromSeed 로 동일한 HCT 알고리즘을 공유한다.

Jetpack Compose

MaterialTheme(
  colorScheme = if (darkTheme) dynamicDarkColorScheme(context)
                else dynamicLightColorScheme(context),
  typography = Typography(
    displayLarge = TextStyle(/* ... */),
  ),
  shapes = Shapes(
    small = RoundedCornerShape(4.dp),
    medium = RoundedCornerShape(12.dp),
    large = RoundedCornerShape(16.dp),
  )
) {
  // MaterialTheme.colorScheme.primary 로 참조
}
m3.../develop/jetpack-compose

Flutter

MaterialApp(
  theme: ThemeData(
    useMaterial3: true,
    colorSchemeSeed: Colors.blue,
    // 또는 ColorScheme.fromSeed(seedColor: brandColor)
  ),
)

ColorScheme.fromSeed() 는 Material Color Utilities 의 HCT 알고리즘을 내부 사용. Android 다이내믹 컬러와 동일한 팔레트 생성 로직.

8 · 안티패턴 vs 올바른 패턴

M3 원칙을 위반하는 전형적 실수와 교정안.

✗ Bad — 하드코딩 컬러

color: Color(0xFF6750A4) 로 Primary 직접 지정. 다크 모드 · 다이내믹 컬러 적용 불가.

✓ Good — System Token

color: colorScheme.primary 참조. 테마 변경 시 자동 전환.

✗ Bad — FAB 2개 이상

화면 한 곳에 Save + Share 두 FAB 배치. 주요 단일 액션 개념 위배.

✓ Good — FAB 1개 + 툴바

가장 중요한 단일 액션만 FAB, 나머지는 TopAppBar 의 액션 아이콘.

✗ Bad — 고정 Bar 강제

태블릿에서도 Navigation Bar(하단) 강제. 화면 넓이를 활용 못함.

✓ Good — 적응형 분기

600dp 경계로 Rail 전환. 1240dp 초과 시 Drawer. 화면 크기에 맞는 UX.

✗ Bad — useMaterial3: false

Flutter 프로젝트에서 M2 유지. 2025 기준 deprecated.

✓ Good — useMaterial3: true

M3 기본 활성. ColorScheme.fromSeed 로 브랜드 색만 지정.

9 · Gotchas 체크리스트

M3 준수 구현 시 design-audit 에서 자주 지적되는 항목.

  • ✓
    Material 3 활성화 — useMaterial3: true (Flutter), Compose 는 androidx.compose.material3 import.
  • ✓
    ColorScheme 단일 소스 — 모든 컬러 참조는 colorScheme.*. 직접 HEX 하드코딩 금지.
  • ✓
    라이트/다크 토큰 분리 — ColorScheme.fromSeed 에 Brightness.light / Brightness.dark 각각 생성.
  • ✓
    타입스케일 15단계 준수 — Display · Headline · Title · Body · Label × Large/Medium/Small. 임의 사이즈 금지.
  • ✓
    코너 반경은 shape scale 을 따른다 — None 0 · Extra small 4 · Small 8 · Medium 12 · Large 16 · Extra large 28 · Full(50%) dp. 임의 반경 금지.
  • ✓
    Elevation 토큰 사용 — md.sys.elevation.level0 ~ level5 6단계만. 임의 그림자 금지.
  • ✓
    적응형 네비게이션 분기 — WindowSizeClass 또는 MediaQuery 로 Bar/Rail/Drawer 자동 전환.
  • ✓
    On-* 대비 자동 보장 — colorScheme.onPrimary 위에 텍스트 배치 시 대비비 자동. 수동 계산 금지.
  • ✓
    Motion 토큰 — Emphasized/Standard/Legacy 이징 + duration 토큰. 임의 Curve/Duration 금지.
  • ✓
    Expressive 점진 도입 — 기존 M3 컴포넌트와 병존 가능. 스프링 모션은 강조 요소부터 단계적.
10 · 실무 팁 · FAQ

M3 도입 시 자주 부딪히는 경계 케이스.

Q. 다이내믹 컬러를 반드시 써야 하나?

강한 브랜드 아이덴티티가 있는 앱은 완전 브랜드 전략으로 비활성 가능. 다만 시스템 · 유틸리티 앱은 사용자 경험 통일을 위해 활성 권장. ColorScheme.fromSeed 는 한 Seed 로 전 팔레트 생성하므로 브랜드 + 접근성 동시 확보.

Q. iOS 에도 M3 를 쓸 수 있나?

Flutter 프로젝트는 useMaterial3: true 가 iOS/Android 공통 적용되며, 플랫폼 감지는 별도 CupertinoApp 분기로 한다. 크로스 플랫폼에서 M3 단일 채택 시 iOS 사용자에게 낯선 패턴이므로 주의.

Q. FAB 과 BottomAppBar 는 같이 쓸 수 있나?

M3 는 BottomAppBar 내부에 FAB 가 embed 되는 패턴을 공식 지원. Embedded FAB · Floating FAB · Docked FAB 세 위치 옵션. 화면당 FAB 하나 원칙은 유지.

Q. Custom theme 과 Material 컴포넌트 충돌?

컴포넌트 토큰 오버라이드로 해결. Compose MaterialTheme(colorScheme = ..., typography = ..., shapes = ...), Flutter ThemeData(extensions: [MyCustomTheme(...)]). Material 기본값은 유지하되 브랜드 포인트만 재정의.

TL;DR — M3 를 한 문장으로

"토큰 3계층(Reference → System → Component)으로 일관성을 확보하고, HCT 색상 공간으로 접근성을 자동화하며, 화면 크기에 따라 Bar/Rail/Drawer 를 자동 분기한다." — 이 세 원칙이 M3 의 핵심.
