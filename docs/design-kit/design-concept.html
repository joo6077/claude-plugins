Design Kit · design-concept

디자인 컨셉

무드·컬러·타이포·레이아웃·UI 패턴의 방향을 근거와 함께 정의하고 디자인 시스템의 입력값이 되는 무드보드로 번역한다.

방향과 원칙을 정하는 단계이며, 스택별 구현 코드와 확정 컬러 값은 만들지 않는다.

Anti-patterns

안티패턴 Bad / Good 비교

컨셉 문서는 구현값이 아니라 합의 가능한 방향을 담는다.

BAD · REJECT

hex 확정값 기재

토큰 설계와 대비 계산을 건너뛴다.

| Accent | #E8965A |   — hex 확정값 기재 → REJECT (SK-06)
GOOD · DIRECTION

역할과 제약 서술

| Accent | 번트 앰버 계열, muted 채도,

색만 바꾼 여러 안

같은 구조에 색상만 바꾸면 컨셉 옵션이 아니다.

GOOD · CONCEPT OPTION

레이아웃 축 변경

구조·밀도·위계·이미지 비중을 바꾸고 pairwise 게이트를 통과시킨다.

Gotchas

Gotchas 체크리스트

원본의 11개 재발 방지 규칙을 작업 전후에 확인한다.

  • Flutter, React, CSS 등 스택별 코드를 생성하지 않는다.
  • 제안마다 리서치 출처를 명시한다.
  • concept.md에는 hex 확정값을 쓰지 않는다.
  • 기존 concept.md를 먼저 로드한다.
  • 키워드를 color/type/image/shape/layout/motion으로 번역한다.
  • 복수 안은 컬러가 아니라 레이아웃으로 차별화한다.
  • 컬러는 다섯 역할로 나눈다.
  • WCAG AA와 APCA 참고값을 고려한다.
  • OKLCH로 사고하되 concept.md에는 값을 확정하지 않는다.
  • 무드보드 7개 필수 섹션을 모두 둔다.
  • 확정 시 승인 기록을 생성한다.
  • 자율 모드도 승인 주체와 근거를 기록한다.
무드보드 예외: 시각화용 hex placeholder에는 상단 “방향 시각화용 참조값” disclaimer가 반드시 필요하다.
Process · 00

Step 0: 자동 감지 및 로드

기존 합의와 폐기 이력을 먼저 읽는다. Gotcha가 아니라 독립 프로세스 단계다.

CURRENT

.design/concept.md

존재하면 수정·확장 모드로 진입하고 사용자에게 요약한다.

HISTORY

.design/approvals/*-concept.md

폐기 대안을 로드하고 요청 없이는 되살리지 않는다.

CONSTRAINT

**/theme/** · **/tokens/**

기존 토큰 체계를 방향 제약으로 활용한다.

# 감지 대상
.design/concept.md          → 기존 컨셉 로드 (수정/확장 모드)
.design/approvals/*-concept.md → 폐기한 컨셉 안 로드
**/theme/** **/tokens/**    → 이미 토큰 체계가 있으면 컨셉 방향 제약으로 활용
Process · 01

Step 1: 사용자 입력 분석

키워드/분위기, 레퍼런스 URL, 또는 둘 다의 경로로 분류한다.

입력 경로

키워드URL키워드 + URL

불명확할 때 확인

프로젝트 성격과 대상 사용자, 키워드 2–3개, 참고 사이트·앱을 묻는다.

Process · 02

Step 2: 웹 리서치

concept-criteria.md에 따라 디자인 트렌드와 유사 제품을 조사한다.

  • 관련 디자인 트렌드와 사례를 검색한다.
  • 유사한 성격의 프로덕트를 분석한다.
  • 컬러 방향, 타이포 트렌드, UI 패턴을 추출한다.
  • 모든 결과에 출처 URL을 기록한다.
Process · 03

Step 3: 컨셉 요소 도출

감성어를 재사용 가능한 시각 규칙으로 구체화한다.

요소방향제약·예시
무드 키워드핵심 형용사 3–5개minimal, warm, professional
시각 번역color/type/image/shape/layout/motionCalm → 저채도, 넓은 여백, 부드러운 코너, 느린 모션
컬러다섯 역할의 톤·채도hex 금지, WCAG AA 가능성 확인
타이포분류, 페어링, 위계weight/size/tracking 방향
레이아웃hero, 그리드, 흐름, 이미지 비중복수 안의 차별화 축
UI 패턴카드/리스트, 내비게이션, 밀도sharp/rounded/fluid
Process · 04

Step 4: 컨셉 문서 생성

templates/concept.md로 .design/concept.md를 생성하거나 갱신한다.

컨셉 선언

무엇을 왜 표현하는지 한 문장으로 쓴다.

무드 키워드

키워드와 각 의미를 기록한다.

키워드 → 시각 언어 매핑

Color, Type, Layout, Image/Shape, Motion으로 번역한다.

컬러 방향

다섯 역할의 톤·채도와 WCAG AA 가능성을 서술한다.

타이포그래피 방향

분류, 페어링, 위계와 스케일 방향을 쓴다.

레이아웃 방향

hero, 그리드 밀도, 흐름, 이미지 비중을 쓴다.

UI 패턴

내비게이션, 밀도와 컴포넌트 톤을 정리한다.

Do / Don't

강조할 것과 피할 것을 명시한다.

레퍼런스

사이트·앱 URL과 참고 요소를 기록한다.
