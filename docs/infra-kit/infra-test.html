Infra Kit v0.1

인프라 테스트 자동 생성

IaC 검증(Terraform test, Terratest, Pulumi), Dockerfile lint, CI 파이프라인 검증, K8s manifest 검증 — 프로젝트 인프라 스택을 감지하고 적합한 테스트 코드를 자동으로 생성한다.

01 · Detection

인프라 스택 감지

프로젝트 루트에서 파일과 디렉토리를 탐색하여 인프라 스택을 자동 식별한다. 감지 결과에 따라 적합한 테스트 도구를 선택한다. 스택 감지 없이 테스트를 생성하면 Terraform 프로젝트에 Pulumi 테스트를 만드는 실수가 발생한다.

03 · IaC Tests

IaC 테스트

Infrastructure as Code 테스트는 plan 모드에서 실행하여 실제 인프라에 영향을 주지 않고 리소스 구성을 검증한다. Terraform은 네이티브 HCL 테스트와 Go 기반 Terratest를 지원하며, Pulumi는 mock 기반 단위 테스트를 제공한다.

TERRAFORM HCL TEST

Terraform 네이티브 테스트

Terraform 1.6+ / OpenTofu 1.7+에서 지원하는 HCL 기반 테스트. command = plan으로 실제 적용 없이 리소스 속성과 출력값을 검증한다.

# tests/{module}.tftest.hcl
run "verify_resource_creation" {
  command = plan

  variables {
    environment    = "test"
    instance_type  = "t3.micro"
  }

  assert {
    condition     = aws_instance.main.instance_type == "t3.micro"
    error_message = "Instance type mismatch"
  }
}

run "verify_output_format" {
  command = plan

  assert {
    condition     = can(regex("^[a-z]", output.resource_name))
    error_message = "Resource name must start with lowercase"
  }
}

TERRATEST (GO)

Go 기반 통합 테스트

복잡한 인프라 검증이 필요할 때 사용한다. Plan 검증이 기본이며, Apply가 필요한 경우 defer Destroy로 격리 환경에서만 실행한다.

// test/{module}_test.go
package test

import (
    "testing"
    "github.com/gruntwork-io/terratest/modules/terraform"
    "github.com/stretchr/testify/assert"
)

func TestModule(t *testing.T) {
    opts := &terraform.Options{
        TerraformDir: "../modules/{module}",
        Vars: map[string]interface{}{
            "environment": "test",
        },
    }
    defer terraform.Destroy(t, opts)
    terraform.InitAndPlan(t, opts)
}

PULUMI UNIT TEST

Pulumi Mock 기반 테스트

Pulumi runtime mock을 사용하여 클라우드 API 호출 없이 인프라 코드를 단위 테스트한다. 리소스 속성과 출력값을 apply 콜백으로 검증한다.

// __tests__/infra.test.ts
import * as pulumi from "@pulumi/pulumi/runtime";
import { describe, it, expect } from "vitest";

pulumi.setMocks({ /* mock provider */ });

describe("Infrastructure", () => {
  it("should create bucket with versioning",
    async () => {
      const { bucket } = await import("../index");
      const versioning = await new Promise(
        resolve =>
          bucket.versioning.apply(v => resolve(v))
      );
      expect(versioning?.enabled).toBe(true);
  });
});

04 · Container Tests

Container 테스트

Dockerfile 정적 분석(hadolint)과 빌드된 이미지의 구조 검증(container-structure-test)은 서로 다른 관심사다. hadolint는 Dockerfile 작성 규칙을, container-structure-test는 실제 이미지 내부의 파일 존재, 포트, 사용자, 명령어를 검증한다.

HADOLINT

Dockerfile 정적 분석

Dockerfile의 베스트 프랙티스 위반을 감지한다. .hadolint.yaml 설정 파일로 프로젝트 정책에 따라 규칙을 조정할 수 있다. 신뢰할 수 있는 레지스트리만 허용하여 공급망 공격을 방지한다.

# .hadolint.yaml
ignored:
  - DL3008   # Pin versions in apt-get
trustedRegistries:
  - docker.io
# 실행
hadolint Dockerfile
hadolint
CONTAINER STRUCTURE TEST

이미지 구조 검증

빌드된 이미지가 예상대로 구성되었는지 확인한다. 바이너리 존재 여부, 실행 사용자, 노출 포트, 명령어 실행 결과까지 YAML 선언으로 테스트한다.

# container-structure-test.yaml
schemaVersion: "2.0.0"
metadataTest:
  exposedPorts: ["8080"]
  cmd: []
  user: "nonroot"
fileExistenceTests:
  - name: "app binary exists"
    path: "/app/server"
    shouldExist: true
commandTests:
  - name: "healthcheck endpoint"
    command: "curl"
    args: ["-f", "http://localhost:8080/health"]
    exitCode: 0
container-structure-test
05 · CI / K8s Tests

CI 파이프라인 & K8s 테스트

CI 워크플로우 파일의 구문 오류와 보안 문제를 사전에 감지하고, Kubernetes manifest가 API 스키마에 부합하는지 검증한다. OPA/Rego 정책으로 조직의 배포 규칙(latest 태그 금지 등)을 강제할 수 있다.

ACTIONLINT

GitHub Actions 정적 분석

워크플로우 YAML의 구문 오류, 잘못된 uses: 참조, 셸 스크립트 오류를 감지한다. 추가로 third-party action의 SHA 고정 여부를 확인하는 구조 검증 스크립트를 병행한다.

# 정적 분석
actionlint .github/workflows/*.yml

# SHA 고정 확인
grep -rn "uses:" .github/workflows/ \
  | grep -v "@[a-f0-9]\{40\}" \
  | grep -v "actions/"
actionlint
KUBECONFORM

K8s Manifest 스키마 검증

kubeval은 deprecated되었으므로 kubeconform을 사용한다. Helm 차트는 helm template으로 렌더링한 후 파이프라인으로 검증한다.

# manifest 직접 검증
kubeconform -strict \
  -kubernetes-version 1.30.0 \
  k8s/*.yaml

# Helm chart 검증
helm template my-release helm/chart/ \
  | kubeconform -strict

# kustomize 빌드 검증
kustomize build k8s/overlays/dev \
  | kubeconform -strict
kubeconform
CONFTEST / OPA

Policy as Code 테스트

OPA/Rego 정책으로 조직의 배포 규칙을 코드화한다. :latest 태그 금지, 리소스 제한 필수 등 운영 정책을 manifest에 자동 적용하고 CI에서 강제한다.

# policy/no-latest-tag.rego
package main

deny[msg] {
  input.kind == "Deployment"
  container := input.spec.template
    .spec.containers[_]
  endswith(container.image, ":latest")
  msg := sprintf(
    "Container '%s' uses :latest tag",
    [container.name]
  )
}

# 실행
conftest test k8s/*.yaml \
  --policy policy/
conftest
06 · Gotchas

Gotchas 체크리스트

✓
스택 감지 없이 테스트 생성 금지. Terraform 프로젝트에 Pulumi 테스트를 생성하면 안 된다. 반드시 프로젝트 루트의 파일을 탐색하여 스택을 먼저 식별한다.
✓
terraform validate만으로 충족 선언 금지. validate는 구문 검사일 뿐이다. 실제 인프라 로직 검증은 terraform test (HCL 기반) 또는 Terratest (Go 기반)로 해야 한다.
✓
프로덕션 인프라에 직접 테스트 실행 금지. IaC 테스트는 반드시 plan/dry-run 모드 또는 격리된 테스트 환경에서 실행한다. terraform apply를 테스트에서 호출하면 안 된다 (Terratest의 auto-destroy 제외).
✓
Dockerfile lint와 빌드 테스트 혼동 금지. hadolint는 정적 분석이고, 실제 빌드 테스트는 docker build --target test 또는 multi-stage test 스테이지로 분리한다. 이 둘은 관심사가 다르다.
✓
CI 파이프라인 테스트에서 시크릿 노출 주의. act (GitHub Actions 로컬 실행) 사용 시 .secrets 파일을 .gitignore에 포함한다. CI 테스트 결과에 환경 변수 덤프를 남기지 마라.
✓
K8s manifest 검증 도구 혼용 주의. kubeval은 deprecated. kubeconform 또는 kubectl --dry-run=server를 사용하라. Helm 차트는 helm template | kubeconform 파이프라인으로 검증한다.
✓
보안 스캔을 테스트로 대체하지 마라. Trivy/Snyk/Checkov는 보안 스캔 도구이지 테스트가 아니다. 스캔 결과를 CI에 게이트로 넣되, 별도 단계로 분리하라. 테스트 통과와 보안 통과는 별개 관심사다.
✓
OpenTofu/Terraform 호환성 주의. OpenTofu 1.7+는 tofu test에서 mocking 지원. Terraform은 1.6+에서 terraform test 지원. 프로젝트가 어떤 도구를 쓰는지 반드시 확인하라.
07 · Anti-patterns

안티패턴 & 올바른 접근

Bad

terraform validate만으로 "테스트 완료" 선언

validate는 HCL 구문과 프로바이더 스키마만 확인한다. 리소스 속성이 의도한 값인지, 출력이 올바른 형식인지는 검증하지 못한다. 구문은 맞지만 로직이 틀린 인프라가 배포된다.

Good

terraform test로 assert 기반 검증

.tftest.hcl 파일에서 command = plan으로 실행하고 assert 블록으로 리소스 속성과 출력값을 검증한다. 실제 적용 없이도 인프라 로직의 정확성을 확인할 수 있다.

Bad

테스트에서 terraform apply 실행

프로덕션 또는 공유 환경에서 apply를 호출하면 실제 리소스가 생성/변경된다. 비용 발생, 데이터 손실, 서비스 중단의 위험이 있으며, 테스트 실패 시 리소스가 남아 고아 인프라가 된다.

Good

plan 모드 + 격리 환경에서만 apply

기본 테스트는 command = plan으로 실행한다. Apply가 반드시 필요한 통합 테스트는 Terratest의 defer Destroy로 격리 환경에서만 실행하고, 완료 후 리소스를 자동 정리한다.

Bad

K8s 배포에 :latest 태그 허용

:latest는 이미지 버전이 불확정이어서 동일 manifest로 다른 결과가 나온다. 롤백이 불가능하고, 캐시된 이미지와 실제 이미지가 달라 디버깅이 극도로 어렵다.

Good

OPA 정책으로 :latest 차단

Conftest + OPA/Rego 정책으로 :latest 태그를 CI에서 자동 차단한다. 시맨틱 버전 또는 커밋 SHA 기반 태그를 강제하여 배포의 재현성과 추적 가능성을 확보한다.
