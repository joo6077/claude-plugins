Infra Kit · infra-test

인프라 테스트 자동 생성

IaC, 컨테이너, CI/CD, Kubernetes 스택을 먼저 감지하고 실환경을 건드리지 않는 테스트와 증거 기반 게이트를 생성하는 실행 가이드.

IaC Container CI/CD Kubernetes Security Gate
01 · Principles

원칙 카드

입력 스택을 확인하고 결과 상태를 숨기지 않으며, 공급망 정책을 구조적으로 판정한다.

PRINCIPLE 01

시크릿 fixture도 ephemeral하게

Terraform 1.10+의 ephemeral 블록이나 OpenTofu 1.7+의 write-only 인수를 쓰는 모듈은 테스트에서도 평문 변수를 주입하지 않는다. 환경 변수 또는 Vault dev 모드를 사용한다.

Terraform ephemeral
PRINCIPLE 02

파이프 실패를 끝까지 전달

검증 스크립트에는 set -euo pipefail을 적용하고 실패를 누적한 뒤 마지막에 종료 코드로 전달한다.

Docker best practices
PRINCIPLE 03

GitHub Actions 셸을 명시

run 스텝에 shell: bash를 명시한다. 비-Windows 기본 셸 bash -e {0}에는 pipefail이 없다.

GitHub Actions workflow syntax
PRINCIPLE 04

원격 액션은 불변 참조로

로컬 참조만 기본 면제한다. 원격 액션은 40자 커밋 SHA, docker://는 @sha256: digest를 요구한다.

GitHub Actions secure use
PRINCIPLE 05

Dependabot 생태계는 실제 파일로 결정

워크플로가 있으면 github-actions를 검토하고, 나머지 생태계는 대응 manifest 또는 lockfile이 탐지될 때만 등록한다.

Dependabot options reference

03 · Guardrails

Gotchas 체크리스트

01
스택 감지 없이 테스트 생성 금지. Terraform 프로젝트에 Pulumi 테스트를 만들지 않는다. Step 0 감지가 필수다.
02
terraform validate만으로 충족 선언 금지. validate는 구문 검사다. 로직은 terraform test 또는 Terratest로 확인한다.
03
프로덕션에 직접 테스트 실행 금지. plan/dry-run 또는 격리 환경을 쓰며 Terratest auto-destroy 외에는 테스트에서 apply를 호출하지 않는다.
04
lint와 빌드 테스트를 혼동하지 않는다. hadolint는 정적 분석이고 실제 빌드는 docker build --target test나 multi-stage test로 분리한다.
05
CI 테스트에서 시크릿 노출 금지. act의 .secrets는 .gitignore에 넣고 환경 변수 덤프를 남기지 않는다.
06
K8s 도구 혼용 주의. kubeval 대신 kubeconform 또는 kubectl --dry-run=server를 쓰고 Helm은 template 파이프라인으로 검증한다.
07
보안 스캔을 테스트로 대체하지 않는다. Trivy·Snyk·Checkov는 CI 게이트의 별도 단계로 둔다.
08
OpenTofu/Terraform 호환성을 확인한다. OpenTofu 1.7+ mocking과 Terraform 1.6+ test 지원을 구분한다.
09
backend-test와 sibling consistency를 유지한다. Step 0 독립 감지, 기존 패턴 탐색, 외부 실환경 강제 금지를 함께 유지한다.
10
ephemeral fixture에 평문 시크릿을 넣지 않는다. 환경 변수나 Vault dev 모드로 전달한다.
11
셸 결과를 exit code로 전파한다. 상태 5종은 taxonomy를 SSOT로 삼고 pipefail·명시적 bash·실패 누적·nullglob를 함께 적용한다.
12
도구 미설치는 PASS가 아니다. [미검증] TOOL_OR_ENV_MISSING과 막는 것·우회·통제 불가 사유·재검증 명령을 기록한다.
13
핵심 도구 부재를 위반으로 오보하지 않는다. 첫 rule 전에 검사하고 없으면 EXECUTION_ERROR와 exit 2로 종료한다.
14
핀닝을 grep으로 판정하지 않는다. YAML 파서로 잡·스텝의 uses를 모두 열거해 full SHA 또는 digest를 검증한다.
15
Dependabot에는 실제 생태계만 등록한다. manifest와 lockfile 탐지 결과를 따른다.

Step 5 · CI 파이프라인 테스트 생성

# 정적 분석
actionlint .github/workflows/*.yml

구조 검증 스크립트는 Gotcha 11·13·14의 골격을 함께 적용하고 상태·exit 정의는 taxonomy를 인용한다.

#!/usr/bin/env bash
set -euo pipefail
shopt -s nullglob

WF_DIR="${WF_DIR:-.github/workflows}"
PIN_ALLOW_FIRST_PARTY_TAGS="${PIN_ALLOW_FIRST_PARTY_TAGS:-0}"
CORE_TOOLS="grep"
OPTIONAL_TOOLS="python3"

have() { command -v "${1}" >/dev/null 2>&1; }
count() { set -- ${1:-}; echo "$#"; }
workflows=("$WF_DIR"/*.yml "$WF_DIR"/*.yaml)

tools_ok=""; tools_missing=""
for t in $CORE_TOOLS $OPTIONAL_TOOLS; do
  if have "$t"; then tools_ok="$tools_ok $t"; else tools_missing="$tools_missing $t"; fi
done

echo "=== CI Workflow Gate ==="
echo "대상 워크플로 수 : ${#workflows[@]}  (${WF_DIR})"
echo "규칙 소스 수     : 2  (checkout-존재 · 원격-action-SHA핀닝)"
echo "사용 가능 도구 수: $(count "$tools_ok") [${tools_ok:- 없음} ]"
echo "미설치 도구 수   : $(count "$tools_missing") [${tools_missing:- 없음} ]"

for t in $CORE_TOOLS; do
  have "$t" || { echo "EXECUTION_ERROR : 핵심 도구 '$t' 미설치"; exit 2; }
done
if [ "${#workflows[@]}" -eq 0 ]; then
  echo "SKIP_NO_TARGET : 대상 없음"
  exit 3
fi

violation=0; unverified=0; exec_error=0
# checkout은 uses: 키로 호출된 줄만 판정한다.
# 핀닝은 python3 + yaml.safe_load로 jobs.<id>.uses와
# jobs.<id>.steps[].uses를 모두 열거한다.
# ./ · ../만 면제, docker://는 @sha256:, 그 외 원격은 40자 SHA.

echo "VIOLATION=$violation  [미검증]=$unverified  EXECUTION_ERROR=$exec_error"
if [ "$exec_error" -gt 0 ] || [ "$unverified" -gt 0 ]; then exit 2; fi
if [ "$violation" -gt 0 ]; then exit 1; fi
exit 0
핵심/선택 도구 분리: 핵심 도구가 없으면 rule을 하나도 실행하지 않고 EXECUTION_ERROR다. 선택 도구가 없으면 해당 rule만 미검증 처리하고 나머지는 계속한다.

골격 음성 대조

요소빼면 생기는 일
머리말 4 카운터위반 0의 분모를 알 수 없다.
핵심 도구 사전 검사grep 부재를 checkout 위반으로 오보한다.
대상 0 가드 + exit 3검사하지 않은 레포가 PASS가 된다.
nullglob리터럴 glob을 YAML 오류로 오보한다.
YAML 파서잡 수준·로컬·docker 참조를 구분하지 못한다.
first-party 기본 0면제 정책이 숨는다.
세 카운터 분리도구 부재가 위반 0에 흡수된다.
argv로 파일 전달공백·따옴표 경로가 파손된다.
내장 count축소 PATH에서 머리말이 깨진다.

알려진 답 대조

임시 워크플로에 checkout 태그, 40자 SHA 액션, v4 태그 액션을 둔다. 참조 수 3, 참조 단위 VIOLATION 2줄, 규칙 단위 VIOLATION=1, exit 1이 기대값이다. 다르면 실제 대상에 돌리기 전에 수정한다.

관측상태exit
실행, 위반 없음PASS0
실행, 위반 발견VIOLATION1
대상 0개SKIP_NO_TARGET3
도구·환경 불가[미검증] TOOL_OR_ENV_MISSING2
실행·파싱·권한 실패EXECUTION_ERROR2

VIOLATION과 실행 불완전이 함께 있으면 2가 우선하며 세 카운트를 모두 출력한다.

Step 8 · 결과 보고 (증거 블록 필수)

1
검사 범위 머리말
대상 수, 규칙 소스 수, 사용 가능 도구 수, 미설치 도구 수.
2
생성된 파일
경로 목록.
3
실행 증거
명령과 출력 또는 exit code. 실패는 수정 후 재실행.
4
미검증 항목
막는 것, 우회, 통제 불가 사유, 재검증 명령과 총건수. 2건 이상이면 부분 완료.
검사 범위:
  대상 워크플로 수  : 3  (.github/workflows)
  규칙 소스 수      : 2  (checkout-존재 · 원격-action-SHA핀닝)
  사용 가능 도구 수 : 2  [grep python3]
  미설치 도구 수    : 2  [kubeconform container-structure-test]
실행 증거:
  $ actionlint .github/workflows/deploy.yml
  (출력 없음 · exit 0)
  $ bash tests/ci-validation.sh
  VIOLATION=0  [미검증]=0  EXECUTION_ERROR=0 · exit 0
미검증:
  [미검증] TOOL_OR_ENV_MISSING: kubeconform
    막는 것: command -v kubeconform → 출력 없음 · exit 1
    시도한 우회: YAML 구문만 확인
    통제 불가 사유: 설치 권한 없음
    재검증 명령: brew install kubeconform && kubeconform -strict k8s/

마지막으로 CI 파이프라인에 통합하는 방법을 안내한다.

05 · Anti-patterns

안티패턴 bad / good 비교

Bad

validate만 통과하면 완료

구문만 맞고 인프라 로직은 틀린 결과를 놓친다.

Good

plan 기반 assert

terraform test나 Terratest로 속성과 출력값을 검증한다.

Bad

경고만 출력하고 exit 0

결함을 찾아도 파이프라인이 항상 통과한다.

Good

실패 누적 뒤 종료

전수 결과와 상태별 카운터를 남기고 taxonomy에 맞춰 종료한다.

Bad

grep으로 핀닝 판정

잡 수준·로컬·docker 참조를 구분하지 못한다.

Good

YAML 파서로 열거

모든 uses를 구조적으로 읽고 SHA·digest 정책을 적용한다.

Bad

도구 미설치를 PASS 처리

실행하지 않은 검사를 통과 수에 넣는다.

Good

미검증 네 칸 기록

막는 것, 우회, 통제 불가 사유, 재검증 명령을 남긴다.

Bad

없는 생태계까지 Dependabot 등록

반복 실패가 진짜 알림을 묻는다.

Good

실제 파일로 등록 결정

manifest·lockfile 탐지 결과에 해당하는 생태계만 넣는다.
