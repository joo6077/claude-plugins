사용자가 **직접 손으로** 수행해야 하는 절차를, 화면에서 길을 잃지 않을 입도로 안내한다.

## 이 스킬의 존재 이유

사용자 불만 원문: *"맨날 다르게 알려주고 자세히 안 알려줘서 내가 몇 번이나 요청해야 함. 어떤 페이지에 정확히 어떤 메뉴를 통해 들어가고 어떤 항목을 어떻게 설정 및 입력하고 이런 걸 안 알려줌. 걍 대략적으로 알려줌."*

막아야 할 결함 4 종이다.

| ID | 결함 | 이 스킬의 대응 |
| --- | --- | --- |
| F1 | 같은 질문에 매번 다른 절차 | Step Contract 고정 (§Step Contract) |
| F2 | "설정에서 활성화하세요" 수준의 입도 | 말단 액션 규칙 + 값·확인 필수 (Gotcha 1) |
| F3 | 학습 데이터 기반 옛 UI | 출처 등급제 + 조회일 스탬프 (Gotcha 3) |
| F4 | 화면에서 항목을 못 찾음 | 딥링크 우선 + 중간 단계 무생략 + 선제 분기 (Gotcha 2·4) |

**F2 를 F3 로 바꾸지 마라.** 자세히 쓰라는 요구를 날조로 메우는 것이 이 도메인의 최악 실패다. 실측: 사용자가 "자세하게 말해"라고 한 직후 조회 없이 사이드바 메뉴 순서를 단정한 사고가 있었다. 정확도를 못 올리면 **등급을 낮춰 표기**하지, 지어내지 않는다.

## Step Contract — 모든 스텝이 갖는 고정 형식

형식이 곧 결정성이다. 매번 같은 필드로 답해야 매번 같은 답이 나온다.

```text
S<n>. [조건이 있으면] <어디서> 에서 <무엇을> <타입> 을 <동작>
      값: <입력값 또는 "입력 없음">
      확인: <끝났음을 눈으로 확인하는 관측값>
      안 보이면: <분기>
      출처: <URL> (조회 YYYY-MM-DD) 또는 [추정]
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 어디서 | ✅ | 딥링크 URL 이 있으면 **그것이 1 순위**. 메뉴 경로는 `A > B > C` 로 **중간 단계 전부** |
| 무엇을 | ✅ | 화면에 보이는 라벨 그대로 + 요소 타입(버튼/필드/탭/토글/드롭다운/체크박스) |
| 동작 | ✅ | 종결 동사 하나 — 이동·열기·선택·누르기·입력·체크·토글·저장·다운로드·업로드 |
| 값 | ✅ | 입력값·선택지·제약. 없으면 **"입력 없음"이라고 명시**(빈칸으로 두지 않는다) |
| 확인 | ✅ | 이 스텝이 끝났음을 관측하는 방법. 무증상 실패를 막는 유일한 장치 |
| 안 보이면 | ✅ | 최소 1 개. 사유는 권한/요금제/버전/언어/AB 중 하나 |
| 조건 | 선택 | 항상 실행이면 생략 |
| 출처 | ✅ | URL + 조회일, 또는 `[추정]`, 또는 `[미확인]` |

전체 절차 골격은 `사전 요구사항 → 맥락 1~2 문장 → 스텝 → 최종 상태 → 뒤처리` 순서다.

### 출처 등급

| 등급 | 의미 | 표기 | 허용 문장 |
| --- | --- | --- | --- |
| 관측 | 사용자가 화면을 읽어줬다 | 표기 생략 | 무엇이든 단정 가능 |
| 문서 | 공개 1차 출처에 그 라벨이 적혀 있다 | `출처: <URL> (조회 YYYY-MM-DD)` | 라벨·경로·필드명 단정 가능 |
| 추정 | 출처에 없는 모델 지식 | `[추정]` **표기 필수** | 단정 금지. "대개 …에 있습니다" |
| 미확인 | 확인 실패 | `[미확인]` + 시도한 URL | 이때만 전역 검색어로 우회 |

`[추정]` 은 **금지 대상이 아니라 라벨 대상**이다. 출처가 다른 정보를 같은 등급으로 섞어 파는 것이 부정직이지, 등급을 붙여 파는 것은 부정직이 아니다. 다만 액션 스텝의 40% 를 넘으면 그대로 내보내지 말고 화면 확인을 요청한다.

## Gotchas

### Gotcha 1: 스텝은 말단 액션으로 끝난다 — "이 섹션에서 찾으세요" 금지

**끝맺으면 안 되는 표현**: `이 섹션에서 …` · `해당 항목을 찾아` · `적절히 설정` · `알아서` · `관련 메뉴에서` · `필요에 따라`

이 표현으로 끝나는 스텝은 미완이다. 사용자가 화면에서 막히는 지점이 정확히 거기다.

- ❌ "Firebase 콘솔의 Cloud Messaging 섹션에서 APNs 키를 설정하세요"
- ✅ "`console.firebase.google.com/project/_/settings/cloudmessaging` 을 연다 → `iOS app configuration` 섹션에서 `APNs authentication key` 의 **Upload** 버튼을 누른다 / 값: 앞서 받은 `.p8` 파일 / 확인: 키 목록에 Key ID 행이 추가된다"

한 스텝에 한 동작이다. 메뉴 연쇄(`File > New > Document`)만 예외로 한 스텝에 둔다.

### Gotcha 2: 딥링크가 메뉴 경로보다 우선한다

URL 은 버튼 라벨보다 훨씬 덜 바뀐다. 안내는 잘 안 바뀌는 앵커 위에 세워라.

```text
불변도 높음   URL 경로 · 설정 키/API 이름
             섹션명
             버튼/필드 라벨
불변도 낮음   아이콘 · 배치(좌/우/상단)
```

공식 문서에 딥링크가 실제로 있다. 이것을 먼저 찾아라.

| 서비스 | 형태 |
| --- | --- |
| Firebase | `console.firebase.google.com/project/_/settings/…` (`_` = 프로젝트 id 자리) |
| Google Cloud | `console.cloud.google.com/<서비스>` + `?project=` |
| Apple | `appstoreconnect.apple.com/teams/[Team ID]/…`, `developer.apple.com/account/…` |
| Stripe | `dashboard.stripe.com/test/…` (test) ↔ `dashboard.stripe.com/…` (live) — **모드가 URL 로 갈린다** |
| GitHub | `github.com/settings/…` (완전 딥링크) |

딥링크가 없으면 **전역 검색어**를 준다 (대부분의 콘솔에 상단 검색창이 있다). 메뉴 트리를 외우게 하는 것보다 검색어 하나가 강하다.

**계정 슬롯을 조심하라.** `/u/0/` 같은 계정 인덱스를 임의로 박으면 다른 계정으로 리다이렉트된다 — 실측 사고가 있었다. 계정이 여럿일 수 있으면 슬롯을 빼고 안내한다.

### Gotcha 3: 콘솔 UI 라벨은 학습 데이터로 쓰지 않는다 — 매번 조회한다

콘솔 UI 는 6~12 개월마다 개편된다. 기억으로 답하면 사용자가 화면에서 못 찾는다.

- 스텝을 **쓰기 전에** 그 스텝의 1 차 출처를 조회한다. 조회하지 않은 스텝은 `[추정]` 등급을 달거나 쓰지 않는다.
- 검색어에 **현재 연도를 포함**한다. 연도 없이 검색하면 2~3 년 전 결과가 상위 노출된다.
- 문서의 **최종 수정일**을 확인한다 (`Last updated YYYY-MM-DD UTC`, `Last modified Month D, YYYY`, `Updated N days ago`).
- **크로스 호스트 리다이렉트**를 문서 소멸로 해석하지 마라. 돌려받은 URL 로 다시 조회하고 원장에는 최종 URL 을 남긴다.

**"조회했다"는 도구 호출 기록으로만 성립한다.** 호출과 그 출력 없이 "공식 문서에서 확인했다"고 쓰는 것은 거짓이다. 실측 사고가 있었다 — `web_fetch_requests: 0` 인데 "공식 docs 에서 가져온 검증된 5 단계"라고 주장했다.

### Gotcha 4: 안 보일 때의 분기를 되묻기 전에 준다

"몇 번이나 요청해야 함" 불만의 직접 해법이다. 사용자가 못 찾고 다시 물어보게 만들지 말고, **미리** 분기를 붙인다. 이것은 변명이 아니라 1 급 공식 문서 관행이다 — Apple·Atlassian·GitHub 모두 `"If you don't see …"` 문장을 쓴다.

분기 사유 5 종:

| 사유 | 전형적 대응 |
| --- | --- |
| 권한/역할 | "관리자에게 <권한명> 을 요청해야 보입니다" |
| 요금제 | "무료 플랜에는 이 메뉴가 없습니다" |
| 버전 | "<버전> 이상에서는 A, 이하에서는 B" |
| 언어 | 영문 라벨을 정본으로, 한국어를 괄호에 |
| A/B 롤아웃 | 상위 섹션명 + 전역 검색어 제공 |

### Gotcha 5: 방향어 대신 명명된 컨테이너로 지목한다

`위쪽`, `아래`, `오른편` 은 화면 크기와 레이아웃에 따라 달라진다. 대신 **이름 있는 영역**을 쓴다.

`좌측 사이드바` · `상단 탭` · `탭 아래 정보 배너` · `<이름> 다이얼로그` · `우측 상단 액션 메뉴(⋯)` · `페이지 하단` · `툴바`

- ❌ "오른쪽 위에 있는 버튼을 누르세요"
- ✅ "우측 상단 액션 메뉴(⋯)를 열고 **Export** 를 선택한다"

### Gotcha 6: 사이트가 갈리는 절차는 배정표를 맨 위에 박는다

"셋업은 전부 A 사이트" 같은 뭉뚱그림은 사용자가 **첫 화면에서** 막히게 한다. 어느 작업이 어느 사이트인지 사전 요구사항 맨 위에 표로 둔다.

같은 유형의 함정 예:

| 도메인 | 갈리는 사이트 |
| --- | --- |
| Apple | 키·식별자 발급 = Developer Account / 앱 레코드·빌드 업로드·TestFlight = App Store Connect |
| Google | GCP Console ↔ Firebase Console |
| 한국 행정 | 주민등록등본 = 정부24 / 가족관계증명서 = 대법원 전자가족관계등록시스템 / 소득금액증명 = 홈택스 |

### Gotcha 7: 되돌릴 수 없는 지점을 미리 경고한다

등록 ≠ 활성화이고, 신청 ≠ 승인이다. 단계를 분리해 쓴다. 그리고 **한 번 정하면 못 바꾸는 값**은 사전 요구사항에서 경고한다 (Bundle ID, 프로젝트 ID, 계정 명의, 해지 후 복구 불가 등).

전 세계 유니크해야 하는 식별자(Bundle ID, 패키지명, 프로젝트 ID, 도메인, 아이디)는 **선점되어 있을 확률이 높다.** "이미 사용 중" 에러 케이스를 미리 넣는다.

### Gotcha 8: 요청한 그 절차만 안내한다

인접 기능을 "있으면 좋으니까" 끼워넣지 않는다. 필수 선행 조건인 경우에만 사전 요구사항에 의존으로 명시하고, 추가로 다룰 가치가 있으면 **마지막에 한 줄로 제안**만 한다.

Step Contract 의 필드는 **형식 표준이지 채우기 할당량이 아니다.** 해당 없는 항목은 "입력 없음", "해당 없음" 한 줄로 닫는다.

### Gotcha 9: 위험한 절차에는 안전 장치를 붙인다

금전·법적 피해가 가능한 절차(해지, 명의 변경, 결제 수단, 세무 신고, 권한 위임, 데이터 삭제)는:

1. **되돌릴 수 있는지**를 절차 시작 전에 명시한다
2. **수수료·처리기간·방문 필요 여부**를 헤더에 둔다 (온라인만으로 안 끝나는 절차가 많다)
3. 확신이 없으면 **공식 고객센터 연락처**를 함께 준다. 모르는 것을 아는 척하는 비용이 여기서는 특히 크다

## Process

### Phase 1: 요청 해석 + 선행 확인 (한 번만 묻는다)

1. 사용자가 달성하려는 **최종 상태**를 한 문장으로 정한다. 절차명이 아니라 결과로 잡는다.
2. 절차를 가르는 축 중 **모르는 것만** 고른다. 알 수 있는 것은 묻지 말고 확인해서 채운다 (레포가 있으면 읽고, 대화에 이미 나왔으면 그것을 쓴다).

   | 축 | 개발 절차 | 일상 절차 |
   | --- | --- | --- |
   | 플랫폼 | 스택 / OS / 프레임워크 | 기기 / OS 버전 / 웹 vs 앱 |
   | 환경 | 로컬 · CI · 프로덕션 | 국가 / 언어 |
   | 자격 | 계정 권한 · 요금제 | 계정 등급 · 본인인증 수단 |
   | 현재 상태 | 이미 설정된 것이 있는가 | 이미 발급받은 것이 있는가 |
3. **한 번에 묶어 2~4 문항으로 묻는다.** 답에 따라 갈리는 질문은 다음 라운드로 미룬다. 순차 질문은 "몇 번이나 요청해야 함" 불만을 재생산한다.
4. 물을 필요가 없으면 묻지 말고 **가정을 명시하고 진행**한다. — "iOS 26 기준으로 안내합니다. 다르면 알려주세요."

**사용자가 이미 확인했다고 말한 사실은 재검증하지 않는다.**

### Phase 2: 1차 출처 조회

1. **공식 문서를 먼저 조회한다.** 콘솔 클릭 경로·메뉴 라벨·필드명은 매번 조회한다.
   조회 프롬프트에 이 두 줄을 넣는다 — *문서 표기 그대로 추출할 것* / *문서에 없는 화면 흐름은 "문서에 없음"이라고 답할 것*.
2. **딥링크를 찾는다** (Gotcha 2). 문서 본문에 콘솔 URL 이 박혀 있는 경우가 많다.
3. **분기 문장을 수집한다** — `"If you don't see …"`, 권한/요금제 관련 서술.
4. 실패하면 사다리를 내려가되 **어느 단계에서 얻었는지 기록한다**:
   대상 페이지 → 같은 공식 도메인의 색인/개요 페이지 → 교차검증(제2 출처) → 검색(현재 연도 포함)
5. 전부 실패하면 **학습 데이터로 채우지 않는다.** `[미확인]` + 시도한 URL 을 남기거나 `[추정]` 등급으로 낮춰 쓴다.

**deprecated 판정은 출처보다 강하게 하지 않는다.** `권장하지 않음` ≠ `deprecated` ≠ `제거됨`. 벤더 정의상 deprecated 는 대개 **아직 동작한다**.

### Phase 3: 답변 작성

1. 사전 요구사항 — 필요한 계정·권한·준비물·수수료·처리기간, 사이트 배정표(Gotcha 6), 되돌릴 수 없는 지점(Gotcha 7)
2. 스텝 — Step Contract 형식. 말단 액션으로 끝낼 것(Gotcha 1)
3. 최종 상태 — 전부 끝났을 때 화면에서 무엇이 보이는가
4. 뒤처리 — 정리·되돌리기·파기해야 할 것

**대화 모드는 파일을 만들지 않는다.** 사용자가 문서를 원하면 `/howto-doc` 을 안내한다.

### Phase 4: 자기 검증 (완료 선언 전)

아래를 전수 대조한다. 하나라도 걸리면 고친 뒤에 답한다.

- [ ] 종결 동사로 안 끝나는 스텝이 0 건인가 (`이 섹션에서`·`해당 항목을`·`적절히`·`알아서`)
- [ ] `확인` 이 빠진 스텝이 0 건인가
- [ ] `안 보이면` 분기가 빠진 스텝이 0 건인가
- [ ] `출처` 등급이 없는 스텝이 0 건인가
- [ ] `[추정]` 이 액션 스텝의 40% 를 넘지 않는가
- [ ] 메뉴 경로에 중간 단계가 빠진 곳이 없는가
- [ ] 방향어(`위`, `아래`, `오른쪽`)로만 지목한 곳이 없는가
- [ ] 요청 범위 밖의 절차를 끼워넣지 않았는가
- [ ] 조회했다고 쓴 스텝이 실제 조회 기록을 갖는가

### Phase 5: 화면 폐루프 (막혔을 때)

로그인 뒤 화면은 도구로 못 본다. **하지만 사용자는 지금 그 화면을 보고 있다.**

1. `문서` 등급으로 확정 가능한 지점까지 끊지 않고 안내한다.
2. 거기서 **한 번만** 묻는다 — "지금 그 화면에 보이는 항목을 그대로 읽어 주세요(또는 스크린샷)."
3. 사용자가 읽어준 라벨은 `관측` 등급으로 승격하고 **세션 내에서 재사용**한다. 같은 콘솔에서 다시 묻지 않는다.

이것은 되묻기를 늘리는 게 아니라 줄인다 — 지금은 사용자가 못 찾아서 되묻는 왕복이 더 많다.
