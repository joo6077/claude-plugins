Howto Kit 개요 — 절차를 끊지 않고 안내한다

어느 화면 → 어느 메뉴 → 어느 항목 → 무슨 값 → 어떻게 확인. 사용자가 화면에서 길을 잃는 지점을 없애는 것이 목표다. 정확도를 못 올리면 등급을 낮춰 표기하지, 지어내지 않는다. v0.1.0 · 갱신 2026-09-08

고치는 결함 4종

사용자 불만 원문: “맨날 다르게 알려주고 자세히 안 알려줘서 내가 몇 번이나 요청해야 함. 어떤 페이지에 정확히 어떤 메뉴를 통해 들어가고 어떤 항목을 어떻게 설정 및 입력하고 이런 걸 안 알려줌.”

ID결함대응
F1같은 질문에 매번 다른 절차Step Contract 고정
F2“설정에서 활성화하세요” 수준의 입도말단 액션 규칙 + 값·확인 필수 (G5·G6)
F3학습 데이터 기반 옛 UI출처 등급제 + 조회일 스탬프
F4화면에서 항목을 못 찾음딥링크 우선 + 중간 단계 무생략 + 선제 분기

F2 를 F3 로 바꾸지 않는 것이 이 킷의 핵심 제약이다. 자세히 쓰라는 요구를 날조로 메우는 것이 이 도메인의 최악 실패다.

차이는 길이가 아니라 끝맺음이다. before 는 “섹션에서 설정하세요”로 끝나 사용자를 화면에 혼자 남긴다. after 는 종결 동사로 끝나고, 무엇을 넣고 무엇을 보고 성공을 판단할지까지 닫는다.

출처 등급제 — “검증 불가 → 침묵”의 대체물

정직성이 요구하는 것은 침묵이 아니라 등급 표시다. 출처가 다른 정보를 같은 등급으로 섞어 파는 것이 부정직이지, 등급을 붙여 파는 것은 부정직이 아니다.

등급표기허용되는 문장
관측표기 생략무엇이든 단정 가능
문서출처: <URL> (조회 YYYY-MM-DD)라벨·경로·필드명 단정 가능
추정[추정] 필수단정 금지. “대개 …에 있습니다”
미확인[미확인] + 시도한 URL이때만 전역 검색어로 우회

추정이 액션 스텝의 40%를 넘으면 그대로 내보내지 않는다 — 화면 폐루프로 사용자에게 묻거나 미확인으로 강등한다.

결정론 게이트 G1~G6

LLM 호출 없는 순수 판정이다. G5·G6 이 이 킷의 존재 이유 — 기존 절차 킷 어디에도 입도를 재는 검사가 없었다.

ID검사실패 조건
G1출처 원장 완전성액션 스텝 수 ≠ 출처 줄 수
G2미검증 마커 분류접미 없는 레거시 마커 ≥1, 또는 INVALID 가 정본 임계 이상
G3도메인 혼용선언과 다른 계열 경로 혼입, 또는 대상 미선언
G4deprecation 근거 결합주장한 스텝의 출처가 뒷받침하지 않음 (한국어 토큰 포함)
G5말단 액션종결 동사로 끝나지 않거나 회피 표현이 섞인 스텝 ≥1
G6입도 완전성값·확인·안 보이면·출처 누락 ≥1, 또는 추정 비율 > 40%

G3 는 대상 플랫폼을 선언하지 않으면 PASS 가 아니라 FAIL 이다. 판정 불가를 통과로 흘리는 것이 no-op 게이트의 정체다 — 기존 킷의 G3 는 스택 인자가 비면 항상 PASS 해서 3개월간 아무것도 잡지 못했다.

게이트는 양쪽 셸에서 돌려야 증명된다

실측 2026-09-08. 같은 게이트, 같은 위반 입력, 다른 셸.

✗ zsh위반을 흘렸다
G5_TERMINAL PASS nonterminal=0 hedge=0
GATE_PASS
✓ bash정상 판정
G5_TERMINAL FAIL nonterminal=2 hedge=2
GATE_FAIL

원인은 set -- $stats. zsh 는 기본적으로 파라미터 확장에 단어분할을 하지 않아서 전체가 $1 에 들어가고, 이후 산술 비교가 전부 조용히 실패했다. bash 에서만 테스트했으면 못 잡았을 결함이다. 그래서 evals 는 두 셸 출력의 동일성까지 검사한다.

이 킷이 사실로 말하지 않는 것

킷의 규칙을 킷 자신에게 먼저 적용한 결과다. 원장은 현재 9 절이며 리서치 사이클이 돌 때마다 늘어난다 — 확정된 것을 옮겨 내고 새로 확인 실패한 것을 더하기 때문이다. 전체는 references/provenance-notes.md 가 정본이다.
