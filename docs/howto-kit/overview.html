Howto Kit 개요 — 절차를 끊지 않고 안내한다

사람이 손으로 하는 절차를 어느 화면 → 어느 메뉴 → 어느 항목 → 무슨 값 → 어떻게 확인까지 안내한다. 기본은 대화창 즉답이고, 요청할 때만 문서로 남긴다. 정확도를 못 올리면 등급을 낮춰 표기하지, 지어내지 않는다.

v0.1.0 스택 · 도메인 무관 스킬 3 · 에이전트 1 · 게이트 G1~G6 원본 howto-kit/README.md
한 스텝이 끝까지 닫는 다섯 칸
1 · 어디서어느 화면딥링크 또는 A > B > C
2 · 어디서어느 메뉴중간 단계를 빼지 않는다
3 · 무엇을어느 항목라벨 + 종류 (버튼 · 탭 · 필드)
4 · 값무슨 값없으면 “입력 없음”
5 · 확인어떻게 확인끝났음을 눈으로 보는 관측값

README 첫 문장이 이 킷의 약속이다. 한 칸이라도 비면 사용자는 그 자리에서 다시 묻는다. 칸 이름은 문서 모드의 고정 마커(어디서 · 무엇을 · 동작 · 값 · 확인 · 안 보이면 · 출처)에서 가져왔고, 스키마 정본은 references/step-contract.md 다.

if [ -n "$GATE" ] && [ -f "$GATE" ]; then

  . "$GATE"; howto_gate <절차 문서>
else

fi

어느 사본을 썼는지 보인다

찾으면 RESOLVED: <경로> 한 줄을 먼저 찍는다. 옛 설치본이 불렸는지 레포 파일이 불렸는지를 출력만 보고 가를 수 있다.

못 찾으면 MISSING: 줄에 시도한 세 곳을 모두 적고 false 로 끝난다. 판정 없이 조용히 넘어가지 않는다.

!

셸 함수는 자식 셸로 넘어가지 않는다

find -exec sh -c 로 여러 파일을 돌릴 때는 스크립트를 sh -c 안에서 읽는다. 부모 셸에서 읽은 howto_gate 는 자식 셸에 없다.

onboarding-kit 과의 관계

onboarding-kit 은 폐기하지 않는다. 개발 레포 안에서 외부 서비스를 붙일 때의 스택 확정과 레포 실측 근거는 실제로 값을 한다.

이 킷이 evals 로 안정화된 뒤 흡수 여부를 다시 판단한다. 그때까지 둘은 나란히 간다 — 레포 안의 연동 코드는 onboarding-kit, 사람이 화면에서 누르는 절차는 이 킷.

놓치기 쉬운 것
  • !자세히 쓰라는 요구를 모르는 메뉴 이름으로 채우지 않는다. 확인 못 한 칸은 [추정] 이나 [미확인] 으로 내린다 (F2 를 F3 로 바꾸지 않는다).
  • !문서 머리에 - 대상: 을 빼면 G3 가 no_target_declared 로 FAIL 한다. 판정 불가는 통과가 아니다.
  • %추정 이 액션 스텝의 40% 를 넘으면 그대로 내보내지 않는다 — 묻거나, 내리거나, 범위를 좁힌다.
  • $게이트 스크립트를 howto-kit/scripts/ 상대 경로 하나로 부르지 않는다. 설치한 프로젝트에는 그 폴더가 없다. 세 곳을 차례로 찾는 블록을 쓴다.
  • $find -exec sh -c 로 여러 파일을 돌릴 때는 스크립트를 자식 셸 안에서 읽는다. 첫 줄이 MISSING: 이면 판정을 내지 말고 그 줄을 그대로 보고한다.
  • ✓게이트를 부르는 블록을 새로 넣으면 evals.json 의 gate_blocks 도 함께 고친다. 안 고치면 러너가 FAIL 을 낸다.
  • ✓셸 하나에서 통과했다고 끝내지 않는다. sh howto-kit/evals/run-evals.sh 가 zsh · bash · sh 를 모두 돈다.
  • ✓확인에 실패한 근거는 “없음”으로 적지 않고 provenance-notes.md 원장에 남긴다.
