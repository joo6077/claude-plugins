Search Strategy — 최신 정보 수집 우선순위

WebFetch → Context7 → Codex → WebSearch 순서로 1차 출처를 수집한다. 학습 데이터 추측은 금지. 그리고 WebFetch가 볼 수 있는 것은 로그인 없이 접근 가능한 공개 문서뿐이다 — 로그인 뒤 콘솔 화면은 어떤 도구로도 확인할 수 없으므로, 그 경계를 가이드 본문에 적는 것까지가 절차다.

4단계 우선순위 래더

위에서 아래로. 상위 도구로 답이 나오면 아래로 내려가지 않는다. 어느 단계에서 얻었는지는 반드시 기록한다 — 그 기록이 출처 원장의 아티팩트다.

1
WebFetch 1순위 콘솔 UI · 공식 help
가장 빠르고 정확. 콘솔 클릭 경로, 메뉴 라벨, + 버튼 옵션 리스트는 매번 WebFetch한다. 단, 닿는 범위는 공개 문서까지다 (아래 §로그인 뒤 콘솔 참조).
2
Context7 SDK API 문서
라이브러리/SDK의 메서드 시그니처, 초기화 코드, 마이그레이션 가이드. 흐름: resolve-library-id로 라이브러리 ID 검색 → query-docs로 구체 API 질의. 대상 예: firebase-ios-sdk, FlutterFire, AWS SDK, Stripe SDK.
3
Codex 위임 정책 · 교차검증 · 깊은 분석
codex-rescue 에이전트에 MODE=research, --write 없이 위임한다. ~/.claude/codex-prompt-template.md 템플릿 필수.
4
WebSearch fallback
위 셋으로 안 잡힐 때만. 검색어에 현재 연도 필수 (2026 Firebase setup). 연도가 없으면 deprecated 결과가 상위 노출된다.
Codex 위임

언제 쓸지

  • 정책 사실 검증 (예: Apple Bundle ID 변경 정책)
  • 여러 출처 교차검증이 필요할 때
  • WebFetch 한 페이지로 답이 안 나올 때
  • 깊은 분석 / 판단이 필요할 때

WebFetch로 닿지 않는 것 — 로그인 뒤 콘솔 화면

Firebase Console · Apple Developer Portal · App Store Connect의 로그인 뒤 실시간 UI는 어떤 도구로도 확인할 수 없다 (실측 2026-08-13). 이 한계를 인정하지 않으면 그럴듯한 버튼 흐름을 지어내게 된다.

없는 확신을 파는 서술
  • 공개 문서에 없는 버튼 단위 흐름을 "이렇게 생겼다"고 단정
  • 한국어 라벨을 정본으로 적음 — 영어 콘솔 사용자가 매칭 실패
  • 확인 못 한 화면을 [미검증:ENV]로 덮음 — 마커 오남용
  • "콘솔에서 앱을 등록하세요" 처럼 상위 섹션조차 없이 뭉뚱그림
경계를 표시하는 서술
  • 인용은 공개 문서에 실제로 적힌 라벨로 한정
  • 확정은 대개 상위 섹션명까지 — 그 아래는 "이 섹션에서 …"로 열어 둔다
  • 가이드 본문에 "로그인 뒤 화면은 다를 수 있다" 한 줄 + 검색어 제공
  • 공개 문서로 확인한 부분은 정상 출처이므로 마커를 붙이지 않는다

이것은 [미검증:ENV]를 붙일 사유가 아니다. 공개 문서로 확인한 부분은 정상 출처이고, 확인 못 한 부분은 애초에 쓰지 않는다. 마커는 "1차 출처 문서 자체에 접근이 불가했을 때" 쓰는 것이지, "로그인해야 보이는 화면이라 못 봤다"에 쓰는 것이 아니다.
버전 확인은 패키지 레지스트리 우선

SDK 버전은 GitHub Releases 페이지 대신 패키지 레지스트리(pub.dev / npm / crates.io / PyPI)를 1차로 쓴다. GitHub Releases는 breaking change 서술을 읽을 때만 보조로 쓴다.

소스실측 2026-07-27 결과용도
github.com/firebase/flutterfire/releases 2020년 프리릴리스만 반환 — 최신 버전 확인에 쓸 수 없었다 breaking change 서술 보조
pub.dev/packages/firebase_messaging 현행 버전과 firebase_core 제약을 즉시 반환 버전 확정 1차
규칙

가이드에 버전을 박지 않는다

문서에 고정한 버전은 몇 달 뒤 반드시 틀린다 — 이 킷의 예제 가이드 이전 판이 그랬다. 대신 설치 명령이 그 시점 최신 제약을 써 주게 한다.

flutter pub add firebase_core firebase_messaging

여러 firebase_* 패키지를 함께 쓸 때는 각 패키지 페이지에서 firebase_core 제약을 확인해 메이저를 맞춘다.

기록

어느 단계에서 얻었는지 남긴다

버전을 레지스트리에서 확정했으면 그 URL과 조회일을 해당 Step의 **출처:** 줄에 적는다. "최신 버전 설치"라고만 쓰면 재현이 불가능하다.

메이저 버전 차이가 발견되면 사용자에게 업그레이드 여부를 확인하고, breaking change가 있으면 마이그레이션 가이드를 별도로 조회한다.

Deprecated 감지 규칙 — 그리고 역방향 금지

매번 검색 결과에서 아래를 확인한다. 다만 감지와 단정은 다르다 — 1차 출처가 말하지 않은 것을 deprecated로 쓰는 것은 날조다.

감지 신호

매번 확인할 4가지

  • !문서/페이지의 마지막 업데이트 날짜 — 2년+ 자동 ⚠️ 경고 박스
  • !본문에 deprecated · legacy · old method · will be removed · removed in 키워드
  • !API/SDK 메이저 버전 변경 안내
  • !use X instead 같은 대체 권장
> **❌ Deprecated:** <옛 방법 + 비추천 이유>
> **✅ 현재 권장:** <새 방법 + 이유>

역방향 금지

출처보다 강한 주장도 날조다

"권장하지 않음(not recommended)" · "레거시" · "제거 예정"은 서로 다른 강도의 주장이다. 강도를 올려 옮기지 않는다.

실측 2026-07-27 · 재확인 2026-08-13: FCM Apple/Flutter 문서는 APNs 인증 키(.p8)를 안내하지만 인증서(.p12)를 deprecated로 표기하지 않는다. 이 문서에서 deprecated로 명시된 것은 Instance ID API다.

.p8을 권장한다는 사실로부터 .p12의 deprecation을 추론하지 마라. 이 승격은 guide_gate G4가 기계적으로 잡는다.

Fetch 실패 시 fallback 사다리

한 단계에서 실패하면 다음으로 내려가되, 어느 단계에서 얻었는지 기록한다. 네 단계 모두 실패하면 학습 데이터로 채우지 않는다.

1
대상 페이지 WebFetch
리다이렉트가 오면 최종 URL로 재시도한다. 본문 없음 = 문서 소멸이 아니다.
2
같은 공식 도메인의 인접 페이지
색인/개요 페이지에서 정확한 하위 경로를 확인한 뒤 재시도한다.
3
Context7 (SDK API 한정) → Codex 위임 (정책/교차검증)
API 시그니처는 Context7, 정책·교차검증은 Codex. 역할을 바꿔 쓰면 둘 다 느려진다.
4
WebSearch (현재 연도 포함)
마지막 수단. 검색어에 연도를 넣지 않으면 deprecated 결과가 상위에 온다.
네 단계 모두 실패했을 때

마커는 사다리를 탄 사람만 쓸 수 있다

**출처:** [미검증:ENV] — <시도한 단계와 실패 출력 · 통제 불가 사유 · 재검증 명령>

접미 없는 [미검증]은 정본에서 INVALID로 해석되므로 쓰지 않는다.

네 단계를 실제로 타지 않았으면 :ENV를 쓸 수 없다. 사다리를 건너뛴 주장은 [미검증:INVALID]로 강등되고, "이번엔 안 조회하기로 했다"는 마커가 아니라 그냥 미완이다.

마커 분류·카운터 분리·임계는 SKILL.md §출처 원장을 따르며, 그 정본은 harness/docs/guides/qa-evaluation-guide.md §Canonical Unverified-Evidence Protocol 이다 — 이 문서에서 임계 숫자를 재정의하지 않는다.

안티패턴 — 잘못된 정보 수집

아래 왼쪽은 전부 실제로 이 킷에서 발생했거나, 발생하면 사용자가 곧바로 막히는 패턴이다.

수집을 건너뛴 서술
  • 학습 데이터로 콘솔 클릭 경로를 재구성 — 라벨이 바뀌어 화면에서 못 찾음
  • GitHub Releases에서 버전 확인 — 실측상 2020년 프리릴리스만 나옴
  • 구 호스트(cloud.google.com/docs/)를 원장에 기록
  • .p8 권장 → .p12 deprecated로 승격 (출처보다 강한 주장)
  • 연도 없는 검색어로 WebSearch — deprecated 결과 상위 노출
  • 클릭 경로 중간 단계(General) 누락
수집 절차를 탄 서술
  • 매번 WebFetch로 공개 문서 라벨을 문서 표기 그대로 추출
  • 버전은 pub.dev 등 레지스트리에서 확정, 가이드엔 고정하지 않음
  • 리다이렉트 이후 최종 URL을 원장에 기록
  • 출처의 강도를 그대로 옮김 — 판단을 대신하지 않음
  • 검색어에 2026 포함
  • 클릭 경로 전 단계 명시 + 영문 라벨 정본
수집 결과가 없다는 것도 결과다. 레포를 읽을 수 있는데 Glob/Grep 결과가 0건인 것은 미검증이 아니라 "아직 없음"이라는 확정 사실이다. 그대로 쓴다. 레포 접근 자체가 불가한 환경일 때만 [미검증:ENV]를 4요건과 함께 붙인다.
