ONBOARDING KIT · SETUP GUIDE

최신 근거로 만드는 외부 서비스 설정 가이드

프로젝트 스택과 실제 파일을 먼저 확인하고, 각 Step의 1차 출처를 조회한 뒤 Firebase·GCP·AWS·FCM·OAuth·Stripe 같은 외부 서비스 설정 가이드를 만든다. “최신”이라는 말은 출처 원장과 결정론적 게이트로 증명한다.

Input

$ARGUMENTS는 특정 서비스에 집중할지, 프로젝트 전체를 스캔할지 결정한다.

  • /setup-guide fcm ios

  • 지정한 서비스와 기능에만 집중한다.

  • 선택 전에는 임의의 가이드를 쓰지 않는다.
핵심 원칙

deprecated된 정보로 사용자가 헤매지 않게 하는 것이 이 스킬의 존재 이유다. 콘솔 UI·버전·CLI·경로는 기억이 아니라 조회 결과로 쓴다.

1
Freshness

각 Step 전에 1차 출처 fetch

학습 데이터의 콘솔 UI 정보는 자주 outdated된다. Step을 쓰기 전에 공식 help 문서를 조회하고, 본문에 출처 URL과 조회일을 남긴다.

fetch하지 않은 Step은 쓰지 않는다. 대표 URL 하나로 전체 가이드를 정당화할 수 없다.

2
Current Year

검색어에 현재 연도 포함

연도 없이 검색하면 2~3년 전 deprecated 결과가 상위에 노출될 수 있다. 검색에는 반드시 현재 연도를 넣는다.

버전 번호, CLI 명령어, 콘솔 UI 경로는 그대로 실행할 수 있을 만큼 구체적으로 적는다.

3
Evidence

미검증은 접미로 분류

통제할 수 없는 접근 실패는 [미검증:ENV], fallback을 안 탔거나 출력이 입증하지 못하면 [미검증:INVALID]다.

접미 없는 [미검증]과 “미확인”, “N/A”, “unverified” 같은 동의어를 만들지 않는다.

Scope

Guide Conformance Gate · E3

규칙은 새 가이드뿐 아니라 이미 배포된 가이드에도 소급된다. 문장(E1)이나 자기보고 체크리스트(E2)가 아니라 LLM을 호출하지 않는 결정론적 게이트(E3)로 판정한다.

왜 필요한가: 2026-08-13 실측에서 쇼케이스 예제가 eval 6개 중 3개를 3개월간 위반했다. 출처 원장 0/8, Flutter 가이드의 네이티브 Swift 초기화, 출처에 없는 .p12 deprecated 단정이 남아 있었다.
게이트판정 대상핵심 조건
G1_LEDGER출처 원장 완전성Step 수와 출처 줄 수가 같고 각 Step에 출처가 정확히 하나
G2_MARKER미검증 마커접미 없는 레거시 0건, INVALID 2건 이상이면 FAIL, ENV는 별도 집계. 2는 이 킷의 새 임계가 아니라 현재 정본을 그대로 구현한 값이다.

함수 원문

원본 onboarding-kit/skills/setup-guide/SKILL.md 의 함수를 그대로 옮겼다. 게이트를 고칠 때는 원본을 먼저 고친다.

# Guide Conformance Gate — LLM 호출 없는 순수 판정. zsh · bash 동일 출력 (2026-08-13 양쪽 실행 확인).
# 사용: guide_gate <가이드.md> <스택>     예) guide_gate docs/setup/firebase/fcm-ios.md flutter
#       스택은 필수다 — 비우면 G3 가 FAIL 한다 (판정 불가를 PASS 로 흘리지 않는다)
guide_gate() {
  g=${1}; stack=${2:-}
  [ -f "$g" ] || { echo "GATE_BLOCKED no_such_file=$g"; return 0; }
  fence=$(printf '\140\140\140')   # 백틱 3 개 — 문서 렌더링 보호를 위해 8 진수로 생성
  fail=0

  # G1 출처 원장 완전성 — Step 수와 출처 줄 수가 같아야 한다 (열거값은 타이핑하지 말고 계산)
  steps=$(grep -c '^## Step ' "$g" || true)
  ledger=$(grep -c '^\*\*출처:\*\*' "$g" || true)
  #    전체 수만 맞추면 한 Step 에 출처 둘 · 다른 Step 에 0 인 배치가 통과한다 — Step 마다 정확히 하나인지 따로 센다
  misplaced=$(awk '
    function flush(){ if (st && n != 1) m++ }
    /^## /           { flush(); st=0; n=0 }
    /^## Step /      { st=1 }
    /^\*\*출처:\*\*/ { n++ }
    END              { flush(); print m+0 }
  ' "$g")
  if [ "$steps" -eq 0 ] || [ "$steps" -ne "$ledger" ]; then
    echo "G1_LEDGER FAIL steps=$steps ledger=$ledger"; fail=1
  elif [ "$misplaced" -ne 0 ]; then
    echo "G1_LEDGER FAIL steps=$steps ledger=$ledger misplaced=$misplaced"; fail=1
  else
    echo "G1_LEDGER PASS steps=$steps ledger=$ledger"
  fi

  # G2 미검증 마커 — 접미 없는 레거시 0 건 · INVALID 는 정본 임계 미만 (ENV 는 별도 카운터).
  #    아래 상수는 정본(qa-evaluation-guide §카운팅 및 자동 REJECT 임계)을 그대로 **구현**한 것이지
  #    킷이 새로 정한 값이 아니다. 정본이 바뀌면 이 상수도 같이 바꾼다 — 여기서 먼저 바꾸지 마라.
  bare=$(grep -oF '[미검증]' "$g" | grep -c . || true)
  inval=$(grep -oF '[미검증:INVALID]' "$g" | grep -c . || true)
  envg=$(grep -oF '[미검증:ENV]' "$g" | grep -c . || true)
  if [ "$bare" -ne 0 ] || [ "$inval" -ge 2 ]; then
    echo "G2_MARKER FAIL bare=$bare invalid=$inval env=$envg"; fail=1
  else
    echo "G2_MARKER PASS bare=$bare invalid=$inval env=$envg"
  fi

  # G3 스택 혼용 — Flutter 가이드에 네이티브 Swift 코드블록이 있으면 실패.
  #    산문으로 "Flutter 는 AppDelegate 를 건드리지 않는다" 고 쓰는 것은 통과한다 — 코드 지시만 잡는다.
  #    스택이 비어 있으면 PASS 가 아니라 FAIL 이다. 2026-09-08 까지는 빈 스택을 PASS 로 흘렸고,
  #    Drift 루프의 $STACK 이 어디에도 정의되지 않아 이 검사가 3 개월간 no-op 이었다.
  sw=$(grep -c "^${fence}swift" "$g" || true)
  if [ -z "$stack" ]; then
    echo "G3_STACKMIX FAIL stack=unset swift_fence=$sw"; fail=1
  elif [ "$stack" = "flutter" ] && [ "$sw" -ne 0 ]; then
    echo "G3_STACKMIX FAIL swift_fence=$sw"; fail=1
  else
    echo "G3_STACKMIX PASS stack=$stack swift_fence=$sw"
  fi

  # G4 deprecation 주장 결합 — Deprecated 박스를 쓴 Step 은 그 Step 의 출처 줄이
  #    "출처가 실제로 deprecated 라고 말했다" 는 근거를 담아야 한다 (출처보다 강한 주장 금지).
  #    근거 토큰은 영문(deprecated/sunset/removed)과 한국어(지원 종료/폐지/중단/서비스 종료/단종)를
  #    모두 인정한다 — 영문 토큰에만 묶여 있던 동안 한국어 1 차 출처는 근거가 있어도 FAIL 이었다.
  g4=$(awk '
    function flush(){ if (st != "" && dep && src !~ /[Dd]eprecat|[Ss]unset|[Rr]emoved|지원 ?종료|폐지|중단|서비스 종료|단종/) print ln }
    /^## /           { flush(); st=""; src=""; dep=0 }
    /^## Step /      { st=$(0); ln=FNR }
    /^\*\*출처:\*\*/ { src=$(0) }
    /❌ Deprecated/  { dep=1 }
    END              { flush() }
  ' "$g" | grep -c . || true)
  if [ "$g4" -ne 0 ]; then
    echo "G4_DEPRECATION FAIL unsourced_boxes=$g4"; fail=1
  else
    echo "G4_DEPRECATION PASS unsourced_boxes=0"
  fi

  [ "$fail" -eq 0 ] && echo GATE_PASS || echo GATE_FAIL
}
  • !
    게이트 출력 5줄을 보고에 그대로 붙인다. “통과함”이라는 문장은 증거가 아니다.
  • !
    G3는 스택 인자가 비어 있으면 FAIL이다. 판정 불가를 PASS로 흘리지 않는다.
  • !
    GATE_FAIL이면 완료 보고를 중단하고 수정한 뒤 다시 실행한다.
  • !
    게이트를 우회하거나 느슨하게 바꾸지 않는다. 정당한 케이스를 막으면 사용자 판단을 받는다.
  • !
    함수를 바꿨다면 sh onboarding-kit/skills/setup-guide/evals/run-gate-evals.sh가 EVALS_PASS로 끝나야 한다.
  • !
    게이트가 잡는 것은 네 가지뿐이다. 사실 정확성·스코프·경로 날조는 별도 검증한다.
Gotchas (반복 실수 방지)

반복 실패를 막는 9개 체크다. 서비스 절차뿐 아니라 스택, 공개 문서의 한계, 범위, 저장소 근거, 비밀 보호까지 통제한다.

  • 1
    스택 확정 없이 작성 금지. Flutter·네이티브 iOS·React Native·Node 백엔드는 SDK, 초기화 코드, CLI가 다르다. 탐지 실패 시 명시적으로 묻는다.
  • 2
    로그인 뒤 콘솔 화면은 검증 불가. 공개 문서에 적힌 라벨만 인용하고 버튼 단위 흐름을 단정하지 않는다. 화면 차이 안내와 상위 섹션 검색어를 남긴다.
  • 3
    Apple 사이트는 작업별로 나눈다. 키·식별자 발급은 Developer Account, 앱 레코드와 배포는 App Store Connect다. GCP/Firebase와 AWS Console/Marketplace도 구분한다.
  • 4
    글로벌 유니크 식별자 충돌. Bundle ID, Package Name, Project ID의 “not available” 해결책으로 조직·도메인의 reverse prefix를 안내한다.
  • 5
    등록과 활성화는 다르다. App ID와 Provisioning Profile, Firebase 프로젝트와 APNs Key 업로드를 별도 단계로 쓴다.
  • 6
    출시 후 변경 불가 정책. Bundle ID는 빌드 업로드 뒤, Firebase Project ID는 생성 뒤 변경 불가임을 사전 요구사항에 둔다.
  • 7
    임의 확장 금지. FCM에 Analytics·Crashlytics·Remote Config를, Stripe에 webhook·refund·subscription을, 단순 셋업에 CI/CD·모니터링·IaC를 자동 추가하지 않는다.
  • 8
    경로·파일명·env 키 날조 금지. 패턴으로 탐색하고 파일:라인으로 열거한다. 0건이면 새로 만든다고 적거나 묻는다. 값이 든 env 파일은 열지 않는다.
  • 9
    막는 요구는 세 칸으로. 실기기·유료 계정·출시 여부마다 출처, 실제로 막히는 작업, 확인된 우회를 적는다.

막는 요구의 세 칸

실기기·유료 계정·출시 필요를 단독으로 쓰면 셋업 전체가 막힌 것으로 오해된다.

1

출처

요구를 실제로 명시한 1차 출처를 연결한다. 출처가 요구하지 않은 조건은 만들지 않는다.

2

막히는 것

출처에서 확인한 우회만 쓴다. 없으면 우회 없음(출처 확인)으로 기록한다.

Process

스택 확정부터 완료 증거까지 네 단계로 진행한다. 기존 가이드가 있으면 새로 쓰기 전에 drift부터 측정한다.

Phase 1
스택 + 외부 서비스 탐지
  1. 의존성 파일 매핑으로 스택을 확정한다. 멀티스택이면 사용자에게 확인한다.
  2. 의존성 파일, .env.example, docker-compose*.yml, terraform/, SDK 초기화 패턴을 종합한다.
  3. 특정 서비스 인자는 집중하고, 빈 인자는 탐지 목록을 제시한 뒤 선택받는다.
  4. 같은 가이드가 이미 있으면 Regeneration Drift 검사를 실행한다.
STACK=flutter   # Phase 1 에서 확정한 스택을 그대로 쓴다. 비워 두면 G3 가 FAIL 한다.
                # 2026-09-08 까지는 이 변수가 어디에도 정의되지 않아 G3 가 항상 PASS 하는 no-op 이었다.
find docs/setup -type f -name '*.md' 2>/dev/null | while IFS= read -r f; do
  printf '%s\n' "--- $f"; guide_gate "$f" "$STACK"
done

GATE_FAIL이 나오면 그것이 첫 산출물이다. 새로 쓸지 기존 것을 고칠지 확인한다. zsh nomatch를 피하려 글로브 대신 find를 쓴다.

Phase 2
최신 정보 수집
순서도구역할
1WebFetch콘솔 UI와 공식 help 페이지 직접 fetch
2Context7SDK API: resolve-library-id → query-docs
3Codex 위임정책 검증·교차검증·깊은 분석
4WebSearchfallback. 검색어에 현재 연도 필수

업데이트 2년 이상, deprecated·legacy·will be removed, 메이저 버전 변경 안내가 있으면 경고와 현재 방법을 함께 쓴다. 출처가 deprecated라고 하지 않았다면 더 강하게 단정하지 않는다.

크로스호스트 리다이렉트 URL을 받으면 새 URL을 다시 fetch하고 원장에는 최종 canonical host를 기록한다.

Phase 3
가이드 MD 생성

references/format-checklist.md의 11개 섹션을 순서대로 채운다. 기본 위치는 docs/setup/<서비스명>/<기능명>.md이며 사용자 지정 위치가 우선이다.

FCM·Analytics·Crashlytics처럼 하위 기능이 여러 개면 각각 별도 파일로 분리한다. 해당 없는 섹션은 한 줄로 닫거나 생략한다.

Phase 4
검증 + 완료 안내
  1. Guide Conformance Gate를 먼저 실행하고 5줄 출력을 그대로 보고한다.
  2. 프로젝트 경로와 env 키를 Glob/Grep 실측 근거와 대조한다.
  3. 외부 URL이 공식 도메인이며 현재 canonical host인지 확인한다.
  4. 11개 포맷 섹션 누락을 확인한다.
  5. 막는 요구마다 출처·막히는 것·우회 세 칸을 확인한다.
  6. G2의 bare·invalid·env 숫자를 그대로 보고한다.
  7. 파일 경로, “막히는 부분 알려주세요”, 코드 지원, 콘솔 화면 차이를 안내한다.
수치 기준과 실측

원본에 명시된 숫자만 모았다. 임계 숫자는 Harness 정본이 소유하므로 여기서 새로 정의하지 않는다.

Gotchas 체크리스트

완료 선언 직전에 확인한다. 하나라도 충족하지 못하면 완료가 아니다.

  • ✓
    스택이 실제 의존성 파일로 확정되었고 멀티스택이면 사용자 선택을 받았다.
  • ✓
    각 Step에 정확히 하나의 1차 출처 URL과 조회일이 있다.
  • ✓
    접미 없는 미검증 마커가 없고 ENV에는 네 근거가 모두 있다.
  • ✓
    로그인 뒤 화면의 한계와 상위 섹션 검색어를 안내했다.
  • ✓
    Apple·Google Cloud·AWS의 사이트 역할을 작업 기준으로 구분했다.
  • ✓
    유니크 식별자 충돌과 변경 불가 정책을 반영했다.
  • ✓
    요청하지 않은 인접 서비스·CI/CD·모니터링·IaC로 확장하지 않았다.
  • ✓
    경로와 env 키는 실측 근거가 있고 비밀 파일을 열지 않았다.
  • ✓
    막는 요구마다 출처·막히는 작업·확인된 우회가 있다.
  • ✓
    기존 가이드가 있다면 drift 게이트를 먼저 실행했다.
  • ✓
    외부 URL이 공식 도메인과 최종 canonical host를 사용한다.
  • ✓
    11개 섹션을 확인했고 해당 없는 내용을 날조하지 않았다.
  • ✓
    G1~G4와 최종 판정 5줄, bare·invalid·env를 보고한다.
