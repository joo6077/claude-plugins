Setup Guide — 외부 서비스 셋업 가이드 자동 생성

Firebase, GCP, AWS, FCM, OAuth, Stripe 등 외부 서비스의 step-by-step 설정 가이드를 그 시점 최신 정보 기반으로 자동 생성한다. WebFetch → Context7 → Codex 우선순위로 deprecated 정보를 회피하고, 11개 표준 섹션으로 누락 없는 가이드를 만든다.

핵심 원칙 (Core Principles)

이 스킬의 존재 이유는 deprecated된 정보로 사용자가 헤매지 않도록 하는 것이다. 학습 데이터의 콘솔 UI 정보는 자주 outdated되어, 매번 1차 출처를 직접 fetch해야 정확한 안내가 가능하다.

1
Freshness First

매번 1차 출처 fetch

콘솔 UI 클릭 경로, 메뉴 라벨, 버튼 이름은 수시로 바뀐다. 학습 데이터로 답하면 사용자가 화면에서 못 찾는다. Apple Developer Portal, Firebase Console, AWS 콘솔 — 어느 플랫폼이든 매번 WebFetch로 현재 상태를 직접 확인한다.

검색 시 반드시 현재 연도 포함 — 연도 없이 검색하면 2~3년 전 deprecated 결과가 상위 노출된다.

↗ firebase.google.com/docs/cloud-messaging
2
Stack First

스택 확정 전 가이드 작성 금지

Flutter / 네이티브 iOS / React Native / Node 백엔드는 같은 서비스라도 SDK 설치 명령, 초기화 코드, CLI 자동화 도구가 완전히 다르다. 스택 확정 없이 작성을 시작하면 사용자가 잘못된 코드를 복사·붙여넣기 하게 된다.

탐지 실패 시 → 명시적으로 질문: "Flutter iOS 기준? 네이티브 Swift 기준?"

↗ firebase.flutter.dev (FlutterFire)
3
Specificity

버전·경로·명령어 구체화

버전 번호, CLI 명령어, 콘솔 UI 경로는 구체적으로 기술한다. "Firebase 설정 페이지에 가세요"가 아니라 "Firebase Console → 프로젝트 설정 ⚙️ → 클라우드 메시징 탭 → Apple 앱 구성 섹션"까지 드릴다운한다.

모호한 안내는 콘솔 UI 변경 시마다 사용자가 헤맨다.

↗ Apple Developer — App ID 등록
4
Deprecated Surfacing

Deprecated 발견 시 명시 경고

deprecated 정보를 조용히 넘어가지 않는다. 가이드 안에 명시적 경고 박스를 삽입한다:

❌ Deprecated: APNs Certificate (.p12)
   매년 갱신 필요, 2020년 이후 비권장
✅ 현재 권장: APNs Key (.p8)
   갱신 불필요, dev/prod 모두 커버
↗ Firebase — APNs 인증서 vs 키
트리거 조건 (Triggers)

설정/세팅/연동/가이드 키워드와 외부 서비스명이 함께 나오면 반드시 트리거된다. 아래 표는 트리거되는 케이스와 트리거되지 않는 케이스를 구분한다.

트리거 — setup-guide 실행
  • "FCM 설정해야 해", "Firebase 어떻게 연동해?"
  • "GCP 설정 가이드 만들어줘"
  • "OAuth 설정", "서드파티 연동 방법"
  • "Stripe 연동 가이드", "push notification 세팅"
  • "외부 서비스 설정", "셋업 가이드 만들어줘"
  • 설정 키워드 + 서비스명 동시 언급
비트리거 — 다른 접근 필요
  • 외부 서비스 언급 없는 일반 코드 질문
  • 이미 완성된 가이드의 코드 수정 요청
  • 서비스 기능 설명만 요청 ("FCM이 뭐야?")
  • 이미 설정 완료된 서비스의 디버깅 요청
인자 사용법: /setup-guide firebase — 특정 서비스 집중. /setup-guide fcm ios — 서비스 + 플랫폼 지정. /setup-guide — 빈 인자로 프로젝트 전체 스캔 후 탐지한 서비스 목록을 사용자에게 제시하고 선택받는다.
4단계 프로세스 (Phases)

스킬은 4개 Phase로 실행된다. Phase 1에서 스택과 서비스를 확정하지 않으면 Phase 3에서 잘못된 가이드가 생성된다 — 건너뛰기 금지.

1
Phase 1

스택 + 외부 서비스 탐지

의존성 파일 글로브 탐색으로 스택을 확정한다. pubspec.yaml → Flutter, Cargo.toml → Rust, package.json → Node/JS. 멀티스택 모노레포라면 하위 디렉토리별로 재스캔한다.

외부 서비스 탐지는 3가지 소스를 종합한다: 의존성 파일, .env* 환경변수, 코드 grep (firebase_core, Sentry.init, stripe.api_key 등).

탐지 결과 0건이면 사용자에게 명시적 질문 — 추측 금지.

↗ pub.dev — firebase_messaging
2
Phase 2

최신 정보 수집

WebFetch → Context7 → Codex → WebSearch 우선순위로 수집한다. 각 도구의 역할이 다르다: WebFetch는 콘솔 UI 경로, Context7는 SDK API 시그니처, Codex는 정책 교차검증, WebSearch는 최후 fallback.

deprecated 감지: 문서 마지막 업데이트 2년+, "deprecated/legacy/will be removed" 키워드, 메이저 버전 변경 안내 중 하나라도 발견하면 가이드에 경고 박스 삽입.

↗ Firebase — FCM iOS 공식 가이드
3
Phase 3

가이드 MD 생성

references/format-checklist.md의 11개 섹션을 순서대로 채운다. 섹션 순서는 사용자가 따라가는 흐름 — 헤더 → 사전 요구사항 → 설정 단계 → 프로젝트 코드 변경 → 권한/IAM → 비용 → 환경 분기 → Rollback → 보안 → 검증 → 트러블슈팅.

저장 위치 기본값: docs/setup/<서비스명>/<기능명>.md. 여러 하위 기능(Firebase → FCM, Analytics, Crashlytics)이면 각각 별도 파일로 분리.

↗ FlutterFire — Messaging 사용법
4
Phase 4

검증 + 완료 안내

생성된 가이드의 모든 외부 URL이 공식 도메인인지 검증한다 (developer.apple.com, firebase.google.com 등). 11개 섹션 누락 여부를 체크한다.

사용자에게 파일 경로와 "막히는 부분 알려주세요" 안내를 함께 전달. 사용자가 코드 변경에 도움 필요하면 직접 도와줄 수 있음도 안내한다.

↗ Apple — App ID 등록 가이드
Gotchas — 반복 실수 방지

아래 6가지는 가이드 생성 시 반복되는 실수 패턴이다. 각 Gotcha는 실제 사용자가 겪는 문제에서 수집되었다.

  • !
    Gotcha 1 — 스택 확정 없이 가이드 작성 금지. Flutter / 네이티브 iOS / React Native / Node 백엔드는 같은 서비스라도 SDK, 코드, CLI가 완전히 다르다. 탐지 실패 시 추측하지 말고 사용자에게 묻는다.
  • !
    Gotcha 2 — 콘솔 UI 클릭 경로는 학습 데이터 추측 금지. Apple Developer Portal, Firebase Console 등의 버튼 옵션, 메뉴 라벨, 화면 순서는 자주 바뀐다. WebFetch 우선 — Codex 위임보다 빠르고 정확하다.
  • !
    Gotcha 3 — Apple 사이트 혼동 주의. Apple Developer Portal (developer.apple.com/account) — App ID·인증서·키 발급. 셋업의 99%가 여기. App Store Connect (appstoreconnect.apple.com) — 앱 출시·심사용, 셋업 단계엔 거의 안 들어감. 가이드 사전 요구사항 섹션에 두 사이트 차이 표 필수.
  • !
    Gotcha 4 — 글로벌 유니크 식별자 충돌. Bundle ID (Apple), Package Name (Android), Project ID (GCP/Firebase)는 전 세계 모든 계정에 걸쳐 유니크해야 한다. 흔한 조합(com.fitpal.app)은 선점됐을 확률이 높다. 가이드 트러블슈팅에 "not available" 에러 케이스 자동 포함.
  • !
    Gotcha 5 — 등록 ≠ 활성화. App ID 등록과 Provisioning Profile 생성은 별개. Firebase 프로젝트 생성과 APNs Key 업로드는 별개. 단계별 분리 명시 — 연결 없이 나열하면 사용자가 놓친다.
  • !
    Gotcha 6 — 출시 후 변경 불가 정책. Bundle ID는 빌드 업로드 후 변경 불가. Firebase Project ID도 생성 후 변경 불가. 가이드 사전 요구사항 섹션 맨 위에 경고. 한 번 실수하면 신규 ID로 전체 재구성이 필요하다.
서비스별 1차 출처 매핑

가이드 생성 시 각 서비스의 공식 도메인을 반드시 사용해야 한다. 비공식 블로그, StackOverflow, 중간 인용 페이지는 1차 출처로 인정하지 않는다.

서비스 1차 출처 도메인 WebFetch 주요 경로 Context7 라이브러리
Apple / APNs developer.apple.com/help/account/ identifiers, keys, devices, profiles 하위 —
Firebase / FCM firebase.google.com/docs/ cloud-messaging, ios/client, ios/certs firebase-ios-sdk, FlutterFire
Google Cloud (GCP) cloud.google.com/docs/ IAM, service-accounts, resource-manager google-cloud-* SDK
AWS docs.aws.amazon.com/ IAM, S3, SNS, SES 각 서비스 하위 @aws-sdk/, boto3
Stripe stripe.com/docs/ payments, api, webhooks stripe SDK (각 언어별)
Sentry docs.sentry.io/ platforms, product, api sentry-sdk
OAuth 2.0 oauth.net/2/ + 각 provider 공식 docs provider별 developer console next-auth, passport-*

비공식 출처에서 얻은 정보는 반드시 위 1차 도메인 교차검증 후 사용

안티패턴 비교

아래는 잘못된 가이드 생성 패턴과 올바른 패턴의 대비다. 나쁜 패턴은 실제로 사용자가 헤맨 케이스에서 수집되었다.

잘못된 패턴 — 사용자 혼란 유발
  • "Firebase 콘솔에서 설정하세요" — 경로 미명시
  • APNs Certificate (.p12) 방식 그대로 안내 — 2020년 이후 deprecated
  • 스택 미확정 상태로 Flutter + Swift 코드 혼용
  • Bundle ID를 com.example.app으로 안내 — 충돌 위험
  • App Store Connect와 Apple Developer Portal 혼용
  • 보안 체크리스트 없이 .p8 파일 저장 방법 미언급
올바른 패턴 — 막힘 없는 가이드
  • "Firebase Console → 프로젝트 설정 ⚙️ → 클라우드 메시징 탭 → Apple 앱 구성" 드릴다운
  • ❌ Deprecated: .p12 / ✅ 현재 권장: .p8 박스 삽입
  • 스택 확정 후 Flutter 전용 코드만 제공
  • 조직 reverse prefix 강조 + 충돌 트러블슈팅 포함
  • 사이트 혼동 주의 표 삽입 (Developer Portal vs App Store Connect)
  • 보안 체크리스트 섹션에 .p8 안전 저장, .gitignore 추가 명시
생성 완료 검증 체크리스트

Phase 4에서 생성된 가이드를 제출하기 전에 아래 항목을 체크한다. 하나라도 FAIL이면 수정 후 재검증한다.

  • ✓
    11개 섹션이 순서대로 모두 포함됨 — 헤더, 사전 요구사항, 설정 단계, 프로젝트 코드 변경, 권한/IAM, 비용, 환경 분기, Rollback, 보안, 검증, 트러블슈팅
  • ✓
    모든 외부 URL이 공식 도메인 (developer.apple.com, firebase.google.com 등) — bare URL이 아닌 마크다운 링크 형식
  • ✓
    각 Step이 3단 구조: 어디서 (URL 또는 터미널 위치) + 무엇을 (클릭 경로 또는 명령어) + 확인 방법
  • ✓
    deprecated 정보 발견 시 ❌/✅ 박스로 명시 — 조용한 생략 금지
  • ✓
    글로벌 유니크 식별자(Bundle ID, Package Name, Project ID) 관련 경고 및 트러블슈팅 포함
  • ✓
    헤더에 작성일, 기준 버전, 공식 문서 URL 세 가지 모두 기재
  • ✓
    사전 요구사항 섹션에 사이트 혼동 주의 표 포함 (Apple/Google 가이드는 필수)
  • ✓
    보안 체크리스트: 비밀 키 안전 저장, .gitignore 패턴, 클라이언트 노출 가능 vs 서버 전용 키 구분
  • ✓
    환경 분기 섹션: dev / staging / prod 분리 패턴 및 Build Configuration 별 차이 안내
  • ✓
    트러블슈팅: 증상 + 원인 + 해결 3단 구조로 최소 3개 에러 케이스 포함
