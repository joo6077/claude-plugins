# onboarding-kit Design — 2026-05-18

## 배경

fit-pal 프로젝트의 `setup-guide` 스킬(`.claude/skills/setup-guide/`)을 독립 플러그인 킷으로 격상한다. 외부 서비스(Firebase, GCP, AWS, FCM, OAuth, Stripe 등) 콘솔 설정을 **그 시점 최신 정보** 기준 step-by-step 가이드로 자동 생성하는 것이 목적. 사용자가 deprecated 정보로 헤매지 않는 것이 핵심 가치.

## 범위

### In scope

- `onboarding-kit` 플러그인 (1 스킬 킷, bambu-kit 패턴)
- 스킬: `/setup-guide` — 그 시점 최신 정보 기반 외부 서비스 셋업 가이드 MD 생성
- 이 레포 개발용: `.claude/skills/onboarding-kaizen/` (스킬 자체 카이젠)
- kaizen-orchestrator 신규 Phase 등록

### Out of scope

- 서비스별 골격 references/services/ 카탈로그 (매 호출 시점에 최신 정보 fetch가 본질)
- 환경 자동 셋업(`/setup-init`) — 별도 스킬 제안되지 않음
- `/onboarding-research` — references/services/ 카탈로그가 없으므로 폴링 대상 없음
- fit-pal의 기존 `.claude/skills/setup-guide/` 직접 삭제 — 사용자가 검증 후 결정

## SKILL.md 보강 규칙

### Process (순서 강제)

1. **스택 확정** — `pubspec.yaml` / `Cargo.toml` / `package.json` / `requirements.txt` / `Podfile` / `go.mod` / `Gemfile` 등 스캔. 멀티스택 모노레포면 사용자에게 명시적 확인. 출처: [[setup-guide-stack-first]]
2. **외부 서비스 의존성 탐지** — 의존성 파일 + 설정 파일(`.env*`, `docker-compose*.yml`, `terraform/`) + 코드 grep(SDK 초기화 패턴)
3. **검색 전략 (우선순위 명시)**
   - **WebFetch 우선**: 콘솔 UI/공식 help 페이지 — 빠르고 정확. 출처: [[setup-guide-console-ui-fetch]]
   - **Context7**: SDK API 문서 (`resolve-library-id` → `query-docs`)
   - **Codex 위임**: 정책 검증, 여러 출처 교차검증, 깊은 분석. read-only `MODE=research`
   - **WebSearch fallback**: 검색어에 현재 연도 필수
4. **Deprecated 감지** — 문서 마지막 업데이트 날짜 추출. 2년+ 자동 경고. "deprecated/legacy/will be removed" 키워드 분리 박스(❌ Deprecated / ✅ 현재 권장)
5. **가이드 생성** — 아래 포맷
6. **검증 체크리스트 + 트러블슈팅**

### 가이드 포맷

기존 6개 섹션(사전 요구사항, 설정 단계, 프로젝트 코드 변경, 검증 체크리스트, 트러블슈팅) + 신규 5개 섹션:

| 섹션 | 목적 |
|------|------|
| 권한/IAM | 최소 권한 원칙, 역할 부여 절차 |
| 비용 | 무료 한도, 유료 진입점, 예상 월비용 |
| 환경 분기 | dev/staging/prod별 차이 (별도 프로젝트/별도 키) |
| Rollback / 정리 | 잘못 설정 시 되돌리는 법, 사용 안 할 때 리소스 정리 |
| 보안 체크 | 키 노출 방지, 시크릿 저장, 클라이언트/서버 노출 구분 |

Step별 3단 구조: **어디서** (URL/터미널) → **무엇을** (클릭 경로/명령어) → **확인 방법**.

### Gotchas (반복 실수 방지)

- **사이트 혼동 사전 박기** — Apple/Google/AWS는 두 사이트 차이를 사전 요구사항에 표로. 출처: [[setup-guide-site-distinction]]
- **글로벌 유니크 식별자 충돌** — Bundle ID, Package Name, Domain 등은 충돌 케이스 자동 트러블슈팅 포함
- **등록 ≠ 활성화** — App ID 등록과 Provisioning Profile 생성은 별개 등 단계별 분리 명시
- **출시 후 변경 불가 정책** — 식별자/Bundle ID/Project ID 등 일부는 출시 후 변경 불가 — 가이드 작성 단계에서 사용자에게 경고

## `/onboarding-kaizen` (이 레포 개발용)

bambu-kaizen/rust-kaizen 패턴.

```text
.claude/skills/onboarding-kaizen/
├── SKILL.md
└── references/
    └── research-sources.md   # Apple/Firebase/GCP/AWS/Stripe 공식 docs URL 목록
```

**역할:**

- onboarding-kit `/setup-guide` SKILL.md + references/ + evals/ 주기적 개선
- 사용자 피드백 메모리(`feedback_setup_guide_*`) 신규 패턴 자동 반영
- 외부 소스 폴링: Apple Developer Account Help, Firebase docs changelog 등

**트리거:**

- `/kaizen` 전체 실행 시 자동 Phase로 호출
- 수동 호출: `/onboarding-kaizen`
- 이벤트: setup-guide 관련 feedback 메모리 누적 (3개+)

## evals 시나리오

`onboarding-kit/skills/setup-guide/evals/evals.json`에 최소 4개:

1. "Firebase FCM iOS Flutter 가이드 생성" — Flutter 스택 자동 감지 + flutterfire CLI 흐름
2. "스택 미감지 사용자 입력 요청" — pubspec/Cargo/package.json 없는 경우 사용자에게 스택 확인
3. "Apple 가이드 사이트 구분 명시" — App Store Connect vs Developer Portal 표 포함
4. "deprecated API 검색 시 경고 박스" — 2년+ 문서 검색되면 ⚠️ Deprecated 박스 자동 삽입
