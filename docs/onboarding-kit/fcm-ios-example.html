사이트 혼동 주의 박스가 맨 위에 위치한다. Apple Developer Portal과 App Store Connect를 혼동하면 필요한 버튼 자체가 없어서 막히게 된다.

⚠️ 사이트 혼동 주의 (Gotcha 3): FCM 셋업의 Apple 쪽 작업은 Apple Developer Portal (developer.apple.com/account)에서 한다. App Store Connect (appstoreconnect.apple.com)는 앱 출시·심사용으로 완전히 다른 사이트. 셋업 단계에서는 거의 들어가지 않는다.
  • □ Apple Developer Program 가입 (연 $99) — Account Holder 또는 Admin 권한 필요
  • □ Firebase 프로젝트 존재 — Editor 이상 권한
  • □ Xcode 16+ 설치 — xcodebuild -version으로 확인
  • □ 앱 Bundle ID 확정 — 예: com.yourorg.fitpal. 등록 후 변경 불가 (Gotcha 6)
  • □ 실기기 — FCM 시뮬레이터도 토큰 수신은 가능하나 발송 테스트는 실기기 필요 (iOS 16+는 시뮬레이터 일부 지원)

어디서: https://developer.apple.com/account → Certificates, Identifiers & Profiles → Identifiers
1Apple Developer에서 App ID에 Push 활성화
  1. 1.Identifiers 페이지 상단 + 버튼 클릭
  2. 2.식별자 유형 선택 → App IDs 선택 → Continue
  3. 3.App ID Type → Explicit 선택 (Wildcard는 Push 불가) → Continue
  4. 4.Description 입력 + Bundle ID 입력 (예: com.yourorg.fitpal)
  5. 5.Capabilities 섹션 → Push Notifications 체크박스 활성화
  6. 6.Continue → 검토 → Register
⚠️ Bundle ID 변경 불가 (Gotcha 6): App Store Connect에 빌드를 한 번이라도 업로드하면 Bundle ID 변경 불가. 변경 필요 시 신규 ID로 전체 재구성 필요.
확인 방법: Identifiers 목록에 새 App ID 표시 + 상세 화면 Capabilities 섹션에 Push Notifications 활성화 표시
어디서: https://developer.apple.com/account → Keys
2APNs Authentication Key (.p8) 발급
❌ Deprecated — 사용하지 마세요

APNs Certificate (.p12) 방식 — 매년 갱신 필요, 환경별 분리, 2020년 이후 비권장. WebFetch 결과: apple.com/help/account/ 현재 페이지에서 Key 방식만 권장.

✅ 현재 권장 — APNs Authentication Key (.p8)

갱신 불필요, dev/prod 모두 커버, Team 전체 앱 공유 가능. 단 한 번만 다운로드 가능 — 분실 시 revoke 후 재발급 필요.

  1. 1.Keys 페이지 → + 버튼 클릭
  2. 2.Key Name 입력 (예: "FCM APNs Key")
  3. 3.Apple Push Notification service 체크 → Configure
  4. 4.Key Restriction → Team Scoped (All Topics) 권장
  5. 5.Save → Continue → Register → Download (.p8 파일)
  6. 6.Key ID (10자리) 메모 + Team ID (Membership Details에서 확인)
🔒 보안 경고: .p8 파일은 단 한 번만 다운로드 가능. 1Password / GCP Secret Manager / AWS Secrets Manager에 즉시 저장. git 커밋 절대 금지.
확인 방법: Keys 목록에 Key Name 표시 + Key ID 확인. .p8 파일이 다운로드 폴더에 존재.

Dart 초기화 + 백그라운드 핸들러

// 백그라운드 핸들러: top-level + @pragma 필수
@pragma('vm:entry-point')
Future<void> _bgHandler(RemoteMessage msg) async {
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
}

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  FirebaseMessaging.onBackgroundMessage(_bgHandler);
  runApp(const MyApp());
}

@pragma('vm:entry-point') 없으면 릴리스 빌드에서 트리 쉐이킹으로 제거됨.

    alert: true, badge: true, sound: true,
  );

  if (settings.authorizationStatus == AuthorizationStatus.authorized ||
      settings.authorizationStatus == AuthorizationStatus.provisional) {
    final token = await messaging.getToken();
    // TODO: 서버에 token 저장 (사용자별 격리)

    messaging.onTokenRefresh.listen((newToken) {
      // TODO: 서버에 새 토큰 업데이트
    });
  }

  // iOS 포그라운드 알림 배너·사운드 표시
  await messaging.setForegroundNotificationPresentationOptions(
    alert: true, badge: true, sound: true,
  );

  // 포그라운드 메시지 수신
  FirebaseMessaging.onMessage.listen((RemoteMessage msg) {
    print('Foreground: ${msg.notification?.title}');
  });
}

5개의 실제 에러 케이스. 각각 증상 + 원인 + 해결 3단 구조를 따른다. 글로벌 유니크 식별자 충돌(Gotcha 4)과 등록/활성화 혼동(Gotcha 5) 케이스 포함.

트러블슈팅 케이스 1

증상: Xcode 콘솔에 FCM token: nil이 계속 출력

원인: APNs 토큰이 먼저 와야 FCM 토큰이 생성됨. APNs 등록 실패가 원인.

해결:
1. didFailToRegisterForRemoteNotificationsWithError 콜백 에러 메시지 확인
2. Provisioning Profile에 aps-environment entitlement 포함 확인
3. 실기기인지 확인 (iOS 16 이전 시뮬레이터는 APNs 불가)

↗ FlutterFire — FCM 토큰 취득
트러블슈팅 케이스 2

증상: Firebase Console 테스트 발송 성공인데 디바이스에 알림 안 옴

원인: APNs Key 업로드 시 Key ID 또는 Team ID 불일치.

해결: Firebase Console → 프로젝트 설정 → 클라우드 메시징 → APNs 인증 키 행의 Key ID와 Apple Developer Keys 페이지 ID 비교. 다르면 삭제 후 재업로드.

↗ Firebase — APNs Key 업로드
트러블슈팅 케이스 3 — Gotcha 4

증상: App ID 등록 시 "An App ID with Identifier 'com.example.app' is not available"

원인: Apple은 Bundle ID를 전 세계 Developer 계정에 걸쳐 유니크하게 관리. 흔한 조합은 이미 선점됨.

해결:
1. 조직/핸들 prefix 강화: com.<github핸들>.appname
2. 환경 suffix 추가: .dev, .staging, .prod
3. 본인 계정에 이미 같은 ID가 있다면 Identifiers에서 재사용 가능

↗ Apple — Bundle ID 유니크 정책
트러블슈팅 케이스 4 — Gotcha 5

증상: Xcode Signing & Capabilities에서 Push Notifications가 안 보이거나 회색

원인: Apple Developer Portal의 App ID에 Push Notifications capability 미활성. 또는 무료 개인 계정 Team 사용 (Push 불가).

해결:
1. Identifiers 페이지 → App ID → Capabilities → Push Notifications 체크 → Save
2. Xcode Team이 유료 Apple Developer 계정인지 확인 (Free 표기면 Push 불가)
3. Xcode 재시작 후 자동 동기화 대기

↗ Apple — Push Notifications Capability
트러블슈팅 케이스 5

증상: 앱이 죽은 상태(force quit)에서 푸시가 안 옴

원인: 사용자가 Settings에서 푸시 권한을 끔, 또는 silent push(data-only 메시지)만 발송 중.

해결: 알림 페이로드에 notification 객체(title/body) 포함 확인. data만 있으면 silent push로 분류되어 죽은 앱은 깨우지 않음. FCM Console의 테스트 메시지는 notification + data 모두 포함하므로 서버 발송 코드에서 페이로드 구조 확인.

↗ FlutterFire — 백그라운드 메시지 처리
