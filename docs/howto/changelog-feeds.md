# 변경 로그 폴링 대상 — 벤더별 피드 실측

`last_updated: 2026-09-09`

절차 안내 문서는 만든 순간부터 낡는다. 콘솔 라벨이 바뀌고 메뉴가 옮겨간다. 이 문서는 그 변화를
**언제 알아챌 것인가**에 답한다 — 각 벤더의 변경 로그를 기계로 읽을 수 있는 주소와, 그 주소가
지금 실제로 무엇을 돌려주는지의 실측 기록이다.

등급 표기는 `howto-kit/references/source-tiers.md` 를 따른다. 아래 표의 값은 전부 **응답 본문
원문에서 추출**했다 — 벤더 문서가 "RSS 를 제공한다" 고 적었다는 사실이 아니라, 그 URL 을 열어
루트 엘리먼트를 읽은 결과다.

---

## 1. 확정된 폴링 대상 5 건

조회일 **2026-09-09**. 포맷 판정 근거는 응답 본문의 루트 엘리먼트다.

| 벤더 | 피드 URL | 포맷 | Content-Type | 조회일 |
| --- | --- | --- | --- | --- |
| Google Cloud release notes | `https://docs.cloud.google.com/feeds/gcp-release-notes.xml` | **Atom 1.0** | `text/xml` | 2026-09-09 |
| Apple Developer News | `https://developer.apple.com/news/rss/news.rss` | **RSS 2.0** | `application/rss+xml; charset=UTF-8` | 2026-09-09 |
| Apple Releases | `https://developer.apple.com/news/releases/rss/releases.rss` | **RSS 2.0** | `application/rss+xml; charset=UTF-8` | 2026-09-09 |
| GitHub Changelog | `https://github.blog/changelog/feed/` | **RSS 2.0** | `application/rss+xml; charset=UTF-8` | 2026-09-09 |
| AWS What's New | `https://aws.amazon.com/about-aws/whats-new/recent/feed/` | **RSS 2.0** | `application/rss+xml;charset=UTF-8` | 2026-09-09 |

### 1.1 Google Cloud release notes

루트 엘리먼트 원문:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- AUTOGENERATED FILE. DO NOT EDIT. -->
<feed xmlns="http://www.w3.org/2005/Atom">
  <id>tag:google.com,2016:gcp-release-notes</id>
  <title>Google Cloud Platform (GCP) - Release notes</title>
```

`<feed xmlns="http://www.w3.org/2005/Atom">` 이므로 **Atom 1.0** 이다. RSS 가 아니다 — 파서를
고를 때 이 구분이 실제로 갈린다. Content-Type 이 `application/atom+xml` 이 아니라 `text/xml`
이므로 **Content-Type 으로 포맷을 판정하면 틀린다.**

최신 항목 (조회 2026-09-09): `<title>September 08, 2026</title>`,
`<updated>2026-09-08T00:00:00-07:00</updated>`. 이 피드는 날짜를 엔트리 제목으로 쓴다.

**호스트 주의** — 구 호스트 `https://cloud.google.com/feeds/gcp-release-notes.xml` 은 살아 있지만
`HTTP/2 301` 로 `https://docs.cloud.google.com/feeds/gcp-release-notes.xml` 에 넘긴다. 리다이렉트를
따르지 않는 클라이언트는 빈 응답을 받는다. **canonical 은 `docs.cloud.google.com` 쪽이다.**

### 1.2 Apple Developer News · Apple Releases

두 피드 모두 루트가 `<rss version="2.0" …>` 이고 self 링크를 자기 안에 박아 둔다:

```xml
<rss version="2.0" xmlns:content="http://purl.org/rss/1.0/modules/content/" xmlns:atom="http://www.w3.org/2005/Atom">
<channel>
<atom:link href="https://developer.apple.com/news/rss/news.rss" rel="self" type="application/rss+xml" />
```

`<atom:link rel="self">` 가 요청한 URL 과 같다는 것이 canonical 근거다 — 벤더 페이지의 안내
문구보다 강한 증거다.

최신 항목 (조회 2026-09-09):

- Developer News — `Hello Developer: September 2026` / `Wed, 02 Sep 2026 08:00:02 PDT`
- Releases — `Transporter 1.4.5` / `Tue, 08 Sep 2026 13:00:00 PDT`

두 피드는 대상이 다르다. **Releases 는 툴·OS 빌드 릴리스**를, **News 는 정책·공지**를 싣는다.
절차 문서의 최신성 감시에는 둘 다 필요하다 — 콘솔 라벨을 바꾸는 것은 News 쪽이고, 업로드
도구의 동작을 바꾸는 것은 Releases 쪽이다.

### 1.3 GitHub Changelog

```xml
<?xml version="1.0" encoding="UTF-8"?><rss version="2.0"
	xmlns:content="http://purl.org/rss/1.0/modules/content/"
	xmlns:wfw="http://wellformedweb.org/CommentAPI/"
```

최신 항목: `GitHub Enterprise Server 3.22 is now generally available` /
`Tue, 08 Sep 2026 21:52:42 +0000`.

### 1.4 AWS What's New

```xml
<?xml version="1.0" encoding="UTF-8" standalone="no"?><rss version="2.0"><channel><link>https://aws.amazon.com/about-aws/whats-new/recent/</link><title>Recent Announcements</title>
```

최신 항목: `OpenAI GPT-6 Astra is now generally available on Amazon Bedrock` /
`Tue, 08 Sep 2026 22:49:00 GMT`.

이 항목은 2026-09-08 원장에 없던 **신규 확정**이다.

## 2. 확인 실패 3 건 — `[미확인]`

아래 세 대상은 **"피드가 없다" 가 아니라 "피드를 확인하지 못했다"** 다. 이 구분이 이 킷의
존재 이유이므로 문장을 흐리지 않는다.

| 대상 | 상태 | 폴링 대체 수단 |
| --- | --- | --- |
| Firebase release notes | `[미확인]` | HTML `https://firebase.google.com/support/releases` |
| Stripe changelog | `[미확인]` | HTML `https://docs.stripe.com/changelog` |
| Azure updates | `[미확인]` | HTML `https://azure.microsoft.com/en-us/updates/` |

### 2.1 Firebase — 시도한 URL

```text
https://firebase.google.com/feeds/support-release-notes.xml   (2026-09-08 실패)
https://firebase.google.com/feeds/firebase-release-notes.xml  → 404, text/html
https://firebase.google.com/support/releases.xml              → 200 이지만 text/html (soft 200)
```

`releases.xml` 이 200 을 돌려주는 것에 속으면 안 된다. Content-Type 이 `text/html` 이고 본문이
`<html lang="en" dir="ltr">` 로 시작한다 — Google 문서 사이트가 미지의 경로에 HTML 페이지를
돌려주는 형태다. **HTTP 상태 코드만으로 피드 존재를 판정하면 틀린다.**

### 2.2 Stripe — 시도한 URL

```text
https://docs.stripe.com/changelog.atom     (2026-09-08 실패)
https://docs.stripe.com/changelog.rss      (2026-09-08 실패)
https://stripe.com/blog/feed.rss           (2026-09-08 실패)
https://docs.stripe.com/changelog/feed.xml → 404
https://docs.stripe.com/changelog/rss.xml  → 404
```

### 2.3 Azure updates — 시도한 URL

```text
https://azure.microsoft.com/en-us/updates/feed/                  → 301 → https://azure.microsoft.com/en-us/updates?id=feed (text/html)
https://www.microsoft.com/releasecommunications/api/v2/azure/rss → 403
https://azurecomcdn.azureedge.net/en-us/updates/feed/            → 200 이지만 image/vnd.microsoft.icon
```

`/updates/feed/` 는 **죽은 것이 아니라 HTML 로 리다이렉트**된다. 과거에 피드였던 주소가 지금은
페이지 쿼리로 넘어가는 형태다. `releasecommunications` 엔드포인트의 `403` 은 **접근 차단이지
부재 증명이 아니다** — 다른 네트워크나 인증 상태에서는 열릴 수 있다. 그래서 `[미확인]` 이다.

## 3. 이번 조사가 무효화한 판정 방법

**피드 autodiscovery 링크가 없다는 것은 피드가 없다는 증거가 아니다.**

HTML 문서의 `<link rel="alternate" type="application/rss+xml">` 는 피드를 찾는 관례적 수단이고,
"이 페이지에 autodiscovery 가 없으니 피드도 없다" 는 추론은 자연스러워 보인다. **AWS 가 그
추론의 반례다.**

`https://aws.amazon.com/new/` 를 열어 `<link>` 태그에서 `rss`/`atom` 을 찾으면 **0 건**이다.
그런데 같은 벤더의 `https://aws.amazon.com/about-aws/whats-new/recent/feed/` 는
`application/rss+xml` 로 정상 응답하고 최신 항목까지 들어 있다 (§1.4).

그러므로 Firebase 와 Stripe 도 **autodiscovery 부재를 근거로 "피드 없음" 이라 쓰지 않는다.**
셋 다 `[미확인]` 이며, 근거는 "찾지 못했다" 이지 "없다" 가 아니다.

## 4. 폴링 운영 규칙

1. **포맷은 Content-Type 이 아니라 루트 엘리먼트로 판정한다.** Google Cloud 가 Atom 을
   `text/xml` 로 내려주는 것이 실측 반례다 (§1.1).
2. **리다이렉트를 따라라.** 구 호스트가 301 로 살아 있는 경우가 있고 (§1.1), 반대로 301 이
   피드가 아닌 HTML 로 데려가는 경우도 있다 (§2.3).
3. **200 을 피드 존재로 읽지 마라.** soft 200 + `text/html` 이 실재한다 (§2.1).
4. **피드가 없는 대상은 HTML 폴링으로 내린다.** 없는 피드를 있다고 적는 것보다, HTML 을 긁는
   비용을 감수하는 편이 낫다.
5. **이 표의 URL 을 인용하기 전에 다시 조회한다.** 위 값은 전부 2026-09-09 확인분이며, 피드
   URL 은 실제로 바뀐다 — 이 문서 자체가 그 증거다 (Google Cloud 호스트 이전).
