# 시각적 계층

UI에서 정보의 중요도를 시각적 수단으로 전달하는 원칙, 도구, 실전 적용법을 정리한다.

---

## 원칙

### 1. 크기가 가장 강력한 계층 신호다

사용자는 큰 요소를 먼저 인지한다. NNGroup의 아이트래킹 연구에서 사용자가 페이지를 스캔할 때 큰 텍스트와 이미지에 시선이 가장 먼저 고정되는 현상이 반복 관찰되었다. 크기만으로도 "이것이 가장 중요하다"는 신호를 보낼 수 있다.

> **출처:** [NNGroup — Text Scanning Patterns: Eyetracking Evidence](https://www.nngroup.com/articles/text-scanning-patterns-eyetracking/)

### 2. 대비가 시선을 끌어당긴다

배경과 전경의 명도 차이가 클수록 해당 요소의 시각적 무게가 커진다. 반대로 낮은 대비는 요소를 배경에 녹아들게 만들어 "보조 정보"로 인식하게 한다. WCAG 2.1은 텍스트에 최소 4.5:1 대비를 요구하지만, 계층 설계에서는 의도적으로 대비 차이를 활용해야 한다.

> **출처:** [WCAG 1.4.3 — Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)

### 3. 여백이 중요도를 결정한다

주변 여백이 넓을수록 해당 요소는 더 중요하게 인식된다. Apple은 히어로 영역에서 광대한 여백을 사용하여 단일 메시지에 집중하게 만든다. 여백은 "비어 있는 공간"이 아니라 "주목을 유도하는 도구"다.

> **출처:** [NNGroup — Why Does a Design Look Good?](https://www.nngroup.com/articles/why-does-design-look-good/)

### 4. 위치는 읽기 순서를 결정한다

서구권 사용자는 좌상단에서 시작해 우하단으로 이동한다. 가장 중요한 정보는 좌상단에, 부가 정보는 우하단에 배치해야 자연스러운 시선 흐름과 정보 우선순위가 일치한다.

> **출처:** [NNGroup — F-Shaped Pattern for Reading Web Content](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)

## 크기와 스케일

### 지배-종속-보조 3단계 구조

모든 화면에는 최소한 3단계의 시각적 계층이 존재해야 한다.

| 단계 | 역할 | 크기 비율 | 예시 |
|------|------|-----------|------|
| **Dominant (지배)** | 가장 먼저 눈에 들어오는 요소 | 1.0 (기준) | 히어로 타이틀, 주요 수치, CTA 버튼 |
| **Subdominant (종속)** | 지배 요소를 보충하는 2차 정보 | 0.6–0.7 | 섹션 제목, 서브헤딩, 카드 타이틀 |
| **Subordinate (보조)** | 세부 정보, 메타데이터 | 0.4–0.5 | 본문 텍스트, 캡션, 타임스탬프 |

### 크기 비율의 실전 수치

- **히어로 타이틀 → 섹션 제목**: 최소 1.5배 차이 (예: 48px → 32px)
- **섹션 제목 → 본문**: 최소 1.25배 차이 (예: 32px → 16px이면 2배로 충분)
- **본문 → 캡션**: 2–4px 차이 (예: 16px → 12px)

크기 차이가 너무 미미하면 계층이 불분명해진다. "비슷해 보이면 같은 계층"으로 인식된다.

### 스케일 비율 시스템

| 비율 | 이름 | 특성 |
|------|------|------|
| 1.067 | Minor Second | 매우 미세한 차이, 조밀한 UI |
| 1.200 | Minor Third | 균형 잡힌 스케일, 범용 |
| 1.250 | Major Third | 명확한 계층, 대시보드 적합 |
| 1.333 | Perfect Fourth | 강한 대비, 마케팅 페이지 |
| 1.414 | Augmented Fourth | 드라마틱, 랜딩 페이지 |
| 1.618 | Golden Ratio | 극적인 스케일, 편집 디자인 |

> **출처:** [Type Scale — A Visual Calculator](https://typescale.com/)

## 색상과 대비

### 대비 = 우선순위

높은 대비는 높은 우선순위를 의미한다. 이 원칙을 체계적으로 적용하면 색상만으로 계층을 전달할 수 있다.

| 요소 유형 | 대비 수준 | 색상 처리 |
|-----------|-----------|-----------|
| 주요 CTA | 최고 대비 | 브랜드 컬러 filled + 흰색 텍스트 |
| 보조 버튼 | 중간 대비 | 아웃라인 또는 tonal 처리 |
| 비활성/힌트 | 최저 대비 | gray-400~500, opacity 0.38 |
| 링크/인터랙티브 | 중상 대비 | 브랜드 컬러 텍스트 |
| 본문 텍스트 | 높은 대비 | 라이트 모드: gray-900, 다크 모드: gray-100 |
| 보조 텍스트 | 중간 대비 | 라이트 모드: gray-600, 다크 모드: gray-400 |

### 색상 계층의 3단계

1. **강조색(Accent)**: 화면에서 10% 이하만 차지하되, 가장 높은 채도로 시선을 끈다
2. **중립색(Neutral)**: 70–80%를 차지하는 배경/텍스트 색상
3. **의미색(Semantic)**: 에러(red), 경고(amber), 성공(green), 정보(blue) — 상태 전달 전용

### 색상으로 계층 깨뜨리는 안티패턴

```
[BAD]  모든 텍스트에 브랜드 블루 사용 → 어디가 클릭 가능한지 알 수 없음
[BAD]  4가지 이상의 강조색 동시 사용 → 무엇이 중요한지 불명확
[BAD]  비활성 버튼에 높은 채도 → 클릭 가능해 보이지만 동작하지 않음
[GOOD] CTA만 브랜드 컬러, 나머지는 중립색 → 시선이 CTA로 수렴
```

## 여백과 근접성

### 게슈탈트 근접성 원칙

가까이 있는 요소는 관련된 것으로 인식된다. NNGroup은 근접성이 색상이나 형태보다 더 강력한 그룹핑 신호라고 밝혔다. 따라서 관련 요소 사이의 간격(내부 간격)은 비관련 요소 사이의 간격(외부 간격)보다 항상 작아야 한다.

> **출처:** [NNGroup — Proximity Principle in Visual Design](https://www.nngroup.com/articles/gestalt-proximity/)

### 근접성 간격 공식

```
내부 간격 ≤ 외부 간격 × 0.5
```

예시:
- 카드 내부 패딩: 16px
- 카드 사이 간격: 24px (내부의 1.5배)
- 섹션 사이 간격: 48px (내부의 3배)

### 여백으로 계층 만들기

| 여백 크기 | 역할 | 수치 예시 |
|-----------|------|-----------|
| **Micro** | 같은 그룹 내 요소 간격 | 4–8px |
| **Small** | 관련 그룹 내 하위 섹션 | 12–16px |
| **Medium** | 독립된 컴포넌트 간격 | 24–32px |
| **Large** | 섹션 구분 | 48–64px |
| **XLarge** | 페이지 영역 구분 | 80–120px |

### 호흡 공간(Breathing Room)

요소 주변에 충분한 여백을 두면:
- 터치 타겟이 넓어져 모바일 사용성이 개선된다 (최소 44x44pt, Apple HIG)
- 시각적 "무게"가 증가하여 중요하게 인식된다
- 인지 부하가 줄어 스캔 속도가 빨라진다

> **출처:** [Apple HIG — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)

## 위치와 시선 흐름

### F-패턴

NNGroup의 232명 사용자 아이트래킹 연구(2006년 원본, 2017년 후속)에서 발견된 패턴이다. 텍스트 중심 페이지에서 사용자는:

1. 상단을 수평으로 스캔한다 (첫 번째 수평선)
2. 약간 아래로 이동해 더 짧은 수평 스캔을 한다 (두 번째 수평선)
3. 왼쪽을 수직으로 훑는다 (F의 줄기)

**핵심**: F-패턴은 구조가 부실한 콘텐츠에서 발생하는 "나쁜 읽기 패턴"이다. 명확한 제목, 짧은 단락, 시각적 구분이 있으면 사용자는 F-패턴 대신 layer-cake 패턴(제목을 순차적으로 읽는 패턴)으로 전환한다.

> **출처:** [NNGroup — F-Shaped Pattern of Reading on the Web: Misunderstood, But Still Relevant](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)

### Z-패턴

텍스트보다 시각적 요소가 많은 페이지(랜딩 페이지, 홈페이지, 광고)에서 나타난다.

```
[Logo/Nav]  ──────────>  [CTA]
                ↘
           [Hero Image/Text]
                ↘
[Social Proof]  ──────────>  [Secondary CTA]
```

Z-패턴을 활용한 배치:
- **좌상단**: 로고, 브랜드 인지
- **우상단**: 내비게이션, 주요 CTA
- **중앙**: 핵심 메시지, 히어로 이미지
- **좌하단**: 부가 정보, 소셜 프루프
- **우하단**: 최종 CTA, 가입 버튼

### 시선 진입점(Entry Point)

사용자의 시선은 다음 순서로 끌린다:

1. **움직임** (애니메이션, 비디오) — 가장 강력하나 남용하면 산만
2. **큰 이미지** — 특히 사람 얼굴
3. **큰 텍스트** — 굵은 제목
4. **고대비 요소** — 밝은 배경 위의 진한 색
5. **색상 차이** — 주변과 다른 색상의 요소

### 시각적 흐름 설계 규칙

| 규칙 | 설명 |
|------|------|
| 하나의 진입점 | 화면에서 시선이 처음 도달하는 곳은 하나여야 한다 |
| 순차적 안내 | 진입점 → 핵심 메시지 → CTA 순서로 시선을 유도한다 |
| 시각적 막다른 길 방지 | 시선이 멈추는 곳 없이 다음 요소로 자연스럽게 이어져야 한다 |
| 좌측 정렬 우선 | 좌측 정렬은 왼쪽 가장자리를 일관된 시선 앵커로 만든다 |
| 중앙 정렬은 제한적 사용 | 히어로, 다이얼로그 등 짧은 텍스트에만 적합하다 |

## 계층 도구의 조합

단일 도구보다 여러 도구를 조합하면 더 명확한 계층을 만들 수 있다.

| 조합 | 효과 | 사용 상황 |
|------|------|-----------|
| 크기 + 굵기 | 가장 기본적인 텍스트 계층 | 제목 vs 본문 |
| 크기 + 색상 | 시각적 강조 극대화 | 히어로 타이틀 + 브랜드 컬러 |
| 여백 + 구분선 | 섹션 분리 | 설정 화면, 폼 그룹 |
| 색상 + 아이콘 | 상태 표시 | 에러/성공/경고 메시지 |
| 위치 + 크기 + 대비 | 완전한 계층 스택 | CTA 영역 설계 |

### 과잉 강조 안티패턴

```
[BAD]  모든 요소에 굵은 텍스트 → 아무것도 강조되지 않음
[BAD]  3개 이상의 동일 크기 CTA → 선택 마비(paradox of choice)
[BAD]  빨간색 텍스트 + 느낌표 + 밑줄 + 굵기 → 모든 도구를 동시에 쓰면 시끄러움
[GOOD] 하나의 Primary CTA + 하나의 Secondary CTA → 명확한 우선순위
```

## 실전 체크리스트

### 계층 감사(Hierarchy Audit) 방법

**1. 흐림(Blur) 테스트**

디자인에 가우시안 블러(5–10px)를 적용한다. 텍스트를 읽을 수 없는 상태에서도 어떤 요소가 가장 중요한지 알 수 있다면 계층 설계가 성공한 것이다.

**2. 5초 테스트**

새로운 사용자에게 디자인을 5초간 보여준 뒤 "가장 먼저 눈에 들어온 것은?"이라고 물어본다. 답이 의도한 주요 요소와 일치하면 합격이다.

**3. 흑백 변환 테스트**

디자인을 그레이스케일로 변환한다. 색상 없이도 계층이 유지되면 구조가 탄탄한 것이다. 색상에만 의존하는 계층은 접근성 문제를 유발한다.

**4. 거리(Distance) 테스트**

화면을 2미터 거리에서 바라본다(또는 축소). 대시보드, 키오스크, 프레젠테이션 UI에서 특히 유효하다.

### 항목별 점검표

| # | 점검 항목 | 판단 기준 |
|---|-----------|-----------|
| 1 | 시각적 진입점이 하나인가? | 화면에서 가장 먼저 눈에 들어오는 요소가 명확히 하나 |
| 2 | 3단계 이상의 크기 계층이 있는가? | Dominant → Subdominant → Subordinate 구분 가능 |
| 3 | 내부 간격 < 외부 간격인가? | 관련 요소가 비관련 요소보다 가까이 배치 |
| 4 | CTA가 시각적 최고점인가? | 주요 행동 유도 버튼이 가장 높은 대비와 색상을 보유 |
| 5 | 텍스트 크기 단계가 2종 이하인가? | 너무 많은 크기 변형은 계층을 혼란스럽게 만듦 (최대 4~5종) |
| 6 | 색상 제거 후에도 계층이 유지되는가? | 그레이스케일 테스트 통과 |
| 7 | 모바일에서도 계층이 명확한가? | 작은 화면에서 크기 비율이 유지되는지 확인 |
| 8 | 스크롤 없이 핵심 메시지를 파악할 수 있는가? | Above the fold에 Dominant 요소 배치 |

## 플랫폼별 고려사항

### 모바일

- 화면이 좁아 수평 계층보다 수직 계층에 의존한다
- 크기 차이를 1.2배 이상으로 유지해야 작은 화면에서도 구분 가능하다
- 터치 타겟 크기(최소 44pt)가 시각적 크기와 일치해야 한다

### 태블릿

- 2컬럼 레이아웃에서 좌측이 Primary, 우측이 Secondary 계층을 담당한다
- Split View에서 각 패널의 독립적 계층 구조가 필요하다

### 데스크톱

- 넓은 화면에서 시선이 분산되기 쉬우므로 Max-width 제한(800–1200px)이 중요하다
- 사이드바, 메인 콘텐츠, 보조 패널의 3단 구조에서 각각의 계층이 독립적으로 작동해야 한다

### 대시보드

- 모든 위젯이 동일한 시각적 무게를 가지면 "정보의 벽"이 된다
- 핵심 KPI 1–3개를 Dominant로, 나머지를 Subordinate로 처리한다
- 색상은 이상치(anomaly) 표시에만 사용하고, 정상 상태는 중립색으로 유지한다
