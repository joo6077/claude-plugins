팔레트 시스템

3계층 토큰 아키텍처, 색상 조화, WCAG 대비, 다크 모드, 브랜드 컬러 선정 -- 색상 시스템의 모든 것을 인터랙티브하게 탐색합니다.

Principles
4가지 컬러 원칙

NNGroup, WCAG, Material Design 3에서 도출한 핵심 원칙입니다.

60-30-10 법칙

60% Surface/Background, 30% Secondary/Container, 10% Primary/Accent. 이 비율을 지키면 시각적 균형과 계층이 자연스럽게 형성된다. Accent를 30% 이상 쓰면 "크리스마스 트리" 현상 발생.

색상만으로 정보 전달 금지

WCAG 1.4.1 — 색상이 유일한 정보 전달 수단이 되면 안 된다. 색각 이상 사용자는 전체 남성의 약 8%. 에러: 빨간색 + 아이콘 + 텍스트 병행 필수.

시맨틱 색상 사용

하드코딩 hex 대신 역할(role) 기반 토큰. #FF0000 대신 color-error. 테마 전환, 다크 모드, 화이트 라벨링을 가능하게 한다.

대비 우선

텍스트 최소 4.5:1(AA), UI 컴포넌트 최소 3:1. WebAIM 2024 분석에서 83.6%가 색상 대비 문제를 보유. 가장 빈번한 실패: 밝은 회색 placeholder.

Semantic Tokens
MD3 시맨틱 컬러 역할

MD3는 색상을 역할(Role) 기반으로 분류하며, 각 역할은 쌍(pair)으로 존재하여 대비를 보장한다.

Architecture
3계층 토큰 아키텍처

Primitive → Semantic → Component 3단계로 색상을 구조화하면 일관성, 유지보수성, 테마 확장성을 확보한다.

Tier 3 — Component Token
컴포넌트 토큰
button-primary-bg → color-action

특정 컴포넌트에 한정된 토큰. 테마별 독립 변형이 필요할 때 사용.

Tier 2 — Semantic Token
시맨틱 토큰
color-action → blue-600 (Light) / blue-400 (Dark)

용도와 맥락을 부여. 다크 모드 전환 시 이 레이어에서 매핑만 변경.

Tier 1 — Primitive Token (Reference)
프리미티브 토큰
blue-600 → #1D6AFF

원시 색상값. 직접 UI에 사용하지 않고 Semantic 토큰이 참조한다.

연결 흐름 시뮬레이션
blue-600 #1D6AFF → color-action → button-primary-bg → Button

Primitive → Semantic → Component → UI 순서로 토큰이 해석된다

Methodology
브랜드 컬러 선정 4단계

경쟁사 감사 → 시뮬레이션 → 접근성 검증 → 다크 모드 적합성의 4단계 프로세스.

01
경쟁사 컬러 감사

동일 업종 상위 10개 앱의 Primary 색상을 수집. 파란색에 몰려 있다면 차별화 검토.

02
60-30-10 시뮬레이션

후보 색상으로 UI 목업에 비율 적용. 3가지 후보 팔레트를 병렬 비교.

03
접근성 사전 검증

흰색/검정 배경 모두에서 AA 대비(4.5:1) 충족 확인. 미충족 시 명도 조정.

04
다크 모드 적합성

다크 모드용 변형(명도 +20~30, 채도 -10~20) 미리 준비.

그림 8. 브랜드 컬러 선정 4단계 프로세스 — 경쟁사 감사부터 다크 모드 적합성까지
