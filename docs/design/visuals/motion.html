Design Foundation

모션 디자인 시스템

애니메이션의 목적, 타이밍, 이징 커브, 성능 예산, 접근성 모션 설정을 다룬다. 모든 모션은 기능적(functional)이어야 하며 장식적 용도는 지양한다.

원칙
🎯

목적 있는 모션만 사용

"멋져 보여서" 추가한 애니메이션은 두 번째 방문부터 짜증이 된다. 시스템이 무엇을 하는지 보여주는 단서 역할이어야 한다.

🧠

인지 부하를 줄인다

호버 애니메이션은 클릭 가능 여부 추측을 없애고, 공유 요소 전환은 어디서 왔고 어디로 가는지를 명확히 한다.

⚡

대부분의 애니메이션은 너무 길다

0.1초(100ms) 차이가 사용자 인식을 바꾼다. 확신이 없으면 짧은 쪽으로 편향하라.

♿

접근성을 고려한다

prefers-reduced-motion 미디어 쿼리를 존중한다. 전정 기관 장애 사용자는 시차 스크롤, 대규모 줌, 회전으로 어지러움을 경험한다.

방향 비대칭

Enter 300ms vs Exit 200ms

등장하는 요소는 사라지는 요소보다 더 긴 듀레이션이 필요하다. 아래 버튼으로 비대칭 타이밍을 체험하라.

Enter: 300ms ease-out
Exit: 200ms ease-in

애니메이션 금지 체크리스트

애니메이션하지 말아야 할 때

아래 상황에서는 모션을 제거하고 즉시 표시하는 것이 사용자 경험에 더 좋다.

  • ✗
    에러 메시지 표시 — 에러를 읽어야 하는 상황에서 슬라이드인은 인지를 방해한다. 즉시 표시가 원칙.
  • ✗
    대량 리스트 렌더링 — 50개 아이템이 순차적으로 페이드인되면 사용자가 스크롤을 시작할 수 없다.
  • ✗
    고빈도 반복 액션 — 이메일 삭제 등 1분에 수십 번 반복하는 액션의 확인 애니메이션은 300ms x 30회 = 9초의 누적 지연.
  • ✗
    prefers-reduced-motion: reduce 활성 — 필수 상태 피드백을 제외한 모든 모션을 제거하거나 크로스페이드로 대체.
  • ✗
    배터리 절약 모드 — 모바일에서 배터리 부족 시 GPU 연산을 줄여야 한다. 복잡한 애니메이션을 단순 페이드로 폴백.
