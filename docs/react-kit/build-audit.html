스킬 02

/react-build — 3-Step 빌드 파이프라인

1. wasm-pack build
→
2. tsc --noEmit
→
3. vite build
wasm-pack이 실패하면 이후 단계를 실행하지 않는다. Vite가 src/wasm/core/에서 .wasm 바이트를 번들링하기 때문에 wasm 아티팩트가 먼저 있어야 한다.
1
wasm-pack build
wasm-pack build crates/core --target web --release --out-dir ../../src/wasm/core
Rust 크레이트를 WebAssembly로 컴파일. --target web은 ESM 바인딩 생성.
2
tsc --noEmit
전체 TypeScript 타입 체크. 오류가 있으면 exit 1. 파일은 생성하지 않는다.
3
vite build
Tailwind v4 CSS 번들 + React 코드 분할 + .wasm 파일 임포트. dist/에 최종 아티팩트 출력.
↗ wasm-pack build 문서 ↗ Vite build 문서 ↗ tsc --noEmit
스킬 03

/react-preflight — Pre-commit 7-Step Gate

커밋 전 품질 게이트. 하나라도 실패하면 즉시 멈추고 다음 단계를 실행하지 않는다.

fix
→
codegen
→
lint
→
tsc
→
test
→
wasm
→
build
1
fix — ESLint auto-fix
pnpm run lint:fix — 자동 수정 가능한 lint 위반을 먼저 정리한다
2
codegen — 코드 생성
tsr generate && lingui extract && lingui compile — 라우터 타입과 i18n 카탈로그 재생성
3
lint — ESLint 검사
pnpm run lint — --max-warnings=0. 경고 1개도 실패 처리
4
tsc — 타입 체크
pnpm run tsc — strict 모드. any, unknown unchecked 전부 오류
5
test — 유닛 + 컴포넌트 테스트
pnpm run test — Vitest run. 실패 테스트가 있으면 exit 1
6
wasm — WASM 빌드 검증
pnpm run wasm:build — Rust 크레이트 컴파일 확인. wasm 바이트가 변경됐으면 업데이트
7
build — 최종 번들 빌드
pnpm run build — tsc → vite build. dist/ 아티팩트가 정상 생성돼야 통과
preflight는 pnpm run preflight로도 실행 가능하다. CI는 preflight를 자동 실행하므로 로컬에서 먼저 통과시켜야 PR 블로킹을 피할 수 있다.
↗ ESLint v9 flat config ↗ TanStack Router codegen

규칙 정책

감사 규칙 중요도 레벨

레벨 기호 의미 CI 행동
error ❌ 반드시 고쳐야 함. 빌드 게이트 exit 1 (preflight 실패)
warn ⚠️ 권장 사항. 고치지 않아도 빌드는 통과 exit 0 + 경고 리포트
info ℹ️ 참고용. 설계 개선 힌트 리포트에 섹션으로 추가
.react-audit.config.ts로 규칙별 레벨을 override할 수 있다. 레거시 마이그레이션 중인 프로젝트는 일부 error를 warn으로 완화하여 점진 수정 가능.

안티패턴 비교

감사 실패를 유발하는 패턴 vs 올바른 패턴

`/react-audit` 의 6 카테고리에서 가장 자주 검출되는 위반 3건을 bad·good 으로 비교한다. 소스: docs/react/kit-design/g6-build-audit.md §4.5 카테고리 체크리스트.

❌ BAD — Library Policy 빌드 게이트
// src/presentation/features/board/Card.tsx
import { motion } from 'framer-motion'

export function Card() {
  return <motion.div animate={{ x: 100 }} />
}

framer-motion import 는 /react-audit Library Policy 카테고리에서 **빌드 실패** 로 즉시 REJECT. Motion/dnd-kit/react-spring/react-transition-group 등은 절대 금지 목록이다.

✅ GOOD — Tailwind + View Transitions
// src/presentation/features/board/Card.tsx
// 라이브러리 0개 — Tailwind 애니메이션 + View Transitions API
export function Card() {
  return (
    <div className="transition-transform duration-300 hover:translate-x-2">
      {/* ... */}
    </div>
  )
}

3-Tier 구조 (Tailwind+CSS / View Transitions API / Custom Pointer Primitives) 만으로 모든 인터랙션 가능. docs/react/kit-design/g5b-animation.md 참조.

❌ BAD — Architecture 경계 위반
// src/domain/usecases/fetch-user.ts
import axios from 'axios'

export async function fetchUser(id: string) {
  const res = await axios.get(`/api/users/${id}`)
  return res.data  // any 타입
}

domain 레이어에서 HTTP 라이브러리 직접 import 금지. Architecture 카테고리 즉시 FAIL. Clean Arch 경계를 위반하면 의존성 방향이 역전된다.

✅ GOOD — Repository 인터페이스 주입
// src/domain/usecases/fetch-user.ts
import type { Result } from 'neverthrow'
import type { User } from '@/domain/entities/user'
import type { UserFailure } from '@/domain/failures/user'

export interface FetchUser {
  (id: string): Promise<Result<User, UserFailure>>
}
// 구현은 src/data/repositories/user-repository.ts 에서
// HTTP 호출은 src/data/datasources/remote/user-api.ts 에서

domain 은 순수 타입/인터페이스만. 실제 HTTP 는 data 레이어의 datasource/repository. /react-audit Architecture grep 패턴이 경계 위반을 자동 검출.

❌ BAD — Strict TS 위반
// src/presentation/features/user/UserList.tsx
const users: any = await fetchUsers()
const first = users[0]!  // non-null 단언
return <div>{first.name as string}</div>

any, ! non-null 단언, as 타입 단언 모두 Strict TS 카테고리 위반. ESLint --max-warnings=0 에서 즉시 실패.

✅ GOOD — unknown + Zod parse
// src/data/datasources/remote/user-api.ts
const raw: unknown = await response.json()
const parsed = UserSchema.safeParse(raw)
if (!parsed.success) {
  return err({ kind: 'user/validation-failed', issues: parsed.error.issues.map(i => i.message) })
}
return ok(parsed.data)  // User 타입 안전

경계에서 unknown + Zod 로 검증 후 신뢰. 내부 코드는 전부 typed. any/as/! 는 eslint rule 로 차단.

Gotchas

빌드·감사 스킬 공통 주의사항

G6 4 스킬 (/react-run, /react-build, /react-preflight, /react-audit) 실행 시 주의할 사항. 소스: g6-build-audit.md §1.4, §2.6, §3.5, §4.7.

  • !
    wasm-pack 순서 엄수 — /react-build 는 반드시 wasm-pack → tsc → vite 순서. 순서가 바뀌면 WASM 산출물이 tsc 에 보이지 않아 타입 에러. package.json 의 build 스크립트를 수정하지 마라.
  • !
    preflight 7 단계 실패 시 롤백 — /react-preflight 의 fix → codegen → lint → tsc → test → wasm-build → vite-build 순서에서 단계별 실패 시 git stash 로 이전 성공 지점 복원. 부분 수정 상태로 commit 금지.
  • !
    --no-verify 절대 금지 — pre-commit hook 이 실패하면 근본 원인을 고쳐라. git commit --no-verify 로 우회하는 순간 preflight 가 무력화된다.
  • !
    audit quick/deep 모드 자동 선택 — 변경 파일 ≤5 면 quick (단일 reviewer), >5 면 deep (4 에이전트 병렬). 수동으로 quick 강제 시 큰 PR 에서 카테고리 누락 위험.
  • !
    Library Policy 는 빌드 게이트 — Motion/framer-motion/dnd-kit/react-spring/react-transition-group 등이 node_modules 또는 import 구문에 존재하면 audit 이 즉시 FAIL. 완화 불가.
  • !
    /react-run 은 상위 워크플로우의 프리미티브 — /react-build, /react-preflight 가 내부적으로 /react-run 의 서브커맨드를 호출. 사용자가 /react-run 을 직접 호출할 때는 구체 서브커맨드 (dev/build/lint/test/wasm-build/format/codegen) 명시 필수.
  • !
    Deep 모드 4 에이전트 병렬 — /react-audit --mode=deep 은 react-reviewer / widget-inspector-react / animation-architect-react / react-reviewer (보안 focus) 를 병렬 dispatch. 순차 실행 금지 (시간 낭비).
  • !
    감사 결과는 재현 가능해야 한다 — /react-audit 출력은 tag 기반 캐시. 같은 commit SHA 에 대해 동일 결과. 결과가 다르면 grep 패턴이 비결정적 (파일 순서 의존 등).
