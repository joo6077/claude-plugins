왜 필요한가

증거가 있어도 아무것도 입증하지 않을 수 있다

/insights 2026-07-27의 53일 · 51세션 분석에서 Friction #2 “시각·런타임 검증을 신뢰할 수 없음”이 신규 최상위 마찰로 올라왔다. 빈 카탈로그 화면을 정상 렌더링의 근거로 반복 제출했지만 원인은 unbounded-height 리스트 collapse였고, 사용자 신뢰가 손상되어 욕설로 끝난 세션이 2건 있었다.

구조적 위험

react-kit 관측 사례는 없지만 같은 사고를 만들 도구 기본값이 있다. Strict TS가 통과한 컴포넌트도 빈 화면을 렌더할 수 있다.

2026-09-24 · F01 · F03 · F05

18세션 분석에는 화면 대신 진입 칩을 만든 사고, 재시작 실패 뒤 갱신 보고, 틀린 인자나 남의 시뮬레이터 때문에 도구를 세 번 오진한 사고가 있었다.

포트가 증거 출처를 가른다

Vite는 지정 포트가 차면 다음 빈 포트로 이동한다. Tauri devUrl과 harness 검사 포트 5173이 실제 서버와 어긋나면 5173에서 다른 서버 화면을 볼 수 있다.

1. Step 0 — 무엇을 바꾸는지 먼저 확정한다 (Friction #1)

편집 전에 응답에 남길 6줄

시각 작업에서는 말만으로 의도가 충분히 규정되지 않는다.

  • 1대상: 컴포넌트를 파일:라인으로 지목한다. 신규면 신규라고 쓴다.
  • 2바꿀 것 / 바꾸지 않을 것: 색·간격·모션·레이아웃·breakpoint 중 유지할 속성을 열거한다.
  • 3교체 여부: shadcn 프리미티브나 다른 컴포넌트로 교체하려면 먼저 승인받는다. 기본값은 기존 컴포넌트 수정이다.
  • 4되말하기: 요소 이름과 배치까지 한 문장으로 되말한다. 두 갈래로 읽히면 묻고 시작한다.
  • 5화면 자체: 화면 요청의 대상은 src/presentation/routes/ 라우트와 src/presentation/features/<feature>/screens/ 화면 컴포넌트다. 진입점이나 흉내 낸 그림이 아니다. 주소도 적는다.
  • 6관례 표: 같은 역할의 서로 다른 기존 화면 2개 이상에서 줄 모양·칩/뱃지·아이콘 뜻·재사용 컴포넌트 경로와 용도를 기록한다.
기존 화면 경로줄 모양칩·뱃지아이콘 뜻재사용 컴포넌트
같은 역할 화면 1카드 / 평평한 줄실제 모양닫기·끝내기·접기경로와 용도
같은 역할 화면 2카드 / 평평한 줄실제 모양닫기·끝내기·접기경로와 용도

재사용 후보는 앱 import를 grep으로 확인한다. Storybook·시안 전용과 grep에 없는 이름은 쓰지 않는다. 2개 미만이면 관례 없음 — 같은 역할 기존 화면 N개, 앱 코드가 없으면 관례 없음 — 앱 코드 없음이라고 쓴다.

Bad

“아이콘이 돌면 좋겠다”를 새 스피너 컴포넌트로 교체하라는 뜻으로 확대해 전면 재작업을 만든다.

Good

icon-button.tsx:24, transform 회전만 변경, 색·크기·aria-label 유지, 교체 없음이라고 확정한 뒤 편집한다.

2. 증거 등급 — 무엇을 제출할 수 있는가

가능한 가장 높은 렌더 증거부터 시도한다

상위 단계가 가능한데 하위로 내려가지 않는다.

R1

실제 렌더 캡처

Playwright toHaveScreenshot() 또는 브라우저 MCP 스냅샷.

R2

렌더된 DOM 단정

Testing Library getByRole / findByText 통과 출력.

R3

정적 확인

클래스·토큰·props를 파일:라인으로 지목하고 [정적]을 붙인다.

R3만 있으면 완료가 아니다

[정적]은 [미검증]을 대체하지 않는다. R1·R2가 불가하면 세 확인 뒤 막는 것 · 시도한 우회 · 통제 불가 사유 · 재검증 명령 네 칸을 채워 부분 완료로 보고한다. 하나라도 비면 [미검증:INVALID]다.

비교 반복 순서 — 지금 보는 화면이 이번 코드인가

1번은 편집 전에, 3번부터는 완료 직전에 한다.

1

기준 캡처

경로와 “목록 3행 · 헤더 ‘내 그룹’ · 하단 여백 있음”처럼 본 요소를 기록하고 반드시 달라질 표식 하나를 정한다. 신규면 신규라고 쓴다.

2

한 번에 한 의도만 수정

여러 변경을 묶지 않아 재캡처의 차이를 가릴 수 있게 한다.

3

반영 확인

  • 서버 출력의 Local: 주소와 브라우저 주소를 대조한다.
  • HMR 로그가 아니라 캡처 표식 변화로 판정한다.
  • 반영 안 됨이면 새로고침 → 서버 중지·재시작 → Rust 수정 시 /react-run wasm-build 후 재시작 순서로 가며 기록한다.
  • 표식이 그대로면 [미검증]이며, 확인 전 “갱신했다”고 말하지 않는다.
4

재캡처

반영이 확인된 캡처의 경로를 남긴다.

5

대조

유지할 속성을 확인한다. 의도 외 변화는 self-reject하고 되돌린다. 최대 3회 뒤에도 실패하면 기준·마지막 캡처와 달라진 속성을 사용자에게 넘긴다.

주소 대조와 “새로고침 → 서버 다시 띄우기 → WASM 다시 빌드”는 공식 문서가 아니라 이 킷의 규칙이다.

캡처 점검 목록

기준 캡처와 재캡처에서 네 가지를 본다

하나라도 걸리면 그 캡처로 PASS를 주지 않는다.

1 · 글자 넘침

잘린 글자, 뜻밖의 말줄임, 컨테이너 밖 텍스트, 문서 본체 가로 스크롤.

2 · 깨진 글리프

네모·빈칸 글자와 이모지. 실제 서비스 글꼴이 아닌 캡처로 글자 모양을 판정하지 않는다.

3 · 칩·뱃지와 줄 모양

형태와 카드/평평한 줄 여부를 §1 관례 표와 대조한다.

4 · 디버그 겹침

개발 도구 단추·패널·오류가 가리면 치우거나 옮겨 다시 찍는다.

전체 화면과 큰 글자

잘라낸 조각만으로 결함이라 단정하기 전에 전체 화면도 찍는다. 넘침은 데이터를 고치지 말고 브라우저 글자 크기를 키워 한 장 더 찍는다.

도구가 고장이라 말하기 전에

실패 호출 뒤 세 가지를 확인한다

도구 이름은 프로젝트 설정에서 읽고, 각 확인의 출력을 응답에 남긴다.

  • 1실패 호출의 인자 이름을 도구 설명과 대조한다. 틀린 키는 도구 고장이 아니다.
  • 2내 서버인지 주소와 포트로 대조한다. 공유 포트·브라우저면 남의 화면일 수 있다.
  • 3대화상자·팝오버·시트 같은 별도 층은 페이지 전체 스냅샷에서 다시 찾는다.
3. 공허한 증거 4 유형 — react 도구 기본값이 만드는 자기충족 통과

초록불이 곧 유효한 증거는 아니다

다음 네 유형은 실제 도구 동작에서 나온다. 제출 전에 모두 배제한다.

a부재 단정이 렌더 실패를 가린다

queryBy*는 없으면 null, queryAllBy*는 빈 배열을 반환하고 throw하지 않는다. 컴포넌트 전체가 렌더되지 않아도 같으므로 양성 대조가 먼저다.

Bad
render(<Skeleton loading={false} />)
expect(screen.queryByTestId('skeleton')).toBeNull()
Good
render(<Skeleton loading={false} />)
expect(screen.getByRole('list')).toBeInTheDocument()
expect(screen.queryByTestId('skeleton')).toBeNull()

b0 테스트 green run

Vitest passWithNoTests는 boolean, 기본값 false다. 플래그나 잘못된 glob으로 0개 실행이 성공할 수 있다. 0개는 “검사되지 않음”이므로 실행 수를 인용한다.

d빈 화면이 baseline으로 굳는다

toHaveScreenshot()은 baseline이 없으면 현재 화면을 golden으로 기록한다. 깨진 화면을 갱신하면 이후 자기 자신과 비교해 통과한다.

  • ✓새 baseline·갱신 이미지에서 조건이 요구한 구체 요소를 지목한다.
  • ✓maxDiffPixels / maxDiffPixelRatio를 통과 목적으로 키우지 않는다.
  • ✓갱신 사유를 남긴다. 사유 없는 --update-snapshots는 증거 삭제다.

## Render Evidence
- 대상: <파일:라인 또는 "신규"> · 라우트: <화면이면 주소>
- 되말하기: <한 문장>
- 관례 표: <같은 역할 기존 화면 경로 2개 이상 | 관례 없음 — 사유>
- 유지할 속성: <열거>
- 증거 등급: R1 | R2 | R3
- 서버 주소: <Local 주소> · 연 주소: <브라우저 주소> (R1 아니면 N/A)
- 기준 캡처: <경로 + 본 것 | 신규> · 표식: <바뀌어야 할 것>
- 반영 확인: <표식이 바뀐 재캡처 경로 | 시도 순서>
- 증거: <명령 + 출력 / 캡처에서 지목한 요소>
- 캡처 점검: 넘침 · 글리프 · 칩·뱃지와 줄 · 디버그 겹침 — 없음 | 걸림
- 실행/스킵 카운트: <passed N · skipped M · 0이면 사유>
- 공허 증거 배제: (a) 양성대조 · (b) 테스트 수 · (c) skipped · (d) baseline
- 대조: <의도한 변경만 | self-reject N회 (최대 3)>
- 미검증: N건 [항목 — 막는 것 — 시도한 우회 — 통제 불가 사유 — 재검증 명령]
