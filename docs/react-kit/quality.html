/react-test — 레이어별 테스트 전략

Clean Architecture 레이어에 따라 다른 테스트 도구를 사용한다. 대상 파일 경로를 보고 자동으로 적합한 유형 선택.

레이어 테스트 유형 도구 특징
domain/ Unit Vitest (node) 순수 함수. 외부 의존성 0개. MSW 불필요
data/ Unit + Integration Vitest + MSW fetch 모의, Zod parse 실패, Result 변환
presentation hooks Component test Vitest + Testing Library + QueryClient renderHook, waitFor, store 초기화
presentation components Component test Vitest + Testing Library + jsdom 렌더, userEvent, getByRole
presentation routes E2E Playwright 실제 브라우저, 라우팅, 폼 제출
infrastructure/ Integration Vitest + mock or Playwright isTauri() mock, invoke 모의

Domain Unit 테스트 — Result 검증

describe('userRepository.fetchUser', () => {
  it('returns ok(User) on 200', async () => {
    server.use(
      http.get('*/users/123', () =>
        HttpResponse.json({
          id: '123',
          email_address: 'jane@example.com',
          display_name: 'Jane',
          created_at: '2026-04-10T00:00:00Z',
        }),
      ),
    )
    const result = await userRepository.fetchUser('123')
    expect(result.isOk()).toBe(true)
    if (result.isOk()) {
      expect(result.value.email).toBe('jane@example.com')
    }
  })

  it('returns err(not-found) on 404', async () => {
    server.use(
      http.get('*/users/999', () =>
        new HttpResponse(null, { status: 404 })),
    )
    const result = await userRepository.fetchUser('999')
    expect(result.isErr()).toBe(true)
    if (result.isErr()) {
      expect(result.error.kind).toBe('user/not-found')
    }
  })
})

/react-test 주의사항
  • !환경 분리 필수 — component 테스트는 jsdom, unit 테스트는 node. environmentMatchGlobs로 경로별 분리.
  • !setupFiles 필수 — @testing-library/jest-dom matchers를 전역 등록하려면 setup 파일에서 expect.extend(matchers).
  • !MSW v2 API — 구 rest.get(...)가 아니라 http.get(...) + HttpResponse. deprecated API 사용 금지.
  • !findBy* 는 await 필수 — 까먹으면 pending Promise로 false positive.
  • !Playwright vs Vitest 파일 분리 — .spec.ts (Playwright) vs .test.ts (Vitest)로 확장자 구분.
/react-error — 3단계 에러 처리 흐름

데이터 경계의 throw → Failure 변환, React 렌더 경계의 Error Boundary, UI 표시를 Severity에 따라 분기한다.

에러 처리 흐름도

1
데이터 경계 — fetch/WASM/Tauri의 throw/reject를 ResultAsync.fromPromise로 Failure 변환. 이 시점이 유일한 throw 허용 위치.
2
Failure 전파 — neverthrow의 Result<T, Failure>로 체인. Severity 매핑: info / warning / error / fatal.
3
UI 표시 — Severity에 따라 Toast / Snackbar / Inline Error / Full Page Error 분기.
B
Error Boundary — Result 패턴이 커버 못 하는 React render-time throw를 최후 안전망으로 포획.

Failure 타입 + Severity 매핑

export type Severity = 'info' | 'warning' | 'error' | 'fatal'

export type UserFailure =
  | { kind: 'user/not-found'; userId: string }
  | { kind: 'user/unauthorized' }
  | { kind: 'user/network-error'; cause: string }
  | { kind: 'user/validation-failed'; issues: string[] }
  | { kind: 'user/rate-limited'; retryAfterSec: number }

export function severityOf(failure: UserFailure): Severity {
  switch (failure.kind) {
    case 'user/not-found':      return 'info'
    case 'user/rate-limited':   return 'warning'
    case 'user/unauthorized':
    case 'user/validation-failed': return 'error'
    case 'user/network-error':  return 'fatal'
  }
}

React Error Boundary (클래스 컴포넌트 필수)

// src/presentation/shared/components/root-error-boundary.tsx
export class RootErrorBoundary extends React.Component<Props, State> {
  state: State = { hasError: false, error: null }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, info: React.ErrorInfo) {
    console.error('RootErrorBoundary:', error, info)
    // 프로덕션: Sentry 전송
  }

  render() {
    if (this.state.hasError) {
      return (
        <div role="alert" className="flex min-h-screen items-center justify-center">
          <div className="space-y-4 text-center">
            <h1 className="text-2xl font-semibold">예기치 못한 오류</h1>
            <button onClick={() => window.location.reload()}>새로고침</button>
          </div>
        </div>
      )
    }
    return this.props.children
  }
}

/react-l10n 주의사항
  • !매크로 import 경로 변경 (v5) — 구 @lingui/macro → @lingui/react/macro (JSX) 또는 @lingui/core/macro (core). /react-audit 검출 항목.
  • !Vite 플러그인 순서 — react({ plugins: [['@lingui/swc-plugin', {}]] })가 반드시 lingui() 앞. SWC가 먼저 매크로를 transpile.
  • !domain 레이어 금지 — Lingui import는 presentation 레이어만. domain은 i18n을 모른다. Failure의 사용자 메시지는 presentation의 display-failure.ts에서 매핑.
  • !RSC 관련 없음 — react-kit은 Vite + TanStack Router 기반. SSR/RSC 없음.
  • !번역 누락 — extract 후 ko.po에 빈 msgstr로 남은 키는 영어 fallback. /react-audit이 경고.
