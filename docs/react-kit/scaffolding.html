/react-screen — 화면 + 라우트 생성

기존 프로젝트에 새 화면을 추가하고 TanStack Router 파일 기반 라우트를 등록한다.

TanStack Router 파일 기반 라우트 등록 절차

1
라우트 파일 생성
src/presentation/routes/<path>.tsx — createFileRoute로 라우트 정의
2
화면 컴포넌트 배치
src/presentation/features/<feature>/screens/<Name>Screen.tsx
3
라우트 파일에서 위임
라우트 파일은 screens 경로를 import하여 얇게 위임
4
자동 코드젠
Vite dev server 실행 중이면 tanstackRouter 플러그인이 routeTree.gen.ts 재생성

Lazy load 패턴

// src/presentation/routes/dashboard.tsx
import { createFileRoute, lazyRouteComponent } from '@tanstack/react-router'

export const Route = createFileRoute('/dashboard')({
  component: lazyRouteComponent(() =>
    import('@/presentation/features/dashboard/screens/DashboardScreen').then(
      (m) => ({ default: m.DashboardScreen }),
    ),
  ),
})
autoCodeSplitting: true 플러그인 옵션이 켜져 있으면 (/react-init 기본값) 수동 lazy 래핑 없이도 자동 분할. 하지만 스킬은 명시적 lazy를 기본으로 생성한다.

스킬 04

/react-widget — shadcn 기반 재사용 컴포넌트

src/presentation/shared/components/에 cva + forwardRef 패턴의 재사용 위젯을 생성한다. 

// src/presentation/shared/components/primary-button.tsx
import * as React from 'react'
import { cva, type VariantProps } from 'class-variance-authority'
import { cn } from '@/presentation/shared/lib/utils'

const primaryButtonVariants = cva(
  'inline-flex items-center justify-center rounded-md font-medium transition-colors focus-visible:outline-none focus-visible:ring-2 disabled:opacity-50 disabled:pointer-events-none',
  {
    variants: {
      variant: {
        default: 'bg-primary text-primary-foreground hover:bg-primary/90',
        destructive: 'bg-destructive text-destructive-foreground hover:bg-destructive/90',
      },
      size: {
        sm: 'h-9 px-3 text-sm',
        md: 'h-10 px-4',
        lg: 'h-11 px-8 text-lg',
      },
    },
    defaultVariants: { variant: 'default', size: 'md' },
  },
)

type PrimaryButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement> &
  VariantProps<typeof primaryButtonVariants>

export const PrimaryButton = React.forwardRef<HTMLButtonElement, PrimaryButtonProps>(
  ({ className, variant, size, ...props }, ref) => (
    <button
      ref={ref}
      className={cn(primaryButtonVariants({ variant, size }), className)}
      {...props}
    />
  ),
)
PrimaryButton.displayName = 'PrimaryButton'

Gotchas

자주 하는 실수 방지

⚠️ Tailwind v4 — npx tailwindcss init 없어짐
v3 문서의 npx tailwindcss init은 v4에서 없어짐. @tailwindcss/vite 플러그인과 @import "tailwindcss";만 쓴다. ↗ Tailwind v4 업그레이드 가이드
⚠️ shadcn 패키지 리네임 (2024-08)
과거 shadcn-ui npm 패키지는 2024년 8월부터 deprecated. 현재는 pnpm dlx shadcn@latest init --template vite 사용. npx shadcn-ui@latest init 더 이상 동작 안 함.
⚠️ TanStack Router — routeTree.gen.ts 수동 수정 금지
플러그인이 자동 생성하고 덮어쓴다. 수정 필요하면 플러그인 옵션 조정. 기본은 .gitignore 제외 권장 (merge conflict 최소화).
⚠️ Rust WASM crate-type 둘 다 필요
crates/core/Cargo.toml에 crate-type = ["cdylib", "rlib"] 둘 다 있어야 WASM 빌드와 Tauri 네이티브 재사용이 동시에 가능. cdylib만 있으면 Tauri 쪽에서 import 불가.
⚠️ eslint-plugin-react-hooks flat config 수동 와이어링
2026-04 기준 flat config 지원이 공식 문서에 완전히 반영되지 않아, eslint.config.js에서 plugins: { 'react-hooks': reactHooks } + rules: reactHooks.configs.recommended.rules 형태로 수동 등록 필요.
⚠️ pnpm workspace ↔ Cargo workspace 혼동
pnpm-workspace.yaml의 packages와 Cargo.toml의 workspace.members를 혼동하지 마라. 전자는 npm 패키지, 후자는 Rust crate. crates/core는 두 파일 모두에 등재되어야 한다.

vite.config.ts 기준 템플릿

/react-init이 생성하는 Vite 설정 파일. Tailwind v4 + TanStack Router + WASM 플러그인이 모두 통합된다.

vitejs.dev/config · Tailwind v4 Vite
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'
import { TanStackRouterVite } from '@tanstack/router-plugin/vite'
import wasm from 'vite-plugin-wasm'
import topLevelAwait from 'vite-plugin-top-level-await'
import path from 'path'

export default defineConfig({
  plugins: [
    TanStackRouterVite(),   // routeTree.gen.ts 자동 생성
    react(),
    tailwindcss(),          // @import "tailwindcss"; 한 줄로 충분
    wasm(),
    topLevelAwait(),
  ],
  resolve: {
    alias: { '@': path.resolve(__dirname, './src') },
  },
  build: {
    target: 'esnext',       // top-level await 지원
  },
})
Tailwind v4 주의: npx tailwindcss init 실행 금지. 설정 파일이 없어야 정상이다. globals.css에 @import "tailwindcss"; 한 줄만 추가하면 된다.
안티패턴 비교

Bad vs Good — G1 핵심 실수 패턴

g1-scaffolding.md §1.6 / §2.6 / §3.5 / §4.6 Gotchas 기반. 반복적으로 관찰된 실수를 코드 수준에서 비교한다.

❌ 안티패턴 — 상대경로 import
// 컴포넌트 이동 후 경로 계산 실패
import { Button } from '../../../shared/ui/button'
import { useUser } from '../../hooks/use-user'

경로 depth가 달라지면 import가 깨진다. /react-extract 이동 후 항상 절대경로로 통일해야 한다.

✅ 권장 — 절대경로 alias
// tsconfig paths + vite resolve.alias 설정 후
import { Button } from '@/presentation/shared/components/ui/button'
import { useUser } from '@/presentation/features/user/hooks/use-user'

@/ alias는 어느 depth에서도 동일하게 동작. /react-init이 tsconfig + vite.config 자동 설정.

❌ 안티패턴 — any 타입 남용
// API 응답 타입을 any로 처리
async function fetchUser(id: string): Promise<any> {
  const res = await fetch(`/api/users/${id}`)
  return res.json() // 타입 검증 없음
}

any는 Strict TS 정책 위반. /react-audit이 AP-10 규칙으로 감지하여 error 레벨 리포트.

✅ 권장 — Zod 경계 검증
import { z } from 'zod'
import { ok, err } from 'neverthrow'

const UserSchema = z.object({ id: z.string(), name: z.string() })

async function fetchUser(id: string) {
  const res = await fetch(`/api/users/${id}`)
  const parsed = UserSchema.safeParse(await res.json())
  if (!parsed.success) return err({ kind: 'ParseError' })
  return ok(parsed.data) // Result<User, Failure>
}

API 진입점에서만 Zod parse. 내부 레이어는 Result<T, Failure>만 전달한다.

❌ 안티패턴 — shadcn 수동 복사
# 컴포넌트를 직접 복사/붙여넣기
cp shadcn-button.tsx src/components/button.tsx
# 또는 구 패키지명 사용
npx shadcn-ui@latest add button

2024-08부터 패키지명이 shadcn으로 변경. shadcn-ui는 deprecated.

✅ 권장 — pnpm dlx shadcn
# 초기화
pnpm dlx shadcn@latest init

# 컴포넌트 추가 (presentation/shared/components/ui/ 에 생성)
pnpm dlx shadcn@latest add button card skeleton

shadcn CLI가 자동으로 components.json 기준 경로에 설치. import 경로 불일치 없음.

Scaffolding 핵심 Gotchas

반복적으로 나타나는 실수 패턴. /react-init 및 /react-feature 실행 전에 반드시 확인하라.

# 실수 패턴 올바른 접근
G1 tailwindcss init 실행 후 tailwind.config.js 생성 v4에는 설정 파일이 없다. @tailwindcss/vite 플러그인만 추가하면 끝
G2 shadcn 패키지를 shadcn-ui로 설치 2024-08부터 패키지명이 shadcn으로 변경됨. npx shadcn@latest init
G3 TanStack Router 라우트 파일을 수동으로 등록 TanStackRouterVite() 플러그인이 routeTree.gen.ts를 자동 생성. 직접 편집 금지
G4 새 feature에서 Zod 스키마를 여러 레이어에 중복 배치 Zod는 최초 진입점(API 응답 파싱 or Form submit)에서만. 내부 레이어는 Result<T>만 전달
G5 domain 레이어에서 throw 사용 domain은 Result<T, AppError>만 반환. throw는 infrastructure 경계에서만 허용
G6 Rust crate-type을 ["cdylib"]만으로 설정 Tauri + WASM 동시 지원 시 ["cdylib", "rlib"] 필수. rlib 없으면 native build 실패
G7 /react-feature 실행 후 rollback 없이 일부 레이어만 생성 4레이어(domain/data/presentation/infrastructure) 전체 생성 또는 전체 롤백. 중간 상태 커밋 금지
