스킬 01

/react-responsive — 반응형 레이아웃 적용

페이지 쿼리 vs 컨테이너 쿼리 결정 규칙

시나리오선택이유
앱 최상위 레이아웃 (사이드바 펼침/접힘, 상단 네비)페이지 (sm/md/lg)뷰포트 전체가 레퍼런스. 전체 앱 구조 결정
그리드 아이템 재배치 (카드 목록 1→2→3 컬럼)페이지 (sm/md/lg)유저가 "화면 크기"로 기대하는 경험
사이드바 안의 카드 (같은 카드가 전체 화면에도, 모달 안에도)컨테이너 (@container)부모 영역 크기에 따라 적응해야 재사용 가능
재사용 컴포넌트 내부 레이아웃 (Card 안의 header/meta)컨테이너 (@container)컴포넌트가 어디에 들어가도 올바르게 보임
모달/드로어 내부컨테이너 (@container)모달 너비 기준, 페이지 너비가 아니라

Tailwind v4 breakpoint 체계

키min-width용도
sm:640px큰 모바일 / 세로 태블릿
md:768px세로 태블릿
lg:1024px가로 태블릿 / 작은 노트북
xl:1280px노트북
2xl:1536px큰 데스크탑

Container Queries — @container (Tailwind v4 내장)

<div className="@container">
  <div className="grid grid-cols-1 @md:grid-cols-2 @xl:grid-cols-3">
    {/* 부모 @container 의 너비가 @md (28rem) 이상이면 2컬럼 */}
  </div>
</div>

{/* 네임드 컨테이너 — 중첩 시 타겟 지정 */}
<div className="@container/sidebar">
  <div className="@md/sidebar:text-lg">
    {/* sidebar 컨테이너가 @md 이상일 때만 */}
  </div>
</div>

변환 예시

Before — 고정 레이아웃
export function ProductGrid({ products }) {
  return (
    <div className="grid grid-cols-3 gap-4">
      {products.map((p) => (
        <ProductCard key={p.id} {...p} />
      ))}
    </div>
  )
}
After — 페이지 쿼리 반응형
export function ProductGrid({ products }) {
  return (
    <div className="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4">
      {products.map((p) => (
        <ProductCard key={p.id} {...p} />
      ))}
    </div>
  )
}
컨테이너 쿼리가 페이지 쿼리를 대체하지 않는다. 둘은 서로 다른 문제를 푼다. Tailwind v3 프로젝트는 @tailwindcss/container-queries 플러그인 설치 필요.

스킬 02

/react-skeleton — 로딩 상태 shimmer 구현

TanStack Query isPending 중에 실 레이아웃 모양의 shadcn Skeleton 조각을 표시. 스피너 대신 "곧 이런 콘텐츠가 나올 거예요"라는 구조 예고.

isPending 연동 패턴

// src/presentation/features/user/components/user-profile-card.tsx
import { Skeleton } from '@/presentation/shared/components/ui/skeleton'
import { useUser } from '../hooks/use-user'

export function UserProfileCard({ userId }: { userId: string }) {
  const { data, isPending, isError, error } = useUser(userId)

  if (isPending) return <UserProfileCardSkeleton />
  if (isError) return <UserProfileCardError error={error} />
  if (!data) return <UserProfileCardEmpty />

  return (
    <div className="rounded-lg border p-6 space-y-4">
      <h2 className="text-xl font-semibold">{data.name}</h2>
      <p className="text-muted-foreground">{data.email}</p>
    </div>
  )
}

function UserProfileCardSkeleton() {
  return (
    <div className="rounded-lg border p-6 space-y-4">
      <Skeleton className="h-7 w-48" />   {/* 제목 자리 */}
      <Skeleton className="h-5 w-64" />   {/* 부제목 자리 */}
    </div>
  )
}

4가지 상태 구분 — 명확히 분기

Loading
isPending === true
Skeleton 표시
Error
isError === true
에러 메시지 + 재시도
Empty
data === undefined
"데이터 없음" + CTA
Success
data 있음
실제 콘텐츠
Skeleton이 쓰이는 건 오직 Loading뿐. Empty 상태에 Skeleton을 써서 "곧 뭐가 나올 것 같다"는 오해를 주지 말 것.

Skeleton 크기 가이드: 텍스트는 h-4~h-7, 버튼은 h-9~h-10, 이미지는 aspect-square/aspect-video. 항상 bg-muted 필수 (없으면 투명해서 안 보임).

스킬 03

/react-extract — 재사용 컴포넌트 추출

feature 내부에 사유화된 위젯 또는 중복된 위젯을 presentation/shared/components/로 추출하고 import 경로를 자동 정리.

추출 8단계 흐름

1
Import 참조 스캔
전체 프로젝트에서 대상 컴포넌트를 import하는 파일 목록 수집 (TypeScript AST 또는 grep 기반)
2
파일 이동
source_path → destination으로 물리 이동
3
컴포넌트 이름 확인
kebab-case 파일명 ↔ PascalCase 컴포넌트명 일관성 검증
4
Props 타입 노출 확인
이동 대상이 export type SomethingProps를 함께 export하는지 (없으면 추가)
5
Import 경로 일괄 수정
참조하는 모든 파일의 import 구문을 @/presentation/shared/components/... absolute import로 업데이트
6
Unused import 정리
원본 feature에 남아있던 import 중 안 쓰는 것 제거
7
tsc + eslint 검증
이동 후 타입 에러/린트 에러 없는지 확인. 에러가 생기면 전체 롤백 후 에러 보고
8
결과 리포트
변경된 파일 수, 이동된 경로, 업데이트된 import 개수 요약

Import 경로 변환 규칙

Before
import { LogoBanner } from './logo-banner'
// feature 내부 상대 경로
After
import { LogoBanner } from '@/presentation/shared/components/logo-banner'
// absolute import

widget-inspector-react 에이전트 연동

🔍

중복 위젯 감지

다른 feature에 같은 이름/구조의 컴포넌트 발견 시 리포트.

📦

과도한 사유화 감지

private이지만 재사용 가능해 보이는 컴포넌트 표시.

📏

복잡도 임계값 초과

컴포넌트 하나가 300줄+ 초과 시 분할 권고.

사용자가 리포트 중 일부를 승인하면 /react-extract가 자동 트리거되어 실제 이동 + import 정리 수행. --dry-run 플래그로 실제 파일 이동 없이 변경 내역만 미리 확인 가능.
추출 전제 조건: named export만 지원 (export default는 먼저 named export로 리팩터 후 이동). Type-only import는 import type으로 분리 (verbatimModuleSyntax: true 정책).

키min-width주요 용도

재사용 컴포넌트에서 @container 사용 예시

// 재사용 ProductCard — 어디에 놓여도 컨테이너 크기에 반응
export function ProductList({ products }: { products: Product[] }) {
  return (
    <div className="@container">
      <div className="grid grid-cols-1 gap-3 @md:grid-cols-2 @xl:grid-cols-3">
        {products.map((p) => <ProductCard key={p.id} {...p} />)}
      </div>
    </div>
  )
}

// 네임드 컨테이너 — 중첩 컨테이너 구분
export function DashboardLayout() {
  return (
    <div className="@container/dashboard">
      <aside className="@container/sidebar">
        <nav className="@sm/sidebar:space-y-2 @md/sidebar:space-y-4">
          {/* sidebar 너비가 @sm 이상일 때 spacing 증가 */}
        </nav>
      </aside>
    </div>
  )
}

Skeleton 심화

실 레이아웃 1:1 매핑 전략

Skeleton과 실제 콘텐츠의 크기가 다르면 전환 시 레이아웃 시프트(CLS)가 발생한다. 동일한 구조로 매핑해야 한다.

콘텐츠 타입Skeleton 클래스비고
h1/h2 제목h-7 w-48 rounded-md너비는 예상 텍스트 길이에 맞게
부제목/설명 텍스트h-5 w-64 rounded-md여러 줄이면 space-y-2로 쌓기
본문 단락 (3줄)h-4 w-full rounded-md × 3마지막 줄은 w-3/4로 자연스럽게
버튼h-9 w-24 rounded-md버튼 크기 (sm: h-9, md: h-10, lg: h-11)
이미지/썸네일 (정사각)aspect-square rounded-md부모 너비 기준 자동 높이
이미지/썸네일 (16:9)aspect-video rounded-md동영상 플레이스홀더
아바타 (원형)h-10 w-10 rounded-full원형은 rounded-full
배지/태그h-5 w-16 rounded-full인라인 뱃지

리스트 Skeleton — 5개 반복

function UserListSkeleton() {
  return (
    <ul className="space-y-3">
      {Array.from({ length: 5 }).map((_, i) => (
        <li key={i} className="flex items-center gap-3 rounded-lg border p-4">
          <Skeleton className="h-10 w-10 rounded-full" />  {/* 아바타 */}
          <div className="flex-1 space-y-2">
            <Skeleton className="h-4 w-32" />             {/* 이름 */}
            <Skeleton className="h-3 w-48" />             {/* 이메일 */}
          </div>
          <Skeleton className="h-8 w-16 rounded-md" />    {/* 버튼 */}
        </li>
      ))}
    </ul>
  )
}

Gotchas

G5 스킬 공통 주의사항

스킬실수올바른 방법
/react-responsive 모든 컴포넌트를 @container로 감쌈 앱 최상위 레이아웃은 페이지 쿼리. 재사용 컴포넌트만 컨테이너 쿼리
/react-responsive 텍스트 크기 반응형 다단 변경 (text-sm md:text-base lg:text-lg) 타이포 리듬 깨짐. 디자인 시스템의 정해진 scale만 사용
/react-skeleton bg-muted 없는 Skeleton 투명해서 animate-pulse가 안 보임. 항상 배경색 포함 필수
/react-skeleton Empty 상태에 Skeleton 표시 Skeleton은 오직 isPending === true일 때만. Empty는 별도 EmptyState UI
/react-skeleton Skeleton 크기가 실제 콘텐츠와 다름 1:1 크기 매핑 필수 — 레이아웃 시프트(CLS) 방지
/react-extract export default 컴포넌트 이동 먼저 named export로 리팩터 후 추출. import type 분리 필수
/react-extract 이동 후 tsc 검증 없이 완료 보고 스킬은 이동 후 반드시 tsc --noEmit + eslint 실행. 에러 시 전체 롤백
