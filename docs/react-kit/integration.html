안티패턴 vs 올바른 패턴

Bad vs Good — 통합 설계 실수 패턴

final-integration.md 안티패턴 목록 + 21 스킬 공통 원칙 기반. 반복 발생하는 3가지 위반 패턴과 올바른 대응을 제시한다.

1. 라이브러리 도입 vs 순수 구현

❌ 안티패턴 — 외부 애니메이션 라이브러리 도입
// Motion import — LP 규칙 위반, /react-audit AP-01 error
import { motion } from 'motion/react'
import { useDraggable } from '@dnd-kit/core'

// 번들에 추가되는 외부 의존성:
// motion/react ~50 kB, @dnd-kit/core ~20 kB
function DraggableCard() {
  return (
    <motion.div drag dragConstraints={...}>
      콘텐츠
    </motion.div>
  )
}

motion, framer-motion, react-spring, @dnd-kit/*, gsap, lottie-react는 AP-01 LibraryPolicy error. 외부 라이브러리 도입은 번들 크기를 늘리고 react-kit 원칙을 위반한다.

✅ 권장 — Tailwind + 브라우저 네이티브 API
// Tier 1: Tailwind CSS 트랜지션 (외부 의존성 0개)
function FadeCard({ visible }: { visible: boolean }) {
  return (
    <div className={`transition-opacity duration-300
      ${visible ? 'opacity-100' : 'opacity-0'}`}>
      콘텐츠
    </div>
  )
}

// Tier 3: Pointer Events API — 드래그 커스텀 훅
import { useDrag } from '@/presentation/shared/hooks/use-drag'

Tailwind T1 → View Transitions API T2 → 커스텀 Pointer Events T3 순서로 판정. 라이브러리 0개 원칙 — 번들 크기와 의존성 없이 동일한 UX를 구현한다.

2. 레이어 경계 위반 vs Clean Architecture

❌ 안티패턴 — presentation에서 Tauri API 직접 import
// presentation 레이어에서 @tauri-apps/* 직접 사용
// AP-02 Architecture error — 웹 빌드 런타임 오류 발생
import { invoke } from '@tauri-apps/api/core'
import { open } from '@tauri-apps/plugin-dialog'

function SettingsScreen() {
  const handleOpen = async () => {
    // 웹 빌드에서 @tauri-apps 미존재 → 런타임 crash
    const path = await open({ multiple: false })
    await invoke('save_config', { path })
  }
}

presentation·domain·data에서 @tauri-apps/*를 직접 import하면 웹 빌드 런타임 오류. Tauri 전용 API는 반드시 infrastructure/tauri/ 래퍼를 경유해야 한다.

✅ 권장 — infrastructure/tauri/ 래퍼 경유
// src/infrastructure/tauri/file-dialog.ts
import { isTauri } from '@/infrastructure/tauri/guard'

export async function openFileDialog(): Promise<string | null> {
  if (!isTauri()) return null
  const { open } = await import('@tauri-apps/plugin-dialog')
  return open({ multiple: false }) as Promise<string | null>
}

// presentation에서는 인프라 래퍼만 import
import { openFileDialog } from '@/infrastructure/tauri/file-dialog'

function SettingsScreen() {
  const handleOpen = async () => {
    const path = await openFileDialog() // 웹에서는 null 반환
  }
}

isTauri() 가드 래퍼로 Tauri API를 감싸면 웹·데스크탑 모두 동작. presentation은 infrastructure 인터페이스만 참조하여 레이어 경계를 유지한다.

3. domain에서 throw vs Result 반환

❌ 안티패턴 — domain에서 throw new Error
// domain/usecases/fetch-user.ts
// AP-40 error — domain에서 throw 감지 시 감사 오류
export async function fetchUser(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`)
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`) // ❌ throw 금지
  }
  const data = await res.json()
  if (!data.id) {
    throw new Error('Invalid user data') // ❌ throw 금지
  }
  return data as User // ❌ as 단언도 금지
}

domain에서 throw는 AP-40 감사 오류. 호출부에서 try/catch를 강제하여 타입 안전성이 깨진다. 예외 경로가 타입에 표현되지 않아 누락 가능성이 높다.

✅ 권장 — neverthrow Result<T, Failure> 반환
// domain/usecases/fetch-user.ts
import { Result, ok, err } from 'neverthrow'
import { UserEntity, UserEntitySchema } from '@/domain/entities/user'
import { Failure } from '@/domain/failures'

export async function fetchUser(
  id: string
): Promise<Result<UserEntity, Failure>> {
  const res = await fetch(`/api/users/${id}`)
  if (!res.ok) {
    return err({ kind: 'NetworkFailure', status: res.status })
  }
  const parsed = UserEntitySchema.safeParse(await res.json())
  if (!parsed.success) {
    return err({ kind: 'ParseFailure', issues: parsed.error.issues })
  }
  return ok(parsed.data)
}

Result<T, Failure>로 성공·실패 경로를 타입에 명시. 호출부는 .match()/.mapErr()로 분기하며 예외 누락이 불가능하다. Zod safeParse로 any/as 없이 검증한다.

Gotchas 체크리스트

21 스킬 교차 공통 주의사항

G1~G6b 스킬 전체를 관통하는 반복 실수 패턴. 구현 착수 전 이 목록을 확인하라. 개별 스킬 Gotchas는 각 그룹 페이지 참조.

  • !
    any / as / ! 금지 — 전 스킬 공통. 생성 코드에 any, as SomeType, value! non-null 단언이 포함되면 /react-audit AP-10·11이 error로 감지한다. Zod safeParse 또는 타입 가드로 대체하라.
  • !
    domain/ 레이어에서 throw 금지. domain은 Result<T, Failure>만 반환한다. throw new Error(...)가 감지되면 AP-40 + /react-audit Architecture 축 error. infrastructure 경계에서만 예외를 받아 Result로 변환하라.
  • !
    Tauri API는 infrastructure/tauri/ 래퍼 경유 필수. @tauri-apps/를 domain·data·presentation에서 직접 import하면 웹 빌드 런타임 오류 + AP-02 error. isTauri() 가드 래퍼를 반드시 거쳐라.
  • !
    WASM 이식 전 G0 카탈로그 확인 필수. 직관으로 이식 결정 금지. wasm-catalog.md §1 권장 카테고리 또는 §5 휴리스틱 3/5 이상일 때만 /react-wasm 실행. 폼 검증·JSON 파싱·DOM 조작은 §2 비권장 카테고리다.
  • !
    애니메이션 라이브러리 import 절대 금지. motion, framer-motion, react-spring, @dnd-kit/*, gsap, lottie-react는 AP-01 규칙 — LibraryPolicy error. Tailwind T1 → View Transitions API T2 → 커스텀 pointer primitives T3 순서로 판정하라.
  • !
    복수 파일 생성 실패 시 전체 롤백. /react-feature·/react-api 등 복수 레이어를 생성하다 하나라도 실패하면 해당 실행으로 생성된 파일 전체를 삭제하고 원상복구한다. 중간 상태 커밋 금지.
  • !
    Zod는 최초 진입점에서만. API 응답 파싱 또는 Form submit 시 한 번만 parse. 내부 레이어(domain → data → presentation)는 이미 검증된 타입만 전달한다. 레이어마다 Zod 재검증은 불필요한 중복이다.
  • !
    Skeleton은 실 레이아웃 1:1 매핑. isPending일 때 스피너 대신 Skeleton을 쓰되, 크기·위치가 실제 콘텐츠와 달라지면 CLS가 발생한다. shadcn Skeleton에 bg-muted 배경색 없으면 투명해서 보이지 않는다.
  • !
    구현 전 반드시 /harness sprint-contract 실행. 2+ 파일 변경, 새 화면·컴포넌트·API 연동 시 계약 없이 착수 금지. 완료 후 qa-evaluator로 APPROVE 받아야 구현 종료다.
