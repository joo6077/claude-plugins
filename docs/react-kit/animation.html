3-Tier 구조 — 낮은 티어 우선

/react-animation 스킬은 요청을 받으면 자동으로 가장 낮은 티어부터 시도한다. "무조건 Motion" 접근과 달리 필요한 만큼만 사용.

티어 도구 적용 시나리오 구현 난이도
T1 animate-* + transition-* + CSS @keyframes 상태 변화 (fade/slide/scale), hover 효과, 단순 loop 낮음

T3 커스텀 Pointer Primitives + FSM + requestAnimationFrame 드래그앤드롭, 제스처, momentum, SVG 연결선 높음

Tier 1 주의사항
  • !transition-all 주의 — 변화하는 속성에만 걸 것. transition-transform/transition-colors처럼 명시적으로.
  • !will-change 남용 금지 — GPU 레이어 힌트지만 남용하면 메모리 낭비. hover 시 동적 추가/제거로 정확히 제어.
  • !Reduced motion 필수 — motion-reduce:transition-none 같은 Tailwind variant 사용. /react-audit 이 누락 검출.
  • !data-state 변경 빈도 — 너무 자주 바뀌면 애니메이션 재시작. 상태 머신으로 전환 타이밍 제어.
Tier 2 — View Transitions API

2026-01 Baseline. Chrome/Safari/Firefox 144+에서 같은 문서 SPA DOM 변경 시 자동 FLIP 애니메이션. 라이브러리가 하던 "shared element transition"을 네이티브로 해결.

기본 유틸리티 래퍼

// src/presentation/shared/lib/view-transition.ts
export function withViewTransition(
  updateDOM: () => void,
  options?: { types?: string[] },
): void {
  if (typeof document.startViewTransition !== 'function') {
    updateDOM()
    return
  }
  try {
    if (options?.types?.length) {
      document.startViewTransition({
        update: updateDOM,
        types: options.types,
      })
    } else {
      document.startViewTransition(updateDOM)
    }
  } catch {
    updateDOM()
  }
}
출처: MDN View Transition API

view-transition-name — 공유 요소

DOM 구조가 바뀌어도 "같은 요소"로 식별되어 자동 FLIP 이동.

<img
  src={user.avatarUrl}
  alt={user.name}
  style={{
    viewTransitionName: `user-avatar-${user.id}`,
  }}
/>

주의: view-transition-name은 전역 고유해야 함. 동시 2개 이상이면 콘솔 에러 발생.

// 뷰 모드 전환 버튼
export function TaskViewSwitcher() {
  const viewMode = useTaskStore((s) => s.viewMode)

  )
}

Tier 2 주의사항
  • !view-transition-name 전역 고유 필수 — 동시 2개 이상이면 "duplicate name" 에러. 동적 id로 고유화.
  • !contain: layout 필요 — 복잡한 요소는 contain: layout CSS 추가로 정확한 전환 보장.
  • !Firefox 144+ types 미지원 — types 파라미터는 Chromium 계열만 안전. withViewTransition의 fallback 코드 필수.
  • !Reduced motion — prefers-reduced-motion: reduce에서 startViewTransition을 건너뛰는 로직 추가 권장.
  • !scroll position 보존 — 전환 후 스크롤 위치가 리셋될 수 있음. scroll-behavior와 함께 조정.
Tier 3 — 커스텀 Pointer Primitives

드래그앤드롭, 제스처, 복잡한 gesture-driven 애니메이션은 Pointer Events API + 상태 머신으로 직접 구현한다. dnd-kit 없이.

왜 Pointer Events인가

  • ✓단일 API로 mouse/touch/pen 통합 — 각각 다른 핸들러 불필요
  • ✓setPointerCapture — 요소 밖으로 나가도 이벤트 계속 수신 (드래그 핵심)
  • ✓touch-action: none — 드래그 중 기본 스크롤/줌 차단

useDrag 커스텀 훅 핵심 구조

// src/presentation/shared/hooks/use-drag.ts
import { useCallback, useReducer, useRef } from 'react'

type DragState =
  | { kind: 'idle' }
  | { kind: 'dragging'; startX: number; startY: number; offsetX: number; offsetY: number; pointerId: number }
  | { kind: 'dropping'; offsetX: number; offsetY: number }

export function useDrag() {
  const [state, dispatch] = useReducer(dragReducer, { kind: 'idle' })
  const ref = useRef<HTMLElement | null>(null)

  const onPointerDown = useCallback((e: React.PointerEvent) => {
    e.currentTarget.setPointerCapture(e.pointerId)
    dispatch({ type: 'start', x: e.clientX, y: e.clientY, pointerId: e.pointerId })
  }, [])

  // onPointerMove, onPointerUp, onPointerCancel ...
  return { state, handlers: { onPointerDown, ... }, ref, resolve }
}
출처: MDN setPointerCapture
