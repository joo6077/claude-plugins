각 Phase의 동일한 실행 프로세스

17 개 Phase는 모두 같은 프로세스를 따른다. 각 Phase는 새 서브에이전트로 실행하고, 자체 리서치를 하며, QA REJECT 시 해당 Phase만 재시도한다.

Phase 프로세스
1
Triage — 피드백 읽기 → 개선 필요? → 불필요 시 SKIP + 로그. 피드백이 0건이면 SKIP하지 않고 리서치 전용 모드로 진행
2
자체 리서치 — 해당 스킬의 search-sources.md 기반, 3-5개 도메인만
3
GAP 분석 — 리서치 + 피드백 + 현재 스킬/가이드 대조
4
예방적 분석 — 리서치 anti-pattern을 현재 프롬프트에 대조
5
Sprint Contract (DRAFT) — 현재 버전 sprint-contract 사용
6
개선안 DRAFT 작성 (파일 미적용)
7
QA Evaluator — 현재 버전으로 DRAFT 평가
8
APPROVE → kaizen-phase-N-pre 태그 생성 → 파일 적용 + 커밋 → Regression Smoke Test
9
Regression 실패 → git revert (kaizen-phase-N-pre 태그) → BLOCKED
10
다음 Phase → 새 서브에이전트 (fresh load)

실행 흐름

17 Phase 실행 순서

Phase 순서는 바꾸지 않는다. 상위 Phase가 바뀌면 하위 Phase가 전수 정합성 감사를 한다. 모든 Phase는 한 브랜치에서 실행하고, Phase 1~4 는 차례로, 킷 Phase 는 동시에 3 개까지 돈다.
