"킷 만들어줘" 한 마디로 끝까지 자동화되는 7 Phase 오케스트레이션.

Overview

7 Phase 파이프라인

create-kit 스킬은 새 플러그인 킷을 처음부터 끝까지 생성한다. 각 Phase는 이전 Phase의 산출물에 의존하며, 병렬화 가능한 단계는 서브에이전트로 동시 실행된다.

Phase 0 · 요구사항 → Phase 1 · 리서치 → Phase 2 · 문서 → Phase 3 · 플러그인 → Phase 4 · 카이젠 → Phase 5 · 레지스트리 → Phase 6 · QA → Phase 7 · docs-site
Phases

단계별 상세

Phase 0에서 요구사항을 확인한 뒤, Phase 1~2는 리서치 기반 SSOT 문서를 구축한다. Phase 3~5는 스캐폴딩과 레지스트리 연동, Phase 6~7은 품질 보증과 시각화다.

0
요구사항 확인
킷 이름, 도메인, 스택 무관 여부, 3번째 스킬 성격(system vs init) 확인.
Output: 킷 메타데이터
1
리서치 (Codex)
Codex에 도메인 분석 위임. skills.sh 마켓플레이스, 커뮤니티 니즈, 자동화 효과 Top 10, 적합한 스킬 아키타입 분석. P1/P2 주제 선정 후 심화 리서치 병렬 실행.
Output: 영역 분석 리포트 + P1/P2 주제 목록
2
리서치 문서 생성
docs/{kit-name}/에 카테고리별 원칙 문서 작성. frontmatter + 원칙(인라인 출처) + 수치 기준 + 안티패턴 + Gotchas 포맷. 서브에이전트로 병렬 생성.
Output: docs/{kit-name}/**/*.md (N개, SSOT)
3
플러그인 스캐폴딩
plugin.json + 3스킬(guide/audit/system|init) + reviewer 에이전트 + evals/ + README.md. design-kit 패턴 준수.
Output: {kit-name}/ 플러그인 전체 구조
4
카이젠 연동
.claude/skills/에 {kit-name}-research + {kit-name}-kaizen 스킬 생성. 플러그인이 아닌 레포 개발용 위치.
Output: .claude/skills/{kit-name}-research, {kit-name}-kaizen
5
레지스트리 & 문서
marketplace.json에 신규 플러그인 등록, CLAUDE.md 스킬 레퍼런스 테이블 갱신.
Output: marketplace.json, CLAUDE.md 업데이트
6
QA 평가
harness:qa-evaluator 에이전트 spawn. 구조 일관성, 리서치 품질, 스킬 품질, 경로 정합성 평가. REJECT 시 최대 3회 수정 후 에스컬레이션.
Output: APPROVE 판정 or 수정 피드백
7
docs-site 페이지
css-tokens.md에 새 accent 추가 후 /docs-site 스킬 실행. 리서치 문서 N개 = HTML 페이지 N개 원칙 (design-kit 22→22 기준).
Output: docs/{kit-name}/*.html (N개) + index.html 등록
Output

생성되는 파일 구조

Phase 1~7이 완료되면 아래와 같은 4개 경로에 파일이 배치된다. 모든 스킬은 docs/{kit-name}/를 SSOT로 참조한다.

docs/{kit-name}/ ← 리서치 SSOT (N개 .md) ├── fundamentals/ ├── patterns/ └── ... {kit-name}/ ← 플러그인 ├── .claude-plugin/plugin.json ├── skills/ │ ├── {kit-name}-guide/ │ ├── {kit-name}-audit/ │ └── {kit-name}-{system|init}/ ├── agents/{kit-name}-reviewer.md ├── evals/ └── README.md .claude/skills/ ← 카이젠 (레포 전용) ├── {kit-name}-research/SKILL.md └── {kit-name}-kaizen/SKILL.md docs/{kit-name}/ ← 시각 문서 (N개 .html) ├── topic-a.html ├── topic-b.html └── ...
Patterns

3스킬 + 1에이전트 패턴

모든 킷은 동일한 구조를 따른다. design-kit, backend-kit, infra-kit 모두 이 패턴의 인스턴스다.

역할스킬/에이전트용도
가이드/{kit-name}-guide개발 중 코드/설정에 원칙 기반 가벼운 리뷰
감사/{kit-name}-audit카테고리별 PASS/FAIL 체계적 감사 (reviewer 에이전트 호출)
세팅/{kit-name}-{system|init}프로젝트 기반 초기 세팅
평가자{kit-name}-reviewer (에이전트)읽기 전용 독립 평가. tools: Read/Grep/Glob, model: sonnet
Gotchas

반복 실수 방지

backend-kit, infra-kit 생성 과정에서 반복적으로 놓친 함정들. 실제 QA REJECT 근거에서 추출.

01 · 리서치 없이 스킬부터 만들지 마라
리서치 문서(SSOT)가 먼저 존재해야 스킬이 참조할 수 있다. design-kit이 22개 문서 위에 3개 스킬을 올린 것처럼, 문서 → 스킬 순서는 절대 뒤집히면 안 된다.
02 · 3스킬 패턴을 벗어나지 마라
모든 킷은 guide(가벼운 리뷰) + audit(체계적 감사) + system/init(초기 세팅) 3종을 따른다. 4번째 스킬이 필요하면 기존 3개에 흡수할 수 없는지 먼저 검토하라.
03 · 1 리서치 문서 = 1 HTML 페이지
여러 문서를 overview로 묶지 마라. design-kit(22→22) 기준을 따라 리서치 문서 N개가 있으면 HTML 페이지도 N개를 만들어야 콘텐츠 밀도가 유지된다.
04 · 카이젠 스킬은 플러그인이 아닌 .claude/skills/에
research/kaizen 스킬은 레포 개발용이다. 플러그인 안에 넣으면 외부 사용자에게 노출되고, 레포 상태(git, 다른 스킬)에 대한 의존이 깨진다.
05 · accent 컬러 충돌 확인
docs-site 페이지 생성 시 css-tokens.md의 기존 accent와 겹치지 않는 컬러를 선택해야 한다. 기존 매핑: Harness #D97757, Flutter #22D3EE, Design #E8965A, Backend #A78BFA, Infra #34D399, Process #4ADE80.
06 · 병렬화 가능한 단계를 직렬로 실행하지 마라
P1/P2 리서치, 문서 작성, 스킬 생성은 모두 서브에이전트로 병렬 처리한다. 직렬 실행하면 시간이 3~4배 늘어난다.
Verification

완료 체크리스트

Phase 7 완료 시 아래 항목을 모두 충족해야 APPROVE된다.

  • ✓docs/{kit-name}/ 리서치 문서 N개 존재 (P1 + P2)
  • ✓모든 리서치 문서에 frontmatter + 인라인 출처 포함
  • ✓{kit-name}/.claude-plugin/plugin.json 존재
  • ✓스킬 3개 (guide, audit, system/init) SKILL.md 존재
  • ✓에이전트 1개 (reviewer) .md 존재
  • ✓principle-index.md 상대경로가 실제 문서와 일치
  • ✓.claude/skills/{kit-name}-research + {kit-name}-kaizen 존재
  • ✓marketplace.json에 새 플러그인 등록
  • ✓qa-evaluator APPROVE 판정
  • ✓docs/{kit-name}/ HTML 페이지 N개 존재 (리서치 문서 수와 동일) + index.html에 전체 등록
