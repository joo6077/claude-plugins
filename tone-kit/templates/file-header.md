# 파일 헤더 템플릿

파일 상단 헤더 주석 블록. 실측 기준 재사용 빈도 1위 템플릿이다 (수기 작성 파일 290개 중 287개, 99%).

**채우는 주체:** `tone-scaffold` · **파라미터 소유:** `project-detection`

## 골격

```dart
/// ----------------------------------------------------------------------------
/// - {label_file}  : {파일명}
/// - {label_desc}   : {한 줄 설명}
/// - {label_author}  : {현재 git user.name}
/// - {label_screen} : {화면 식별자 또는 없음 표기}
/// - {label_ref}    : {참고 URL 또는 없음 표기}
/// - {label_history} :
///   - {YYYY-MM-DD} : {최초 생성}
/// ----------------------------------------------------------------------------
```

## 필드 구성

| 필드 | 필수 | 실측 | 비고 |
|---|---|---|---|
| 파일명 | 필수 | 287/287 | 실제 파일명과 일치해야 한다. 파일을 리네임하면 같이 고친다 |
| 설명 | 필수 | 287/287 | 한 줄. 파일명을 한국어로 옮기기만 한 설명은 금지 |
| 작성자 | 필수 | 287/287 | **현재 `git config user.name`.** 기존 파일에서 복사 금지 |
| 화면ID | 선택 | 207/287 | 클래스에 화면 식별자 상수가 있으면 생략한다 |
| 참고 | 선택 | 205/287 | 디자인 링크·이슈 URL. 없으면 필드를 지우거나 없음 표기 |
| 수정이력 | 필수 | 287/287 | 날짜 + 변경 요지. 여러 명이 만졌으면 항목마다 작성자 병기 |

## 구분선 정책

실측 코퍼스에 세 변종이 공존한다 — 위아래 모두(234) · 아래만 · 없음(3). **프로젝트가 하나를 고르고 그것만 쓴다.** 혼재는 그 자체가 일관성 결함이다.

구분선을 쓰기로 했다면 길이도 고정한다. 길이가 파일마다 다르면 diff 노이즈가 된다.

## 정렬

한글 라벨은 글자 폭이 달라 공백 수를 라벨별로 다르게 준다 (`파일명` 뒤 2칸, `설명` 뒤 3칸, `참고` 뒤 4칸). 이 정렬은 시각적 규약이지 파싱 대상이 아니다 — 자동 포매터가 무너뜨리지 않는지 한 번 확인한다.

## 규칙

- 라벨 문자열은 **언어 의존 상수** 다. 한국어 프로젝트가 아니면 라벨 집합 전체를 그 언어로 교체한다. 정책은 `locale-korean.md` 가 소유한다.
- 작성자를 옛 파일에서 복사하는 사고가 실제로 발생했다. 스캐폴딩 시 `git config user.name` 을 읽어 채운다.
- 생성 파일(코드 생성기 산출물)에는 붙이지 않는다.
- 필드를 늘리고 싶으면 프로젝트 파라미터로 추가한다. 킷이 필드 집합을 고정하지 않는다.
