## 축 모델

이 킷의 규칙은 세 축이 **직교** 한다. 두 축(코어/어댑터)만으로는 표현되지 않는다.

| 축 | 값 | 소유 파일 | 예 |
|---|---|---|---|
| A 스택 | core / adapter | `core-*.md` · `adapter-*.md` | 구분선 주석 금지 = core · `_build*` 금지 = adapter |
| B 언어 | neutral / locale | `locale-*.md` | 이름 대신 변수명 = neutral · `- 반환값:` 라벨 = locale-ko |
| C 프로젝트 | universal / param | `project-detection.md` | 역할 접미사 taxonomy = universal · 위젯 prefix = param |

한 규칙이 여러 축에 걸릴 수 있다. doc 주석의 `- 반환값: 없음` 은 **어댑터(Dart) × 로케일(한국어) × universal** 이다. 이 규칙을 어댑터에만 두면 영어 프로젝트로 옮길 때 라벨이 따라가고, 로케일에만 두면 Dart 가 아닌 스택에서 포맷이 깨진다.

## 슬롯 정의

어댑터는 아래 슬롯을 채운다. **필수** 슬롯이 비면 그 어댑터는 동작하지 않는다.

| 슬롯 | 필수 | 타입 | 설명 |
|---|---|---|---|
| `comment_syntax` | 필수 | 문자열 | 라인 주석과 문서 주석 표기. 블록 주석 허용 여부 |
| `doc_param_format` | 필수 | 포맷 문자열 | 파라미터 문서화 한 줄 형식. 식별자 링크 문법 포함 |
| `doc_return_label` | 필수 | 포맷 문자열 | 반환값 줄 형식. **라벨 문자열 자체는 B축 소유** — 어댑터는 구조만 정의하고 값은 로케일에서 가져온다 |
| `helper_prefix_forbidden` | 선택 | 패턴 | 금지할 헬퍼 접두사. 해당 관용구가 없는 스택이면 비운다 |
| `separator_pattern` | 필수 | 규칙 | 요소 사이 간격·구분자를 만드는 정식 방법. 금지 형태 포함 |
| `fallback_identifier_pattern` | 선택 | 정규식 | 기본값 해소 식별자의 금지 접두사 패턴 |
| `naming_suffix` | 필수 | 표 | 클래스·타입별 접미사 규약과 대소문자 규칙 |
| `state_lib` | 선택 | 목록 | 상태 관리 스택. UI 스택이 아니면 비운다 |
| `codegen_cmd` | 선택 | 감지값 | **상수가 아니다.** 프로젝트 감지 대상이며 `project-detection.md` 가 소유한다 |
| `audit_greps` | 필수 | 목록 | 완료 게이트 검색 패턴. 각 패턴에 "히트가 곧 위반인지" 판정을 병기한다 |

### 슬롯 작성 규칙

- 정규식은 **실행 검증한 것만** 싣는다. bash 와 zsh 양쪽에서 돌리고, 각 패턴이 합성 양성 케이스를 실제로 잡는 것을 확인한다. 서술만 있고 실행되지 않는 패턴은 죽은 가드다.
- 히트가 곧 위반이 아닌 패턴은 그 사실을 표에 적는다. 적지 않으면 오탐이 위반으로 보고된다.
- 준수 상태에서 0건이 정상인 패턴은 별도 표시하고, 합성 양성 케이스로 살아 있음을 증명한다. 0건은 "위반 없음" 과 "패턴이 죽음" 을 구분하지 못한다.

## 코어 단독 동작 범위

**코어는 어댑터 없이 동작한다.** 어댑터가 없으면 다음이 비활성화되고 나머지는 그대로 적용된다.

| 어댑터 없을 때 | 상태 |
|---|---|
| `core-comment.md` · `core-naming.md` · `core-structure.md` · `core-antipatterns.md` | 전부 적용 |
| `locale-korean.md` | 주석 언어가 한국어면 적용 |
| 스택 고유 grep 게이트 | 비활성. 수동 검토로 대체 |
| 스캐폴딩 템플릿 중 스택 의존분 | 비활성. 스택 무관 템플릿만 생성 |

## 어댑터 추가 절차

새 스택 어댑터는 **위반이 실제로 관측된 뒤** 만든다. 관측 없이 만드는 것은 추측 구현이다.

1. 대상 스택 코퍼스에서 코어 규칙 위반을 실측한다. 그 스택에 맞는 검색 패턴으로 재측정한다 — 다른 스택의 패턴을 그대로 쓰면 거짓 양성이 나온다.
2. 실측이 유의미하면 `adapter-<stack>.md` 를 만들고 위 슬롯을 채운다.
3. 슬롯의 정규식을 실행 검증한다.
4. `project-detection.md` 에 그 스택의 감지 규칙을 추가한다.

**"지금 위반이 0" 과 "규칙이 적용 불가" 는 다르다.** 이 킷은 기존 코드 정리용이 아니라 새 코드 작성 표준이므로, 위반 0인 스택에도 코어는 유효하다. 어댑터를 만들지 않는 이유는 규칙이 안 맞아서가 아니라 결속할 관용구가 아직 관측되지 않아서다.

## 현재 어댑터 현황

| 어댑터 | 상태 | 근거 |
|---|---|---|
| `adapter-dart-flutter.md` | 채워짐 | 코퍼스 실측에서 유의미한 위반 관측 |
| 그 외 스택 | 없음 | 위반 실측 부재. 계약만 정의해 두고 관측 시 파일 하나 추가로 대응 |
