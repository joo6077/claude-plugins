# 프로젝트 파라미터 감지

프로젝트마다 달라지는 값을 코드에서 감지하는 규칙. **킷은 값을 정하지 않는다** — 감지하거나 사용자에게 묻는다.

## 3분류

파라미터는 감지 가능성에 따라 셋으로 나뉜다. 분류를 섞으면 확신할 수 없는 값을 확신한 것처럼 쓰게 된다.

| 분류 | 판단 근거 | 처리 |
|---|---|---|
| 결정론적 감지 | 파일·디렉토리 존재, 선언 검색으로 100% 확정 | 자동 감지. 사용자 확인 불필요 |
| 감지 후 확인 | 관례 선언이라 빈도만으로는 확신 불가 | 감지 후 **사용자에게 확인** |
| 정책 상수 | 프로젝트마다 달라질 값이 아님 | references 에 내장 |

## 결정론적 감지

| 키 | 감지 방법 |
|---|---|
| `scope_paths` | 작업 대상 디렉토리 존재 확인 |
| `token_class_names` | 스타일·토큰 클래스 선언 검색 |
| `state_lib` | 의존성 파일에서 상태 관리 패키지 식별 |
| `test_dir` | 테스트 디렉토리 존재 확인 |
| `shared_component_dir` | 공용 컴포넌트 디렉토리 존재 확인 |
| `i18n_keys_class` | i18n 생성 파일에서 키 클래스 식별 |
| `comment_language` | 기존 주석 표본에서 문자 범위 판별 |
| `adapter` | 의존성·확장자로 스택 판별 |

이 값들은 코드에서 다시 읽으면 복구되므로 낡아도 안전하다.

## 감지 후 확인

| 키 | 왜 확인이 필요한가 |
|---|---|
| `widget_prefix` | 빈도가 높아도 그것이 규약인지 우연인지 코드만으로는 모른다 |
| `widget_suffix` | 접미사를 안 쓰기로 한 프로젝트도 유효하다 |
| `props_suffix` | 다른 이름의 동일 패턴이 있을 수 있다 |
| `screen_split_path` | 현재 구조가 의도인지 미정리 상태인지 구분 불가 |
| `file_header_fields` | 필드 집합이 관례인지 잔존물인지 불명 |
| `divider_style` | 실측 코퍼스에서 세 변종이 공존했다. 다수결이 곧 규약은 아니다 |

**이 값들은 낡으면 조용히 틀린다.** 확인 날짜를 오버레이 파일에 남긴다.

빈도만으로 확정하지 마라. 코드베이스의 다수 패턴이 정리 대상일 수 있다 — 그 경우 감지가 오염을 규칙으로 승격시킨다.

## 정책 상수

프로젝트마다 달라질 값이 아니므로 감지하지 않고 references 에 내장한다.

| 키 | 소유 파일 |
|---|---|
| `doc_return_label` · `doc_void_value` | `locale-korean.md` |
| 파일 헤더 라벨 집합 | `locale-korean.md` |
| 역할 접미사 taxonomy | `core-naming.md` |
| 안티패턴 카테고리 코드 | `core-antipatterns.md` |
| 어댑터 슬롯 구조 | `adapter-contract.md` |

## 감지 절차

```text
1. 어댑터 판별
   의존성 파일 · 소스 확장자로 스택을 정한다. 해당 어댑터가 없으면 코어만 로드한다.

2. 주석 언어 판별
   기존 주석 표본에서 문자 범위를 본다. 한국어면 locale-korean.md 를 추가 로드한다.

3. 결정론적 값 수집
   위 표의 방법으로 읽는다. 실패하면 그 키를 비우고 진행한다 — 추측값을 넣지 않는다.

4. 확인 대상 제시
   후보값과 근거(관측 건수·위치)를 표로 제시하고 한 번에 확인받는다.
   키마다 따로 묻지 않는다.

5. 오버레이 기록
   확정값과 확인 날짜를 프로젝트 오버레이 파일에 남긴다.
```

기존 오버레이 파일이 있으면 1~4를 건너뛰고 읽는다. 다만 결정론적 값은 코드가 바뀌었을 수 있으므로 재확인한다.

## 오버레이 파일

형식은 `../templates/tone-project.md` 를 쓴다. 프로젝트의 `.claude/` 아래에 둔다.

규칙:

- **오버레이는 값과 판정만 담는다.** 규칙 본문을 복사하지 않는다 — 복사하면 킷 갱신 시 두 벌이 갈라지고 갈라진 사실을 아무도 모른다.
- 빌드·코드생성 명령이 프로젝트 설정에 이미 있으면 그것을 읽는다. 중복 스키마를 만들지 않는다.
- 용어 번역표의 기준 디렉토리는 **정리 이력이 없는 쪽** 으로 명시한다.
- 규칙 충돌에 대한 프로젝트 판정(예: 필드 문서 주석 허용 범위)도 여기 기록한다. 판정이 없으면 세션마다 재논쟁한다.
