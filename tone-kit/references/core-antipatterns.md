# 안티패턴 판정 카탈로그 A~J

`tone-guide` 와 `tone-campaign` 이 위반을 판정할 때 런타임에 Read 하는 운영 카탈로그. 근거·통계·문헌 인용은 리서치 문서가 갖고 있고, 이 파일은 **판정표 · 실행 가능한 grep · 처리 방침** 만 담는다.

**H 는 위반이 아니라 보존 대상이다.** A~J 를 "안티패턴 10종"으로 읽고 일괄 삭제하는 것이 이 카탈로그의 최대 오용이다. H 는 나머지 9개를 지울 때 좋은 주석이 함께 지워지는 것을 막는 방어 카테고리이며, 어떤 리포트에서도 위반 열·위반 건수에 넣지 않는다.

## 판정 순서

**삭제 후보를 고르기 전에 보존 후보(H)를 먼저 표시한다.** 순서를 뒤집으면 좋은 주석이 삭제 후보에 섞여 같이 지워진다.

1. **H 표시** — 대상 파일을 읽고 보존 주석에 먼저 표를 붙인다. 이 단계 이후 H 로 표시된 줄은 어떤 카테고리로도 재분류하지 않는다.
2. **후보 수집** — E · F · I 는 grep 으로, 나머지는 리뷰로 후보를 모은다. 이 단계의 결과는 후보이지 위반이 아니다.
3. **처리 형태 배정** — 각 후보에 삭제 / 개명 / 구조 흡수 / 수렴 / 보존 중 하나를 배정한다. 형태가 다르면 작업 범위와 검증 방법이 다르다.
4. **파일 단위 확인** — 한 파일씩 사람이 확인하고 적용한다. 정규식 일괄 치환은 금지한다.

## 카테고리 요약표

| 코드 | 이름 | 처리 | 강도 | 축 | grep |
|---|---|---|---|---|---|
| A | 이름 번역 주석 | 삭제 (이름이 약하면 개명) | MUST | 코어 · 한국어 신호 | 없음 — 리뷰 판정 |
| B | 템플릿 마커 | 삭제 | MUST | 코어 | 없음 — 빈도 집계 |
| C | 메서드명 반복 doc | 삭제 | SHOULD | 코어 | 없음 — 리뷰 판정 |
| D | 프레임워크 기본 설명 | 삭제 | MUST | 코어 | 없음 — 리뷰 판정 |
| E | 접두사 fallback 변수명 | 개명 (호출부 전수 동반) | 관측 컨벤션 | 코어 | `\b(effective\|resolved)[A-Z]` |
| F | 구분선 블록 | 삭제 | MUST | 코어 | `^[[:space:]]*//[[:space:]]*[-=]{5,}` |
| G | 자명 구조 라벨 | 구조 흡수 | SHOULD | 코어 · 한국어 신호 | 없음 — 리뷰 판정 |
| H | 좋은 주석 | **보존 — 위반 아님** | MUST 보존 | 코어 | 없음 — 리뷰 판정 |
| I | 과도한 빌더 분할 | 재구성 (인라인 또는 위젯 추출) | SHOULD | 어댑터 dart-flutter | `\b_build[A-Z][A-Za-z0-9]*\(` |
| J | 중복 구현 | 공통 요소로 수렴 | SHOULD | 코어 + 프로젝트 파라미터 | 없음 — 프로젝트 목록 선행 |

강도 3등급: `MUST` (예외 없음) / `SHOULD` (명시 예외 존재) / `관측 컨벤션` (공개 근거 없음, 국지 실측만 존재).

## 처리 형태

카테고리 라벨만 붙이고 처리 형태를 구분하지 않으면 작업이 어긋난다. 형태별로 완료 조건이 다르다.

| 형태 | 대상 | 완료 조건 |
|---|---|---|
| 삭제 | B · C · D · F, 그리고 이름이 충분한 A | 줄이 사라지고 정보 손실이 0 |
| 개명 | E, 이름이 약한 A | 선언 + **호출부 전수** 가 함께 바뀌고 빌드가 통과 |
| 구조 흡수 | G | 라벨이 담던 의미가 변수명·위젯명으로 옮겨간 뒤 라벨 삭제 |
| 수렴 | J | 호출부가 공통 요소를 쓰도록 바뀜. 공통 요소에 파라미터를 늘리는 반대 방향 금지 |
| 재구성 | I | 인라인하거나 별도 위젯으로 추출. 헬퍼 메서드 유지가 아님 |
| 보존 | H | 아무것도 하지 않음. 삭제 후보 목록에서 제외된 상태로 남음 |

## 집계 규칙

- **코드 생성 산출물을 제외한다.** 제외하지 않으면 빈도 상위가 생성기 배너로 채워져 실제 마커가 보이지 않는다.

```bash
grep -rnE '<패턴>' <대상 경로> --exclude='*.g.*' --exclude='*.freezed.*'
```

- **grep 히트 수를 위반 건수로 보고하지 않는다.** 히트는 후보다. E 패턴은 정당한 fallback 변수를 함께 잡고, F 패턴은 생성기 배너를 함께 잡는다.
- **검증되지 않은 정규식을 카탈로그에 추가하지 않는다.** 아래 상세에 실린 세 패턴은 bash·zsh 양쪽 실행 확인을 거쳤다. 새 패턴은 같은 확인을 거친 뒤에만 들어온다.

## 카테고리 상세

### A 이름 번역 주석 — 삭제 · MUST · 코어

식별자 이름과 타입이 이미 담고 있는 의미를 주석이 되풀이하는 것. 지워도 정보 손실이 0이다.

- **판정 신호** — 선언 뒤에 붙은 인라인 주석이 그 선언의 이름·타입을 다른 언어로 옮긴 것에 그친다.
- **처리** — 삭제. 단, **이름이 약해서 주석이 필요한 경우에는 주석이 아니라 이름을 고친다.** 주석만 지우고 약한 이름을 남기면 원래보다 나빠진다.
- **예외** — 값에서 사람이 곧바로 읽어낼 수 없는 메타 정보(색상 hex 의 alpha 퍼센트 등)는 A 가 아니다.
- **정규식 없음** — 형태 기반 패턴은 H 를 동일하게 잡는다. 선언 뒤 주석이라는 형태가 같고 내용만 다르기 때문에, 이 카테고리는 사람이 한 줄씩 읽어 판정한다.

### B 템플릿 마커 — 삭제 · MUST · 코어

파일마다 같은 위치에 기계적으로 반복되는 고정 라벨. 그 파일이 무엇인지는 선언부가 이미 말한다.

- **판정 신호** — 동일한 주석 줄의 코퍼스 전역 빈도. 주석 줄만 뽑아 정규화한 뒤 빈도순으로 정렬하고, 상위에 뜨는 짧은 라벨을 후보로 본다. 집계 전 생성 산출물을 제외한다.
- **처리** — 삭제.
- **예외** — 없다. 파일 구조를 알리는 역할이 필요하면 그것은 파일 분할이나 이름으로 해결할 문제다.

### C 메서드명 반복 doc — 삭제 · SHOULD · 코어

메서드 이름을 자연어 문장으로 풀어 쓴 doc 주석. 번역투 종결형이 함께 따라온다.

- **판정 신호** — doc 주석의 내용이 메서드 이름의 재서술 이상을 담지 못한다.
- **처리** — 삭제.
- **예외 1** — public API 계약, 그리고 부수효과 순서가 호출자에게 중요한 경우. 이때는 doc 을 남기되 이름의 반복이 아니라 계약을 쓴다.
- **예외 2** — 파라미터·반환값 블록의 표기 형식은 이 카탈로그가 아니라 어댑터의 정책 상수가 정한다. **어댑터가 유지를 지시하면 C 로 판정하지 않는다. 카탈로그가 어댑터를 이기지 않는다.**

### D 프레임워크 기본 설명 — 삭제 · MUST · 코어

프레임워크 공식 문서에 이미 적힌 기본 동작을 코드 옆에 옮겨 적은 주석.

- **판정 신호** — 정규식으로 분리되지 않는다. 판정 질문은 하나다. **주석이 설명하는 내용이 그 API 문서 첫 문단에 있는가.** 있으면 D 다.
- **처리** — 삭제하되 "왜 이 선택을 했는가" 는 남긴다. 남는 그 한 줄은 D 가 아니라 H 로 승격된다.
- **근거** — 기본 동작 서술은 정보량이 0일 뿐 아니라 프레임워크 버전이 오르면 거짓이 되므로 유지 비용이 음수다.

### E 접두사 fallback 변수명 — 개명 · 관측 컨벤션 · 코어

`effective*` / `resolved*` 접두사로 "기본값이 적용된 값" 임을 이름에 박는 것. fallback 연산자가 이미 그 사실을 표현하므로 접두사는 역할이 아니라 계산 과정을 드러낸다.

```bash
grep -rnE '\b(effective|resolved)[A-Z]' <대상 경로> --exclude='*.g.*' --exclude='*.freezed.*'
```

- **처리** — 삭제가 아니라 **도메인·역할명으로 개명**. 그 값이 무엇인지로 바꾼다.
- **주의** — 개명은 선언만 고치면 컴파일이 깨진다. 호출부 전수를 함께 바꾸고 빌드로 확인한다.
- **강도** — 이 카테고리는 **공개 통계 근거가 없다.** 접두사별 과대표집 통계는 공개 1차 문헌에서 확인되지 않았다. 그래서 강도를 `관측 컨벤션` 으로 두고 **각주를 붙이지 않는다.** 국지 실측을 문헌 근거로 격상시키는 순간 이 규칙의 신뢰도가 무너진다. 동시에 실측은 유효한 국지 근거이므로 규칙을 지우지도 않는다.

### F 구분선 블록 — 삭제 · MUST · 코어

주석 기호 뒤에 하이픈이나 등호를 늘여 만든 시각적 구획. 한 파일에 여러 개가 쌓이면 구분 기능 자체가 사라진다.

```bash
grep -rnE '^[[:space:]]*//[[:space:]]*[-=]{5,}' <대상 경로> --exclude='*.g.*' --exclude='*.freezed.*'
```

- **처리** — 삭제. 대체 수단은 빈 줄과 의미 있는 함수·클래스 이름이다.
- **예외** — 코드 생성기가 만드는 배너. 생성 산출물은 대상에서 제외한다.

### G 자명 구조 라벨 — 구조 흡수 · SHOULD · 코어

블록이나 트리 위에 붙은 짧은 명사구 라벨. 바로 아래 코드가 그대로 말하는 내용이다.

- **판정 신호** — 단독 줄의 짧은 명사구 주석이고, 바로 아래 선언의 이름과 같은 뜻이다.
- **처리** — 삭제가 아니라 **흡수**. 라벨이 담던 의미를 변수명이나 추출한 위젯 이름으로 옮긴 뒤 라벨을 지운다. 지우기만 하면 구획 정보가 이름으로 옮겨가지 않고 그냥 없어진다.
- **예외** — 섹션 라벨의 경제성 규칙. 라벨이 **2개 이상의 선언을 묶고** 그 묶음의 축을 이름으로 표현할 수 없을 때만 남긴다. 선언 1개짜리 섹션 라벨, 라벨과 변수명이 같은 뜻인 경우는 G 다.

### H 좋은 주석 — 보존 · MUST · 코어 · **위반 아님**

**H 는 안티패턴이 아니다.** 코드만 읽어서는 복원할 수 없는 정보를 담은 주석이며, 이 카탈로그에 들어 있는 유일한 이유는 A~G 를 일괄 처리할 때 함께 지워지는 사고를 막기 위해서다. 리포트의 위반 열, 위반 합계, 캠페인 잔여 건수 어디에도 H 를 넣지 않는다.

보존 기준은 셋이고, 하나라도 해당하면 남긴다.

| 기준 | 판정 질문 |
|---|---|
| 프레임워크 함정 | 프레임워크가 문서화하지 않았거나 직관에 반하는 동작을 설명하는가 |
| 제약·trade-off | 대안을 못 쓴 이유, 값이 그 값인 이유를 남기는가 |
| 실패 모드 | 이 코드를 "단순화" 하면 무엇이 깨지는지 알려주는가 |

- **표시 신호** — 인과 접속이 들어간 주석은 정규식이 아니라 읽기로 먼저 표시한다. `때문` · `안 하면` · `무시되` · `제약` · `하드코딩` · 버그 언급이 전형적인 단서다. 이 단서들은 후보 표시용이며, 해당 없이도 위 3기준을 만족하면 H 다.
- **경계** — D 와 H 는 같은 API 를 언급해도 다른 카테고리다. 기본 동작 서술은 D, 그 동작 때문에 이렇게 쓸 수밖에 없었다는 이유는 H 다.

### I 과도한 빌더 분할 — 재구성 · SHOULD · 어댑터 dart-flutter

빌드 메서드가 다단 헬퍼 호출 체인으로 흩어진 것. 이름이 본문보다 정보를 더 주지 못하는데 호출 단계만 늘어난다.

```bash
grep -rnE '\b_build[A-Z][A-Za-z0-9]*\(' <대상 경로> --exclude='*.g.*' --exclude='*.freezed.*'
```

- **처리** — "무조건 인라인" 도 "무조건 분할" 도 아니다. 분할이 정당한 조건은 셋이다. **의미 경계가 실제로 다른가 / 재사용되는가 / 독립 테스트 대상인가.** 셋 다 아니면 인라인한다. 하나라도 해당하면 헬퍼 메서드가 아니라 별도 위젯으로 뺀다.
- **임계치** — 줄 수, 헬퍼 개수, 추출 위치는 이 카탈로그가 아니라 어댑터가 정한다.
- **적용 범위** — 코어로 올리지 않는다. 다른 스택에 적용하려면 그 스택에서 위반이 실제로 관측된 뒤 어댑터를 추가한다.

### J 중복 구현 — 수렴 · SHOULD · 코어 + 프로젝트 파라미터

프로젝트에 이미 있는 공통 컴포넌트를 쓰지 않고 그것이 감싸던 저수준 조합을 호출부에서 다시 조립하는 것.

- **선행 입력** — **공통 컴포넌트 목록과 각 컴포넌트가 감싸는 저수준 요소** 가 있어야 판정이 성립한다. 이 목록 없이는 무엇이 중복인지 정의되지 않는다. grep 은 목록을 채운 뒤 저수준 요소를 패턴으로, 공통 컴포넌트 파일 경로를 제외 대상으로 삼아 그 자리에서 만든다.
- **처리** — 공통 요소로 수렴.
- **방향** — 수렴 방향을 뒤집지 마라. 호출부를 공통 컴포넌트에 맞추는 것이 원칙이고, 공통 컴포넌트에 파라미터를 늘려 호출부를 수용하는 것이 아니다.
- **예외** — 의도된 divergence. 공통 컴포넌트로 표현할 수 없는 요구라서 갈라놓은 것이면 그 이유를 주석으로 남긴다. **그 주석은 H 이므로 이후 삭제 대상이 되지 않는다.**

## 판정 실패 모드

| 실패 | 결과 |
|---|---|
| H 를 위반 목록에 넣고 A~J 를 일괄 삭제 | 코드로 복원 불가능한 정보가 사라진다. H 는 방어 카테고리다 |
| 삭제 후보를 먼저 뽑고 보존을 나중에 검토 | 이미 지워진 뒤에 검토하게 된다. 보존 표시가 항상 먼저다 |
| 이름은 그대로 두고 A 주석만 삭제 | 약한 이름 + 주석 없음이 되어 원래보다 나빠진다 |
| G 라벨을 흡수 없이 삭제 | 구획 정보가 이름으로 옮겨가지 않고 그냥 없어진다 |
| grep 히트 수를 위반 건수로 보고 | 히트는 후보다. 판정은 파일을 읽어야 나온다 |
| grep 결과를 확인 없이 일괄 치환 | 같은 패턴에 걸린 H 가 조용히 삭제된다. 파일 단위 확인이 캠페인 루프의 존재 이유다 |
| E 에 문헌 각주를 붙여 근거를 격상 | 접두사별 공개 통계는 존재하지 않는다. 국지 실측을 문헌 근거로 위장하게 된다 |
| J 를 공통 컴포넌트 목록 없이 판정 | 판정 입력이 빠져 있어 판정 자체가 성립하지 않는다 |
