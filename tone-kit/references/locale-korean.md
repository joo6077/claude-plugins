# 한국어 축 운영 규칙 (locale-korean)

**이 킷의 "언어 의존" 축 SSOT다.** 다른 reference 와 어댑터는 한국어 규칙을 다시 정의하지 말고 이 파일을 가리킨다. 이 파일은 판정용 표·체크리스트·grep 만 담고, 각 규칙의 근거는 문서 하단 출처 절에 URL 로 있다. (원칙별 상세 근거 문서는 킷 개발 레포에만 존재하며 배포본에는 포함되지 않는다.)

## 로드 조건

| 조건 | 판정 |
|---|---|
| 주석·doc 언어가 한국어 | 이 파일을 로드한다 |
| 주석·doc 언어가 한국어가 아님 | 로드하지 않는다. 규칙 골격은 그대로 두고 라벨 문자열만 해당 언어 파일이 갖는다 |
| 코드 식별자(타입·함수·변수) | 언어 축 대상이 아니다. 영어를 그대로 둔다 |

언어 축은 스택 축과 **직교한다.** doc 의 `- 반환값:` 라벨은 Dart 의존이 아니라 한국어 의존이다. 영어 프로젝트에서는 `- Returns:` 가 되지만 "파라미터와 반환값을 doc 하단 라벨 블록으로 붙인다"는 골격, "void 는 한 표기로 통일한다"는 제약, 커버리지 기준은 그대로 남는다. 반대로 스택을 Dart 에서 Rust 로 바꾸면 주석 문법은 바뀌어도 이 파일의 문체 규칙은 한 줄도 안 바뀐다.

```text
한국어 프로젝트: /// - 반환값: 연결되어 있으면 true
영어 프로젝트  : /// - Returns: true when connected
```

## 2. 번역투 킬러 패턴 치환표

6종은 종결형 규칙과 독립이다. 종결어미만 `한다`체로 바꿔도 문장 구조가 그대로면 번역투는 남는다 — 4행·5행은 종결형과 아무 상관이 없다.

| 금지 | 대체 | grep |
|---|---|---|
| `~을 처리합니다` · `~을 관리합니다` | 실제 동작 동사를 쓴다 → `길게 누르기 반복을 시작한다` | `(을\|를) ?(처리\|관리)(합니다\|한다)` |
| `~에 대해서` · `~에 대해` | 목적격 조사로 줄인다 → `선택된 서버 이름을 보여 준다` | `에 대해서?` |
| `~하도록 합니다` | 단정형 `~한다` → `키보드 입력을 이어 간다` | `하도록 (합니다\|한다)` |
| `~에 의해` | 주어를 되살린 능동형 → `surface tint 가 배경색을 덮는다` | `에 의(해\|하여)` |
| `~되어 있는 경우` | 조건을 직설로 → `값이 없으면 빈 영역을 만들지 않는다` | `되어 있(는 경우\|을 때)` |
| 과한 수동태 (`표시됩니다` · `적용됩니다`) | 주체 + 능동 → `이 위젯이 배경을 그린다` | `(표시\|적용\|호출\|생성\|반환)(됩니다\|된다)` |

한 문장이 두 규칙을 동시에 어기는 사례가 흔하다 — Bad 예시 `배경색이 오버레이에 의해 변경됩니다` 는 번역투와 음역이 겹쳐 있으므로 고칠 때 둘 다 본다.

## 3. 종결형 정책

| 자리 | 정책 |
|---|---|
| doc 본문 (`///`) | `한다`체 고정. `만든다` · `수집한다` · `건너뛴다` · `검증한다` |
| doc 본문 | `합니다`체와 명사형 종결을 섞지 않는다. 두 종결형이 공존하면 grep 기준이 무너진다 |
| 인라인 주석 (`//`) | 파편형·단문 허용. 코드만 읽어도 뜻이 통하면 지운다 |
| 라벨 블록 | 종결형 대상이 아니다. §5 상수를 그대로 쓴다 |

종결형 고정은 **문장을 쓰기로 한 자리**에만 걸린다. 실측 근거는 공용 패키지 한 곳의 번역투 doc 129건이고 그중 `반환합니다` 종결이 125건이다.

## 4. 외래어 3원칙

1. **공식 API 이름은 영어 원문.** `surface tint` · `BoxDecoration` · `strokeAlign` 을 번역하지 않는다. 문서·검색·자동완성이 원문 기준으로 움직인다.
2. **일반 명사는 한국어.** 배경색 · 그림자 · 테두리. 원문을 남길 이유가 없으면 한국어가 기본값이다.
3. **음역 금지.** `보더 라디우스` 는 한국어도 영어도 아니라 검색이 안 되고 공식 API 이름과도 어긋난다.

경계에 정착 외래어가 있다. `다운로드` · `업로드` · `파싱` · `파일` · `폴더` 는 한국어 어휘로 굳었으므로 허용한다. 반대로 `잡` 은 `작업`, `큐` 는 `대기열` 로 쓴다. 정착 여부는 팀이 한 번 판정하고 결과를 §6 표에 적는다. 매 세션 재논쟁하지 않는다.

## 5. 언어 의존 상수 표

| 슬롯 | 한국어 값 | 템플릿 자리 |
|---|---|---|
| `doc_return_label` | `- 반환값:` | `{label_return}` |
| `doc_void_value` | `없음` | `{label_void}` |
| `header_label_file` | `파일명` | `{label_file}` |
| `header_label_desc` | `설명` | `{label_desc}` |
| `header_label_author` | `작성자` | `{label_author}` |
| `header_label_screen` | `화면ID` | `{label_screen}` |
| `header_label_ref` | `참고` | `{label_ref}` |
| `header_label_history` | `수정이력` | `{label_history}` |
| `header_empty_value` | `없음` | 선택 필드를 비울 때 쓴다 |

`doc_param_label` (`- [name]:`) 은 대괄호 링크 문법이라 스택 축이 소유한다. 이 표에 넣지 않는다.

> **경고 — 부분 변경 금지.** 위 값을 "더 자연스럽게" 다듬고 싶어지는 순간이 온다. `- 반환값:` 을 `- 리턴:` 이나 `- 결과:` 로 바꾸거나, void 에 `N/A` 를 새로 도입하거나, `- 반환값: 없음` 을 노이즈로 보고 지우는 세 가지가 대표 사고다. 실측 규모는 `- 반환값:` 577건 / 80파일, `- [param]:` 788건이다. 이 규모에서 표기가 둘로 갈리면 §8 grep 게이트와 커버리지 측정이 동시에 깨지고, "doc 이 없는 것"과 "반환값이 없는 것"을 구분할 수 없다. 표기를 바꾸려면 전수 치환을 같은 커밋에서 끝낸다.

관련 템플릿은 같은 킷의 `../templates/dart-doc.md` 와 `../templates/file-header.md` 다 — 두 파일은 자리표시자만 갖고 값은 이 표에서 가져간다.

## 6. 용어 번역표 작성·유지 규칙

표 자체는 프로젝트 저장소가 소유한다. 킷이 옮기는 것은 만드는 방법이고, 행은 각 프로젝트가 자기 도메인으로 채운다.

1. **3열 고정** — 용어(영어 원문) / 주석에서 쓸 표기 / 비고(판정 근거). 비고에는 §4 의 어느 갈래인지 적는다.
2. **판정이 갈렸던 것만 올린다** — §4 로 자명하게 갈리는 단어를 나열하면 표가 규칙을 대체한다. 초기 6행 안팎이면 충분하다.
3. **미리 채우지 않는다** — 새 케이스가 생길 때 한 행씩 늘린다.
4. **기준 디렉토리를 표 하단에 명시한다** — 기준은 **정리 이력이 없는 쪽**으로 잡는다. AI 톤이 낀 영역을 기준으로 삼으면 정리 대상이던 표기가 표를 통해 정식 규칙으로 승격된다.
5. **킷으로 승격하지 않는다** — 도메인 어휘 판정을 공용화하면 다른 프로젝트에 잘못된 번역을 강제한다.

## 7. 이름 번역 주석 판정

식별자가 영어이고 주석이 한국어라서 번역이 정보를 더하는 것처럼 보인다. 실제로는 같은 내용의 반복이다. 실측에서 이 유형은 48파일 약 85건으로 단일 최대 카테고리였고 전체 안티패턴 약 275건의 30% 를 차지했다.

```dart
String? text,        // 버튼 텍스트   ← text 가 이미 '텍스트'
bool isChecked,      // 체크 여부     ← isChecked 가 이미 '체크 여부'
double min,          // 최소값        ← min 이 이미 '최소값'
```

판정 순서는 셋 중 하나로 끝낸다.

| 상황 | 처리 |
|---|---|
| 이름·타입이 이미 뜻을 담는다 | 주석을 지운다 |
| 이름이 약해서 주석이 필요했다 | **주석이 아니라 이름을 고친다.** 고친 뒤 주석을 지운다 |
| 이름·타입에서 안 읽히는 계약이 있다 | 남긴다. 값의 우선순위, 무효화 조건, 허용 범위가 여기 해당한다 |

## 8. 완료 전 대조 grep

문서·주석 수정을 끝낸 뒤 변경 파일만 대상으로 실행한다. 디렉토리 전체를 자동 치환하지 않는다.

```bash
FILES=("$@")   # 이번 작업에서 실제로 건드린 파일만 넘긴다

# G-1 킬러 패턴 6종 — 잔존 0 이 목표
grep -nE '(을|를) ?(처리|관리)(합니다|한다)|에 대해서?|하도록 (합니다|한다)|에 의(해|하여)|되어 있(는 경우|을 때)|(표시|적용|호출|생성|반환)(됩니다|된다)' "${FILES[@]}"

# G-2 종결형 혼용 — doc 본문에 남은 `합니다`체
grep -nE '^\s*///.*(합니다|습니다)\s*\.?\s*$' "${FILES[@]}"

# G-3 라벨 파손 — 승인된 표기 이외의 변종
grep -nE '^\s*///\s*-\s*(리턴|결과|리턴값|Return)s?\s*:|^\s*///\s*-\s*반환값\s*:\s*(N/A|없슴|-)\s*$' "${FILES[@]}"

# G-4 라벨 커버리지 — 반환값 라벨 수를 세어 doc 총수와 대조한다
grep -c -- '- 반환값:' "${FILES[@]}"
```

G-1 잔존이 0 이 아니면 완료로 보고하지 않는다. G-3 은 한 건이라도 나오면 §5 경고에 해당하므로 전수 치환으로 되돌린다. 이름 번역 주석(§7) 검출 grep 은 주석 문법이 스택마다 달라 어댑터가 소유한다.

## 9. 자기모순 검사

규칙을 설명하는 문장에서 킬러 패턴이 특히 잘 나온다. 한국어 규칙 문서나 리뷰 코멘트를 **직접 쓴 뒤**, 자기 본문에 6종을 1회 grep 한다. 치환표 행과 `Bad` 예시 줄은 규칙상 패턴을 담고 있으므로 제외한다.

```bash
grep -nE '(을|를) ?(처리|관리)(합니다|한다)|에 대해서?|하도록 (합니다|한다)|에 의(해|하여)|되어 있(는 경우|을 때)|(표시|적용|호출|생성|반환)(됩니다|된다)' locale-korean.md \
  | grep -vE '^[0-9]+:\||Bad|grep -nE'
```

보고 형식은 `자기모순 검사 잔존 N건` 이다. N 이 0 이 아니면 해당 줄을 고치고 다시 돌린다 — 이 절차를 건너뛰면 규칙 문서 자신이 규칙 위반 예시가 된다.
