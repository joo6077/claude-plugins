# QA Evaluator — 반려 뒤 재평가

같은 슬러그의 직전 리포트가 `Verdict: REJECT` 일 때 읽는다. 고친 커밋이 한두 조건만 건드렸는데 열몇 조건을 처음부터 다시 재지 않도록, 바뀌지 않은 조건은 직전 회차의 증거를 다시 쓴다. 재사용은 「증거를 다시 모으지 않는 것」 이지 「판정을 건너뛰는 것」 이 아니다 — 재사용한 조건도 판정 줄과 근거를 리포트에 남긴다.

## 1. 먼저 범위를 뽑는다 — 새 리포트를 쓰기 전에

새 리포트는 직전 리포트와 같은 경로에 쓰이므로, 덮어쓰기 전에 아래를 한 번 돌려 직전 내용을 읽는다.

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/qa-reeval-scope.sh" <직전 리포트> <구현 저장소> "$CONTRACT" [<개정 파일>]
```

출력의 `CHANGED <경로>` 가 직전 평가 커밋 이후 바뀐 파일(커밋한 것 + 커밋 안 한 것 + 추적 안 된 새 파일), `PREV_FAIL` · `PREV_PASS` · `PREV_NA` 가 직전 판정, `REUSE=yes|no reason=…` 가 재사용 가능 여부다. 도구가 다시 만드는 생성물은 `IGNORED` 로 따로 나오고 세지 않는다.

`finish.md` Step 5 는 「앞 회차 리포트가 커밋되지 않은 채 남아 있으면 판정 근거로 쓰지 않는다」 고 한다. **재평가에 한해 이 규칙의 예외로, 커밋 안 된 직전 리포트도 재사용 근거로 쓴다** — 그 리포트의 평가 커밋 · 계약 지문 · 개정 지문이 아래 전제로 묶여 있기 때문이다.

## 2. 재사용 전제 넷 — 하나라도 깨지면 처음부터 잰다

1. 같은 슬러그 직전 리포트가 `Verdict: REJECT` 다
2. 그 리포트에 `Evaluated-Head:` 가 있고 그 커밋이 구현 저장소에 있다
3. 지금 계약 sha256 이 직전 리포트 `## Contract Fingerprint` 의 sha256 과 같다
4. 지금 개정 파일 sha256 이 직전 `Amendments-Sha256:` 과 같다 (개정 파일이 없으면 둘 다 `none`)

범위 스크립트가 `REUSE=no` 를 내면 그 사유를 리포트에 적고 이 파일을 덮은 채 평소대로 전부 잰다.

## 3. 늘 다시 재는 것

- 직전 FAIL · `[미검증]` 조건
- 측정이 읽는 경로가 `CHANGED` 파일과 겹치는 조건
- 구현 커밋 구간 전체를 재는 조건 — 바뀐 파일 합집합 · 구현 커밋이 더한 줄 검사 · 분석처럼 커밋이 하나 늘면 결과가 달라질 수 있는 것
- 시험을 돌리는 조건 전부 — 시험 실행은 새로 한다. `${CLAUDE_PLUGIN_ROOT}/scripts/qa-test-batch.sh` 한 번으로 돌린다
- 범위 · 봉인 · 삭제 감사

## 4. 재사용하는 것과 표기

위 3 에 들지 않는 직전 PASS · N/A 조건은 증거를 다시 모으지 않는다. 시험 조건은 실행 결과는 새로 받고, 시험 본문 검토(단언이 조건을 실제로 재는지)만 재사용한다 — 그 시험 파일이 `CHANGED` 에 없을 때만.

리포트 표기:

- 조건 판정 줄은 조건마다 한 줄이다. 번호를 쉼표로 묶지 않는다
- 꼴은 `- [x] <번호> <PASS|FAIL|N/A> — …` — 번호 바로 뒤에 판정을 적는다. N/A 도 같다: `- N/A 재사용-01` 처럼 판정을 번호 앞에 쓰지 않는다
- 재사용한 조건의 줄에는 `재사용: Iteration <N> · <커밋 앞 8 자리> 이후 대상 경로 변경 0` 을 적는다. `<N>` 은 직전 리포트의 `Iteration` 값, 커밋은 직전 `Evaluated-Head` 다
- FAIL 줄에는 재사용 표기를 쓰지 않는다 — FAIL 은 이번 회차에 새로 잰 증거로만 낸다

예:

```markdown
- [x] AR-02 PASS — 재사용: Iteration <N> · <직전 커밋 8 자리> 이후 대상 경로 변경 0 (설계 문서 grep 0 · 1)
- [x] UI-01 PASS — 시험 새로 실행 `NAME … PASS`. 본문 검토는 재사용: Iteration <N> · <직전 커밋 8 자리> 이후 대상 경로 변경 0
- [x] 재사용-01 N/A — 사유: 새 공용 위젯 없음. 재사용: Iteration <N> · <직전 커밋 8 자리> 이후 대상 경로 변경 0
- [ ] UI-02 FAIL — 시험 새로 실행 `NAME … FAIL` (feed_pending_failed.dart 가 CHANGED)
```
