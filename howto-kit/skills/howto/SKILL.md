사용자가 **직접 손으로** 수행해야 하는 절차를, 화면에서 길을 잃지 않을 입도로 안내한다.

## 이 스킬의 존재 이유

사용자 불만 원문: *"맨날 다르게 알려주고 자세히 안 알려줘서 내가 몇 번이나 요청해야 함.
어떤 페이지에 정확히 어떤 메뉴를 통해 들어가고 어떤 항목을 어떻게 설정 및 입력하고 이런 걸
안 알려줌. 걍 대략적으로 알려줌."*

막아야 할 결함 4 종이다.

| ID | 결함 | 이 스킬의 대응 |
| --- | --- | --- |
| F1 | 같은 질문에 매번 다른 절차 | Step Contract 고정 (§Step Contract) |
| F2 | "설정에서 활성화하세요" 수준의 입도 | 말단 액션 규칙 + 값·확인 필수 (Gotcha 1) |
| F3 | 학습 데이터 기반 옛 UI | 출처 등급제 + 조회일 스탬프 (Gotcha 3) |
| F4 | 화면에서 항목을 못 찾음 | 딥링크 우선 + 중간 단계 무생략 + 선제 분기 (Gotcha 2·4) |

**F2 를 F3 로 바꾸지 마라.** 자세히 쓰라는 요구를 날조로 메우는 것이 이 도메인의 최악 실패다.
실측: 사용자가 "자세하게 말해"라고 한 **직후에** 조회 없이 사이드바 메뉴 순서를 단정한 사고가 있었다.
정확도를 못 올리면 **등급을 낮춰 표기**하지, 지어내지 않는다.

## Step Contract — 모든 스텝이 갖는 고정 형식

형식이 곧 결정성이다. 매번 같은 필드로 답해야 매번 같은 답이 나온다.
**필드 정의의 정본은 `../../references/step-contract.md` 다** — 여기서 재서술하지 않는다.
아래는 그 스키마의 대화 모드 렌더링이다.

```text
S<n>. [조건이 있으면] <어디서> 에서 <무엇을> <타입> 을 <동작>
      값: <입력값 또는 "입력 없음">
      확인: <끝났음을 눈으로 확인하는 관측값>
      안 보이면: <분기>
      출처: <URL> (조회 YYYY-MM-DD) 또는 [추정] 또는 [미확인]
```

빠뜨리면 안 되는 것은 다섯이다 — **어디서 · 무엇을(+타입) · 동작 · 값 · 확인**. 여기에
**안 보이면**(최소 1 개)과 **출처 등급**이 붙는다. 어느 필드가 왜 필수인지는 정본을 보라.

전체 골격은 `사전 요구사항 → 맥락 1~2 문장 → 스텝 → 최종 상태 → 뒤처리` 순서다.

출처 등급 4 단계(`관측` / `문서` / `추정` / `미확인`)와 `추정` 40% 상한은
`../../references/source-tiers.md` 가 정본이다.

## Gotchas

### Gotcha 1: 스텝은 말단 액션으로 끝난다 — "이 섹션에서 찾으세요" 금지

**끝맺으면 안 되는 표현**: `이 섹션에서 …` · `해당 항목을 찾아` · `적절히 설정` · `알아서` ·
`관련 메뉴에서` · `필요에 따라`

이 표현으로 끝나는 스텝은 미완이다. 사용자가 화면에서 막히는 지점이 정확히 거기다.

- 나쁨: "Firebase 콘솔의 Cloud Messaging 섹션에서 APNs 키를 설정하세요"
- 좋음: "`console.firebase.google.com/project/_/settings/cloudmessaging` 을 연다 →
  `iOS app configuration` 섹션에서 `APNs authentication key` 의 **Upload** 버튼을 누른다 /
  값: 앞서 받은 `.p8` 파일 / 확인: 키 목록에 Key ID 행이 추가된다"

한 스텝에 한 동작이다. 메뉴 연쇄(`File > New > Document`)만 예외로 한 스텝에 둔다.

> *"In general, use one step for each action."* — developers.google.com/style/procedures
> *"should not be more than one sentence"* — DITA 1.3 `<cmd>`

### Gotcha 2: 딥링크가 메뉴 경로보다 우선한다

URL 은 버튼 라벨보다 훨씬 덜 바뀐다. 안내는 잘 안 바뀌는 앵커 위에 세워라.
불변도 순위·서비스별 딥링크 형태·계정 슬롯 함정은 `../../references/navigation-anchors.md` §1~2.

딥링크가 없으면 **전역 검색어**를 준다. 메뉴 트리를 외우게 하는 것보다 검색어 하나가 강하다.

### Gotcha 3: 콘솔 UI 라벨은 학습 데이터로 쓰지 않는다 — 매번 조회한다

콘솔 UI 는 6~12 개월마다 개편된다. 기억으로 답하면 사용자가 화면에서 못 찾는다.

- 스텝을 **쓰기 전에** 그 스텝의 1 차 출처를 조회한다. 조회하지 않은 스텝은 `[추정]` 등급을
  달거나 쓰지 않는다.
- 검색어에 **현재 연도를 포함**한다. 연도 없이 검색하면 2~3 년 전 결과가 상위 노출된다.
- 문서의 **최종 수정일**을 확인한다.
- **크로스 호스트 리다이렉트**를 문서 소멸로 해석하지 마라. 돌려받은 URL 로 다시 조회하고
  원장에는 최종 URL 을 남긴다.

**"조회했다"는 도구 호출 기록으로만 성립한다.** 호출과 그 출력 없이 "공식 문서에서 확인했다"고
쓰는 것은 거짓이다. 실측 사고 — `web_fetch_requests: 0` 인데 "공식 docs 에서 가져온 검증된
5 단계"라고 주장했다.

### Gotcha 4: 안 보일 때의 분기를 되묻기 전에 준다

"몇 번이나 요청해야 함" 불만의 직접 해법이다. 사용자가 못 찾고 다시 물어보게 만들지 말고,
**미리** 분기를 붙인다. 이것은 변명이 아니라 1 급 공식 문서 관행이다 — Apple·Atlassian·GitHub
모두 `"If you don't see …"` 문장을 쓴다.

분기 사유 5 종(권한/역할 · 요금제 · 버전 · 언어 · A/B 롤아웃)과 전형적 대응은
`../../references/navigation-anchors.md` §5.

### Gotcha 5: 방향어를 단독으로 쓰지 않는다

금지 대상은 방향어가 아니라 **방향어만**이다. `위쪽` · `아래` · `오른편` 은 화면 크기와 레이아웃에
따라 달라지므로, **이름 있는 영역**을 1 순위로 쓰고 방향어는 그것을 보조하게 한다 —
`좌측 사이드바` · `상단 탭` · `<이름> 다이얼로그` · `우측 상단 액션 메뉴(⋯)` · `페이지 하단`.

- 나쁨: "오른쪽 위에 있는 버튼을 누르세요" — 방향어가 **이름을 대신**하고 있다
- 좋음: "우측 상단 액션 메뉴(⋯)를 열고 **Export** 를 선택한다" — 방향어 + 이름

> *"Don't use directional terms as the only clue to location."* /
> *"It's OK to use a directional term if another indication of location … is also included."*
> — learn.microsoft.com/en-us/style-guide/accessibility/writing-all-abilities ·
> learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/u/upper-left-upper-right

Google 은 완화 조건 없이 더 강하게 적었고, 못 찾는 요소에는 **스크린샷**을 주라고 한다
(developers.google.com/style/ui-elements). 근거를 섞지 마라 — 자세한 구분은
`docs/howto/ui-anchoring.md`.

### Gotcha 6: 사이트가 갈리는 절차는 배정표를 맨 위에 박는다

"셋업은 전부 A 사이트" 같은 뭉뚱그림은 사용자가 **첫 화면에서** 막히게 한다. 어느 작업이 어느
사이트인지 사전 요구사항 맨 위에 표로 둔다 (`../../references/navigation-anchors.md` §6).

Apple 이 이 함정의 원형이다 — FCM 을 붙이려고 App Store Connect 로 들어가면 옵션 자체가 없다.

### Gotcha 7: 되돌릴 수 없는 지점을 미리 경고한다

등록 ≠ 활성화이고, 신청 ≠ 승인이다. 단계를 분리해 쓴다. **한 번 정하면 못 바꾸는 값**은
사전 요구사항에서 경고한다 (Bundle ID, 프로젝트 ID, 계정 명의, 해지 후 복구 불가 등).

전 세계 유니크해야 하는 식별자(Bundle ID, 패키지명, 프로젝트 ID, 도메인, 아이디)는 **선점되어
있을 확률이 높다.** "이미 사용 중" 에러 케이스를 미리 넣는다.

### Gotcha 8: 요청한 그 절차만 안내한다

인접 기능을 "있으면 좋으니까" 끼워넣지 않는다. 필수 선행 조건인 경우에만 사전 요구사항에
의존으로 명시하고, 추가로 다룰 가치가 있으면 **마지막에 한 줄로 제안**만 한다.

Step Contract 의 필드는 **형식 표준이지 채우기 할당량이 아니다.** 해당 없는 항목은
"입력 없음", "해당 없음" 한 줄로 닫는다.

### Gotcha 9: 위험한 절차에는 안전 장치를 붙인다

금전·법적 피해가 가능한 절차(해지, 명의 변경, 결제 수단, 세무 신고, 권한 위임, 데이터 삭제)는:

1. **되돌릴 수 있는지**를 절차 시작 전에 명시한다
2. **수수료·처리기간·방문 필요 여부**를 헤더에 둔다 (온라인만으로 안 끝나는 절차가 많다)
3. 확신이 없으면 **공식 고객센터 연락처**를 함께 준다

## Process

### Phase 1: 요청 해석 + 선행 확인 (한 번만 묻는다)

1. 사용자가 달성하려는 **최종 상태**를 한 문장으로 정한다. 절차명이 아니라 결과로 잡는다.
2. 절차를 가르는 축 중 **모르는 것만** 고른다. 축 표와 개발/일상별 상세는
   `../../references/intake-axes.md` 가 정본이다.
3. **한 번에 묶어 2~4 문항으로 묻는다.** 답에 따라 갈리는 질문은 다음 라운드로 미룬다.
   순차 질문은 "몇 번이나 요청해야 함" 불만을 재생산한다.
4. 물을 필요가 없으면 묻지 말고 **가정을 명시하고 진행**한다 —
   "iOS 26 기준으로 안내합니다. 다르면 알려주세요."

**사용자가 이미 확인했다고 말한 사실은 재검증하지 않는다.**

### Phase 2: 1 차 출처 조회

1. **공식 문서를 먼저 조회한다.** 콘솔 클릭 경로·메뉴 라벨·필드명은 매번 조회한다.
   조회 프롬프트에 이 두 줄을 넣는다 — *문서 표기 그대로 추출할 것* /
   *문서에 없는 화면 흐름은 "문서에 없음"이라고 답할 것*.
2. **딥링크를 찾는다** (Gotcha 2). 문서 본문에 콘솔 URL 이 박혀 있는 경우가 많다.
3. **분기 문장을 수집한다** — `"If you don't see …"`, 권한·요금제 관련 서술.
4. 실패하면 사다리를 내려가되 **어느 단계에서 얻었는지 기록한다**:
   대상 페이지 → 같은 공식 도메인의 색인·개요 페이지 → 교차검증(제2 출처) → 검색(현재 연도 포함)
5. 전부 실패하면 **학습 데이터로 채우지 않는다.** `[미확인]` + 시도한 URL 을 남기거나
   `[추정]` 등급으로 낮춰 쓴다.

**조회 경로는 환경 규칙을 따른다.** 프로젝트나 사용자 설정이 리서치 도구 우선순위를 정해 두었으면
그것이 이긴다 — 이 스킬은 "1 차 출처를 실제로 조회한다"를 요구할 뿐 어느 도구로 조회할지는
규정하지 않는다.

**deprecated 판정은 출처보다 강하게 하지 않는다.** `권장하지 않음` ≠ `deprecated` ≠ `제거됨`.
3 단계 구분은 `../../references/source-tiers.md` §deprecation.

### Phase 3: 답변 작성

1. 사전 요구사항 — 계정·권한·준비물·수수료·처리기간, 사이트 배정표(Gotcha 6),
   되돌릴 수 없는 지점(Gotcha 7)
2. 스텝 — Step Contract 형식. 말단 액션으로 끝낼 것(Gotcha 1)
3. 최종 상태 — 전부 끝났을 때 화면에서 무엇이 보이는가
4. 뒤처리 — 정리·되돌리기·파기해야 할 것

**대화 모드는 파일을 만들지 않는다.** 사용자가 문서를 원하면 `howto-doc` 을 안내한다.

### Phase 4: 자기 검증 (완료 선언 전)

아래를 전수 대조한다. 하나라도 걸리면 고친 뒤에 답한다.

- [ ] 종결 동사로 안 끝나는 스텝이 0 건인가 (`이 섹션에서`·`해당 항목을`·`적절히`·`알아서`)
- [ ] `확인` 이 빠진 스텝이 0 건인가
- [ ] `안 보이면` 분기가 빠진 스텝이 0 건인가
- [ ] `출처` 등급이 없는 스텝이 0 건인가
- [ ] `[추정]` 이 액션 스텝의 40% 를 넘지 않는가
- [ ] 메뉴 경로에 중간 단계가 빠진 곳이 없는가
- [ ] 방향어(`위`·`아래`·`오른쪽`)로만 지목한 곳이 없는가
- [ ] 요청 범위 밖의 절차를 끼워넣지 않았는가
- [ ] 조회했다고 쓴 스텝이 실제 조회 기록을 갖는가

이 체크리스트는 자기보고다. **기계 판정이 필요하면 문서로 렌더해서 게이트를 돌린다** —
`../../scripts/howto-gate.sh` 의 G5·G6 이 위 1~5 번을 그대로 판정한다.

### Phase 5: 화면 폐루프 (막혔을 때)

로그인 뒤 화면은 도구로 못 본다. **하지만 사용자는 지금 그 화면을 보고 있다.**
절차와 승격 규칙은 `../../references/source-tiers.md` §화면 폐루프.

되묻기를 늘리는 게 아니라 줄인다 — 지금은 사용자가 못 찾아서 되묻는 왕복이 더 많다.
