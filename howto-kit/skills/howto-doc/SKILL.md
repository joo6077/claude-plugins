절차를 **영속 아티팩트**로 남긴다. 대화는 사라지지만 문서는 남아서 계속 읽히므로, 대화 모드보다
판정 기준이 강하다.

## 대화 모드와 무엇이 다른가

같은 Step Contract 스키마를 쓴다 (`../../references/step-contract.md` 가 정본).
**렌더링과 판정만 다르다.**

| | `howto` (대화) | `howto-doc` (문서) |
| --- | --- | --- |
| 산출물 | 대화 텍스트 | MD 파일 |
| 형식 | 자유 렌더 | **고정 마커** (게이트가 읽는다) |
| 판정 | 자기보고 체크리스트 | **결정론 게이트 G1~G6** |
| `관측` 등급 출처 줄 | 생략 가능 | **생략 불가** — G1 이 스텝 수와 출처 줄 수를 대조한다 |
| 소급 재측정 | 없음 | 기존 산출물 전수 재게이트 |

## 고정 마커 — 게이트가 읽는 형식

마커 문자열은 `../../references/step-contract.md` §문서 모드 렌더링 이 정본이고
`../../scripts/howto-gate.sh` 의 판정식과 **짝**이다. 한쪽만 고치면 게이트가 조용히 0 건을 센다.

문서 헤더에 `- 대상:` 을 **반드시** 넣는다. 없으면 G3 가 `no_target_declared` 로 실패한다.
이것은 의도된 설계다 — 대상 플랫폼을 선언하지 않으면 플랫폼 혼용을 판정할 수 없고,
판정할 수 없는 것을 PASS 로 흘리는 것이 기존 킷 G3 의 결함이었다.

## Gotchas

### Gotcha 1: 게이트를 돌리기 전에 완료를 보고하지 마라

`GATE_FAIL` 이면 **그것이 이번 작업의 첫 산출물**이다. 어느 검사가 왜 깨졌는지 보고하고 고친다.

**게이트 출력 전문을 그대로 붙인다.** "게이트 통과함"이라는 문장은 증거가 아니다 —
`GATE_PASS` 를 포함한 7 줄 출력이 증거다.

### Gotcha 2: 게이트를 우회하거나 조건을 느슨하게 고치지 마라

우회된 게이트는 없는 게이트보다 나쁘다. 게이트가 정당한 케이스를 막는다고 판단되면
그 사실을 사용자에게 보고하고 판단을 받는다. 임계 숫자를 킷 안에서 재정의하지 마라 —
같은 상태를 다른 판정으로 가르는 drift 가 실측됐다.

### Gotcha 3: 소급 재측정을 실행 초입에 둔다

절차 문서는 영속 아티팩트라 규칙이 바뀌면 **이미 나간 산출물이 조용히 위반 상태가 된다.**
실측: 한 킷의 쇼케이스 예제가 자기 evals 6 중 3 을 **3 개월간** 위반한 채 배포돼 있었다.
규칙과 evals 는 고쳤는데 이미 나간 산출물을 다시 재는 경로가 없었다.

기존 산출물을 전수 재게이트할 때 **`find` 를 쓴다.** 글로빙을 쓰지 마라 —
zsh 는 `nomatch` 가 기본이라 매치 0 건인 글로브가 명령을 통째로 죽인다.

```bash
find docs -type f -name '*.md' -exec sh -c '
  . howto-kit/scripts/howto-gate.sh
  for f in "$@"; do echo "### $f"; howto_gate "$f"; done
' sh {} +
```

### Gotcha 4: 게이트는 기계 판정 가능한 것만 잡는다

사실 정확성·경로 날조·범위 이탈은 게이트가 못 잡는다. 그것은 여전히 `howto` 의 Gotchas 와
자기 검증 단계의 몫이다. **단일 게이트는 보장이 아니다.**

### Gotcha 5: 파일을 덮어쓰기 전에 읽는다

같은 경로에 기존 문서가 있으면 먼저 읽고, 갱신인지 신규인지 사용자에게 확인받는다.
절차 문서는 사람이 손으로 보태 놓은 현장 지식이 섞여 있는 경우가 많다.

## Process

### Phase 1: 내용 확보

이미 `howto` 로 안내한 절차가 대화에 있으면 그것을 쓴다. 없으면 `howto` 의
Phase 1~2(선행 확인 → 1 차 출처 조회)를 먼저 수행한다. **조회 없이 문서를 만들지 마라** —
문서는 대화보다 오래 남으므로 날조의 수명도 길다.

### Phase 2: 경로 확정

사용자가 경로를 주지 않았으면 묻는다. 추측해서 쓰지 마라. 기존 파일이 있으면 Gotcha 5.

### Phase 3: 렌더

`../../references/step-contract.md` §문서 모드 렌더링 의 고정 마커로 쓴다.
헤더에 `- 대상:` · 적용 범위 스탬프(버전/지역/언어) · 수수료·처리기간·되돌리기 가능 여부를 둔다.

### Phase 4: 게이트 실행 (E3)

```bash
. howto-kit/scripts/howto-gate.sh
howto_gate <생성한 문서>
```

출력 7 줄을 보고에 **그대로** 붙인다. `GATE_FAIL` 이면 고치고 다시 돌린다.

### Phase 5: 완료 보고

게이트 출력 전문 + 생성 경로 + `[추정]`/`[미확인]` 등급 스텝의 건수를 함께 보고한다.
`[추정]` 이 남아 있으면 그것이 무엇인지 명시한다 — 등급을 붙여 파는 것은 정직하지만,
등급이 있다는 사실을 안 알리는 것은 정직하지 않다.

## 관련 스킬

- `howto` — 대화창 즉답. 파일이 필요 없을 때의 기본 모드.
- `howto-audit` — 이미 있는 문서를 판정만 한다 (생성·수정하지 않는다).
