# Howto Kit

> **v0.1.0** — 사람이 손으로 하는 절차를 끊지 않고 안내하는 스택·도메인 무관 킷.

어느 화면 → 어느 메뉴 → 어느 항목 → 무슨 값 → 어떻게 확인까지 안내한다. 기본은 대화창 즉답이고,
요청할 때만 문서로 남긴다. 개발(콘솔 설정, SDK 연동, CI 구성)과 일상(행정 민원, 기기 설정,
계정·구독, 금융·통신) 절차를 모두 다룬다.

## 이 킷이 고치는 것

사용자 불만 원문: *"맨날 다르게 알려주고 자세히 안 알려줘서 내가 몇 번이나 요청해야 함.
어떤 페이지에 정확히 어떤 메뉴를 통해 들어가고 어떤 항목을 어떻게 설정 및 입력하고 이런 걸
안 알려줌."*

| ID | 결함 | 대응 |
|---|---|---|
| F1 | 같은 질문에 매번 다른 절차 | Step Contract 고정 |
| F2 | "설정에서 활성화하세요" 수준의 입도 | 말단 액션 규칙 + 값·확인 필수 (G5·G6) |
| F3 | 학습 데이터 기반 옛 UI | 출처 등급제 + 조회일 스탬프 |
| F4 | 화면에서 항목을 못 찾음 | 딥링크 우선 + 중간 단계 무생략 + 선제 분기 |

**F2 를 F3 로 바꾸지 않는 것**이 이 킷의 핵심 제약이다. 자세히 쓰라는 요구를 날조로 메우는 것이
이 도메인의 최악 실패다. 정확도를 못 올리면 **등급을 낮춰 표기**하지, 지어내지 않는다.

## 출처 등급제

"검증 불가 → 침묵"의 대체물이다. 정직성이 요구하는 것은 침묵이 아니라 등급 표시다.

| 등급 | 표기 | 허용되는 문장 |
|---|---|---|
| `관측` | 표기 생략 | 무엇이든 단정 가능 |
| `문서` | `출처: <URL> (조회 YYYY-MM-DD)` | 라벨·경로·필드명 단정 가능 |
| `추정` | `[추정]` 필수 | 단정 금지. "대개 …에 있습니다" |
| `미확인` | `[미확인]` + 시도한 URL | 이때만 전역 검색어로 우회 |

`추정` 은 금지 대상이 아니라 **라벨 대상**이다. 다만 액션 스텝의 40% 를 넘으면 그대로 내보내지 않는다.

## 결정론 게이트 G1~G6

LLM 호출 없는 순수 판정이다. **G5·G6 이 이 킷의 존재 이유** — 기존 절차 킷 어디에도 입도를 재는
검사가 없었다.

| ID | 검사 | 실패 조건 |
|---|---|---|
| G1 | 출처 원장 완전성 | 액션 스텝 수 ≠ 출처 줄 수 |
| G2 | 미검증 마커 분류 | 접미 없는 레거시 마커 ≥1, 또는 `INVALID` 가 정본 임계 이상 |
| G3 | 도메인 혼용 | 선언한 플랫폼과 다른 계열 경로 혼입, 또는 **대상 미선언** |
| G4 | deprecation 근거 결합 | 주장한 스텝의 출처가 그것을 뒷받침하지 않음 (한국어 토큰 포함) |
| G5 | **말단 액션** | 종결 동사로 끝나지 않거나 회피 표현이 섞인 스텝 ≥1 |
| G6 | **입도 완전성** | `값`·`확인`·`안 보이면`·`출처` 누락 ≥1, 또는 `추정` 비율 > 40% |

G3 는 대상을 선언하지 않으면 **PASS 가 아니라 FAIL** 이다. 판정 불가를 통과로 흘리는 것이
no-op 게이트의 정체다.

```bash
. howto-kit/scripts/howto-gate.sh
howto_gate docs/setup/fcm-ios.md
```

evals 는 서술이 아니라 **실행 결과**로 판정한다. 모든 케이스를 zsh 와 bash 양쪽에서 돌려 출력이
동일한지까지 본다.

```bash
sh howto-kit/evals/run-evals.sh
```

셸 이식성 결함은 한쪽에서만 조용히 통과한다 — 실측 2026-09-08: `set -- $var` 가 zsh 에서
단어분할되지 않아 G5·G6 위반이 zsh 에서만 `GATE_PASS` 로 샜다.

## 이 킷이 사실로 말하지 않는 것

`references/provenance-notes.md` 에 미확정 근거 원장이 있다. **현재 9 절**이며 리서치 사이클이
돌 때마다 늘어난다 — 확정된 것을 옮겨 내고 새로 확인 실패한 것을 더하기 때문이다.

| 절 | 항목 |
| --- | --- |
| 1 | 체크리스트 방법론의 1 차 출처 (READ-DO / DO-CONFIRM · 5~9 항목 · killer item) |
| 2 | Microsoft Learn 권한 인용 1 건 |
| 3 | 변경 로그 피드 3 건 (Firebase · Stripe · Azure updates) |
| 4 | `howto-kit` 외부 이름 충돌 |
| 5 | 딥링크 함정 2 건 (Google 계정 슬롯 · Firebase `_` 설명) |
| 6 | Apple 의 방향어 규정 |
| 7 | 분기 카탈로그 2 건 (언어 분기 문장 · 선제 분기 스타일 조항) |
| 8 | Apple 의 일반 deprecation 정책 |
| 9 | 절차 표준 2 건 (ISO 세부 조항 · verification 규정) |

**확인 실패는 "없음" 이 아니다.** 피드 autodiscovery 링크가 없어도 피드가 살아 있는 반례를
확보했기 때문에 §3 을 "피드 없음" 으로 승격하지 않는다. 같은 이유로 `iso.org` 가 스텁을 주는
것(§9)도 부재가 아니라 접근 차단으로 적는다.

확정된 항목은 원장이 아니라 `docs/howto/` 의 리서치 문서 6 종이 정본이다.

## onboarding-kit 과의 관계

`onboarding-kit` 은 폐기하지 않는다. 개발 레포 안에서 외부 서비스를 붙일 때의 스택 확정과
레포 실측 근거는 실제로 값을 한다. 이 킷이 evals 로 안정화된 뒤 흡수 여부를 재판단한다.
