# 선행 확인 축 (Intake Axes)

절차를 가르는 축만 묻는다. **한 번에 묶어 2~4 문항.** 순차 질문은 "몇 번이나 요청해야 함" 불만을
그대로 재생산한다.

## 원칙

1. **알 수 있는 것은 묻지 않는다.** 레포가 있으면 읽고, 대화에 이미 나왔으면 그것을 쓴다.
2. **답에 따라 갈리는 질문은 다음 라운드로 미룬다.** 1 라운드에 다 묻겠다고 조건부 질문을
   나열하면 사용자가 답할 수 없다.
3. **물을 필요가 없으면 가정을 명시하고 진행한다** — "iOS 26 기준으로 안내합니다. 다르면 알려주세요."
4. **사용자가 이미 확인했다고 말한 사실은 재검증하지 않는다.**

## 축 표

| 축 | 개발 절차 | 일상 절차 |
| --- | --- | --- |
| 플랫폼 | 스택 / OS / 프레임워크 | 기기 / OS 버전 / 웹 vs 앱 |
| 환경 | 로컬 · CI · 프로덕션 | 국가 / 언어 |
| 자격 | 계정 권한 · 요금제 | 계정 등급 · 본인인증 수단 |
| 현재 상태 | 이미 설정된 것이 있는가 | 이미 발급받은 것이 있는가 |

## 개발 절차 축 상세

- **스택** — 같은 서비스를 붙여도 Flutter / 네이티브 / RN 은 SDK·CLI·초기화 코드가 전부 다르다.
  의존성 파일(`pubspec.yaml` · `package.json` · `build.gradle` · `Podfile`)을 먼저 스캔하고,
  확정 못 하면 선택지를 제시해 묻는다.
- **플랫폼/OS** — iOS 와 Android 는 콘솔 화면 자체가 갈린다. 한쪽만 물으면 다른 쪽 경로가 섞인다
  (게이트 G3 가 이 혼입을 잡는다).
- **환경** — 로컬 / CI / 프로덕션에 따라 키의 종류와 저장 위치가 다르다.
- **기존 설정 유무** — 이미 프로젝트가 있는지, 처음부터 만드는지에 따라 첫 스텝이 달라진다.
- **로컬 설치본을 기준값으로 쓸 때는 버전 확인을 첫 단계에 둔다.** 읽은 값은 정확해도 그 시점의 값이다.

## 일상 절차 축 상세

실측으로 확인된 필수 축이다.

- **사이트 배정** — 주민등록등본 = 정부24 / 가족관계증명서 = 대법원 전자가족관계등록시스템 /
  소득금액증명 = 홈택스. **서로 다른 사이트다.** Apple 의 Developer Portal ↔ App Store Connect 와
  같은 유형의 함정이고, 사전 요구사항 맨 위에 작업별 배정표로 박아야 한다
  (`navigation-anchors.md` §6).
- **본인인증 수단** — 정부24 는 *"간편인증 또는 인증서(공동, 금융)"* 로 열거한다. 어느 수단을 쓸지가
  화면 흐름을 가른다.
- **온라인으로 안 끝나는 경우** — 정부24 는 개요에 `신청방법: 인터넷, 방문, 우편, 무인발급기` ·
  `처리기간: 지체없이` · `수수료: 등본 1000원, 초본 500원` 을 구조화해 둔다.
  **이 세 필드를 절차 헤더에 승계한다.** 온라인 안내만 하고 끝내면 방문이 필요한 사용자가 막힌다.
- **기기 / OS 버전** — 같은 설정도 OS 버전마다 경로가 다르다.
- **국가 / 언어** — UI 라벨과 제공 여부가 갈린다.
- **계정 등급 / 권한** — 무료·유료·관리자 여부로 메뉴 자체가 사라진다.

## 되물음 예산

선행 질문은 **1 라운드가 기본, 최대 2 라운드**다. 3 라운드가 필요하다고 느껴지면 축을 잘못
고른 것이다 — 가정을 명시하고 진행한 뒤 화면 폐루프(`source-tiers.md` §화면 폐루프)로
막힌 지점에서 한 번 묻는 편이 왕복이 적다.
