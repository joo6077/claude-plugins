# `grounding` — 메모리 엔트리의 근거 축 (SSOT)

이 파일이 `grounding` 4 값의 **유일한 정의처**다. 다른 스킬·에이전트·스크립트는 값을
재정의하지 말고 이 파일을 참조하라. 정의를 복제하면 판정 기준이 갈라진다.

적용 대상: `~/.claude/projects/*/memory/*.md` 의 `metadata.type: feedback` 엔트리.

```yaml
metadata:
  type: feedback
  grounding: <4 값 중 하나>
```

---

## 왜 저자가 아니라 근거로 가르는가

메모리의 `feedback_*` 엔트리는 **전부 Claude 가 썼다.** 저자(세션 / 카이젠)로 가르면 모두 같은
쪽에 떨어져 아무것도 끊기지 않는다. 가를 축은 **무엇이 그 교훈을 뒷받침하느냐** 다.

문헌이 지목한 오염 경로는 *"국소적으로 맞지만 이전 불가능한 경험을 과일반화"* —
즉 **아무도 확인하지 않은 자기추론**이 영속 규칙으로 증류되는 것이다.
QA 가 REJECT 를 냈다거나 명령 출력이 그렇다는 것은 자기주장이 아니라 **기계적 뒷받침**이다.
차단할 것은 "누가 썼다" 가 아니라 **"아무도 확인하지 않았다"** 다.

---

## 4 값

| 값 | 근거의 성격 | 판정 기준 |
| --- | --- | --- |
| `user_correction` | 외부 **인간** 신호 | 사용자의 교정·지시·불만 발화가 그 교훈의 근거다 |
| `execution_evidence` | 외부 **기계** 신호 | QA verdict · 명령 출력 · 로그 · 실측 수치가 근거다 |
| `mixed` | 둘 다 | 인간 신호와 기계 신호가 **둘 다** 근거로 서술돼 있다 |
| `self_inference` | 외부 검증 **없음** | 근거 서술이 없거나 일반론·추론뿐이다 ← **오염 후보** |

### `user_correction` — 인정 신호

- 사용자 발화의 직접 인용 (`사용자: "..."`, `"..." 라고 지적`)
- "사용자가 ~하라고 지시/교정/요청했다", "사용자 지적으로", "사용자가 분노/불만"
- 사용자가 정한 컨벤션·용어·선호를 그대로 옮긴 것
- 사용자가 제공한 스크린샷·재현 절차로 결함이 드러난 것

### `execution_evidence` — 인정 신호

- QA / 리뷰 verdict: `REJECT`, `APPROVE`, 조건 ID 인용 (`AR-03`, `SC-01` 등)
- 실제 명령 출력 인용: `analyze` 결과, 테스트 실패, exit code, 스택 트레이스, 로그 라인
- 실측 수치: "N 건 확인", "27 곳 vs 3 곳", "760 엔트리 중 351 건"
- 런타임 관측: 스크린샷 대조, 렌더 결과, MCP 도구 응답, 프레임워크 소스 확인
- 도구·API 가 실제로 그렇게 동작함을 **확인한** 서술 (문서 인용 포함)

### `mixed`

위 두 절의 신호가 **각각 하나 이상** 본문에 있다. 흔한 형태:
사용자가 문제를 제기 → 조사·실행으로 원인 확인 → 교훈 도출.

### `self_inference`

- 근거 절(`**Why:**` 등)이 없다
- 있어도 "~하는 것이 좋다", "~가 일반적이다" 같은 **일반론·모범사례 서술**뿐이다
- 실패가 있었다고만 쓰고 무엇이 그것을 드러냈는지(사용자 발화 / 명령 출력)가 없다
- 사후에 스스로 정리한 규칙을 근거 없이 규범화한 것

> `self_inference` 는 **결함 라벨이 아니다.** 맞는 교훈일 수 있다.
> 다만 **아무도 확인하지 않았다**는 사실을 기록해 소비면이 가중치를 낮출 수 있게 한다.

## 판정 절차

1. 본문 전체(특히 근거 절)를 읽는다. `description` 만 보고 판정하지 마라.
2. 인간 신호 유무 · 기계 신호 유무를 **각각** 본다.
3. 둘 다 → `mixed` / 인간만 → 인간 값 / 기계만 → 기계 값 / 둘 다 없음 → `self_inference`.
4. **근거가 없으면 없는 것이다.** 그럴듯하다는 이유로 다른 값을 주지 마라.

### 경계 사례

- **어휘 계수는 근거가 아니다.** "사용자" 라는 단어가 있어도 사용자가 *무엇을 교정했는지*
  서술돼 있지 않으면 인간 신호로 치지 않는다.
- **버그 서술은 그 자체로 기계 신호가 아니다.** "이렇게 하면 깨진다" 는 추론일 수 있다.
  깨진 것을 **관측한 흔적**(출력 · 수치 · verdict)이 있어야 한다.
- **프레임워크 동작 설명**은 소스·문서를 실제로 확인한 서술이면 기계 신호, 통념 인용이면 아니다.
- **사용자가 결정한 정책**(용어·컨벤션·범위)은 검증 대상이 아니라 제약이다 → 인간 신호.
- **다른 엔트리에서 빌려온 관측은 이 엔트리의 근거가 아니다.** 본문이 인용한 도구 동작이
  *이 사건에서 관측된 것*인지, 다른 교훈의 결론을 참조한 것인지 구분하라. 후자는 안 센다.
- **물리 세계 결과는 사용자가 유일한 관측 채널이다.** 출력물 품질, 기기 거동, 육안 렌더 판정처럼
  어시스턴트가 직접 볼 수 없는 결과를 근거로 쓰면, 귀속 문구가 없어도 **인간 신호로 센다.**
  (같은 엔트리에 프로파일 값·메시 수치 같은 검증 산출물이 함께 있으면 둘 다 → `mixed`.)

---

## 소비면 취급 규칙

- 데이터 풀·회수 단계는 외부 신호 보유분(인간 · 기계 · 둘 다)을 **우선 주입**한다.
- `self_inference` 는 **제외하거나 명시 라벨**을 달아 근거로 삼지 않게 한다.
  계약 조건의 PASS 근거로 쓰지 마라.
- 값이 4 값 밖이면 **집계에서 제외하고 제외 건수를 보고**한다. 조용히 삼키지 마라.
- 필드 부재(`grounding` 없음)와 `self_inference` 는 다르다. 부재는 **미태깅**이다.
