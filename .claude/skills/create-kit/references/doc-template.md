# Research Document Template

리서치 문서는 스킬이 참조할 SSOT(Single Source of Truth)다. 모든 스킬은 이 문서의 원칙을 근거로 판단한다.

## 포맷 규칙

```markdown
---
title: {한국어 제목}
version: 0.1.0
last_updated: YYYY-MM-DD
---

# {한국어 제목}

{1-2줄 요약 — 이 문서가 다루는 범위와 핵심}

---

## 원칙

### 1. {원칙 이름}

{구체적 설명. 수치/기준값 포함. 왜 이 원칙이 중요한지.}

> **출처:** [{출처명}]({URL})

### 2. {원칙 이름}
...

---

## 수치 기준

| 항목 | 값 |
|------|-----|
| {구체적 지표} | {숫자 + 단위} |

---

## 안티패턴

| 안티패턴 | 문제 |
|----------|------|
| {잘못된 패턴} | {왜 문제인지} |

---

## Gotchas

- **{반복 실수 패턴}** — {왜 일어나는지 + 어떻게 피하는지}
```

## 작성 원칙

### 1. 출처 없는 원칙은 쓰지 마라

모든 원칙에 `> **출처:** [이름](URL)` 인라인 인용 필수. RFC, 공식 문서, OWASP, CNCF, 학술 논문, 신뢰 엔지니어링 블로그(Netflix/Uber/Stripe/Cloudflare/AWS 등)만 인용. 일반 블로그는 교차 검증 후에만.

### 2. 수치는 구체적으로

"빠른 응답" ✗ → "p50 < 100ms, p99 < 500ms" ✓
"큰 페이지 크기" ✗ → "cursor 기본 20~100" ✓

### 3. 안티패턴은 원인과 함께

문제 현상만 나열하지 말고 "왜 문제인가"를 한 줄로 설명한다.

### 4. Gotchas는 반복 실수

일반 지식이 아니라 "처음 접하면 놓치기 쉬운" 함정만 기록한다.
