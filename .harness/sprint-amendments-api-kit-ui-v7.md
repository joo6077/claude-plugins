## A-06 · 테이블 헤더 이식 (2026-09-03)

**지시** — "테이블 헤더도 가져오지? 그 문서 형식으로 처리한거 / 요청, 응답 이쪽에다가"

park-golf `.table th` (`px-4 py-3 · text-sm · font-semibold · text-secondary · bg-primary-700/10`)
를 세 곳에 붙였다.

| 위치 | 헤더 |
|---|---|
| 요청 파라미터 (경로·쿼리) | `파라미터 · 타입` \| `값 · 설명` |
| 응답 헤더 | `헤더` \| `값` \| `비고` |
| 응답 본문 JSON | `필드 · 값` \| `설명` \| `타입` \| `필수` \| `변경` (sticky) |

**열 정렬을 맞추는 데 세 번 실패했고 원인이 각각 달랐다.**

1. **행마다 셀 개수가 달랐다** — `.j-desc` / `.j-req` / `.j-note` / `.j-pin` 이 해당 값이 있을 때만
   렌더돼 메타 폭이 행마다 달라졌다 (199 행 중 154 행 어긋남). 빈 셀도 항상 그리도록 고쳤다.
2. **헤더에만 padding 을 더했다** — `.j-thead .j-type{padding-left}` 등이 25px 밀었다. 제거.
3. **`ch` 단위가 폰트 크기에 딸려갔다** — 헤더 13px / 행 12px 라 같은 `22ch` 가 191px vs 166px 였다.
   px 고정폭으로 교체. 최종 199 행 중 어긋남 12 행.

**대가** — 메타 열을 고정폭으로 만들자 코드 열이 좁아져 **값이 사라졌다** (실측: `"orderId":` 뒤가 공백).
설명 176→128px, 타입 66→58px, 변경 52→44px 로 줄이고 기본 좌우 분할을 46%→40% 로 옮겨
응답 패널을 넓혔다. 값 있는 119 행 중 값이 안 보이는 행 3 행까지 줄었다.

## A-07 · 구조 diff 탭 제거 — SK-06 무효 (2026-09-03)

**지시** — "구조 diff를 따로 뺄 필요가 있나?"

본문 트리가 인라인으로 같은 정보를 보여주므로 탭을 없앴다. 탭을 남기면 사용자가 두 곳을 번갈아
보게 되고 어느 쪽이 정본인지 흐려진다. 응답 탭은 `본문 / 헤더 / 타이밍` 3 종이 됐다.

거기에만 있던 **「계약 갱신이 필요합니다」 경고는 본문 상단으로 옮겼다.** pin 된 필드가 변경에
걸린 경우에만 뜨고, 변경 표시를 끄면 함께 사라진다 (`pinBreakHTML`).

**direction: relaxing — 계약 조건 SK-06 은 이 결정으로 무효다.**
SK-06 은 "「구조 diff」 탭이 3 건 카드 목록과 계약 갱신 callout 문구를 그대로 유지한다" 를
요구했고, 지금 구현은 그 탭 자체가 없어 **FAIL 이 확정**이다. 사용자 지시에 따른 의도적 폐기이며
평가 시 이 항목은 N/A 로 처리한다. 나머지 28 조건은 유효하다.

## A-09 · 스키마를 JSON 행에서 떼어내 별도 표로 (2026-09-03)

**지시** — "데이터 구조랑 파라미터 얘기한건데 왜 요청 파라미터로 됨? 그리고 json body 없고"

| `.j-note--add` 전부 제거 | gut 3 vs note 0 | 불일치를 잡는다 |

### 재측정

- 배지 7개: `+` 3 · `−` 3 · `string → number` 1. 전부 `title` 보유(chg 제외 — 내용이 곧 설명)
- 행 표본: `+ "discountRate": 0.15, · number +` / `− "legacyCode": 없음 · string −`
- 좌측 거터와 우측 배지가 같은 기호가 되어 **한 행에 같은 기호가 두 번** 나온다.
  좌측은 행 전체를 훑는 열 마커이고 우측은 스키마 열의 배지라 역할이 다르지만,
  중복으로 읽히면 한쪽을 뺄 수 있다 — 사용자 확인 대기

## A-17 · 메타 셀 박스 모델 수정 — 배지가 따로 놀던 원인 (2026-09-04)

**지시** — "플러스 마이너스 좀 따로노는데? 영역이 이상함 중앙이 아니고 그리고 왜 크기가 달라?"

**원인 3가지가 겹쳐 있었다. 전부 A-16 에서 내가 만든 것이다.**

1. **중앙 정렬이 안 먹었다** — `.j-note` 에 `justify-content:center` 를 걸었는데 `<span>` 의 기본값은
   `display:inline` 이다. `.j-meta` 의 flex **아이템**이라 `min-width`·`flex` 는 적용되지만,
   자기 안의 텍스트를 가운데로 밀려면 자신이 flex **컨테이너**여야 한다. 텍스트가 좌측에 붙어 있었다
2. **높이가 제각각이었다** — `.j-note` 는 `padding:1px 6px` 로 내용 높이에 딸려가고,
   `.j-pin` 은 `height:14px` 고정, `.j-type` 은 무지정이었다
3. **`+` 와 `−` 의 폭이 달랐다** — 글리프 폭이 다른데 `padding` 이 고정이라 그 차이가 배지 폭 차이로 그대로 나왔다

**조치** — 메타 셀 4종(`.j-type` · `.j-req` · `.j-note` · `.j-pin`)을 한 규칙으로 묶어
`display:inline-flex; align-items:center; justify-content:center; height:18px; line-height:1` 로 통일.
`.j-star` 도 폭 10px 로 고정했다. `.j-type` 만 `justify-content:flex-end` 로 우측 정렬을 유지한다.

### 재측정

- `+` 배지 **22×18** · `−` 배지 **22×18** — 폭·높이 동일
- 같은 행의 `j-gut` · `j-type` · `j-note` 세로 중심이 **전부 행 중심(972.1)과 일치** (허용 오차 0.6px 내)
- `.j-pin` 18×18, `chg` 배지 113.3×18 (내용이 길어 폭만 다르고 높이는 동일)

## A-18 · pin 툴팁 보강 (2026-09-04)

**질문** — "근데 핀은 무슨 뜻이여?"

UI 가 `고정된 필드` / `계약 pin` 이라고만 적어 두고 **그래서 무슨 일이 생기는지**를 말하지 않았다.
툴팁을 다음으로 바꿨다 (JSON 트리·스키마 표 2곳):

> 계약에 pin 된 필드 — 이 필드의 타입이나 존재가 바뀌면 프로브가 실패합니다

설계문서 §12 "계약 실패 기준 = partial 기본 + pin + exact 옵트인" 의 UI 측 표현이다.
`partial` 모드에서는 응답에 필드가 늘어도 통과하지만, **pin 된 필드만은 예외로 엄격 비교**한다.
`orders.list` 의 `$.meta.total` 이 정확히 그 사례다 — pin 인데 타입이 `string → number` 로 바뀌어
계약 갱신 경고가 뜬다.

## A-19 · pin 재정의 — '값 고정' → '경로별 추가 검사' (2026-09-04)

**질문** — "그러니깐 데이터 고정이 핀이라는거지?" → (내 답이 애매하자) "이거 다시 검색해봐"

**내가 두 번 틀렸다.** 처음엔 "값이 아니라 형태"라고 했고(설계문서 §9.2 와 반대), 그다음엔
설계문서를 그대로 읽어 "값 고정"이라고 했는데 그 정의 자체가 픽스처와 모순이었다.
사용자가 "형태는 원래 고정돼야 하는 게 맞지 않냐"고 짚은 것이 정확했다 — 형태는 partial 이 이미 본다.

### 리서치 (Codex, MODE=research, read-only, foreground)

`pin` 은 조사한 주류 도구 어디에서도 "경로를 값까지 고정" 이라는 뜻으로 쓰이지 않는다.
발견된 용례는 **버전 pin**(Dredd)과 **기준 snapshot pin** 뿐 — 기준물 고정이지 필드별 검증 강도가 아니다.

| 도구 | 값 고정 | 형태 검증 |
|---|---|---|
| JSON Schema | `const` (표준 이름) | `type` · `required` · `enum` |
| Hurl (이 킷의 엔진) | `==` | `exists` · `isInteger` · `matches` |
| Karate | `match ==` | `#string` · `#uuid` · `#ignore` |
| Pact | `equalTo` | matcher / type matching |
| Dredd | hook·custom expectation | **기본이 구조만** (키 존재 + 타입) |
| Jest · insta · ApprovalTests | (기본 exact) | propertyMatcher · redaction · scrubber |

권장 모델은 `partial / assert / exact` 이고 중간 단계는 **경로별 명시 assertion** 이다.
값 고정은 그중 한 종류(`const`)일 뿐이며 total·cursor·id·timestamp 에는 부적합하다.

### 조치 — 이름은 `pin` 유지, 의미만 재정의 (사용자 지시: "재정의하고")

UI 전반에 pin 아이콘이 이미 깔려 있어 이름은 남긴다.

- **픽스처**: `pins:['$.meta.total', …]` → `pins:[{p:'$.meta.total', c:'≥ $.data 길이'}, …]`.
  12 엔드포인트 전부 의미 있는 조건으로 교체 (`= "Bearer"` · `∈ active·shipped·cancelled` ·
  `> 0` · `^ord_ 로 시작` · `true 인 항목 정확히 1개`)
- **상단 strip**: `고정된 필드 📌 $.meta.total` → `추가 검사 📌 $.meta.total │ ≥ $.data 길이`.
  라벨 툴팁에 역할 한 줄
- **행·표 아이콘 툴팁**: `추가 검사 — {경로} {조건}`
- **스키마 표**: pin 행에 조건을 `.sch-cond` 로 함께 표시
- **헤더 배지** `pin 2` → `검사 2` · **범례** `계약 pin` → `추가 검사` ·
  **팔레트 스코프** `pin 보유` → `추가 검사가 걸린 엔드포인트`
- **경고 문구 귀속 수정**: "pin 대상이므로 계약 갱신" → "타입이 바뀌었습니다 — **기본 검사**(존재·타입)에서
  실패합니다. 이 필드에는 추가 검사(…)도 걸려 있어 함께 다시 봐야 합니다."
  타입 변경은 pin 이 아니라 partial 이 잡는다. 픽스처 diff 노트의 같은 오귀속도 고쳤다
- **설계문서**: §9.2 표 + 근거 문단(도구별 어휘·필드 성격별 assertion 표·출처 URL), §12 결정 갱신

### 곁가지 수정

`.callout b{display:block}` 이라 문장 중간의 `<b>추가 검사</b>` 가 줄을 끊었다.
인라인 강조용 `.callout .em` 을 따로 뒀다.

### 재측정 (1280×820, 11 엔드포인트 전수)

- 칩·표·툴팁·배지·범례 전부 조건 노출 확인 (auth.token `= "Bearer"` / `≥ 60`,
  users.addresses `true 인 항목 정확히 1개` 등)
- 값 잘림 1 (기존 `auth.token $.scope`, A-14 에서 title 부여) · 넘침 0 · 콘솔 에러 0
- strip 높이 73px, 줄바꿈 없음
