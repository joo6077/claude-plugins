## A-01 — ER-02 측정이 오탐을 낸다 (취지는 만족, 재는 낱말이 넓다)

**앵커**: ER-02 측정 — 대상 20 개 파일에 `grep -c '10 카테고리\|V1~V10\|V1-V10'` 이 **0**

**무엇이 어긋났나**: 고친 뒤 재니 **3 건**이 나온다. 전부 검사 카테고리와 무관하다.

| 파일 | 줄 | 실제 내용 |
| --- | --- | --- |
| `.claude/skills/backend-kaizen/SKILL.md` | 26 | backend-kit 감사의 **10 카테고리 명명 규칙** (Architecture · API Design · Database …) |
| `.claude/skills/infra-kaizen/SKILL.md` | 25 | infra-kit 감사의 **10 카테고리 명명 규칙** (Container · CI/CD · Kubernetes …) |
| `.claude/skills/rust-kaizen/SKILL.md` | 105 | backend-audit 참조 — `10 카테고리 Rule-by-Rule` |

**내 변경이 만든 것이 아니다.** 봉인 전에도 있었다 (실측: `git show 2ae9794~1` 에서 같은 줄
1 건 확인). 셋 다 "감사 카테고리 10 종" 이라는 다른 개념이다.

**취지는 만족한다.** 조건의 취지는 "검사 개수를 새로 박지 않았는가" 이고, 검사 번호 표기만
좁혀 재면 **0 이다**.

```bash
# 취지대로 좁혀 재기 — 검사 번호 표기만
grep -c 'V1~V10\|V1-V10' <대상 20 개>   # 총 0
```

**왜 이런 조건을 썼나 — 내가 이번 세션에 만든 규칙을 또 어겼다.** 세 스프린트 전에
`contract-design-guide` 에 "취지가 서술 부재라면 낱말 하나로 재지 마라 · 재려는 낱말이 다른
문맥에서 이미 쓰이고 있으면 아무것도 안 고쳐도 통과한다 · **그 낱말의 현재 건수를 봉인 전에
실측**하라" 를 넣었다. 그런데 이 계약을 쓸 때 `10 카테고리` 의 현재 건수를 재지 않고 봉인했다.
`V1~V10` 은 0 임을 확인했지만 `10 카테고리` 는 안 봤다. 이번에는 방향이 반대다 — 안 고쳐도
통과하는 것이 아니라 **고쳤는데도 FAIL 이 난다.**

**amend_direction**: `unchanged` — 조건을 고치지 않았다. 판정은 QA 에 맡긴다. 취지 대 측정의
어긋남을 그대로 보고하는 것이 봉인 규칙을 지키는 길이다.

**다음 계약에 반영할 것**: 개수 표기를 재는 조건은 `V1~VN` 형태(검사 번호)만 쓴다. `N 카테고리`
는 이 레포에서 감사 카테고리와 겹친다. 그리고 규칙대로 **재려는 낱말 전부의 현재 건수를 봉인 전에
실측**한다 — 하나만 재고 넘어가면 이번과 같은 일이 생긴다.

## A-02 — 구현 중 고친 것 3건 (조건 판정에 영향 없음)

1. **명령 블록이 번호 목록을 끊었다.** 검사 목록을 얻는 명령을 `design-kaizen` 등 3 개 파일의
   5 번 항목 뒤에 넣었더니 6 번 항목이 목록에서 떨어져 마크다운 경고 5 조합이 늘었다
   (MD029 · MD031 · MD032). 목록 밖(다음 `##` 헤더 앞)으로 옮겨 해소했다. 앞 스프린트가
   문서 삽입으로 표를 끊은 것과 같은 형태다 — 이번엔 **목록**이었다.
2. **`` `|-: ` `` 코드 span 안 공백** 이 MD038 을 냈다. "파이프 · 붙임표 · 콜론 · 공백" 으로
   풀어 적었다.
3. **`**FAIL 예시**`** 가 MD036 을 냈다. 그 파일의 기존 절들이 같은 형태를 쓰지만 새로 늘리지
   않으려고 평문("FAIL 출력은 이런 형태다")으로 바꿨다.

셋 다 고친 뒤 마크다운 경고가 기준값과 같다 (347 건 · 49 조합 · 늘어난 조합 0).

## 다음 스프린트로 남기는 것

**측정 명령이 조건 둘째 줄부터라 봉인에 안 덮인다.** `conditions_digest` 는 조건의 **첫 줄만**
해싱하고 평가자의 1-e-3 걸러내기도 첫 줄만 뺀다. 그래서 이어지는 줄 — **재는 명령이 사는
자리** — 은 봉인에도 안 덮이고 조건 변경으로도 안 잡힌다. 조건을 느슨하게 만든 행위와 배경
설명을 늘린 행위가 같은 무게로 취급된다.

하위 호환 문제가 있다. 해싱 범위를 넓히면 기존 계약 63 개가 전부 `SEAL_BROKEN` 이 된다.
새 필드(`measurement_digest` 같은)를 두고 없는 계약은 `ABSENT` 로 다루는 설계가 필요하다 —
`SEAL_ABSENT` 를 다루는 방식과 같다.
