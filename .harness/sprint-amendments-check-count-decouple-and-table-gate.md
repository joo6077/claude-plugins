
**왜 이런 조건을 썼나 — 내가 이번 세션에 만든 규칙을 또 어겼다.** 세 스프린트 전에

문맥에서 이미 쓰이고 있으면 아무것도 안 고쳐도 통과한다 · **그 낱말의 현재 건수를 봉인 전에
실측**하라" 를 넣었다. 그런데 이 계약을 쓸 때 `10 카테고리` 의 현재 건수를 재지 않고 봉인했다.
`V1~V10` 은 0 임을 확인했지만 `10 카테고리` 는 안 봤다. 이번에는 방향이 반대다 — 안 고쳐도
통과하는 것이 아니라 **고쳤는데도 FAIL 이 난다.**

**amend_direction**: `unchanged` — 조건을 고치지 않았다. 판정은 QA 에 맡긴다. 취지 대 측정의
어긋남을 그대로 보고하는 것이 봉인 규칙을 지키는 길이다.

**다음 계약에 반영할 것**: 개수 표기를 재는 조건은 `V1~VN` 형태(검사 번호)만 쓴다. `N 카테고리`
는 이 레포에서 감사 카테고리와 겹친다. 그리고 규칙대로 **재려는 낱말 전부의 현재 건수를 봉인 전에
실측**한다 — 하나만 재고 넘어가면 이번과 같은 일이 생긴다.

## A-05 — 판정 뒤 고친 것 (조건 판정에 영향 없음)

부모 교차 진단이 판정을 뒤집을 근거는 없다고 하면서 흠 몇 가지를 짚었다. 이 스프린트 범위 안에서
고칠 수 있는 것만 고쳤다.

1. **V10 의 코드 블록 인식이 들여쓴 블록을 못 알아봤다.** V6 은 `line.strip().startswith` 인데
   V10 은 `startswith` 만 썼다. V6 과 같은 기준으로 맞췄다
2. **범위를 넓힌 이유가 사실과 달랐다.** 계약·함수 설명·기준 문서 세 곳이 "표가 끊긴 자리는
   `harness/docs/guides/` 였고 V6 범위 밖" 이라 적었는데, 실제로 끊긴 자리는
   `harness/references/contract-schema.md` 라 **원래 V6 범위 안**이었다. 함수 설명과 기준 문서를
   "같은 종류의 문서가 `docs/` 에도 있어서" 로 고쳤다. 계약 본문은 봉인돼 고치지 않는다
3. **`validate-plugin.py` 도움말과 주석에 옛 개수(9)가 남아 있었다.** 사용자에게 보이는 `--help`
   가 틀린 개수를 말했다. 개수를 빼고 "등록된 검사 전부" 로 바꿨다 — 이 스프린트의 요지를 스크립트
   자신에게도 적용한 것이다. SK-01 의 측정이 `.py` 를 건너뛰어 조건으로는 안 잡혔다
