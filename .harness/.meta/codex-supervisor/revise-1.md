계약 수정 요청 (반복 1 회차 / 상한 2). 파일 범위 · 제약 · 검증 · 출력 규칙은 처음 지시 그대로다. 아래 지적만 반영하고, 지적과 무관한 조건 줄은 바꾸지 마라.

## 지적 1 — 출처: Claude 평가자 계약 검토 (판정 REJECT)
- 전체 문제: 요구사항 §2 의 「『엄격한 감사관』 같은 역할 말은 넣지 않는다」, 「프롬프트는 짧게, 예시를 잔뜩 붙이지 않는다」 가 어느 조건에도 없다. 구조-02 의 지시문 검사(measure.py `isolation()`)는 있어야 할 낱말(PASS · FAIL · 증거 · 데이터 · 긍정 · 반대 · 빠진)만 보고, 없어야 할 낱말은 보지 않는다. 구현이 지시문에 「엄격한 감사관」 을 넣거나 예시를 과하게 붙여도 통과한다.
- 고칠 방법: 해당 조건(구조-02 또는 새 조건)에 금지 낱말 검사를 넣는다 — 역할 · 엄격성 부여 말(예: 엄격, 감사관, strict, harsh, auditor 의 역할 부여 꼴). 「짧게」 는 잴 수 있는 기준(예: 판정 지시문 크기 상한)으로 바꾸고 기준값의 근거를 적는다.
- 확인 방법: 템플릿 지시문에 금지 낱말을 넣은 음성 대조 사본에서 그 검사가 FAIL 하는지 `--negative` 로 확인한다. 금지 낱말 검사가 0 을 기대하므로 양성 대조(금지 낱말이 든 표본에서 1 이상)도 붙인다.

## 지적 2 — 출처: 부모(구현을 맡을 Claude) 지적. 요구사항 문서 본문에 근거가 있다
- 전체 문제: 요구사항 §2 마지막 줄 「운영 전에 답을 아는 좋은 예 · 나쁜 예로 감독관이 맞게 판정하는지 확인한다」 가 조건에 없다. 계약 `## 배경` 은 「실제 Codex 호출은 이 묶음에 0 회」 라고 적어, 실제 감독관(모델)이 좋은 구현을 APPROVE · 나쁜 구현을 REJECT 하는지, 실제 세션 기록에 모델 · 생각 강도가 남는지(사용자 결정 7)를 아무 조건도 실제로 재지 않는다. 가짜 codex 시험만으로는 판정 지시문 · 답 모양이 실제 모델에서 통하는지 알 수 없다.
- 고칠 방법: 실제 codex 를 부르는 조건을 최소로(1 개 권장) 추가한다. 작은 임시 git 저장소에 조건 1 ~ 2 개짜리 계약과 좋은 구현 · 나쁜 구현을 만들어 `impl` 을 각각 돌리고, 좋은 예 종료 0 · 나쁜 예 종료 1 · 나쁜 예 `## 고칠 것` 세 칸 채움 · `report.md` 차례 줄의 모델 · 생각 강도가 실제 세션 기록의 `turn_context` 값과 같음을 잰다. 조건 아래에 「실제 codex 호출 · 비용 발생」 을 적는다. 감독용 폴더는 감독 설정 기본값을 따른다.
- 확인 방법: 구현 전인 지금은 그 조건이 MISSING 으로 FAIL 한다. 측정이 실제 codex 없이는 PASS 할 수 없는지(가짜 CODEX_BIN 을 거부하거나 실제 세션 기록을 요구하는지) 측정 코드로 보인다.

## 그 밖
- 조건을 더하면 frontmatter `conditions:` 와 `## 범위 경계` 의 대응표를 맞춘다. 기능 조건이 20 을 넘으면 범위 경계에 이유를 적는다.
- 끝나면 처음 지시의 검증(구문 · 저장 검사 · verify.py)을 다시 돌리고, 최종 답에 바꾼 조건 번호 목록과 그 명령 출력을 적는다.
