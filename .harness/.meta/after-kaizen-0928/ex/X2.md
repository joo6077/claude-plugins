## 2. 주장별 판정과 인용

### FCM 설정에서는 APNs 인증 키를 업로드해야 한다 — 맞음

Firebase 원문:

> “Upload your APNs authentication key to Firebase.”

또한 업로드 단계에서 적어도 하나의 개발 또는 프로덕션 인증 키가 필요하다고 명시한다. 다만 이 페이지 본문에는 `.p8` 문자열이 없다.

### APNs 인증 키 파일은 `.p8`이다 — 맞음, 단 Firebase 문서 단독 근거로는 원문에 없음

Apple 원문:

> “An authentication token signing key, specified as a text file (with a `.p8` file extension).”

따라서 기술적으로 APNs 인증 키를 `.p8`이라고 설명하는 것은 맞다. 하지만 현재 `source`에 적힌 Firebase iOS 설정 문서만으로 `guide_includes(".p8")`를 요구하는 것은 출처 충실성 기준에서 틀림이다. Apple 문서를 추가 출처로 붙이면 정당화된다.

### Apple이 `.p8`을 `.p12`보다 일반적으로 “권장”한다 — 원문에 없음

Apple은 토큰 방식의 성능·운영상 이점을 설명하지만, `.p8`을 `.p12`보다 모든 경우에 권장한다는 포괄적 문장은 찾지 못했다.

인증서 기반 문서의 실제 표현은 조건부다:

> “As a result, it’s often simpler to use token-based authentication to support multiple apps.”

즉 “여러 앱을 지원할 때 토큰 방식이 흔히 더 단순하다”는 뜻이다.

추론: 토큰 방식이 더 빠르고, 하나의 토큰을 여러 서버·앱에 쓸 수 있다는 설명은 선택 근거가 될 수 있지만, 이를 “Apple 권장 방식”으로 일반화하면 원문보다 강한 표현이다.

### `.p12` 인증서 방식은 deprecated다 — 틀림

Apple은 현재도 TLS 인증서 방식을 공식 절차로 문서화한다. `.p12`도 명시한다:

> “The certificate and key are saved … in the Personal Information Exchange format (a file with a `.p12` file extension).”

따라서 `.p12`를 deprecated라고 쓰면 원문과 배치된다.

### Firebase iOS 설정 문서에는 `.p12` 또는 certificate가 언급되지 않는다 — 맞음

현재 페이지 본문 검색 결과 `.p12`, `certificate` 모두 일치 항목이 없었다. 다만 `.p8` 역시 언급되지 않는다. 문서가 직접 말하는 것은 `APNs authentication key` 업로드다.
