### C. “GitHub 밖 CI의 기준 커밋 조회 명령은 없다”

저장소 문장:

- [phase8-notes.md:70](/Users/jackson/Hub/10_Dev/claude-plugins/.claude/worktrees/after-0928/.harness/.meta/kaizen-0924/phase8-notes.md:70): “GitHub 밖 CI 의 기준 커밋 조회 명령 — 근거 파일에 없다”
- [phase8-notes.md:123](/Users/jackson/Hub/10_Dev/claude-plugins/.claude/worktrees/after-0928/.harness/.meta/kaizen-0924/phase8-notes.md:123): “GitHub 밖 CI 의 조회 명령은 없다.”

원문:

- GitLab: `sha` 매개변수는 “Return pipelines for the specified commit SHA.” ([원문](https://docs.gitlab.com/api/pipelines/), 2026-09-28)
- GitLab 엔드포인트: `GET /projects/:id/pipelines`
- Buildkite: `commit`은 “Filters the results by the commit (only works for full SHA, not for shortened ones).” ([원문](https://buildkite.com/docs/apis/rest-api/builds), 2026-09-28)
- Buildkite는 pipeline별 build 목록 엔드포인트도 제공한다.

판정:

- “당시 근거 파일에 없었다”는 [70행]의 기록: **맞음**. 이는 그 근거 파일의 범위에 관한 말이다.
- “GitHub 밖 CI의 조회 명령은 없다”는 [123행]의 일반 주장: **틀림**. GitLab과 Buildkite 모두 공식 API에서 커밋 SHA 필터를 제공한다.

추론: 공식 매개변수를 결합하면 다음 조회가 가능하다.

```sh
# GitLab
curl --header "PRIVATE-TOKEN: <token>" \
  "https://gitlab.example.com/api/v4/projects/<project-id>/pipelines?sha=<full-sha>"

# Buildkite
curl -H "Authorization: Bearer $TOKEN" \
  "https://api.buildkite.com/v2/organizations/<org>/pipelines/<pipeline>/builds?commit=<full-sha>&exclude_jobs=true"
```

이 API들은 해당 SHA의 실행을 찾게 해 주지만, 그 결과 하나만으로 “필수 검사 집합 전체가 통과했다”거나 실패 원인이 무엇인지까지 증명하지는 않는다.

## 4. 못 가져온 것 / 열린 질문

- 웹 열기 도구는 해당 페이지들의 본문을 반환하지 않았다. 요청대로 `curl`로 다시 시도했고, 위 여덟 원문은 모두 성공적으로 가져왔다.
- Argo CD 3.5 문서에서 Flux처럼 “API가 제거됐다”는 원문은 찾지 못했다. 확인된 것은 이벤트 조회 gRPC 응답 타입 변경, REST 경로 유지, 일부 플래그·기능의 폐기 예정이다.
- GitLab·Buildkite 공식 문서는 SHA별 실행 조회를 뒷받침하지만, 저장소의 “내 변경/기준 실패/환경” 분류 자체를 공식 규범으로 정하지는 않는다. 그 분류는 계속 킷 자체 규칙으로 표시해야 한다.
