# 계약 수정 요청 1 (반복 1 회차 / 상한 2)

지적과 무관한 조건 줄은 바꾸지 않는다.

## 지적 1 — 출처: Claude 평가자 계약 검토 (REJECT)
- 오류-02 문제: `codex-audit.sh models` 를 단독으로 부를 때 조회 실패(HTTP 401 · 깨진 JSON · 시간 초과 · 인증 파일 없음 · npm 실패 · 명령 없음)를 어떻게 처리하는지 재지 않는다. 측정 `discovery_failures()` 는 실패를 draft · revise · impl 안에서만 주입하고, `models` 는 성공하는 기준 · 복구 호출에만 쓴다. `models` 가 처리 안 된 예외로 죽어도 모든 조건이 통과한다.
- 고칠 방법: 오류-02 에 「또는 `models` 를 단독으로 부르면」 을 더하고, 실패 주입 뒤 `models` 를 직접 불러 `모델 확인 못 함: 사유` 출력과 정한 종료 코드를 재는 분기를 측정에 더한다.
- 확인 방법: `models` 가 처리 안 된 예외로 죽는 가짜 수정에서 새 분기가 FAIL 하는지 음성 대조로 확인한다.

## 지적 2 — 출처: Claude 평가자 계약 검토
- 오류-02 문제: 조건은 「조회 상한 2 초」 인데 측정은 `http_delay=5` 에서 전체가 15 초 미만인지만 본다. 상한을 무시하고 5 초를 기다려도 통과한다.
- 고칠 방법: 경계를 좁히거나(예: 4 초 미만) 가짜 서버 쪽에서 요청이 끊긴 시점을 직접 잰다.
- 확인 방법: 상한을 무시하는 가짜 구현에서 FAIL 하는지 확인한다.

## 지적 3 — 출처: 부모(구현을 맡을 Claude), 사용자 발언 근거
- 전체 문제: 2026-10-06 대화에서 사용자가 진행 보고를 두고 「너무 많이 로그를 남기는 거 같기도」 라고 했다. 명령 하나마다 줄을 찍으면 진행 창이 금방 길어지고, 그 줄을 채팅으로 옮기면 Claude 가 줄마다 깨어나 토큰을 많이 쓴다. 진행 창(백그라운드 작업 카드) 출력 자체는 Claude 를 깨우지 않으므로 토큰이 들지 않는다.
- 고칠 방법: `follow` 의 Codex 상태 줄은 명령마다가 아니라 (가) 큰 단계 줄(감독 시작 · 사전 측정 끝 · 차례 시작 · 차례 끝 · 다시 시도 · 조사 · 재심 · 최종 판정)은 바로, (나) 그 밖의 Codex 활동은 정한 간격(기본 60 초)마다 요약 한 줄 — 그 사이 실행한 명령 수와 지금 하는 일(자료 읽기 · 측정 시험 · 파일 쓰기 · 생각 중 · 답 작성) — 로 찍는다. (다) 오류 · 조용함 경고는 바로 찍는다. 사전 측정 n/m 줄은 조건이 많으면 같은 간격 요약으로 묶어도 된다. 문서(SKILL · qa-evaluator)의 「채팅에 옮긴다」 는 큰 단계 · 오류 · 조용함 · 최종 판정만으로 좁힌다.
- 확인 방법: 명령 수십 개를 내는 가짜 Codex 로 follow 줄 수가 (큰 단계 수 + 경과 분 수 + 경고 수) 안쪽인지 잰다.
