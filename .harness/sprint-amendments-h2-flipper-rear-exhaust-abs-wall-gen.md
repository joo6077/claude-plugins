## A-01 · 「묶음 지문」은 접는 방법이 값을 바꾼다 — QA 의 결함 보고는 오진이었다

QA 는 PETG 폴더 묶음 지문을 「같은 방법으로 재현할 수 없었다」며 계약 결함으로 올리고, 파일 수정
시각과 자체 지문식으로 대신 뒷받침했다. 교차 진단이 이것을 반증했고 내가 직접 다시 쟀다 —
**같은 폴더 같은 10 개 파일인데 접는 방법에 따라 여섯 값이 나온다.**

```text
(a) cd 뒤 상대경로 + xargs            d422a04c00816cfa   ← 이 계약 기준 2 가 적은 값
(b) 절대경로 + 맨 xargs               e3b0c44298fc1c14   ← 경로 공백에 쪼개져 빈 입력. 파일 0 개
(c) 절대경로 + print0 / xargs -0      5d8dea48e2925664   ← 앞선 PETG 스프린트가 적은 값
(d) cd 뒤 상대 + 내용만 (경로 제외)   f8d06c6963cd7de4
(e) cd 뒤 상대 + sort 없이            742c4935bc0885e1
(f) 결과를 한 번 더 정렬              058027e4257789d2
```

(a) 가 이 계약이 쓴 방법이고 지금도 그 값이 나온다. 그러니 **기록값은 재현 가능하며 계약 결함은
「재현 불가」가 아니다.** 진짜 결함은 **계약이 그 방법을 안 적어서 여섯 갈래 중 어느 것인지 알 수
없게 둔 것**이다. 같은 폴더가 앞선 스프린트에서는 (c) 로 적혀 있어, 두 값이 같은 대상을 가리키면서
서로 다르다.

가장 위험한 것은 **(b)** 다. `60_3D Print` 의 공백에 `xargs` 가 쪼개져 `shasum` 이 파일을 하나도
읽지 못하는데, 빈 문자열의 지문 `e3b0c44298fc1c14` 가 조용히 나온다 — 검사가 죽었는데 값이 있다.

올바른 방법은 이것이다.

```bash
cd "/Users/jackson/Hub/60_3D Print/Settings/h2-flipper-rear-exhaust"
find . -type f | sort | xargs shasum -a 256 | shasum -a 256 | cut -c1-16
# → d422a04c00816cfa   (2026-09-26 12:20 재확인, 파일 10 개)
```

**QA 쪽 절반도 빠져 있었다** — 기록된 값을 「재현 못 했다」고 결론내기 전에 **실행 위치를 바꿔 한 번
더 재는** 절차가 없었다. 강한 근거(직접 대조)가 `cd` 한 줄 거리에 있는데 약한 근거(파일 시각)로
내려갔다. 그리고 QA 가 권한 개선안(`! -name '.DS_Store'` 를 덧붙이기)은 **기록값을 낼 때 없었던
제외 조건을 나중에 끼워 넣는 것**이라 대조가 조용히 깨지는 길이다 — 채택하지 않는다.

## A-02 · DG-02 의 N/A 사유가 틀렸다 (판정은 유지)

계약은 DG-02 를 `N/A (… 레포 쪽 변경은 마크다운과 JSON 뿐이라 편집기 진단 대상이 아니다)` 로
적었다. **사실이 아니다** — 마크다운은 진단 대상이고 이 레포는 과거에 바로 그것 때문에 REJECT 가
났다. 실측으로 대신 확인했다.

```text
기준 커밋 f81568d 판   332 건
현재 판                332 건        → 새 경고 0 건
줄 길이 규칙을 켜면    972 건        → 검사가 살아 있다 (값이 갈린다)
```

바꾼 MD 3 개(SKILL.md · surface-recipes.md · bambu-fields-baseline.md), 편집기와 같은 설정
(`MD013` 끔). 결과는 문제없고 **사유만 틀렸다.** 다음 계약에서는 N/A 사유를 「그건 검사 대상이
아니다」로 쓰지 말고 **돌려서 0 건임을 보인 뒤** N/A 로 내린다.

## A-03 · RE-01 의 N/A 사유가 약하다 (판정은 유지)

사유가 「재사용 단위 코드 0 개」인데, 실제로는 `SKILL.md` 안에 박힌 파이썬 검사 코드가 바뀌었다
(벽 예산 판정 4 줄 → 세 갈래 8 줄). 새 함수·모듈을 만든 것은 아니어서 판정은 유지되지만, 문서에
박힌 코드도 재사용 단위로 볼 여지가 있다. 미리 N/A 로 선언하는 조건은 **봉인 전에 사유를 한 번
실측으로 확인**하고 그 출력을 계약에 남겨야 이런 어긋남이 안 생긴다.

## A-04 · 아무도 재지 않은 축 — 「숫자만 쓰는 길」이 열려 있다

새 검사는 `_wall_outer_block_ratio` 가 **적혀 있기만** 하면 통과한다. 그 값이 실제로 두 번 잘라 센
것인지, 손으로 그럴듯하게 써 넣은 것인지 구분하지 못한다. `"_wall_outer_block_ratio": "0.9"` 를
타이핑한 설정은 실측한 설정과 똑같이 통과한다. 세 갈래 설계는 「안 재고 넘어가는 길」은 막았지만
「숫자만 쓰는 길」은 열어 뒀다.

계약도 QA 도 이 축을 다루지 않았다. **이번 범위 밖으로 둔다** — 값의 출처를 요구하려면 측정 명령 ·
산출물 경로 · 측정 시각을 함께 기록하게 해야 하고, 그것은 기록 키 하나를 넘어 Phase 1.0 측정 절차와
기록 형식을 건드리는 별개 스프린트다. 사용자 판단으로 넘긴다.
