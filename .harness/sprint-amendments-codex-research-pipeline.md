# sprint-amendments-codex-research-pipeline

계약 본문은 봉인돼 있다. 조건 문구를 고치지 않고 여기에 적는다.

## A-01 — SC-01 · SC-02 · SC-03 · SC-04 · ER-03 의 측정 명령 정정

- amend_direction_oracle: **narrowing**
- 확정 시각: 2026-09-12 18:45

### 무엇을 바꿨나

원 측정 `grep -c '^## '` → 개정 측정 `grep -c '^- rollout: '`.

### 왜

원 측정은 엔트리 개수를 세지 못한다. 로그는 codex 응답을 원문 그대로 담는데, 그 응답 본문에
마크다운 제목(`## ...`)이 들어 있으면 그것까지 엔트리로 센다. 실측으로 확인했다.

- `2026-04.md` — 원 측정 5496, 개정 측정 1597
- `2026-09.md` — 원 측정 30, 개정 측정 30 (이 파일은 우연히 일치)

엔트리 1건마다 `- rollout: ` 줄이 정확히 하나씩 붙으므로 개정 측정이 엔트리 수와 일대일 대응한다.

### 방향 계산

개정 측정이 세는 줄의 집합은 원 측정이 세는 줄의 집합의 부분집합이다(`- rollout: ` 로 시작하는
줄은 `## ` 로 시작하지 않으므로 실제로는 서로 다른 줄을 세지만, 계수 결과로 보면 개정 측정이
원 측정보다 작거나 같다 — 4월 5496 → 1597, 9월 30 → 30). 거짓 통과 여지가 줄어들므로
**narrowing** 이다. 계약 조건을 느슨하게 만들지 않았다.

### 재실행 결과

정정한 측정으로 격리 검증 19항목을 다시 돌려 전부 통과했다(PASS=19 FAIL=0). 음성 대조 4항목도
별도로 통과해, 구현을 무력화하면 해당 측정이 실제로 실패한다는 것을 확인했다.

4곳은 전부 codex-kaizen 쪽이었다. 조건(AR-04·SK-02)의 측정 대상은 처음부터 각 파일을 따로
보고 있었으므로 판정에는 영향이 없다. 배경 서술의 오류로만 남긴다.

## A-03 — DG-04 측정문 정정 (QA 지적)

- amend_direction_oracle: **narrowing**
- 확정 시각: 2026-09-12 19:10 · 근거: QA 평가

원 측정은 훅 실행 후 로그의 누적 `via:` 개수가 1 이상인지만 보았다. 그 값은 이번 스프린트
이전부터 이미 25건 이상이라, **훅이 아무 일도 하지 않아도 항상 PASS** 가 나왔다. 실행 전후
개수를 계산은 했지만 판정에 쓰지 않은 것이 원인이다.

개정 측정은 상태 목록에서 한 건을 빼고 훅을 돌려 그 한 건이 다시 담기는지 본다(증가 >= 1).
시험 후 상태 목록은 원래대로 되돌린다.

양성 대조로 측정이 살아 있음을 확인했다 — 아무 일도 하지 않는 가짜 훅으로 돌리면 증가 0 으로
FAIL, 진짜 훅으로 돌리면 증가 1 로 PASS.

같은 지적으로 `negative_control.sh` 의 `probe()` 가 쓰던 구버전 지표(`^## `)도 `^- rollout: `
으로 맞췄다. 이 데이터셋에서는 판정이 바뀌지 않았지만 A-01 과 같은 유형의 재발 소지였다.

거짓 통과 여지가 줄어들므로 두 정정 모두 narrowing 이다.

## A-04 — 읽을 수 없는 파일도 기록 (QA 권장, 계약 범위 밖 후속)

- amend_direction: 해당 없음 (조건 추가가 아니라 계약 이후 개선)
- 확정 시각: 2026-09-12 19:40 · 근거: QA 평가의 권장 + 사용자 승인

QA 가 지적한 사각지대를 메웠다. 훅이 세션 기록을 읽다 예외를 만나면 상태 목록에만 넣고 로그에는
아무 흔적도 남기지 않았다. ER-02(종료 코드 0)는 충족했지만, 이 스프린트가 고치려던 문제
("개선 근거가 되어야 할 실패가 안 남는다")와 같은 유형이 파싱 예외 쪽에 그대로 남아 있었다.

이제 `unreadable` 상태로 엔트리를 남기고 실패 이유를 `errors` 줄에 적는다. 세션 시각을 못 읽으
므로 달은 파일명에서 골라낸다(`month_for`). 기본값이 두 곳에 중복되지 않도록 `empty_result()`
로 뺐다.

검증: 격리 시험에 ER-04 4항목을 더해 23/23 통과. 음성 대조도 항목을 더해 5/5.

### 음성 대조 자체의 결함도 고쳤다

SC-03 의 변이가 현재 코드와 맞지 않아 **원본이 그대로 실행**되고 있었는데, 결과는 "눈먼 측정"
으로 보고돼 엉뚱한 곳을 의심하게 만들었다. 이제 모든 변이에 `cmp` 로 적용 여부를 먼저 확인하고,
적용되지 않았으면 «변이 실패 — 시험 무효» 로 구분해 보고한다. 무력화하지 않은 시험을 통과로
세지 않는다.

로그 개수를 세는 자리의 zsh 글로빙도 `find … -exec` 로 바꿨다. 로그 파일이 0 건일 때
`*.md` 확장이 실패해 명령이 통째로 죽고, 그것이 판정 오류로 이어졌다.
