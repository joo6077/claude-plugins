# TOOL-CALL-EVIDENCE 조건 검증 절차 (generic)

스킬/도구 호출을 주장하는 계약 조건은 "주장"이 아니라 **호출 명령 + 출력 산출물**로 검증한다.
인사이트 Friction #5(스킬/도구 가짜 호출 — `/insights`를 실제 호출하지 않고 기존 파일만 읽은 뒤
"호출했다"고 주장)에 대응한다. 글로벌 룰(스킬호출증거)의 운영판으로, QA 검증 시점에 적용한다.

## 검증 방법

1. 계약 조건에서 "X 스킬/도구를 호출/실행했다", "생성/갱신했다" 류 동사를 식별한다
2. 각 주장에 대해 **산출물 1개**를 요구한다 — 호출 명령 텍스트, 도구 출력, 또는 변경된 파일 경로+라인
3. 산출물이 없거나 "읽기만 하고 호출했다고 주장"한 흔적이면 해당 조건 FAIL

## 정적 검증 최소 증거

| 조건 유형 | PASS 가능한 최소 증거 |
|-----------|----------------------|
| "{스킬/도구}를 호출했다" | 호출 명령 텍스트 + 출력 일부(파일 경로/exit code/생성물) |
| "{파일}을 생성/갱신했다" | `git diff --stat` 또는 대상 파일 경로:라인 인용 |
| "{검사/빌드}를 실행했다" | 명령 + 종료 코드 또는 결과 요약(테스트 N pass 등) |

## 금지 패턴 (선택)

- 호출 주장 옆에 산출물이 0개 — Read만 하고 실행으로 보고하는 false-completion
- "호출했습니다"만 있고 명령/출력 인용 없음 — 검증 불가 = FAIL
