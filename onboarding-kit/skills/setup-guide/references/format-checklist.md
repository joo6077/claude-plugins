# Format Checklist — 가이드 MD 포맷 표준

생성되는 가이드 MD는 아래 11개 섹션을 **이 순서로** 구성한다. 순서는 표준이지만 채우기 할당량은 아니다 — 요청 서비스에 해당 없는 섹션(클라이언트 전용 SDK의 IAM, 단발 셋업의 환경 분기 등)은 "해당 없음" 한 줄로 닫거나 생략한다. 억지 내용으로 부피를 늘리지 말 것 (SKILL.md Gotcha 7). 사용자가 따라가다 막히지 않도록 각 섹션의 누락 방지 체크리스트.

## 필수 섹션 순서

### 1. 헤더

- 가이드 제목 (`# <서비스명> 설정 가이드`)
- `> 작성일: YYYY-MM-DD`
- `> 기준 버전: <SDK/CLI 버전>` (가능한 한 정확한 버전 명시)
- `> 공식 문서: <URL>` (1차 출처)

### 2. 사전 요구사항

- 필요한 계정/권한 (예: Apple Developer Program 가입)
- 설치해야 할 CLI 도구 (버전 포함)
- 프로젝트 전제조건

> **사이트 혼동 주의 박스** (Apple/Google/AWS 가이드는 필수): 진입할 사이트 URL과 다른 비슷한 사이트의 차이를 표로 명시.

### 3. 설정 단계 (Step 1~N)

각 Step은 4단 구조. 맨 위 `**출처:**` 가 출처 원장(SKILL.md §출처 원장)의 아티팩트다 — **이 줄을 채울 수 없으면 그 Step 은 아직 쓸 준비가 안 된 것이다.**

```text
**출처:** <이 Step 의 근거 1차 출처 URL — 조회 YYYY-MM-DD>

**어디서:** <URL 또는 터미널 위치>

**무엇을:**

1. <구체적 액션 — 클릭 경로 또는 명령어>
2. ...

**확인 방법:** <성공 검증 방법 — 명령어, 콘솔 위치, 예상 출력>
```

- 여러 Step 이 같은 문서를 근거로 하면 같은 URL 을 반복해도 된다 — 생략하지 않는다
- fetch 가 끝까지 실패했으면 `**출처:** [미검증] — <사유>` 로 남긴다. 이 표기가 2 건 이상이면 가이드는 완료가 아니라 부분 완료다
- 헤더(§1)의 대표 `공식 문서:` URL 은 Step 별 출처를 **대체하지 않는다**

각 Step에 필요시:

- ⚠️ 주의 박스 — 흔한 실수
- ❌ Deprecated / ✅ 현재 권장 박스 — 더 이상 안 쓰는 방법

### 4. 프로젝트 코드 변경

스택별로 변경할 파일과 코드를 구체적으로:

- 파일 경로 명시 (예: `lib/main.dart`, `ios/Runner/AppDelegate.swift`)
- 추가/변경할 코드 블록 (언어 라벨 필수)
- 설정 파일 변경 (예: `pubspec.yaml`, `.env`)

### 5. 권한 / IAM

| 시스템 | 필요한 권한 | 누구에게 |
|--------|-------------|----------|

최소 권한 원칙. 셋업용 권한과 운영용 권한 분리 권장.

### 6. 비용

- 무료 한도 (예: FCM 무제한, Firebase Spark plan)
- 유료 진입점 (어느 시점부터 과금)
- 예상 월비용 범위

### 7. 환경 분기 (dev / staging / prod)

- 환경별로 별도 프로젝트가 필요한지
- 환경별 키/설정 파일 분리 패턴
- Build Configuration 별 차이

### 8. Rollback / 정리

- 잘못 설정했을 때 되돌리는 방법 (구체적 명령어 또는 콘솔 경로)
- 사용 안 할 때 리소스 정리 (과금 방지)

### 9. 보안 체크리스트

- [ ] 비밀 키 (`.p8`, JSON service account 등) 안전 저장소 보관
- [ ] `.gitignore`에 비밀 파일 패턴 추가
- [ ] 클라이언트 노출 가능 키와 서버 전용 키 구분
- [ ] FCM 등록 토큰/사용자 토큰의 서버 측 격리

### 10. 검증 체크리스트

- [ ] <검증 항목 1> — 확인 명령어/위치
- [ ] <검증 항목 2>
- [ ] <검증 항목 3>

### 11. 트러블슈팅

각 항목:

```text
**증상:** <에러 메시지 또는 현상>
**원인:** <원인 분석>
**해결:**

1. <구체적 단계>
2. ...
```

## 톤 / 표기 규칙

- 모든 클릭 경로는 `→` 화살표로. **중간 단계를 건너뛰지 않는다** — 한 단계라도 빠지면 사용자가 화면에서 못 찾는다. 실측 예 (Firebase Console — [FCM Apple 클라이언트 문서](https://firebase.google.com/docs/cloud-messaging/ios/client) 2026-07-27 조회, 문서 표기 그대로): `Settings ⚙️ → General → Cloud Messaging 탭 → iOS app configuration → APNs authentication key → Upload`. 이전 표기는 `General` 단계가 빠져 있었다
- 명령어는 코드 블록 + 언어 라벨 (`bash`, `swift`, `dart` 등)
- 한국어 라벨과 영어 라벨 병기 (`업로드 (Upload)`) — 콘솔이 다국어 지원 시 사용자가 화면에서 매칭 가능하게. **단 1차 출처는 대개 영문이므로, 한국어 라벨은 번역 추정이다** — 영문 라벨을 정본으로 적고 한국어를 괄호에 넣는다. 반대로 하면 사용자가 화면에서 못 찾는다
- 외부 도메인은 마크다운 링크로 (`[Identifiers 페이지](https://...)`) — bare URL 금지
- 어려운 용어는 괄호 풀이 (`Service Account (서비스 계정 — 자동화용 가상 사용자)`)
