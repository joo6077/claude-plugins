# Gotchas

1. **원칙/가이드라인 추출 금지** — 이 스킬은 비주얼 사례만 수집한다. NNGroup, Apple HIG 등의 원칙을 정리하거나 `docs/design/`에 쓰지 마라. 그건 design-research 영역이다.
2. **오픈소스 DS API/구조/철학 분석 금지** — Radix, Shadcn 등의 아키텍처나 코드 구조를 분석하지 마라. `docs/design/systems/`에 이미 있다. 렌더링된 컴포넌트의 시각적 형태만 수집한다.
3. **컨셉 도출 금지** — 레퍼런스를 모아서 컨셉을 도출하는 것은 design-concept의 역할이다. 이 스킬은 수집과 분류까지만 하고, 컨셉 해석은 하지 않는다.
4. **접근 불가 사이트 강제 크롤링 금지** — WebFetch 실패 시 에러를 던지지 말고 건너뛰어라. 대체 소스에서 수량을 채운다. 최종 수집 수가 목표의 80% 미만이면 사용자에게 알린다.

# Process

## Step 0: 자동 감지 및 로드

`.design/concept.md`가 존재하는지 확인한다:
- 존재 → 컨셉의 무드 키워드, 컬러 방향, UI 패턴을 검색 키워드로 활용
- 미존재 → 사용자가 직접 키워드를 제공

## Step 1: 검색 키워드 구성

수집 대상을 결정한다:
- 사용자 입력 키워드 (예: "미니멀 SaaS 대시보드")
- 컨셉 문서에서 추출한 무드 키워드
- 수량: 기본 30개, `--count N`으로 사용자 조절 가능

## Step 2: 소스별 크롤링

references/crawl-sources.md를 참조하여 3개 소스 채널에서 크롤링한다:

### 2-1: 디자인 갤러리 (~10개)
- Dribbble, Awwwards, siteinspire에서 키워드 검색
- WebSearch로 관련 작품 URL 수집 → WebFetch로 시각 정보 분석
- 수집 항목: 레이아웃 구조, 컬러 조합, 타이포 사용, 전체 분위기

### 2-2: 실제 프로덕트 사이트 (~12개)
- 해당 도메인의 실제 서비스 사이트 크롤링
- WebFetch로 HTML 구조, 사용된 컬러, 간격, 컴포넌트 패턴 분석
- 수집 항목: 네비게이션 패턴, 정보 구조, 인터랙션 패턴

### 2-3: 오픈소스 DS 컴포넌트 비주얼 (~8개)
- Ant Design, Chakra UI, Radix, shadcn/ui 등의 컴포넌트 쇼케이스 페이지
- 렌더링된 컴포넌트의 시각적 형태만 수집 (API/구조 분석 안 함)
- 수집 항목: 버튼/카드/입력 필드 등의 시각 스타일, variant, 상태 표현

### 접근 불가 시 처리
- WebFetch 실패 → 해당 사이트 건너뛰기
- 같은 소스 채널 내 다른 사이트로 대체
- 최종 수집 수가 목표의 80% 미만이면 사용자에게 알림

## Step 3: 분석 문서 생성

templates/references.md 포맷으로 `.design/references.md`를 생성한다:

```markdown
# 디자인 레퍼런스

> 생성일: {{date}}
> 키워드: {{keywords}}
> 수집 수: {{count}}/{{target}}

## 디자인 갤러리
| # | 소스 | URL | 레이아웃 | 컬러 | 타이포 | 참고 포인트 |
|---|------|-----|----------|------|--------|-------------|
| 1 | Dribbble | {{url}} | {{설명}} | {{설명}} | {{설명}} | {{설명}} |

## 실제 프로덕트
| # | 서비스명 | URL | 네비게이션 | 정보 구조 | 컴포넌트 패턴 | 참고 포인트 |
|---|----------|-----|-----------|-----------|---------------|-------------|

## 오픈소스 DS 컴포넌트
| # | DS명 | 컴포넌트 | 시각 스타일 | variant | 상태 표현 | 참고 포인트 |
|---|------|----------|------------|---------|-----------|-------------|
```

## Step 4: 비주얼 카탈로그 HTML 생성

templates/reference-catalog.html 포맷으로 `.design/reference-catalog.html`을 생성한다:
- 소스 채널별로 분류된 시각 카탈로그
- 각 레퍼런스의 핵심 시각 요소를 CSS로 재현 (컬러 팔레트, 레이아웃 스케치, 컴포넌트 형태)
- 필터링 가능 (소스 채널별, 참고 포인트별)
- 브라우저에서 바로 열어 확인 가능한 standalone HTML

## Step 5: 사용자 피드백

- 분석 문서와 비주얼 카탈로그를 사용자에게 제시
- 추가 크롤링 요청이나 특정 레퍼런스 삭제 요청 반영
- 확정 시 다음 단계 안내: `/design-mockup`으로 시안 생성 또는 `/design-component`로 컴포넌트 정의
