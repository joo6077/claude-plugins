# 다크 패턴 방지 & 윤리적 디자인

사용자를 기만하는 디자인 패턴을 식별하고 윤리적 대안을 제시하며, 관련 법적 기준과 감사 방법을 정리한다.

---

## 원칙

### 1. 사용자 자율성을 존중한다

사용자는 충분한 정보를 바탕으로 자유롭게 의사결정할 수 있어야 한다. 선택의 자유를 보장하되, 그 선택이 정보에 기반한 것(informed choice)이어야 한다. 옵션을 숨기거나 이해하기 어렵게 만들어 특정 선택을 유도하는 것은 자율성 침해다.

### 2. 투명성을 유지한다

가격, 약관, 데이터 수집 범위, 구독 조건은 사용자가 결정을 내리기 **전에** 명확히 공개해야 한다. 결제 직전에 숨겨진 비용이 나타나거나, 작은 글씨로 조건을 숨기는 것은 투명성 위반이다.

### 3. 동의는 명시적이어야 한다

GDPR과 한국 개인정보보호법 모두 "명시적 동의(explicit consent)"를 요구한다. 사전 체크된 체크박스, 스크롤하면 동의한 것으로 간주, 번들 동의(하나를 수락하면 전부 수락)는 유효한 동의가 아니다.

### 4. 가입만큼 탈퇴도 쉬워야 한다

서비스 가입이 3단계면 해지도 3단계 이내여야 한다. "Roach Motel" 패턴 — 들어가기는 쉽고 나오기는 어려운 — 은 가장 흔하고 가장 해로운 다크 패턴 중 하나다.

## 다크 패턴 분류

Harry Brignull은 2010년 darkpatterns.org를 등록하고 기만적 사용자 인터페이스를 체계적으로 분류했다. 이후 학계, 규제 기관, 소비자 보호 단체가 이 분류 체계를 채택했다.

> **출처:** [Wikipedia — Dark Pattern](https://en.wikipedia.org/wiki/Dark_pattern)

### 12가지 다크 패턴 유형

#### 1. Confirmshaming (수치 유발 거절)

거절 옵션을 수치스럽게 표현하여 수락을 유도한다.

```
[다크 패턴]
  ┌──────────────────────────────┐
  │  20% 할인 쿠폰 받으세요!     │
  │                              │
  │  [네, 할인 받을래요!]         │
  │                              │
  │  아니요, 저는 돈을 아끼는 데  │
  │  관심 없어요                  │
  └──────────────────────────────┘

[윤리적 대안]
  ┌──────────────────────────────┐
  │  20% 할인 쿠폰 받으세요!     │
  │                              │
  │  [쿠폰 받기]  [괜찮습니다]    │
  └──────────────────────────────┘
```

#### 2. Roach Motel (바퀴벌레 모텔)

가입/구독은 쉽지만 해지/탈퇴는 극도로 어렵게 만든다.

| 다크 패턴 예시 | 윤리적 대안 |
|---------------|------------|
| 해지하려면 전화 필수 | 온라인 해지 제공 |
| 해지 버튼이 설정 깊은 곳에 숨김 | 구독 관리 → 해지 버튼 명확히 배치 |
| 해지 전 5단계 인터뷰 강제 | 1클릭 해지 + 선택적 피드백 |

#### 3. Trick Questions (함정 질문)

이중 부정이나 혼란스러운 문구로 사용자가 의도하지 않은 선택을 하게 만든다.

```
[다크 패턴]
  □ 마케팅 이메일을 받지 않으려면 체크하지 마세요
  (이중 부정: 체크 안 하면 받겠다는 건지, 안 받겠다는 건지 혼란)

[윤리적 대안]
  □ 마케팅 이메일 수신에 동의합니다 (기본: 체크 해제)
```

#### 4. Sneak into Basket (몰래 장바구니 추가)

사용자가 요청하지 않은 항목을 장바구니에 자동 추가한다.

#### 5. Hidden Costs (숨겨진 비용)

결제 마지막 단계에서 배송비, 수수료, 세금 등 추가 비용을 공개한다.

| 다크 패턴 | 윤리적 대안 |
|-----------|------------|
| 결제 직전에 "서비스 수수료 ₩3,000" 표시 | 상품 페이지에서 총 비용 표시 |
| "무료 배송" 표기 후 조건부 부과 | 무료 배송 최소 금액 명시 |

#### 6. Bait and Switch (미끼 전환)

사용자가 기대한 결과와 다른 결과를 제공한다. X 버튼을 누르면 창이 닫히는 대신 다른 페이지로 이동하는 경우가 대표적이다.

#### 7. Forced Continuity (강제 연장)

무료 체험이 끝나면 사전 경고 없이 유료 결제로 전환한다.

| 다크 패턴 | 윤리적 대안 |
|-----------|------------|
| 무료 체험 종료 후 자동 결제 | 종료 3일 전 이메일/알림 + 원클릭 취소 |
| 결제 정보 입력 필수 무료 체험 | 결제 정보 없이 체험 가능, 전환 시 결제 요청 |

#### 8. Friend Spam (친구 스팸)

사용자의 연락처에 무단으로 초대/홍보 메시지를 발송한다.

#### 9. Disguised Ads (위장 광고)

광고를 콘텐츠나 내비게이션처럼 위장한다. "다운로드" 버튼처럼 보이는 광고 배너가 대표적이다.

#### 10. Misdirection (시선 유도)

사용자의 시선을 의도적으로 다른 곳으로 유도하여 특정 옵션을 놓치게 만든다.

```
[다크 패턴]
  ┌─────────────────────────────┐
  │  [██ 프리미엄 시작하기 ██]   │  ← 크고 화려한 버튼
  │                             │
  │      무료로 계속하기          │  ← 작고 흐린 텍스트 링크
  └─────────────────────────────┘

[윤리적 대안]
  ┌─────────────────────────────┐
  │  [프리미엄 시작하기]          │  ← Primary 버튼
  │  [무료로 계속하기]            │  ← Secondary 버튼 (동일 크기)
  └─────────────────────────────┘
```

#### 11. Privacy Zuckering (프라이버시 속임수)

기본 설정을 최대 데이터 공유로 해놓고, 프라이버시 보호는 복잡한 설정 메뉴 깊은 곳에 숨긴다.

| 다크 패턴 | 윤리적 대안 |
|-----------|------------|
| 기본값: 모든 데이터 공유 허용 | 기본값: 최소 수집, 필요시 사용자가 확대 |
| 프라이버시 설정 7단계 중첩 | 설정 최상위에 프라이버시 섹션 배치 |
| "맞춤 경험을 위해 필요합니다" | 각 데이터 항목별 구체적 사용 목적 설명 |

#### 12. Price Comparison Prevention (가격 비교 방해)

제품 간 가격 비교를 어렵게 만드는 의도적 패키지/가격 구조 설계.

## 법적 기준

### EU Digital Services Act (DSA)

2023년 8월 초대형 플랫폼(월 4,500만+ EU 사용자)에 먼저 적용, 2024년 2월부터 모든 플랫폼에 적용된 EU 규정이다. 공격적인 팝업, 혼란스러운 동의 버튼 등 기만적 디자인 전술을 명시적으로 금지한다.

X(트위터), Meta, Shein, Temu, TikTok, AliExpress 등이 다크 패턴 사용 혐의로 법적 조치를 받고 있다.

> **출처:** [CBTW — Dark Patterns Are Now Illegal in the EU](https://cbtw.tech/insights/illegal-dark-patterns-europe)

### EU Digital Fairness Act (DFA) — 예정

DSA와 DMA(Digital Markets Act)를 보완하는 법안으로, 2025년 공개 의견 수렴, 2026년 초안 발표가 예정되어 있다. 기만적 패턴에 대한 규제 공백을 메우는 것이 목적이다.

> **출처:** [Digital Fairness Act Updates](https://www.digital-fairness-act.com/)

### FTC (미국 연방거래위원회)

FTC의 2024년 조사에서 642개 웹사이트/앱 중 **76%**가 최소 하나의 기만적 패턴을 사용하고, **67%**가 복수의 기만적 패턴을 사용하고 있었다. FTC는 기만적 디자인에 대해 벌금 부과 권한을 강화하고 있다.

> **출처:** [EU Parliament — Regulating Dark Patterns](https://www.europarl.europa.eu/RegData/etudes/ATAG/2025/767191/EPRS_ATA(2025)767191_EN.pdf)

### 한국 전자상거래법

2024년 2월 13일 국회 통과, 2025년 2월 14일 시행된 개정 전자상거래 등에서의 소비자보호에 관한 법률은 6가지 유형의 다크 패턴을 규제한다.

| 유형 | 한국어 명칭 | 설명 |
|------|------------|------|
| Hidden Renewal | 숨겨진 자동 갱신 | 구독 갱신/가격 인상 시 별도 동의 없이 자동 진행 |
| Sequential Price Disclosure | 순차적 가격 공개 | 결제 단계별로 추가 비용이 나타남 |
| Pre-selected Options | 사전 선택 옵션 | 추가 상품/서비스가 기본으로 체크 |
| Poor Hierarchy | 불량 계층 구조 | 해지/거부 버튼을 찾기 어렵게 배치 |
| Obstruction | 해지 방해 | 탈퇴/해지 절차를 불필요하게 복잡하게 만듦 |
| Repeated Interference | 반복 방해 | 거부한 제안을 반복적으로 표시 |

공정거래위원회는 2024년 10월 구독 플랫폼 4개사에 시정 명령과 과징금을 부과했다. 2025년 10월에는 소비자보호 지침을 추가 개정하여 시행 중이다.

> **출처:** [김·장 법률사무소 — 다크패턴 규제 강화를 위한 전자상거래법 개정](https://www.kimchang.com/ko/insights/detail.kc?sch_section=4&idx=29766)

## 윤리적 대안

각 다크 패턴에 대응하는 윤리적 디자인 대안을 정리한다.

| 다크 패턴 | 윤리적 대안 | 설계 원칙 |
|-----------|------------|-----------|
| **Confirmshaming** | 중립적 거절 문구 ("괜찮습니다", "건너뛰기") | 존중 |
| **Roach Motel** | 가입 경로와 동일한 수준의 해지 경로 | 대칭성 |
| **Trick Questions** | 긍정형 단문, 사전 체크 해제 | 명확성 |
| **Sneak into Basket** | 추가 항목은 명시적 "추가" 버튼 필요 | 명시성 |
| **Hidden Costs** | 상품 페이지에서 총 비용(세금, 배송비 포함) 표시 | 투명성 |
| **Bait and Switch** | 버튼/링크의 동작이 라벨과 정확히 일치 | 예측 가능성 |
| **Forced Continuity** | 체험 종료 3일 전 알림 + 원클릭 취소 | 알림 의무 |
| **Friend Spam** | 연락처 접근 전 명확한 설명 + 개별 동의 | 동의 |
| **Disguised Ads** | 광고에 "광고" 라벨 명시, 콘텐츠와 시각적 구분 | 구분성 |
| **Misdirection** | 모든 선택지에 동등한 시각적 무게 부여 | 공정성 |
| **Privacy Zuckering** | 기본값을 최소 수집으로, 설정 접근 용이하게 | 프라이버시 |
| **Price Comparison Prevention** | 동일 단위(월/연, 1인/팀)로 가격 표시 | 비교 용이성 |

## 넛지 vs 조작

### Richard Thaler의 자유주의적 개입주의 (Libertarian Paternalism)

Richard Thaler와 Cass Sunstein은 2008년 "Nudge: Improving Decisions About Health, Wealth, and Happiness"에서 넛지(nudge) 개념을 제안했다. 넛지란 **선택지를 제거하거나 경제적 인센티브를 크게 바꾸지 않으면서** 예측 가능한 방식으로 행동을 변화시키는 선택 설계(choice architecture)의 요소다.

> **출처:** [Wikipedia — Nudge (book)](https://en.wikipedia.org/wiki/Nudge_(book))

### 넛지의 조건

| 조건 | 설명 |
|------|------|
| 선택의 자유 보장 | 사용자가 언제든 다른 선택을 할 수 있어야 한다 |
| 이탈 비용 없음 | opt-out이 쉽고 불이익이 없어야 한다 |
| 사용자 이익 지향 | 넛지의 방향이 사용자의 이익에 부합해야 한다 |
| 투명성 | 넛지의 존재를 숨기지 않는다 |

### 넛지 → 조작의 경계선

| 요소 | 넛지 (윤리적) | 조작 (비윤리적) |
|------|--------------|----------------|
| **기본값** | 에너지 절약 모드를 기본으로 | 데이터 공유를 기본으로 |
| **프레이밍** | "90%의 의사가 권장" | "이 약을 먹지 않으면 위험" |
| **시각적 강조** | 건강한 메뉴에 초록 라벨 | 해지 버튼을 회색으로 숨기기 |
| **사회적 증거** | "80%의 고객이 이 요금제 선택" | "서두르세요! 3명이 보고 있습니다" (가짜) |
| **선택 구조** | 중요 옵션을 상단에 배치 | 불리한 옵션만 눈에 띄게 배치 |

### 판별 기준: 3가지 질문

1. **사용자가 알면 반대할까?** 넛지의 존재를 사용자에게 설명했을 때 "그래, 그게 좋겠다"고 동의한다면 넛지. "속았다"고 느낀다면 조작.

2. **이탈 비용이 있는가?** opt-out이 opt-in만큼 쉬우면 넛지. 해지하려면 전화해야 하고 30분 대기해야 한다면 조작.

3. **누구의 이익인가?** 사용자의 장기적 이익에 부합하면 넛지. 기업의 매출만을 위한 것이면 조작.

> **출처:** [Cambridge Core — Nudge and the Manipulation of Choice](https://www.cambridge.org/core/services/aop-cambridge-core/content/view/D1ED64479FF868BD79FFE90E76A4AB54/S1867299X00002762a.pdf)

## 디자인 감사 체크리스트

### 다크 패턴 감사 프로세스

**1단계: 사용자 여정 매핑**
주요 플로우(가입, 구매, 구독, 해지, 데이터 설정)를 단계별로 기록한다.

**2단계: 각 단계에서 다음을 검증**

| # | 점검 항목 | 위반 유형 |
|---|-----------|-----------|
| 1 | 모든 비용이 결제 전에 공개되었는가? | Hidden Costs |
| 2 | 기본값이 사용자 이익에 부합하는가? | Privacy Zuckering, Pre-selected Options |
| 3 | 거절/해지 경로가 수락/가입 경로만큼 쉬운가? | Roach Motel, Obstruction |
| 4 | 거절 문구가 중립적인가? | Confirmshaming |
| 5 | 체크박스가 기본 해제 상태인가? | Trick Questions, Pre-selected Options |
| 6 | 구독 갱신/가격 변경 전 사전 알림이 있는가? | Forced Continuity, Hidden Renewal |
| 7 | 모든 선택지에 동등한 시각적 무게가 부여되었는가? | Misdirection, Poor Hierarchy |
| 8 | 광고가 콘텐츠와 명확히 구분되는가? | Disguised Ads |
| 9 | 연락처/데이터 접근 전 명확한 설명이 있는가? | Friend Spam, Privacy Zuckering |
| 10 | 장바구니에 사용자가 직접 추가하지 않은 항목이 있는가? | Sneak into Basket |
| 11 | 한 번 거부한 제안이 반복 표시되는가? | Repeated Interference |
| 12 | 버튼/링크의 동작이 라벨과 일치하는가? | Bait and Switch |

**3단계: 긴급도 분류**

| 등급 | 기준 | 조치 기한 |
|------|------|-----------|
| **Critical** | 법적 위반 (전자상거래법, GDPR, DSA) | 즉시 수정 |
| **High** | 사용자 이탈/신뢰 손상 직결 | 1주 내 |
| **Medium** | 사용자 경험 저하 | 1개월 내 |
| **Low** | 개선 권장 | 다음 스프린트 |

### 정기 감사 주기

| 대상 | 주기 | 담당 |
|------|------|------|
| 결제/구독 플로우 | 분기 1회 | 제품 + 법무 |
| 개인정보 설정 | 법률 변경 시 | 법무 + 제품 |
| 마케팅 팝업/배너 | 캠페인 변경 시 | 마케팅 + UX |
| 전체 서비스 | 연 1회 | 외부 UX 감사 |

## 조직 문화

### 윤리적 디자인을 유지하려면

1. **다크 패턴 차단을 OKR/KPI에 포함**: "단기 전환율 상승"만 측정하면 다크 패턴이 유인된다. 해지율, 고객 불만 건수, 신뢰 점수를 함께 추적한다.

2. **"고객이 알면 화낼까?" 테스트를 디자인 리뷰에 포함**: 새 기능/UI 변경 시 이 질문을 공식 체크리스트에 넣는다.

3. **A/B 테스트 윤리 가이드라인**: 전환율 향상을 위한 A/B 테스트가 다크 패턴 실험이 되지 않도록 사전 윤리 검토를 수행한다.

4. **디자이너의 거부권**: UX 디자이너가 비윤리적 요구를 거부할 수 있는 조직 문화와 절차가 필요하다.
